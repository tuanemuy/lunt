# サービス運営（OM）

サービス運営者が、対応の必要な申請・申立て・連絡を把握し、対象を探して運営し、カテゴリーと役割を管理する画面を定める。画面の一覧、ナビゲーション、共通の状態（CS）、共通の機能（CF）、状態の示し方は [index.md](index.md) が定める。

- OM のすべての画面は、サービス運営者の役割を持つ利用者だけが開ける（CS-05）
- 申請の判断は CM-01、管理者の権限の解除と管理権限の付与は CM-02 が負う。店舗・掲載・地域・イベントの内容を変える操作は、店舗管理・地域運営・イベント運営と同じ画面を代行で開いて行う。OM の画面は入口だけを持つ
- サービス運営者は全員が同じ操作範囲を持つ。別のサービス運営者が先に確定した操作は CS-08 で、先に保存した内容との競合は CS-07 で示す

## OM-01 対応が必要なもの

- 目的: サービス運営者の対応を待つ申請・代行できる申請・申立て・連絡を、種類を区別して確かめる
- シナリオ: OPE-01、APP-08
- 入口: MY-01 のサービス運営、運営のナビゲーション「対応が必要なもの」、サービス運営者の役割の付与の通知

### 機能

- 対応が必要なものを、次の4種に分けて一覧で確かめる。種ごとに件数を示し、対応を待ち始めた日時の古い順に並べる
  - サービス運営者が承認者である確認中の申請
  - 代行できる申請（地域運営者・イベント運営者が一定の期間確認していない、所属・離脱・参加の確認中の申請）
  - 対応を終えていない取り下げの申立て
  - 対応を終えていない情報の誤り・閉店の連絡
- 1件ごとに、種類、対象、申請者（申立てでは申立人、連絡では連絡した利用者）を示す。示し方は index.md の「申請の状態」による
- 1件を選び、対応する画面へ進む。申請は CM-01、代行できる申請は CM-01 の代行、申立ては OM-04、連絡は OM-05 を開く
- 一覧に示す範囲は、index.md の「申請の状態」による。開いた画面で判断・対応が成立した件と、申請者・運営者・他のサービス運営者の操作で対応が要らなくなった件は、一覧から外れる
- この画面は、判断と対応の操作を持たない

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-09 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 一覧 | 4種を区別して示す | 画面を開く |
| CS-09 空 | 対応が必要なものが1件もないことを示す。1件もない種は、種ごとにないことを示す | 対応が必要なものがない |

選んだ1件がすでに対応を要しない状態になっていた場合は、開いた画面（CM-01、OM-04、OM-05）が CS-08 で現在の状態を示し、この画面へ戻す。

## OM-02 対象を探す

- 目的: 店舗・掲載・地域・イベントを、非公開のものを含めて探し、対象の運営か新しい登録へ進む
- シナリオ: SHP-12、SHP-13、LST-15、LST-16、MEM-05、REG-12、REG-13、EVT-12、EVT-13、MOD-07、MOD-08、MOD-09
- 入口: 運営のナビゲーション「対象を探す」

### 機能

- キーワード（店舗は店名・住所）で、店舗・掲載・地域・イベントを探す。閲覧者に表示されない対象（下書き、一時非公開、公開の取り下げ、運営による非公開、非公開の店舗）も結果に含める
- 結果は種類を分けて、関連度の高い順に示す。対象ごとに、管理者の有無と、対象の状態を示す（index.md の「管理する対象の状態」）。掲載は店舗名を併せて示す
- 対象を選び、OM-03 へ進む
- 新しい登録へ進む。店舗の代理登録は SM-02、地域の登録は RM-02、イベントの登録は EM-02 を、新規の状態で開く
- 店舗の代理登録の入口は、店名・住所で店舗を探した結果と併せて示す（RQ-02 の新規店舗の登録の入口と同じ型）。登録する店舗が、非公開の店舗を含めて存在しないことを、結果で確かめてから進む
- 重複する店舗は、それぞれをここで探して OM-03 で確かめる

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-09 と CF-05 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力前 | キーワードの入力と、地域・イベントの登録の入口を示す | 画面を開く |
| 結果 | 種類ごとの結果を示す。店舗を探した結果には、店舗の代理登録の入口を併せて示す | キーワードで探す |
| CS-09 空 | 合う対象がないことを示す。キーワードを変えるか、新しい登録へ進める | 結果が0件 |

## OM-03 対象の運営

- 目的: 選んだ対象の公開の状態と管理者の有無を確かめ、非公開とその解除を行い、代行とメンバーの管理へ進む
- シナリオ: MOD-07、MOD-08、MOD-09、MEM-05
- 入口: OM-02、OM-04（申立ての対象）、OM-05（連絡の対象）、CM-01（登録申請の照合）、管理者が不在の対象についての管理者宛ての通知

### 機能

- 対象の種類、名称、状態、管理者の有無を示す。掲載は紐づく店舗を示し、その店舗の OM-03 へ進める。閲覧者が閲覧できる対象は、閲覧側の詳細（DT-01〜DT-04）へ進める
- 掲載・地域・イベントを運営による非公開にし、解除する。店舗を非公開にし、解除する。管理者の有無と、対象の公開状態（下書き・公開・一時非公開・公開の取り下げ）を問わない。非公開にする操作は、確定の前に結果を確かめる（CS-12）
- 解除の後の掲載・地域・イベントの公開状態は CF-08 による。店舗は再び閲覧でき、その掲載は現在の公開状態に従う。解除の操作とともに、解除の後の状態を示す。解除は、確定の前の確認（CS-12）を持たない
- 管理者のいない対象では、代行の入口を示す。店舗は SM-02 と SM-03、掲載は SM-04、地域は RM-01、イベントは EM-01 を代行で開く。管理者のいる対象では、代行の入口を示さず、管理者がいるため代行できないことを示す
- 店舗・地域・イベントでは、管理者の有無にかかわらず CM-02 へ進める。管理者の権限の解除、地域・イベントの管理権限の付与、管理者が不在の間の承諾前の招待の取り消しは CM-02 で行う
- 管理者が不在の対象についての管理者宛ての通知から開いたときは、その対象を示し、通知の出来事に応じた代行の画面へ進める
- 重複する店舗の整理は、残す店舗を決めて、もう一方の店舗を非公開にすることで行う。店舗を統合する操作は持たない。必要な掲載は、残す店舗の代行（店舗管理者がいなければ）で作り直す
- 読みものは対象にしない

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-06、CS-08、CS-12、CS-13 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 非公開でない | 対象の公開状態を示す。非公開にできる | 対象を開く。または解除が成立する |
| 運営による非公開・店舗の非公開 | 非公開であることを、公開状態に重ねて示す。解除できる | 非公開が成立する。または非公開の対象を開く |
| 管理者あり | 代行の入口を示さない。CM-02 へ進める | 対象に管理者がいる |
| 管理者不在 | 代行の入口を示す。CM-02 へ進める（掲載を除く）。承諾前の招待が残っていれば、そのことを示す | 対象に管理者がいない |
| CS-12 非公開の確認 | 対象が閲覧できなくなることを示す。店舗では、紐づく掲載も閲覧できなくなること、地域の所属店舗とイベントの参加店舗にも表示されなくなること、掲載・所属・参加・保存は他の店舗に引き継がれないことを示す。管理者は情報を更新できるが公開状態を変えられなくなること（店舗の非公開を除く）を示す | 非公開にする操作を始める |
| CS-13 完了 | 非公開または解除が成立したことを示す | 非公開・解除が成立する |
| CS-08 状態の変化 | 別のサービス運営者がすでに非公開にしている、または解除している。現在の状態を示す | 非公開・解除の時点で前提がない |
| CS-06 対象がない | 掲載が削除されていて、運営する対象がない。OM-02 へ戻る | 削除された掲載を開く。または操作の時点で掲載が削除されている |

## OM-04 申立ての対応

- 目的: 取り下げの申立て1件を確かめ、写真を削除し、結果を添えて対応を終える
- シナリオ: MOD-02
- 入口: OM-01、申立ての通知

### 機能

- 申立ての内容を確かめる。対象、申立人の立場、示された写真、理由、申立人のメールアドレス、状態（未対応・対応済み）を示す。申立人との追加の確認はメールで行い、この画面は連絡の操作を持たない
- 対象の現在の状態（閲覧できる、非公開、削除済み）を示す。対象の閲覧側の詳細と、OM-03 へ進める
- 対象の写真から選んで削除する。掲載・店舗・地域・イベント・読みもののどの写真も削除できる。申立人が示した写真は、それと分かる。運営による非公開の間の対象の写真も削除できる。確定の前に結果を確かめる（CS-12）。削除は確定の時点で反映し、対応を終える操作を待たない
- 掲載と店舗の非公開は、OM-03 へ進んで行う
- 結果（行った措置、または措置を行わないこと）を入力して、対応を終える。結果は必須とする。確定の前に結果を確かめる（CS-12）。申立ては対応済みになり、結果が申立人にメールで届く
- 対応済みの申立ては、結果とともに示し、操作を持たない。OM-01 へ戻って次の申立て・連絡へ進める。措置の結果は、この画面が示す対象の現在の状態と、対象の OM-03 で確かめる

### 状態

共通の状態のうち CS-01、CS-02、CS-04〜CS-06、CS-08、CS-10〜CS-13 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 未対応 | 写真の削除、OM-03 への移動、結果の入力、対応を終える操作を行える | 未対応の申立てを開く |
| 対応済み | 添えた結果を示す。操作を持たない | 対応を終える操作が成立する。または対応済みの申立てを開く |
| CS-06 対象・写真がない | 対象または示された写真が、すでに削除されている。削除の操作を示さない。措置を行わないことを結果に添えて対応を終える | 開いた時点で対象または写真がない |
| 対象が非公開 | 対象がすでに非公開であることを示す。写真の削除と、結果を添えて対応を終える操作は行える | 開いた時点で対象が非公開 |
| CS-12 写真の削除の確認 | 削除した写真は戻せないこと、1枚目を削除すると次の写真が代表写真になることを示す。写真がなくなる場合は、掲載は一時非公開に、地域・イベント・読みものは公開の取り下げになること（運営による非公開の間の対象を含む。CF-08）、店舗は公開が続くことを示す | 写真の削除を始める |
| CS-13 削除の完了 | 写真が削除されたことと、対象の現在の公開状態を示す。続けて別の写真を削除できる | 写真の削除が成立する |
| CS-10 結果の不足 | 結果を入力せずに対応を終えられないことを示す | 結果なしで対応を終えようとする |
| CS-12 対応を終える確認 | 申立てが対応済みになること、入力した結果が申立人にメールで届くこと、取り消せないことを示す | 対応を終える操作を始める |
| CS-08 対応済み | 別のサービス運営者がすでに対応を終えている。結果を示し、OM-01 へ戻る。削除しようとした写真を別のサービス運営者がすでに削除している場合は、対象の現在の写真を示す | 操作の時点で申立てが対応済み、または写真が削除済み |

## OM-05 連絡の対応

- 目的: 情報の誤り・閉店の連絡1件を確かめ、店舗管理者に確認を依頼し、店舗の現在の情報を見て対応を終える
- シナリオ: MOD-05
- 入口: OM-01、連絡の通知

### 機能

- 連絡の内容を確かめる。対象の店舗または掲載、連絡の種類（情報の誤り・閉店）、内容、連絡した利用者、状態（未対応・確認依頼中・対応済み）を示す
- 対象の店舗に店舗管理者がいるかどうかを示す。店舗と掲載の現在の内容は、閲覧側の詳細（DT-02、DT-01）で確かめる
- 店舗管理者に確認を依頼する。連絡の内容を添えた依頼がその店舗のすべての店舗管理者に届き、連絡は確認依頼中になる。依頼は取り消せない。確定の前に結果を確かめる（CS-12）
- 確認依頼中の連絡は、店舗管理者からの返答を持たない。サービス運営者が、店舗と掲載の現在の内容を見て、店舗管理者が対応したか、誤りが残っていないかを判断する
- 対応を終える。未対応の連絡は依頼せずに終えられ、確認依頼中の連絡は対応が済んだと判断したときに終える。連絡は対応済みになる。対応済みにできるのはサービス運営者だけ。確定の前に結果を確かめる（CS-12）
- 店舗管理者が対応しないと判断したときは、OM-03 へ進む。CM-02 でその店舗のすべての店舗管理者の権限を解除し、代行で店舗の情報（SM-02）と掲載（SM-03、SM-04）を更新してから、この画面で対応を終える。店舗管理者が1人でも残る間は、代行の入口は示されない

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-06、CS-08、CS-12、CS-13 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 未対応 | 確認の依頼と、対応を終える操作を行える | 未対応の連絡を開く |
| 確認依頼中 | 依頼済みであることを示す。対応を終える操作と、OM-03 への移動を行える。依頼の操作は示さない | 確認の依頼が成立する。または確認依頼中の連絡を開く |
| 対応済み | 対応済みであることを示す。操作を持たない | 対応を終える操作が成立する。または対応済みの連絡を開く |
| 店舗管理者が不在 | 連絡の後に店舗管理者がいなくなった。依頼の操作を示さず、OM-03 から代行で更新して対応を終えることを示す | 開いた時点、または依頼の時点で店舗管理者がいない |
| CS-06 対象がない | 対象の掲載が削除されている。そのことを示す。対応を終える操作は行える | 開いた時点で対象の掲載が削除済み |
| 対象が非公開 | 対象がすでに非公開であることを示し、OM-03 へ進める。依頼と、対応を終える操作は行える | 開いた時点で対象が非公開 |
| CS-12 依頼の確認 | すべての店舗管理者に依頼が届くことと、依頼は取り消せないことを示す | 確認の依頼を始める |
| CS-12 対応を終える確認 | 連絡が対応済みになることと、取り消せないことを示す | 対応を終える操作を始める |
| CS-08 状態の変化 | 別のサービス運営者がすでに対応を終えている、または確認を依頼している。現在の状態を示す。対応済みの場合は OM-01 へ戻る | 操作の時点で連絡が対応済み、または確認依頼中 |

## OM-06 カテゴリーの管理

- 目的: カテゴリーを追加・変更し、移行先を指定して廃止する
- シナリオ: OPE-02、OPE-03
- 入口: 運営のナビゲーション「カテゴリー」

### 機能

- 現在のカテゴリーを、作成順の一覧で確かめる。カテゴリーは1階層とする
- 名称を入力して、カテゴリーを追加する。追加したカテゴリーは並びの最後に入る
- カテゴリーを選び、名称を変更して保存する
- カテゴリーを選び、移行先のカテゴリーを廃止するカテゴリー以外から1つ選んで、廃止する。移行先は、そのカテゴリーの掲載と申請が1件もなくても必須とする。確定の前に結果を確かめる（CS-12）
- 廃止を取り消す操作と、並び順を変える操作は持たない

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-07、CS-08、CS-10〜CS-13 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 一覧 | カテゴリーを作成順に示す | 画面を開く |
| CS-10 名称の誤り | 名称が空、または他のカテゴリーと同じ名称で、追加・保存できないことを示す | 追加・保存の時点で名称が誤っている |
| CS-10 移行先の不足 | 移行先を選ばずに廃止できないことを示す | 移行先なしで廃止を確定しようとする |
| 廃止できない | カテゴリーが1つだけで、移行先にできるカテゴリーがない。廃止の操作を示さず、カテゴリーを追加してから廃止することを示す | カテゴリーが1つだけ |
| CS-12 廃止の確認 | 廃止するカテゴリーと移行先を示す。そのカテゴリーを設定したすべての掲載と、確認中・差し戻し中の掲載の申請・修正の申請が移行先に付け替わること、選択肢から消えること、廃止は取り消せないことを示す | 廃止を始めて移行先を選ぶ |
| CS-13 完了 | 追加・変更・廃止が成立したことを、一覧に反映して示す | 追加・保存・廃止が成立する |
| CS-08 廃止済み | 変更・廃止しようとしたカテゴリー、または選んだ移行先を、別のサービス運営者がすでに廃止している。廃止も付け替えも反映せず、最新の一覧を示す | 保存・廃止の確定の時点でカテゴリーが廃止済み |

## OM-07 役割の管理

- 目的: 編集担当者とサービス運営者を確かめ、任命・付与し、解除する
- シナリオ: OPE-04、OPE-05
- 入口: 運営のナビゲーション「役割」、MY-07（サービス運営者が1人だけのとき）

### 機能

- 編集担当者とサービス運営者を、役割ごとの一覧で確かめる。メールアドレスで示し、自分がどれかが分かる
- 既存のアカウントのメールアドレスを指定して、編集担当者に任命する。サービス運営者の役割を付与する。自分自身も編集担当者に任命できる。相手の承諾は要らず、確定の時点で効く
- 一覧から1人を選び、編集担当者の任命を解く。サービス運営者の役割を解除する。確定の前に結果を確かめる（CS-12）
- 最後の編集担当者の任命も解ける。サービス運営者は、2人以上いる間は自分自身も解除できる。1人だけの間は解除できない
- MY-07 から開いたサービス運営者は、別の利用者にサービス運営者の役割を付与してから、MY-07 へ戻って退会する
- 店舗・地域・イベントの管理権限は扱わない（CM-02）

### 状態

共通の状態のうち CS-01、CS-02、CS-04、CS-05、CS-08、CS-09、CS-10、CS-12、CS-13 が当てはまる。この画面に固有の内容を持つものを表に書く。

| 状態 | 内容 | 遷移のきっかけ |

| CS-09 空 | 編集担当者がいないことを示し、任命へ進める。サービス運営者の一覧は空にならない | 編集担当者が1人もいない |
