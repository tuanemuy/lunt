# 申請・申立て・連絡（RQ）

店舗向けの案内と既存店舗の確認、承認を求める申請の提出、取り下げの申立て、情報の誤り・閉店の連絡の画面を定める。画面の一覧、入口、共通の状態（CS）、共通の機能（CF）、申請を提出する画面の状態、状態の示し方は [index.md](index.md) が定める。

## 申請を提出する画面（RQ-02〜RQ-06）の機能

RQ-02〜RQ-06 は、画面ごとの機能に加えて、次の機能を持つ。状態は、index.md の「申請を提出する画面の状態」（入力・再提出・受け付けない・提出済み）を持ち、各画面の状態の表はその画面に固有の内容だけを書く。

- 申請の対象（店舗・掲載・地域・イベント）を示す。店舗・掲載は入口が決め、この画面では変えない。地域は RQ-05、イベントは RQ-06 で選ぶ（CF-02）。DT-03 から開いた RQ-05 と DT-04 から開いた RQ-06 は、入口が地域・イベントを決め、店舗をこの画面で選ぶ。再提出と再申請は、元の申請と同じ種類・同じ対象で始まる
- 提出の前に、入力した内容を確かめる。提出すると申請は確認中になり、MY-05 へ進める（CS-13）
- index.md の「受け付けない事情」を確かめる。確かめる時点と、再提出に当たる事情（申請の前提だけ）は、そこが定める。当たれば「受け付けない」の状態になり、提出・再提出できない。入口があらかじめ選んだ地域・イベント（DT-03 から開いた RQ-05、DT-04 から開いた RQ-06）が事情に当たるときは、そこが定めるとおり入力を止めず、別の地域・イベントを選べる。事情と行き先は、各画面では繰り返さない
- 再提出の状態では、承認者が求める追加の確認を示し、申請の内容を修正し、回答を添えられる
- 再申請の始まりの内容は、index.md の「申請を提出する画面の状態」が定める
- 修正の申請で変更した項目の示し方は、index.md の「申請の状態」が定める
- 提出の後は、この画面で申請を修正・取り下げしない。確認・取り下げ・再提出・再申請の入口は MY-05 が持つ
- 提出せずにやめると、申請は作られず、入力した内容は残らない（CS-11）。再提出せずにやめると、申請は差し戻しのまま変わらない

## RQ-01 店舗を探す

- 目的: 店舗向けの案内を読み、名称・所在地で既存の店舗を確かめ、店舗の詳細か新規店舗の登録へ進む
- シナリオ: SHP-01、SHP-02、LST-12
- 入口: MY-01 の「店舗を登録・管理する」

### 機能

- 探す前に、店舗向けの案内として、店舗の登録、管理権限の取得、店舗情報と掲載の管理でできることを伝える
- 名称・所在地で、公開中の店舗を探す（`spec/scenario/index.md` の「探し方」）。ログインせずに行える
- 「探し方」が定める店舗を、そこが定める順に一覧で示す（CF-05）。店舗ごとに名称・所在地・写真を示す。参照の場面として、休業・閉店の店舗も状態を区別して示す。写真のない店舗の示し方は、index.md の「公開中の対象の状態」に従う
- 店舗を選ぶと DT-02 を開く。その店舗への手続きは、index.md の「詳細の手続きの入口」から始める
- 探した後に、新規店舗の登録（RQ-02）への入口を示す。結果がある場合も、結果がない場合も示す。探す前は示さない
- 非公開の店舗は結果に現れない

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力前 | 店舗向けの案内と、名称・所在地の入力を示す。登録の入口は示さない | 開く |
| 結果あり | 一致する店舗の一覧と、登録の入口を示す | 探して、一致する店舗がある |
| CS-09 | 一致する店舗がないことと、語を変えて探し直せること、登録の入口を示す | 探して、一致する店舗がない |
| CS-10 | 名称も所在地も入力していないため、探せないことを示す | 何も入力せずに探す |
| CS-01、CS-02 | index.md のとおり | |

## RQ-02 店舗の申請

- 目的: 新規店舗の登録、または管理者のいない店舗の情報修正と営業状況の変更を申請する
- シナリオ: SHP-03、SHP-08、APP-02、APP-04
- 入口: 登録は RQ-01、修正は DT-02（index.md の「詳細の手続きの入口」）、再提出と再申請は MY-05

### 機能

- 登録の申請では、名称、写真、紹介、所在地、位置、営業時間、連絡先を入力する。提出には、CF-08 の店舗の公開条件を満たす内容が要る
- 所在地は CF-07、位置は CF-09 で入力する。エリアは入力しない
- 写真は CF-01 で登録する
- 登録の申請では、管理権限の申請を併せるかを選ぶ。併せるときは、店舗との関係と、確認に使える連絡先または資料を文章で記す。ファイルは添えない。併せることをやめれば、登録だけを提出できる
- 修正の申請では、店舗の現在の情報と営業状況を示し、直す項目を変える。登録と同じ項目を修正できる
- 修正の申請では、営業状況を営業中・休業・閉店のどれへも変える申請ができる。情報の修正と併せても、単独でも提出できる
- 修正の申請は、現在の内容から何も変えていなければ提出できない。公開条件を欠く修正も提出できない（CF-08。CS-10）
- 登録申請に併せた管理権限の申請は別の申請として状態を持ち、この画面の再提出では直さない。差し戻されたら RQ-03 の再提出で直し、取り下げは MY-05 で別に行う
- 登録申請の再提出では、登録申請の内容と回答だけを入力し、管理権限の申請を併せるかどうかは変えない。併せていない登録申請の店舗の管理権限は、登録の承認の後に RQ-03 で申請する

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力（登録） | 空の内容で始まる。再申請は、写真を含む前の登録申請の内容で始まる。併せる管理権限の申請の入力は、併せることを選んでいる間だけ示す | RQ-01 から開く。MY-05 の登録申請から再申請する |
| 入力（修正） | 店舗の現在の情報と営業状況が入った内容で始まる。再申請は、そこに前の申請が変更した項目（写真を含む）が入った内容で始まる。管理権限の申請を併せる選択は示さない | DT-02 から開く。MY-05 の修正の申請から再申請する |
| 再提出 | 差し戻された登録または修正の内容で始まる。修正の申請は、店舗の現在の情報に、申請が変更した項目が入った内容で始まる。管理権限の申請を併せる選択は示さない | MY-05 の差し戻しの申請から開く |
| CS-01、CS-02、CS-04、CS-07、CS-10、CS-11、CS-13 | index.md のとおり | |

## RQ-03 管理権限の申請

- 目的: 店舗との関係と確認に使える連絡先・資料を添えて、店舗の管理権限を申請する
- シナリオ: SHP-04、APP-02、APP-04
- 入口: DT-02 の「このお店を管理する」（index.md の「詳細の手続きの入口」）、MY-05

### 機能

- 対象の店舗に店舗管理者がいるかどうかに応じた案内を示す。店舗管理者がいる店舗では、既存の店舗管理者から招待を受ける方法を案内し、申請も続けられることを示す
- 店舗との関係と、確認に使える連絡先または資料を文章で記す。どちらも提出に要る。ファイルは添えない
- 再提出では、求められた確認に、申請の内容の修正と回答で答える
- 登録申請に併せた管理権限の申請の再提出と、その否認・取り下げの後の再申請も、この画面で行う

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力（店舗管理者がいる店舗） | 招待を受ける方法の案内と、申請の入力を示す | 店舗管理者がいる店舗で開く |
| 入力（店舗管理者がいない店舗） | 申請の入力を示す | 店舗管理者がいない店舗で開く |
| 入力（再申請） | 前の申請の内容で始まる。案内は、店舗管理者の有無に応じて示す | MY-05 の否認・取り下げ・失効の申請から再申請する |
| 再提出 | 差し戻された内容で始まる | MY-05 の差し戻しの申請から開く |
| CS-01、CS-02、CS-04、CS-07、CS-10、CS-11、CS-13 | index.md のとおり | |

## RQ-04 掲載の申請

- 目的: 管理者のいない店舗の新しい掲載、または公開された掲載の修正を申請する
- シナリオ: LST-12、LST-13、APP-02、APP-04
- 入口: 新しい掲載は DT-02、修正は DT-01（index.md の「詳細の手続きの入口」）、再提出と再申請は MY-05

### 機能

- 新しい掲載の申請では、写真、名称、カテゴリー、説明、提供の設定を入力する。提出には、CF-08 の掲載の公開条件を満たす内容が要る。価格とキャッチコピーの入力欄を持たない。所在地と所属地域は入力しない
- 写真は CF-01 で登録し、写真ごとに見せる範囲を調整する
- カテゴリーは、現役のカテゴリー（`spec/scenario/listing.md` の「掲載の内容」）から1つを選ぶ
- 提供の設定は CF-06 で行う
- 修正の申請では、掲載の現在の内容を示し、直す項目（名称、説明、カテゴリー、写真、提供の設定）を変える。写真は、加える・外す・並び替える・見せる範囲を調整する、のどれもできる
- 修正の申請は、現在の内容から何も変えていなければ提出できない。公開条件を欠く修正も提出できない（CF-08。CS-10）
- 提出の前に、公開前の確認（CM-03）を開いて、入力した内容の閲覧者への見え方を確かめられる。CM-03 からこの画面へ戻ると、入力した内容は保たれている。RQ-04 から開いた CM-03 は公開の操作を持たない
- 提出済みの状態で、承認されても申請者は掲載の管理権限を得ないことを示す

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力（新しい掲載） | 空の内容で始まる。再申請は、写真を含む前の申請の内容で始まる。前の申請のカテゴリーが廃止されていれば、index.md の「申請の状態」のとおり移行先で始まる | DT-02 から開く。CM-03 から戻る。MY-05 の掲載の申請から再申請する |
| 入力（修正） | 掲載の現在の内容が入った内容で始まる。再申請は、そこに前の申請が変更した項目（写真を含む）が入った内容で始まる。廃止されたカテゴリーは、新しい掲載と同じく移行先で始まる | DT-01 から開く。CM-03 から戻る。MY-05 の修正の申請から再申請する |
| 再提出 | 差し戻された内容で始まる。修正の申請は、掲載の現在の内容に、申請が変更した項目が入った内容で始まる | MY-05 の差し戻しの申請から開く |
| CS-08 | 選んだカテゴリーが提出・再提出までに廃止されていた。提出せず、入力した内容を保ったまま、現役のカテゴリーから選び直すことを示す | 提出・再提出の時点で、選んだカテゴリーが廃止されている |
| CS-01、CS-02、CS-04、CS-07、CS-10、CS-11、CS-13 | index.md のとおり | |

## RQ-05 所属・離脱の申請

- 目的: 店舗の地域への所属、または地域からの離脱を申請する
- シナリオ: REG-01、REG-02、REG-03、APP-02、APP-04
- 入口: 店舗管理者は SM-05、利用者は DT-02、所属は DT-03（index.md の「詳細の手続きの入口」）、再提出と再申請は MY-05

### 機能

- 店舗管理者は、管理する店舗について、店舗管理者として申請する。利用者は、管理者のいない店舗について、個人として申請する
- 申請の種類（所属・離脱）を選ぶ。SM-05 からは、選んだ種類と、離脱では選んだ地域が入った状態で開く。DT-02 からは、この画面で種類を選ぶ。DT-03 からは、所属の申請で、その地域が選ばれた状態で開く
- DT-03 から開いたときは、申請する店舗を選ぶ。管理する店舗は、店舗管理者としての申請の候補に示し、1つだけなら選んだ状態で始まる。管理者のいない公開中の店舗は、キーワードで探して選び（CF-02）、個人として申請する。選んだ店舗は選び直せる
- 所属の申請では、公開中の地域から対象を選ぶ（CF-02）。候補から地域の詳細（DT-03）を確かめられる
- 離脱の申請では、店舗が所属中の地域から対象を選ぶ。店舗管理者には、公開を取り下げた地域と運営による非公開の地域との所属も、状態とともに示し、選べる。利用者には、閲覧者に表示される所属地域（公開中で、運営による非公開でない地域）だけを示す
- 地域と店舗の候補は、上に書いた範囲の中だけを示す。範囲の中で index.md の「受け付けない事情」に当たるもの（所属がすでにある、同じ申請者の申請が確認中・差し戻しにある）は、そこが定めるとおり選べない対象として示す
- 店舗・地域・申請の種類を確かめて提出する。離脱の申請では、承認されるまで所属が続くことを示す
- 再提出では、店舗・地域・種類を変えず、回答を添えて追加の確認に答える

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力（所属） | 店舗と、地域の選択（CF-02）を示す。DT-03 から開いたときは、選ばれた地域と、店舗の選択を示す。選ばれた地域が事情に当たれば、理由とともに示し、地域を選び直せる | 所属の申請を選ぶ。DT-03 から開く。MY-05 の所属の申請から再申請する（元の申請の地域が入った状態） |
| 入力（離脱） | 店舗と、所属中の地域の選択を示す。所属中の地域がなければ、離脱を選べない | 離脱の申請を選ぶ。MY-05 の離脱の申請から再申請する（元の申請の地域が入った状態） |
| 再提出 | 差し戻された申請の店舗・地域・種類で始まる | MY-05 の差し戻しの申請から開く |
| 提出済み | 店舗管理者は SM-05 へも進める | 提出が成立する |
| CS-01、CS-02、CS-04、CS-05、CS-07、CS-10、CS-11、CS-13 | index.md のとおり。CS-05 は、店舗管理者として開いた店舗の管理権限を持たない、または申請の途中で失った場合に当たる。管理権限を持たない店舗に直接たどり着いた利用者には、店舗の DT-02 へ進め、管理者のいない店舗なら個人としての申請（この画面を DT-02 から開く）へ、管理者のいる店舗なら管理権限の申請（RQ-03）へ進める（REG-01） | |

## RQ-06 参加の申請

- 目的: 参加するイベントを選び、掲載と参加日を添えて、店舗のイベントへの参加を申請する
- シナリオ: EVT-01、APP-02、APP-04
- 入口: SM-06、DT-04（index.md の「詳細の手続きの入口」）、再提出と再申請は MY-05

### 機能

- 申請する店舗を示す。SM-06 から開くと、その店舗で始まる。DT-04 から開くと、管理する店舗から申請する店舗を選ぶ。管理する店舗が1つなら、選んだ状態で始まる。選んだ店舗は選び直せる
- 参加するイベントをキーワードで探して選ぶ（CF-02）。DT-04 から開くと、そのイベントが選ばれた状態で始まり、そのイベントが事情に当たれば、理由とともに示し、イベントを選び直せる。候補は、公開中で、開催前または開催中のイベントに限り、終了・中止したイベントと閲覧できないイベントは示さない。候補の中で index.md の「受け付けない事情」に当たるイベント（参加がすでにある、同じ店舗の申請が確認中・差し戻しにある）は、そこが定めるとおり選べない対象として示す。候補から DT-04 を開いて、開催期間・開催場所・紹介を確かめられる。選んだイベントの開催期間を示す
- イベントで提供する掲載を、その店舗の公開中の掲載から選んで添える。提供状態は問わず、提供開始前・提供終了の掲載は状態を区別して示す。下書き・一時非公開・運営による非公開の掲載は候補に示さない
- 参加日を、開催期間内の日付から選んで添える。開催期間の外の日付を添えた申請は提出できない（CS-10）
- 掲載と参加日は、どちらも複数添えられ、添えずに提出できる
- 店舗・イベント・添える掲載・参加日を確かめて提出する
- 再提出では、店舗とイベントを変えず、添える掲載と参加日を修正し、回答を添える。閲覧できなくなった添えた掲載は、状態とともに示し、外せる（index.md の「管理する対象の状態」）

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力 | SM-06 から開くとイベントの選択（CF-02）から、DT-04 から開くと店舗の選択から始まり、店舗とイベントを選んだ後は添える掲載も参加日もない内容になる。候補がなければ、参加を申請できるイベントがないことを示す。再申請は、前の申請のイベント・掲載・参加日が入った内容で始まる。前の申請の掲載と参加日のうち、`spec/scenario/event.md` の共通の規則が外すもの（添える候補にない掲載と、開催期間の外の参加日）は始まりの内容から外し、外した掲載と参加日を示す。外した掲載は、状態（一時非公開・運営による非公開・削除）とともに示す。添えられる掲載がなければ、そのことと、添えずに提出できることを示す。添えたい掲載が公開されていなければ、先に SM-04 で公開することを示し、SM-03 へ進める | SM-06 から開く。DT-04 から開く。MY-05 の参加の申請から再申請する |
| 再提出 | 差し戻された申請のイベント・掲載・参加日で始まる | MY-05 の差し戻しの申請から開く |
| 提出済み | SM-06 へも進める | 提出が成立する |

## RQ-07 取り下げの申立て

- 目的: 店舗本人または写真の権利者が、ログインせずに取り下げを申し立てる
- シナリオ: MOD-01
- 入口: DT-01〜DT-05（index.md の「詳細の手続きの入口」）

### 機能

- 申立ての対象（入口の詳細が示す掲載・店舗・地域・イベント・読みもの）を示す。ログインせずに行える
- 申立人の立場（店舗本人、写真の権利者）を選ぶ。DT-03・DT-04・DT-05 から開いたときは、写真の権利者だけを選べる
- 写真の権利者は、対象の写真から、削除を求める写真を選んで示す
- 理由とメールアドレスを入力して提出する。立場・理由・メールアドレスは提出に要る。写真の権利者は、写真の指定も要る
- 提出すると、申立てを受け付けたことと、結果が入力したメールアドレスに届くことを示す（CS-13）。MY-05 へは進めない
- 店舗の掲載をやめたい店舗管理者も、DT-02 から店舗本人として、同じ流れで申し立てる
- 提出した申立ての状況を確かめる画面と、申立てを取り消す操作を持たない

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力 | 対象と、立場・写真の指定・理由・メールアドレスの入力を示す。写真の指定は、写真の権利者を選んでいる間だけ示す | DT-01〜DT-05 から開く |
| 受け付け済み | 申立てを受け付けたことと、結果が入力したメールアドレスに届くことを示す（CS-13）。元の詳細へ戻れる | 提出が成立する |
| CS-06 | 対象が閲覧できない。申立ては送られない | 開いた時点、または提出の時点で、対象が非公開・公開の取り下げ・削除になっている |
| 写真が外された | 示した写真が対象から外されていて、申立ては送られない。外された写真を示し、入力した内容を保ったまま、対象の現在の写真から選び直せる。やめることもできる | 提出の時点で、対象は閲覧できるが、写真の権利者が示した写真が対象の現在の写真にない |
| CS-01、CS-02、CS-10、CS-11 | index.md のとおり | |

## RQ-08 情報の誤り・閉店の連絡

- 目的: 管理者のいる店舗とその掲載の情報の誤り・閉店を、サービス運営者に連絡する
- シナリオ: MOD-04
- 入口: DT-01・DT-02（index.md の「詳細の手続きの入口」）、RQ-02・RQ-04・RQ-05 の受け付けない状態

### 機能

- 連絡の対象（店舗、または掲載とその店舗）を示す。RQ-02・RQ-04・RQ-05 から送られたときは、その申請の対象を引き継ぐ
- 連絡の種類（情報の誤り、閉店）を選び、内容を入力して提出する。種類と内容は提出に要る
- 提出すると、連絡を受け付けたことを示す（CS-13）。MY-05 へは進めない。連絡の結果の通知は届かず、更新された内容は DT-01・DT-02 で確かめる
- 提出した連絡の状況を確かめる画面と、連絡を取り消す操作を持たない

### 状態

| 状態 | 内容 | 遷移のきっかけ |

| 受け付け済み | 連絡を受け付けたことを示す（CS-13）。元の詳細へ戻れる | 提出が成立する |
| CS-06 | 対象が閲覧できない。連絡は送られない | 開いた時点、または提出の時点で、対象が非公開または削除になっている |
| CS-01、CS-02、CS-04、CS-10、CS-11 | index.md のとおり | |
