# アカウントと自分の申請（MY）

ログイン、通知、自分の申請、招待の承諾、退会の画面を定める。画面の一覧、入口、共通の状態（CS）、共通の機能（CF）、状態の示し方は [index.md](index.md) が定める。

## MY-01 マイページ

- 目的: ログインの状態と、持っている管理権限・役割に応じた行き先へ進む
- シナリオ: ACC-01、ACC-03、ACC-04、APP-01、SHP-01、SHP-05、EDT-01、OPE-01
- 入口: 閲覧側の5つのタブ画面のアカウントの入口、管理ナビゲーション

### 機能

- ログインしているかどうかを示す。ログインしている間は、アカウントのメールアドレスを示す
- index.md の「マイページからの入口」の条件に合う入口を示し、選んだ画面を開く。管理する店舗・地域・イベントは、対象ごとに名称で示す
- 「店舗を登録・管理する」の入口は RQ-01 を開き、店舗向けの案内と既存店舗の確認へ進む
- ログインせずに開ける。ログインしていない間は、ログインと「店舗を登録・管理する」の入口だけを示す
- MY-01 から始めたログインが成立すると、MY-01 へ戻る
- ログアウトとメールアドレスの変更の操作を持たない

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 未ログイン | ログインしていないことと、ログイン（MY-02）・「店舗を登録・管理する」（RQ-01）の入口を示す | ログインせずに開く。退会が成立する |
| ログイン中 | アカウントのメールアドレスと、持っている管理権限・役割に応じた入口を示す | ログインした状態で開く。ログインまたはアカウントの切り替えが成立して戻る |
| CS-01、CS-02 | index.md のとおり | |

## MY-02 ログイン

- 目的: メールアドレス（メールに届くリンクまたはコード）または外部アカウントでログインし、元の操作へ戻る
- シナリオ: ACC-01、ACC-02、KEP-04
- 入口: MY-01、VW-10 の案内、ログインが必要な操作（CS-04）、ログイン用のメールのリンク、MY-06（招待の宛先と違うアカウントでログイン中）

### 機能

- メールアドレスを入力して、ログイン用のメールを送る。メールは、ワンタイムのリンクとワンタイムのコードの両方を載せる
- メールアドレスを入力したブラウザでコードを入力すると、そのブラウザでログインが成立する。メールのリンクを開くと、リンクを開いたブラウザでログインが成立する。どちらも有効期間を持ち、一方を使うと他方は無効になる。コードの誤入力が回数の上限に達すると、リンクとコードはどちらも無効になる
- 外部アカウントでのログインを選び、提供元での認証と、Lunt にメールアドレスを渡すことの承認を経てログインする。提供元が確認済みとしたメールアドレスだけを受け取る
- パスワードを求めない。登録の画面を持たない。そのメールアドレスのアカウントがなければ、ログインの成立と同時に作られる
- ログインが成立すると、成立したブラウザで元の画面と操作へ戻る（CS-04）。MY-01 から始めた場合は MY-01 へ、VW-10 の案内から始めた場合は VW-10 へ、MY-06 から始めた場合は MY-06 へ戻る。リンクを開いたブラウザに元の画面と操作がなければ、MY-01 を開く
- ログインが成立すると、成立したブラウザの端末の保存が、確認を求めずにアカウントの保存へ合流する。合流の結果と、合流の通信エラーは VW-10 が示す
- ログインしている利用者が、別のメールアドレスまたは外部アカウントでログインすると、そのブラウザのアカウントが切り替わる
- ログインせずにやめると、元の画面へ戻る。始めようとした操作は始まらない

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 入力 | メールアドレスの入力と、外部アカウントでのログインの選択を示す。ログインしている間は、ログイン中のアカウントのメールアドレスと、ログインするとアカウントが切り替わることを併せて示す | 入口から開く |
| コード入力 | ログイン用のメールを送ったことと、コードの入力を示す。メールのリンクを開いてもログインが成立することと、リンクを別のブラウザで開くとそのブラウザでログインが成立し、このブラウザの端末の保存は合流しないことを示す。メールアドレスを確かめて送り直せる。外部アカウントでのログインへ切り替えられる | メールの送信が成立する |
| リンク・コード無効 | リンクまたはコードが、有効期間を過ぎている、一方の使用で無効になっている、またはコードの誤入力が回数の上限に達していて、ログインが成立しないことを示す。メールアドレスの入力からやり直せる | 無効なリンクを開く。無効なコードを入力する。コードの誤入力が上限に達する |
| メールアドレスを受け取れない | 外部アカウントから確認済みのメールアドレスを受け取れず、ログインが成立しないことと、確認済みのメールアドレスが必要であることを示す。アカウントは作られない。メールアドレスでのログインか、別の外部アカウントを選べる | 外部アカウントの認証から、確認済みのメールアドレスなしで戻る |
| 外部アカウントの認証の不成立 | 提供元での認証または承認をやめた、もしくは提供元の障害で、ログインが成立しなかったことを示す。入力の状態からやり直せる | 外部アカウントの認証から、不成立で戻る |
| ログイン成立 | 元の画面と操作へ戻る。リンクを開いたブラウザに元の画面と操作がなければ MY-01 を開く | 正しいコードを入力する。メールのリンクを開く。外部アカウントの認証が成立する |
| CS-10 | メールアドレスの形式の誤り（メールは送らない）、または正しくないコードを示す。誤入力が回数の上限に達するまでは、コードを入力し直せる | 形式の正しくないメールアドレスで送る。正しくないコードを入力する |
| 送信の上限 | 同じメールアドレスへのログイン用メールが上限に達していて、送らなかったことを示す。届いているメールのリンクかコードを使うか、時間をおいて送り直せる（有効期間を過ぎたメールの分だけ送れるようになる） | 有効期間内に上限の数だけログイン用メールを送ったメールアドレスで、もう一度送る |
| CS-01、CS-02 | index.md のとおり。メールの送信と、リンク・コードの確認の通信エラーを含む | |

## MY-03 通知一覧

- 目的: 自分に届いた通知を確かめ、出来事に応じた画面へ進む
- シナリオ: ACC-03、APP-05
- 入口: MY-01、通知のメール

### 機能

- 自分に届いた通知を、新しい順に示す（CF-05）。複数の管理権限・役割に届いた通知も、1つの一覧に示す
- 通知ごとに、起きた出来事とその対象を示す
- 通知を選ぶと、index.md の「通知から開く画面」の画面を開く。開く画面を持たない通知は、この一覧で確かめるだけ
- 通知のメールは、同じ画面を直接開く。メールを見落としても、同じ通知をこの一覧で確かめられる
- 通知から開いた画面が CS-05、CS-06、CS-17 のどれかを示したときは、MY-03 へ戻れる
- 通知を受けた時点でアカウントのない宛先への招待は、メールだけで届く。メールから MY-06 を開く

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 一覧 | 通知を新しい順に示す | 開く |
| CS-09 | 通知がないことを示す | 通知が1件もない |
| CS-01、CS-02、CS-04 | index.md のとおり | |

## MY-04 自分の申請の一覧

- 目的: 個人として行った申請と、管理する店舗の店舗管理者として行った申請を、状態とともに一覧で確かめる
- シナリオ: APP-01、APP-06
- 入口: MY-01、SM-01・SM-05・SM-06（その店舗の申請に絞って開く）

### 機能

- 個人として行った申請と、管理する店舗の店舗管理者として行った申請を、1つの一覧に示す（CF-05）。同じ店舗の別の店舗管理者が出した申請を含む
- 申請ごとの示し方は、index.md の「申請の状態」に従う。登録申請に併せた管理権限の申請は、別の行で示す
- SM-01・SM-05・SM-06 から開くと、その店舗の店舗管理者として行った申請だけを示す。絞り込みを外すと、すべての申請を示す
- 申請を選ぶと MY-05 を開く
- 申請を始める入口を持たない。申請は、閲覧側の詳細（index.md の「詳細の手続きの入口」）、店舗を探す（RQ-01。登録の申請）、店舗の管理（SM-05、SM-06）から始める
- 辞任した店舗、または管理権限を解除された店舗の店舗管理者として行った申請は示さない

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| すべての申請 | 個人として行った申請と、管理するすべての店舗の店舗管理者として行った申請を示す | MY-01 から開く。絞り込みを外す |
| 店舗の申請 | 1つの店舗の店舗管理者として行った申請だけを、店舗の名称とともに示す | SM-01・SM-05・SM-06 から開く |
| CS-09 | 申請がないことと、申請を始める入口のある画面を示す | 申請が1件もない |
| CS-05 | 店舗の申請に絞って開いた店舗の管理権限を持たない | 管理権限のない店舗で絞って開く |
| CS-01、CS-02、CS-04 | index.md のとおり | |

## MY-05 申請の詳細

- 目的: 申請者が1件の申請の内容・状態・結果を確かめ、取り下げ、再提出と再申請へ進む
- シナリオ: APP-01、APP-02、APP-03、APP-04、APP-05、APP-06
- 入口: MY-04、通知（index.md の「通知から開く画面」）、申請の提出後、SM-01 の対応が必要なこと、SM-05・SM-06 の申請の行

### 機能

- 申請の種類、対象、申請者、申請した内容、状態を示す。示し方（再提出に添えた回答、廃止されたカテゴリーの読み替え、対象がなくなった修正の申請を含む）は index.md の「申請の状態」に従う
- 対象と、承認で反映された先を開ける。対象がまだない申請（確認中の登録申請と、登録の承認前の併せた管理権限の申請）は、対象を開く入口を示さない。反映先は閲覧側の詳細（DT-01〜DT-04）、管理権限の承認では SM-01。開いた先が閲覧できなくなっていれば CS-06 を示し、申請の結果はこの画面で確かめられる
- 登録申請と、それに併せた管理権限の申請は、互いの MY-05 へ進める
- 確認中または差し戻しの申請を取り下げる（CS-12）。管理権限の申請を併せた登録申請の取り下げでは、併せた申請が失効することを、確定の前に示す
- 差し戻しの申請は、その申請を提出した画面（RQ-02〜RQ-06）の再提出の状態へ進む。登録申請に併せた管理権限の申請は RQ-03 へ進む
- 否認・取り下げ・失効の申請は、同じ種類・同じ対象の再申請へ進む。再申請は、その申請を提出した画面（RQ-02〜RQ-06）の入力の状態で、写真を含む前の申請の内容から始まる。始まりの内容は index.md の「申請を提出する画面の状態」が定める。参加の申請の再申請は、始まりの内容から外した掲載と参加日を、開いた RQ-06 が示す。前の申請はそのまま残る。前提が成り立たず再申請できない場合は、開いた画面の「受け付けない」の状態が理由を示す
- 失効の申請は、成り立たなくなった前提（CS-08）と、再申請のほかに事情に応じて行える次の行き先（APP-05 の表。RQ-08、SM-01、参加がすでに成立した参加の申請では SM-06 など）を示す。次の操作が要らない事情では、行き先を示さない
- 確認中の申請は修正できない。修正の操作を示さない
- 店舗管理者として行った申請は、その店舗のどの店舗管理者にも、同じ内容と同じ操作を示す

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 確認中 | 承認者の判断を待っていることを示す。取り下げの操作を示す | 提出または再提出が成立する |
| 差し戻し | 承認者が求める追加の確認を示す。再提出の入口と、取り下げの操作を示す | 承認者が差し戻す |
| 承認 | 反映された内容と、反映先への入口を示す | 承認者が承認する |
| 否認 | 否認の理由と、再申請の入口を示す | 承認者が否認する |
| 取り下げ | 申請者が取り下げたことと、再申請の入口を示す | 取り下げが成立する（CS-13） |
| 失効 | 成り立たなくなった前提と、再申請の入口、次の行き先を示す。元に戻す操作を持たない | 申請が前提を失う |
| CS-12 | 取り下げが元に戻せないことを示す。やめると申請は変わらない | 取り下げを選ぶ |
| CS-05 | 他の利用者の申請、または管理権限を失った店舗の申請を開いた。申請の内容を示さない。MY-04 へ戻れる | 扱えない申請を開く |
| CS-06 | 存在しない申請を開いた。MY-04 へ戻れる | 存在しない申請を開く |
| CS-07 | 開いてから取り下げるまでの間に、同じ店舗の別の店舗管理者が申請を再提出していて、見ていた内容が変わっている | 取り下げを確定する |
| CS-08 | 取り下げる前に、同じ店舗の別の店舗管理者が取り下げた、承認者が承認・否認した、または申請が失効した。現在の状態を示す | 取り下げを確定する |
| CS-01、CS-02、CS-04 | index.md のとおり | |

## MY-06 招待の承諾

- 目的: 管理メンバーへの招待の対象を確かめ、承諾して管理者になる
- シナリオ: MEM-03
- 入口: 通知（index.md の「通知から開く画面」）。招待はメールと MY-03 で届く

### 機能

- 招待の対象（店舗・地域・イベントの別と名称）と、管理者として行えることを示す
- 承諾すると、その対象の管理者になり、対象の管理へ進む。店舗は SM-01、地域は RM-01、イベントは EM-01
- 承諾は、招待されたメールアドレスのアカウントだけが行える。ログインしていなければ MY-02 へ送り（CS-04）、ログインの成立後にこの画面へ戻る。アカウントがなければ、招待されたメールアドレスでのログインで作られる
- 断る操作を持たない。承諾しなければ、招待は承諾前のまま残る
- 管理者が不在の対象への招待も、承諾できる。承諾すると対象に管理者が就く
- 店舗の招待の承諾で失効した自分の申請（その店舗の管理権限の申請、管理者のいなかった店舗に個人として行った申請）は、通知と MY-05 で確かめる

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 承諾前 | 招待の対象と、管理者として行えること、承諾の操作を示す | 招待されたメールアドレスのアカウントで開く |
| 別のアカウントでログイン中 | 承諾できないことと、招待されたメールアドレスのアカウントでのログインが要ることを示す。MY-02 へ送り、アカウントの切り替えが成立するとこの画面へ戻る | 招待されたメールアドレスと異なるアカウントで開く |
| 招待の取り消し（CS-08） | 招待が取り消されたことを示す。承諾の操作を示さない | 取り消された招待を開く。承諾の時点で招待が取り消されている |
| すでに管理者（CS-08） | すでにその対象の管理者であることを示し、対象の管理へ進める | 管理者になった後で招待を開く、または承諾する |
| CS-13 | 管理者になったことを示し、対象の管理へ進める | 承諾が成立する |
| CS-01、CS-02、CS-04 | index.md のとおり | |

## MY-07 退会

- 目的: 退会で起きることを確かめて、退会する
- シナリオ: ACC-04
- 入口: MY-01

### 機能

- 退会で起きることを示す
  - 失うもの: アカウントの保存、店舗・地域・イベントの管理権限、編集担当者・サービス運営者の役割
  - 個人として行った確認中・差し戻しの申請が取り下げになること
  - 店舗管理者として行った申請は、その店舗の他の店舗管理者が引き続き扱うこと
  - 自分が最後の管理者である店舗・地域・イベントの名称と、それぞれの管理者不在の帰結（index.md の「管理する対象の状態」）
  - 公開済みの内容が残ること
  - 退会は取り消せず、同じメールアドレスでログインすると新しいアカウントになること
- 管理者不在になる対象があるときは、退会をやめて、その対象のメンバーの管理（CM-02）へ進み、後任を招待できる。後任の承諾を待たずに退会できる。承諾前の招待は退会の後も有効で、後任は後から承諾して管理者になる
- 内容を確かめて退会する（CS-12）。やめるとアカウントは変わらない
- 退会が成立すると、ログインしていない状態になる

### 状態

| 状態 | 内容 | 遷移のきっかけ |
| --- | --- | --- |
| 確認 | 退会で起きることと、退会の操作を示す。管理者不在になる対象があるときは、その対象と CM-02 への入口を併せて示す | MY-01 から開く |
| 退会できない | サービス運営者が自分1人だけであるため、退会できないことと理由を示す。退会の操作を示さない。役割の管理（OM-07）へ進める | 唯一のサービス運営者が開く。確定の時点で唯一のサービス運営者になっている |
| 退会済み | 退会が成立し、ログインしていない状態になったことを示す。閲覧側の画面へ進める | 退会が成立する |
| 退会の前にログインが切れた | 確定の時点でログインしていない状態になっていた（別の端末で退会が先に成立していた場合を含む）。退会の操作は行わず、ログインしていない状態になったことと、同じメールアドレスでログインすると新しいアカウントとして始まることを示す。閲覧側の画面へ進める。ログイン（CS-04）へは送らない | 退会を確定した時点で、ログインしていない |
| CS-01、CS-02、CS-04、CS-12 | index.md のとおり。CS-04 は、開いた時点でログインしていない場合に当たる。通信エラーで退会が成立しなければ、アカウントは変わらない | |
