# アカウントと通知 テスト

## 概要

このドキュメントは、メールアドレスまたは外部アカウントでのログイン、通知の確認、退会に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/account.md`（ACC-01〜ACC-04）

対象の画面: MY-01 マイページ、MY-02 ログイン、MY-03 通知一覧、MY-07 退会。通知から開く画面（MY-05、MY-06、CM-01、SM-02、SM-04、OM-01）と、確認に使う画面（VW-10、DT-02、RQ-02、CM-02、OM-02、OM-03、OM-07）は、到達と状態だけを確かめる。

テストケースの ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-ACC-047・TC-ACC-050 は正常系の TC-ACC-006 の後、TC-ACC-055 は TC-ACC-008 の後、TC-ACC-058 は TC-ACC-009 の後、TC-ACC-052 は異常系の TC-ACC-023 の後、TC-ACC-056 は TC-ACC-028 の後、TC-ACC-053 は TC-ACC-032 の後、TC-ACC-057 は TC-ACC-053 の後、TC-ACC-054 は TC-ACC-038 の後に置く）。

## 前提条件

### 環境

- テスト環境の Lunt に、PC のブラウザでアクセスできる
- 独立した3つのブラウザ（以下「ブラウザ A」「ブラウザ B」「ブラウザ C」。別のブラウザ、または Cookie を共有しない別のプロファイル）を使う。特に断りがなければブラウザ A で操作する。ブラウザ C はログインせず、閲覧者として確かめる行だけで使う
- 「ログインしていないブラウザ A（または B）で」と書いた行は、そのブラウザの Cookie とサイトデータを消去してから始める
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」と書く）。リンクで行う手順と外部アカウントで行う手順は、そのことを手順に書く
- 手順の「MY-02 を開き」「MY-02 から」は、そのブラウザの MY-01 のログインの入口から MY-02 を開くことを指す（MY-02 の URL を直接開いたときの戻り先は spec が定めていない）。CS-04 とメールのリンクで MY-02 が開く手順は、その手順に書いたとおりに開く
- 1つのブラウザで操作する利用者を替えるときは、次のどちらかで替える。手順の「{利用者} でログインし」「{利用者} で」は、断りがなければ (a) を指す
  - (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから替える利用者のメールアドレスでログインする（端末の保存も消える）
  - (b) 別のブラウザの MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクを、替えるブラウザで開く
- 閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」「{イベント}の DT-04」「{地域}の DT-03」は、そのブラウザで VW-03 を開き、対象の名称で検索して結果から開くことを指す（地域は VW-05 から開いてもよい）。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
- サービス運営者の手順の「OM-02 から」「OM-07 を開き」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーションの「対象を探す」（OM-02）または「役割」（OM-07）で進むことを指す。「{対象} の OM-03 から」「OM-03 から」は、OM-02 でその対象の名称で探して（店舗は店舗の名称に、地域はキーワードに入力する）OM-03 を開くことを指す
- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ
- サービス運営者が OM-01 から申請の CM-01 を開く手順は、開く行を、申請の種類と対象（店舗と、地域・イベント）の名称で書く。一覧に同じ種類・同じ対象の申請が複数並ぶときは、開いた CM-01 の申請の値がそのテストケースの申請の値であることを確かめ、違えば一覧へ戻って別の行を開く。申請者が MY-04 から申請の MY-05 を開く手順も、開く行を申請の種類と対象の名称で書く。同じ種類・同じ対象の申請が複数並ぶときは状態か申請の値を添え、申請の値で書いた行は、開いた MY-05 の申請の値がその値であることを確かめ、違えば MY-04 へ戻って別の行を開く
- テスト環境が送るメールは、宛先にかかわらずテスト環境で受け取り、件名・本文・リンクを確かめられる（以下「テスト環境で受け取ったメール」）
- テスト環境に外部アカウントの提供元（以下「提供元」）が1つ設定され、次のテスト用の外部アカウントを使える
  - `ext-new@example.com` を確認済みのメールアドレスとして持つ外部アカウント（Lunt のアカウントはない）
  - `user-a@example.com` を確認済みのメールアドレスとして持つ外部アカウント
  - 確認済みのメールアドレスを持たない外部アカウント（以下「未確認の外部アカウント」）
- ドメインイベントのリレーと消費者（通知の配送、申請の取り下げ、通知の削除）が動いている。通知と、退会に伴う取り下げは非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる
- テスト環境の時刻を進められ、日次のジョブ（使用済み・誤入力の上限に達した・有効期間を過ぎたログインの確認の削除）を手動で実行できる（以下「テスト環境の時刻を N 分進める」「テスト環境で日次のジョブを実行する」）。日次のジョブは、手順が実行を指示したときだけ動く（テスト環境で自動の実行を止めておく）。時刻を進めるのは TC-ACC-028（T+1 分）、TC-ACC-056（T+1 分）、TC-ACC-051（(T−4) 分）だけで、合わせて約 3T 分進む。時刻は戻さない。どのテストケースも、その中で送ったログイン用のメールだけを使う
- 通信エラーは、ブラウザの開発者ツールでネットワークをオフラインにして起こす
- 設定値: コードの誤入力の上限と、ログインの確認の有効期間は、テスト環境の設定値を確かめて記録する（以下「上限 N 回」「有効期間 T 分」）。N が 1 の環境では、1回目の誤入力で上限に達するため、TC-ACC-023 と TC-ACC-049 は行わない。T は 4 分以上であることを前提にする（TC-ACC-051 が時刻を (T−4) 分進める）。同じメールアドレスへのログイン用メールの送信の上限（有効期間内の数）も設定値を確かめて記録する（以下「送信の上限 M 通」）。ほかのテストケースが上限に当たらないよう、M は 20 以上の環境で行う

### 事前準備

1. 他の文書のテストデータを残さず、この文書のテストデータだけを投入した環境で始める（同じメールアドレス・名称が他の文書では別の立場・状態を持つ）
2. テスト環境の設定値（上限 N 回、有効期間 T 分）を確かめて記録する
3. 上のアカウント、店舗、地域、イベント、掲載を用意する。アカウントのない閲覧者のメールアドレスで、ログインしたことがないことを確かめる
4. ブラウザ A・B・C の Cookie とサイトデータを消去し、どれもログインしていない状態にする
5. テストケースは文書の順に行う。前のテストの結果（TC-ACC-001・TC-ACC-006 で作ったアカウント、TC-ACC-008・TC-ACC-010 の申請と通知など）を後のテストが前提として使う。ただし退会のテストはアカウントを消すため、ほかのテストの後に、TC-ACC-017、TC-ACC-018、TC-ACC-019、TC-ACC-020、TC-ACC-043、TC-ACC-044、TC-ACC-046、TC-ACC-041 の順に行う。やり直すときは、上のアカウントと管理権限を作り直す

## 正常系

### TC-ACC-001: メールアドレスとコードで初めてログインし、アカウントが作られる

**シナリオ**: ACC-01 / MY-01、MY-02
**種別**: 正常系
**目的**: アカウントのないメールアドレスでコードを入力するとログインが成立し、アカウントが作られて、始めた MY-01 へ戻ることを確かめる

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | ログインしていないブラウザ A で VW-01 を開き、アカウントの入口を選ぶ | MY-01 が未ログインの状態で開く。ログイン（MY-02）と「店舗を登録・管理する」の入口だけが示される |
| 2 | ログインの入口を選ぶ | MY-02 が入力の状態で開く。メールアドレスの入力欄と、外部アカウントでのログインの選択が示される。パスワードの入力欄はない |
| 3 | メールアドレス欄に `new-user1@example.com` と入力して送る | MY-02 がコード入力の状態になる。メールを送ったこと、コードの入力欄、メールのリンクを開いてもログインが成立すること、リンクを別のブラウザで開くとそのブラウザでログインが成立しこのブラウザの端末の保存は合流しないことが示される |
| 4 | `new-user1@example.com` 宛てにテスト環境で受け取ったメールを開く | ログイン用のメールが1通あり、ワンタイムのリンクとワンタイムのコードの両方が載っている |
| 5 | ブラウザ A の MY-02 で、メールのコードを入力する | ログインが成立し、MY-01 がログイン中の状態で開く。メールアドレス `new-user1@example.com` が示される |
| 6 | MY-01 の入口を確かめる | 「店舗を登録・管理する」、通知、自分の申請、退会の入口が示される。管理する店舗・地域・イベント、読みもの編集、サービス運営の入口は示されない |

**確認ポイント**:
- 登録の画面や、パスワードを決める手順を経ずにアカウントが作られている
- MY-03 を開くと CS-09（通知がない）、MY-04 を開くと CS-09（申請がない）になる

### TC-ACC-047: 大文字と前後の空白を含むメールアドレスは、同じアカウントを指す

**シナリオ**: ACC-01 / MY-02
**種別**: 正常系
**目的**: メールアドレスの前後の空白が除かれ、大文字と小文字が区別されずに同じアカウントへログインすることを確かめる

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | ログインしていないブラウザ A で MY-02 を開き、メールアドレス欄に ` Multi@Example.COM `（前後に半角空白）と入力して送る | コード入力の状態になる |
| 2 | テスト環境で受け取ったメールを確かめる | `multi@example.com` 宛てにログイン用のメールが届いている |
| 3 | メールのコードを入力する | ログインが成立し、MY-01 に `multi@example.com` と管理する店舗「喫茶こもれび」・地域「谷中ぐるり」の入口が示される（新しいアカウントは作られない） |

**確認ポイント**:
- MY-02 のメールアドレス欄は、ブラウザが入力の前後の空白を除いてから送る。この手順で確かめるのは、前後に空白を入力しても送れることと、大文字と小文字が区別されないこと。前後の空白を除く規則そのもの（`EmailAddress.create`、`spec/domains/index.md` の EmailAddress）は、ドメインの単体テストが確かめる
