# 申請の共通の進み方 テスト

## 概要

このドキュメントは、承認を必要とする申請に共通する、申請者の確認・再提出・取り下げ・再申請・失効の把握と、承認者の承認・否認・差し戻し、期間超過の代行に関するマニュアルテストの手順書です。申請ごとの入力項目と、判断で反映される内容の詳細は、各カテゴリー（shop、listing、region、event）の手順書が扱う。

対応シナリオ: `spec/scenario/application.md`（APP-01〜APP-08）

対象の画面: MY-04 自分の申請の一覧、MY-05 申請の詳細、RQ-02〜RQ-06 の再提出と再申請の状態、CM-01 申請の判断、OM-01 対応が必要なもの。確認に使う画面（MY-01、MY-03、SM-01、SM-05、RM-01、EM-01、EM-02、CM-02、OM-02、OM-03、OM-07、DT-01〜DT-03）は、到達と状態だけを確かめる。

テストケースの ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-APP-074 は正常系の TC-APP-029 の後、TC-APP-077 は異常系の TC-APP-039 の後、TC-APP-079 は異常系の TC-APP-040 の後、TC-APP-078 は異常系の TC-APP-054 の後、TC-APP-075・TC-APP-076 は異常系の最後に置く）。TC-APP-035 は欠番。

## 前提条件

### 環境

- テスト環境の Lunt に、PC のブラウザでアクセスできる
- 独立した3つのブラウザ（以下「ブラウザ A」「ブラウザ B」「ブラウザ C」。別のブラウザ、または Cookie を共有しない別のプロファイル）を使う。特に断りがなければブラウザ A で操作する。ブラウザ C はログインせず、閲覧者として確かめる行だけで使う
- テスト環境が送るメールは、宛先にかかわらずテスト環境で受け取り、内容とリンクを確かめられる（以下「テスト環境で受け取ったメール」）
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」と書く）。リンクで行う手順は、そのことを手順に書く
- 1つのブラウザで操作する利用者を替えるときは、次のどちらかで替える。手順の「{利用者} でログインし」「{利用者} で」は、断りがなければ (a) を指す
  - (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから替える利用者のメールアドレスでログインする
  - (b) 別のブラウザの MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクを、替えるブラウザで開く
- 閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」「{地域}の DT-03」は、そのブラウザで VW-03 を開き、対象の名称で検索して結果から開くことを指す（地域は VW-05 から開いてもよい）。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
- 店舗管理者（招待の承諾で店舗管理者になった利用者を含む）の手順の「{店舗}の CM-02 を開く」「{店舗}の CM-02 から」は、MY-01 の管理する店舗「{店舗}」から SM-01 を開き、メンバーの管理（CM-02）へ進むことを指す。店舗を書かない「CM-02 から」は、そのテストケースの店舗の CM-02 を指す。地域運営者・イベント運営者の「{地域}の CM-02」「{イベント}の CM-02」は、MY-01 の管理する地域・イベントから RM-01・EM-01 を開き、管理ナビゲーション「メンバー」で開くことを指す。通知・MY-07・OM-03・OM-05 から開く手順は、そのことを書く
- 承認者が申請の CM-01 を開く手順は、断りがなければ、サービス運営者は OM-01、地域運営者は RM-01、イベント運営者は EM-01 の申請の行から開くことを指す。開く行は、申請の種類と対象（店舗と、地域・イベント）の名称で書く。一覧に同じ種類・同じ対象の申請が複数並ぶときは、開いた CM-01 の申請の値がそのテストケースの申請の値であることを確かめ、違えば一覧へ戻って別の行を開く。サービス運営者の「OM-02 から」「{対象} の OM-03 から」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーションの「対象を探す」で OM-02 へ進み、その対象の名称で探して（店舗は店舗の名称に、掲載・地域はキーワードに入力する）OM-03 を開くことを指す
- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ
- 申請者が MY-04 から申請の MY-05 を開く手順も、開く行を申請の種類と対象（店舗と、地域・イベント）の名称で書く。同じ種類・同じ対象の申請が複数並ぶときは状態か申請の値を添え、申請の値で書いた行は、開いた MY-05 の申請の値がその値であることを確かめ、違えば MY-04 へ戻って別の行を開く
- ドメインイベントのリレーと消費者（通知の配送、申請の前提の再評価による失効、退会に伴う取り下げ）が動いている。通知と失効は非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる
- テスト環境の時刻を進められ、日次のジョブ（開催の状態の記録、期間を超えた申請の通知）を手動で実行できる（以下「テスト環境の時刻を N 日進める」「テスト環境で日次のジョブを実行する」）。日次のジョブは、手順が実行を指示したときだけ動く（テスト環境で自動の実行を止めておく）
- 期間超過の代行の期間（設定値）を確かめて記録する（以下「P 日」）。P は2日以上を前提にする（P が1日なら TC-APP-070 は行えないので、行えなかったことを記録する）
- 日付は、テストを始めた日（以下「今日」）を基準にする。テスト環境の時刻を進めても基準は変えない。時刻は戻さない。時刻を進めるテストケース（TC-APP-028・TC-APP-029・TC-APP-062・TC-APP-067 で各 P+1 日、TC-APP-069 で P 日と1時間、TC-APP-070 で 2P 日と1時間）を通して、合わせて 7P+4 日と約2時間進む。イベント「秋の古書まつり」を最後に使う TC-APP-073 を開催前に行えるよう、進める時刻（7P+4 日と2時間）とテストの実行にかかる日数の合計が 180 日に満たないこと（P が 24 日以下なら、実行が7日を超えない限り満たす）を前提にしている。満たさない場合は、開催期間の始まりがその合計より後になるよう、イベントの開催期間と、テストの参加日・開催期間の日付をそろえて後ろへずらす
- 通信エラーは、ブラウザの開発者ツールでネットワークをオフラインにして起こす
- 写真として、自ら撮影したテスト用の画像ファイル `photo1.jpg`、`photo2.jpg`、`photo3.jpg` を用意する。写真用のファイルは、それぞれ見た目で区別できる画像にする（例: ファイル名を画像の中に大きく描き込む）。期待結果のファイル名（例: `photo2.jpg`）は、写真に描き込んだ名前で確かめる

### TC-APP-001: 自分の申請の一覧に、個人の申請と、管理する店舗の申請が並ぶ

### TC-APP-004: 承認・否認・取り下げの申請の詳細で、結果と次の行き先を確かめる
