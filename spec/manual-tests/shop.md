# 店舗 テスト

## 概要

このドキュメントは、店舗の管理を始める入口、既存店舗の確認、新規店舗の登録と管理権限の申請、店舗情報と営業状況の更新、管理者のいない店舗の修正の申請、それらの申請に対するサービス運営者の判断、店舗の代理登録と不在の代行に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/shop.md`

| --- | --- |

| 異常系 | 76 |
| 境界値 | 1 |
| 合計 | 109 |

ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-SHP-099〜TC-SHP-101 と、TC-SHP-102〜TC-SHP-109）。

### アカウント

ログインは MY-02 でメールアドレスを入力し、テスト環境で受け取ったメールのコードで行う。Lunt にはログアウトの操作がないため、1つのブラウザで利用者を替えるときは、次のどちらかで行う。

- (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから、替える利用者のメールアドレスでログインする
- (b) 別のブラウザの MY-02 で、替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクをこのブラウザで開く（リンクを開いたブラウザでログインが成立し、そのブラウザのアカウントが切り替わる）

手順の「{利用者}（{ブラウザ}）で」「{利用者}（{ブラウザ}）でログインし」は、そのブラウザでその利用者としてログインしている状態で操作することを指す。そのブラウザが別の利用者でログインしていれば、先に (a) か (b) で替える。「閲覧者（ブラウザ3）で」はログインしていないブラウザ3 で操作することを、「ログインしていないブラウザ1 で」はブラウザ1 の Cookie とサイトデータを消去してから操作することを指す。前提の準備は、書いてある利用者として、書いてあるブラウザ（書いていなければブラウザ1）で行う。

閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」は、そのブラウザで VW-03 を開き、対象の名称（S1 などの呼び名は、テストデータの表の名称）で検索して結果から開くことを指す。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く。

手順の「OM-02 で」「OM-02 から」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーションの「対象を探す」で進んだ OM-02 で操作することを指す。「RQ-01 から RQ-02 の登録を開く」「RQ-02 の登録を開く」は、RQ-01 でその手順で入力する名称（名称を空にする手順では任意の名称）を探し、結果の新規店舗の登録の入口から RQ-02 を開くことを指す。「OM-02 から SM-02 の新規を開く」は、OM-02 で登録する名称を探し、結果の代理登録の入口から開くことを指す。店舗管理者の「{店舗}の CM-02」「CM-02 で」は、MY-01 の管理する店舗「{店舗}」から SM-01 を開き、メンバーの管理（CM-02）へ進むことを指す。

承認者が申請の CM-01 を開く手順は、OM-01 の、手順が書く種類・対象の申請の行から開く。一覧に同じ種類・同じ対象の申請が複数並ぶときは、開いた CM-01 の申請の値がそのテストケースの申請の値であることを確かめ、違えば一覧へ戻って別の行を開く。
