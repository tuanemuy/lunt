# 地域 テスト

## 概要

このドキュメントは、店舗の地域への所属・離脱・除外と、地域の運営者による地域の運営（地域情報の更新、公開と公開の取り下げ、所属・離脱の申請の判断、イベントからの関連づけの解除、サービス運営者による地域の登録と不在の代行）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/region.md`

テストケースの ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-REG-107〜TC-REG-126 は、関わるテストケースの近くに置いている。TC-REG-102 は、正常系の最後に置いている）。

## 前提条件

### 環境

- テスト環境の Lunt に、PC のブラウザでアクセスできる
- 3つの独立したセッション（通常のウィンドウ、シークレットウィンドウ、別のブラウザなど。シークレットウィンドウ（プライベートウィンドウ）を使うなら3つのうち1つだけ）を同時に使える。手順の「ブラウザ1」「ブラウザ2」「ブラウザ3」は、別々のログインを保つセッションを指す。「ブラウザ2（ログインしない）」は、Cookie とサイトデータを消去し、ログインしていない状態のブラウザ2で閲覧者として見ることを指す
- 手順の行にブラウザを書かないときは、直前の行と同じブラウザで行う。テストケースの最初の行にブラウザを書かないときは、ブラウザ1で行う
- 手順の「{メールアドレス} でログインし」「{メールアドレス} で」は、そのブラウザがその利用者でログインしていなければ、次のどちらかで利用者を替えてから操作することを指す。ログアウトの操作は使わない（MY の画面はログアウトを持たない）
  - (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから、替える利用者でログインする
  - (b) 別のブラウザの MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクをこのブラウザで開く（MY-02「リンクを開いたブラウザでログインが成立する」「ログインしている利用者が、別のメールアドレスでログインすると、そのブラウザのアカウントが切り替わる」）
- テスト環境で送られたメール（ログインのリンク・コード、通知のメール）を受け取って読める。以下「テスト環境で受け取ったメール」と書く
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」「〜でログインし」と書く）。リンクで行う手順と外部アカウントで行う手順は、そのことを手順に書く
- 店舗管理者の手順の「{店舗}の SM-01」「{店舗}の SM-05」は、MY-01 の管理する店舗「{店舗}」から SM-01 を開き、SM-05 へは SM-01 から進むことを指す。「{店舗}の SM-03」は、その SM-01 から管理ナビゲーション「掲載」で開く SM-03 を指す。店舗管理者が開く CM-02 は、SM-01 から進む
- 地域運営者の手順の「{地域}の RM-01」「RM-02」「RM-03」は、MY-01 の管理する地域「{地域}」から RM-01 を開き、RM-02・RM-03 へは管理ナビゲーション「地域情報」「関連イベント」で進むことを指す
- イベント運営者の手順の「{イベント}の EM-03」は、MY-01 の管理するイベント「{イベント}」から EM-01 を開き、管理ナビゲーション「開催地域」で進むことを指す
- サービス運営者の手順の「OM-02 から」「OM-02 で」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーション「対象を探す」で OM-02 へ進むことを指す。「{対象}の OM-03」は、OM-02 でその対象を探し（店舗は店舗の名称に、地域・イベントはキーワードに入力する。手順が入力する語を書かないときは、対象の名称を入力する）、結果から開く OM-03 を指す
- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ
- 閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」「{イベント}の DT-04」は、そのブラウザで VW-03 を開き、対象の名称で検索して結果から開くことを指す。「{地域}の DT-03」は、同じく VW-03 で地域の名称を検索するか、VW-05 から開くことを指す。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
- ドメインイベントのリレーと消費者（通知の配送、申請の前提の再評価による失効）が動いている。通知と申請の失効は非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる。通知を MY-03 で確かめるときと、失効を確かめるときは、手順に書いていなくても反映を待って読み込み直す。失効しないことは、待つだけでは反映の前と区別できないため、同じ出来事で別の宛先に届く通知を先に確かめてから見る
- テスト環境の時刻を進め、戻せる。日次のジョブ（期間を超えた申請の通知）を実行できる。日次のジョブは、手順が実行を指示したときだけ動く（テスト環境で自動の実行を止めておく）
- ブラウザの開発者ツールで通信を切断できる（TC-REG-069）
- 「今日」を T と書く。T+10 は今日から10日後を指す
- 期間超過の代行ができるようになるまでの期間は、テスト環境の設定値を確かめ、以下 D 日と書く

### 事前準備

1. 他の文書のテストデータを残さず、この文書のテストデータだけを投入した環境で始める（同じメールアドレス・名称が他の文書では別の立場・状態を持つ）
2. 上の「テストデータ」のアカウント、地域、店舗、掲載、イベント、参加を、テスト環境のデータ投入で用意する。画面から用意する場合は、地域は REG-12、イベントは EVT-12、店舗は SHP-12、管理権限は REG-12・EVT-12 の付与と MEM-03 の招待の承諾、所属は所属の申請と承認、参加は参加の申請と承認（EVT-01・EVT-08）、運営による非公開は MOD-07 で作る
3. 各テストケースは、この事前準備の状態から始める。前のテストケースで変わった状態は、データを投入し直して戻す。時刻を進めたテストケースの後は、テスト環境の時刻を戻してからデータを投入し直す。各テストケースの始めに、ブラウザ1・ブラウザ2 で、テスト環境の位置情報の許可を消す（Chrome はサイト設定で「確認する（デフォルト）」に戻す。Firefox はサイトの権限から位置情報の許可を消す）。位置情報の許可はサイトデータの消去では戻らず、残っていると VW-01 は現在地を利用中の状態で、VW-05 は周辺の地域の状態で開く（pages/browse.md VW-01・VW-05）
4. テストケースが「事前準備」の行または「前提」を持つときは、その手順を先に行う
5. 「URL を控える」は、書かれたブラウザ・利用者で画面を開き、アドレスバーの URL を写しておくことを指す。控える手順は、そのテストケースの前提か手順に、ブラウザ・利用者・開く画面とともに書く

## TC-REG-001: 店舗管理者が所属地域の状況から、キーワードで地域を選んで所属を申請する

**シナリオ**: REG-01 / SM-05、RQ-05
**種別**: 正常系
**目的**: 店舗管理者が、管理する店舗の所属地域の状況から地域を探して選び、所属を申請できることを確かめる

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | `owner2@example.com` でログインし、MY-01 の管理する店舗「みなと雑貨」から SM-01 を開き、SM-05 へ進む | SM-05 が「所属がない」の状態で開く。所属中の地域がないことと、所属の申請への入口が示される |
| 2 | 所属の申請へ進む | RQ-05 が「入力（所属）」の状態で開く。店舗「みなと雑貨」と、地域の選択が示される |
| 3 | 地域の選択で `みなと` と入力して探す | 候補に「みなと商店街」だけが示される。紹介に `みなと` を含む旧市街（公開の取り下げ）と運河地区（運営による非公開）は候補に示されない |
| 4 | 候補の「みなと商店街」から DT-03 を開いて確かめ、RQ-05 へ戻る | DT-03 に地域の写真・名称・キャッチコピー・紹介・所在地が示される。RQ-05 に戻ると、それまでの入力は変わっていない |

| 7 | MY-04 を開く | 店舗の申請に、申請者を店舗「みなと雑貨」とする所属の申請が確認中として示される |

## カバレッジ

### ユースケースエラーケース対応表

対象は、実現する欄に REG-01〜REG-13 を含むユースケース。suspendRegion・unsuspendRegion（MOD-07）は moderation.md の範囲とする。対応TC の備考の「操作が示されないことの確認」は、そのテストケースが画面の入口・操作が示されないことを確かめるもので、そのユースケースのエラーを起こす操作はしない。

提出の時点の受け付けない事情: pages/index.md の「受け付けない事情」は、どの事情も開いた時点と提出の時点で確かめる1つの規則である。提出の時点の確かめは、店舗に店舗管理者がいる（shop.md TC-SHP-064）、申請者がその店舗の店舗管理者でない（region.md TC-REG-118、event.md TC-EVT-143）、対象の掲載がない（listing.md TC-LST-084）、所属がすでにある（region.md TC-REG-041 手順2）、所属がない（region.md TC-REG-047）、イベントが終了または中止している（event.md TC-EVT-048）、同じ申請者の同じ種類・同じ対象の申請が確認中・差し戻しにある（region.md TC-REG-125）、閲覧できなければならない対象が閲覧できない（region.md TC-REG-039・TC-REG-110、event.md TC-EVT-046、listing.md TC-LST-077）が確かめる。残りの事情（申請者がすでにその店舗の店舗管理者である、併せた登録申請が否認・取り下げになっている、参加がすでにある）は開いた時点・候補で確かめ、提出の時点は同じ規則として TC を置かない。対応表で開いた時点・候補の確かめを当てた行は、備考にそう書く。
