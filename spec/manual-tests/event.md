# イベント テスト

## 概要

このドキュメントは、店舗のイベントへの参加の申請・参加内容の変更・取りやめ・除外・直接の追加と、イベントの運営者によるイベントの運営（情報の更新と延期、開催地域の関連づけ、公開と取り下げ、中止と中止の取り消し、登録と管理権限の付与、不在の代行）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/event.md`

テストケースの ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-EVT-136〜TC-EVT-155 は、関わるテストケースの近くに置いている。TC-EVT-129 は、正常系の最後に置いている）。

## 前提条件

### 環境

- テスト環境の Lunt に、PC のブラウザでアクセスできる。3つの独立したセッション（通常のウィンドウ、シークレットウィンドウ、別のブラウザなど。シークレットウィンドウ（プライベートウィンドウ）を使うなら3つのうち1つだけ）を同時に使える。手順の「ブラウザ1」「ブラウザ2」「ブラウザ3」は、別々のログインを保つセッションを指す。「（ブラウザ2・ログインしない）」は、Cookie とサイトデータを消去し、ログインしていない状態のブラウザ2で閲覧者として見ることを指す
- 手順の行にブラウザを書かないときは、直前の行と同じブラウザで行う。テストケースの最初の行にブラウザを書かないときは、ブラウザ1で行う
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」「〜でログインし」と書く）。リンクで行う手順と外部アカウントで行う手順は、そのことを手順に書く
- 手順の「{メールアドレス} でログインし」「{メールアドレス} で」「{利用者} で」は、そのブラウザがその利用者でログインしていなければ、次のどちらかで利用者を替えてから操作することを指す。ログアウトの操作は使わない（MY の画面はログアウトを持たない）
  - (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから、替える利用者でログインする
  - (b) 別のブラウザの MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクをこのブラウザで開く（MY-02「リンクを開いたブラウザでログインが成立する」「ログインしている利用者が、別のメールアドレスでログインすると、そのブラウザのアカウントが切り替わる」）
- テスト環境で受け取ったメール（ログインのリンク・コード、通知のメール）を確かめられる
- VW-07 は、下部ナビゲーション「みつける」（VW-01）のイベントの一覧の入口から開く
- 「{店舗}の参加を{イベント}へ申請する」は、その店舗の店舗管理者で SM-06（{店舗}）から RQ-06 を開き、キーワードでイベントを選んで提出することを指す
- 「{店舗}の{イベント}の参加を取りやめる」は、その店舗の店舗管理者で SM-06（{店舗}）から{イベント}の CM-04 を開き、参加の取りやめを選んで CS-12 で確定することを指す
- 「{イベント}の EM-01 から{店舗}を除外する」は、イベントの運営者で{イベント}の EM-01 の参加店舗から{店舗}の除外を選び、CS-12 で確定することを指す。確定しない手順は「{店舗}の除外を選ぶ」と書く
- 店舗管理者の手順の「SM-06（{店舗}）」は、MY-01 の管理する店舗「{店舗}」から SM-01 を開き、管理ナビゲーション「イベント」で開く SM-06 を指す。「{イベント}の CM-04」は、その SM-06 で参加中の{イベント}を選んで開く CM-04 を指す。「SM-04 で{掲載}」「{掲載}の SM-04」は、同じ店舗の管理ナビゲーション「掲載」で SM-03 を開き、{掲載}を選んで開く SM-04 を指す
- 地域運営者の手順の「{地域}の RM-01」「RM-02」「RM-03」は、MY-01 の管理する地域「{地域}」から RM-01 を開き、RM-02・RM-03 へは管理ナビゲーション「地域情報」「関連イベント」で進むことを指す
- イベントの運営者の手順の「{イベント}の EM-01」「EM-02」「EM-03」は、MY-01 の管理するイベント「{イベント}」から EM-01 を開き、EM-02・EM-03 へは管理ナビゲーション「イベント情報」「開催地域」で進むことを指す。「{イベント}の{店舗}の参加内容」は、{イベント}の EM-01 の参加店舗から{店舗}の参加内容を選んで開く CM-04 を指す
- サービス運営者の手順の「OM-02 から」「OM-02 で」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーション「対象を探す」で OM-02 へ進むことを指す。「{対象}の OM-03」は、OM-02 でその対象を探し（店舗は店舗の名称に、掲載・地域・イベントはキーワードに入力する。手順が入力する語を書かないときは、対象の名称を入力する）、結果から開く OM-03 を指す。不在の代行の画面は、OM-02 の結果の管理者のいない対象の行にある不在の代行の入口から開く。店舗は SM-02・SM-03、掲載は SM-04、地域は RM-01、イベントは EM-01 が開く。不在の代行で開いたイベントの EM-02・EM-03 へは、開いた EM-01 の管理ナビゲーション「イベント情報」「開催地域」で進む（CS-14）
- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ
- 閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」「{イベント}の DT-04」「{地域}の DT-03」は、そのブラウザで VW-03 を開き、対象の名称で検索して結果から開くことを指す（地域は VW-05 から開いてもよい）。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
- テスト環境で日次のジョブ（開催の状態の記録、期間を超えた申請の通知）を実行できる。日次のジョブは、手順が実行を指示したときだけ動く。テスト環境の時刻を進め、戻せる
- ドメインイベントのリレーと消費者（通知の配送、申請の前提の再評価による失効）が動いている。通知と申請の失効は非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる。手順が「失効として示される」「失効しない」を確かめるときと、通知を MY-03 で確かめるときも同じ。失効しないことは、待つだけでは反映の前と区別できないため、同じ出来事で別の宛先に届く通知を先に確かめてから見る
- 期間超過の代行ができるようになるまでの期間は、テスト環境の設定値 D 日とする。D は 8 以下にしておく（みなと夏まつりが D+1 日後に終了しないようにするため）
- 通信エラーは、ブラウザの開発者ツールでネットワークをオフラインにして起こす
- 日付は、テストを始める日（今日）を T として相対で書く。テスト環境の時刻を進めた後も、日付は最初の T を基準に書く

### 事前準備

1. 他の文書のテストデータを残さず、この文書のテストデータだけを投入した環境で始める（同じメールアドレス・名称が他の文書では別の立場・状態を持つ）
2. テスト環境に上のアカウント・店舗・掲載・地域・イベントのデータを投入する
3. 各テストケースは事前準備の状態から始める。前のテストケースで変わった状態は、データを投入し直して戻す。時刻を進めたテストケースの後は、テスト環境の時刻を戻してからデータを投入し直す
4. テスト環境の時刻と日付を実際の今日（T）に合わせる
5. 「URL を控える」は、書かれたブラウザ・利用者で画面を開き、アドレスバーの URL を写しておくことを指す。控える手順は、そのテストケースの前提か手順に、ブラウザ・利用者・開く画面とともに書く

### ユースケースエラーケース対応表

対象は、実現する欄に EVT-01〜EVT-13 を含むユースケース。suspendOccasion・unsuspendOccasion（MOD-07）は moderation.md の範囲とする。対応TC の備考の「操作が示されないことの確認」は、そのテストケースが画面の入口・操作が示されないことを確かめるもので、そのユースケースのエラーを起こす操作はしない。

提出の時点の受け付けない事情: pages/index.md の「受け付けない事情」は、どの事情も開いた時点と提出の時点で確かめる1つの規則である。提出の時点の確かめは、店舗に店舗管理者がいる（shop.md TC-SHP-064）、申請者がその店舗の店舗管理者でない（region.md TC-REG-118、event.md TC-EVT-143）、対象の掲載がない（listing.md TC-LST-084）、所属がすでにある（region.md TC-REG-041 手順2）、所属がない（region.md TC-REG-047）、イベントが終了または中止している（event.md TC-EVT-048）、同じ申請者の同じ種類・同じ対象の申請が確認中・差し戻しにある（region.md TC-REG-125）、閲覧できなければならない対象が閲覧できない（region.md TC-REG-039・TC-REG-110、event.md TC-EVT-046、listing.md TC-LST-077）が確かめる。残りの事情（申請者がすでにその店舗の店舗管理者である、併せた登録申請が否認・取り下げになっている、参加がすでにある）は開いた時点・候補で確かめ、提出の時点は同じ規則として TC を置かない。対応表で開いた時点・候補の確かめを当てた行は、備考にそう書く。
