# サービス運営 テスト

## 概要

このドキュメントは、サービス運営者が対応の必要な申請・申立て・連絡を確かめる操作、カテゴリーの追加・変更・廃止、編集担当者の任命と解除、サービス運営者の役割の付与と解除に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/operation.md`

画面名・画面 ID・共通の状態（CS）・共通の機能（CF）は `spec/pages/` の用語に従う。期待結果の「CS-xx の状態」は `spec/pages/index.md` の「共通の状態」が定める内容を指す。画面に示す文面は pages が定めないため、期待結果は画面の状態・示される内容・遷移先で書く。

ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-OPE-064 は TC-OPE-005 の後に、TC-OPE-065 は TC-OPE-058 の後に、TC-OPE-066 は TC-OPE-032 の後に、TC-OPE-067 は TC-OPE-028 の後に、TC-OPE-068・TC-OPE-069 は TC-OPE-066 の後に、TC-OPE-070 は TC-OPE-045 の後にある）。

## 前提条件

### 環境

- テスト環境で Lunt が起動していて、PC のブラウザからアクセスできる
- テスト環境が送るメールを、宛先のメールアドレスごとに確かめられる（以下「テスト環境で受け取ったメール」）
- ドメインイベントのリレーと消費者（通知の配送）が動いている。通知は非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる
- テスト環境の時刻を進め、戻せる。日次のジョブ（期間を超えた申請の通知）を任意の時点で実行できる（期間超過の代行の確認に使う）。日次のジョブは、手順が実行を指示したときだけ動く（テスト環境で自動の実行を止めておく）
- 期間超過の代行の期間（設定値）を、テスト環境の設定で確かめて記録する（以下「期間 P」）
- Cookie を共有しない3つのブラウザ（別のブラウザ、または別のプロファイル。プライベートウィンドウを使うなら3つのうち1つだけ）を使う。以下、ブラウザ A・ブラウザ B・ブラウザ C と書く。ブラウザ C は閲覧者の確認に使い、ログインしない
- ログインは MY-02 で、メールアドレスを入力し、テスト環境で受け取ったメールのコードを入力して行う
- 手順の「OM-02 で」「OM-06 で」「OM-07 で」は、MY-01 のサービス運営から OM-01 を開き、運営のナビゲーションの「対象を探す」「カテゴリー」「役割」で進んだ OM-02・OM-06・OM-07 で操作することを指す

- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ

- 通信エラーの確認には、ブラウザの開発者ツールでネットワークをオフラインにする
- 郵便番号・町域のデータに `110-0001`（東京都台東区谷中）と `113-0031`（東京都文京区根津）が入っている

## TC-OPE-001: 対応が必要なものを4種に分けて確かめる

**シナリオ**: OPE-01 / MY-01、OM-01
**種別**: 正常系
**目的**: サービス運営者が、承認者である申請・期間超過の代行ができる申請・申立て・連絡を種類を区別して確かめ、1件ごとに種類・対象・申請者を確かめられることを確かめる

**前提**: 次の4件を用意する
- ブラウザ B で user1 としてログインし、MY-01 から RQ-01 を開いて名称「喫茶こもれび」で探し、新規店舗の登録の入口から RQ-02 を開く。管理権限の申請を併せるかの選択で「登録だけを申請する」を選び、名称「喫茶こもれび」、郵便番号 `110-0001` から町域「谷中」、町域より後の部分「2-10-1」、位置（地図で谷中二丁目の1点を選ぶ）を入力して提出する
- ブラウザ B（user1）で DT-02「古書ほおずき」から、地域「谷中ぶらり」への所属を RQ-05 で申請し、提出した時刻を控える。その後、テスト環境の時刻を、控えた時刻から期間 P を超える時点まで進め、テスト環境で日次のジョブを実行する
- ブラウザ C で、DT-02「喫茶ひだまり」から、店舗本人・理由 `掲載をやめたい`・`claimant@example.com` の申立てを提出する
