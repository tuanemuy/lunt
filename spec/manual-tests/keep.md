# 保存 テスト

## 概要

このドキュメントは、閲覧者が掲載と店舗を保存・解除し、保存一覧で見返し、閲覧できなくなった保存を解除し、ログインして端末の保存をアカウントに引き継ぐ操作に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/keep.md`（KEP-01〜KEP-04）

対象画面: VW-10 保存（`spec/pages/browse.md`）、保存の操作（CF-04）を持つ VW-01 みつける・DT-01 掲載詳細・DT-02 店舗詳細、MY-02 ログイン（`spec/pages/account.md`）。ログインの異常系の網羅は account.md の手順書が持ち、ここでは端末の保存がどうなるかを確かめる。

ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-KEP-045・TC-KEP-047・TC-KEP-050 は正常系の最後の TC-KEP-026 の後、TC-KEP-048 は TC-KEP-029 の後、TC-KEP-049 は TC-KEP-033 の後にある）。

## 前提条件

### 環境

- ブラウザ1（端末1）: Google Chrome の通常のウィンドウ。閲覧者の操作に使う
- ブラウザ2: Google Chrome のシークレットウィンドウ。管理側（店舗管理者・地域運営者・サービス運営者）の操作に使う
- ブラウザ3（端末2）: Firefox。同じアカウントの別の端末として使う
- 通信エラーは、ブラウザ1の DevTools の Network で「Offline」に切り替えて起こす。保存の引き継ぎの通信だけを失敗させるテストは、DevTools の「Network request blocking」を使う（事前準備5）
- テスト環境で受け取ったメールを確認できる
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」「〜でログインし」と書く）。リンクで行う手順と外部アカウントで行う手順は、そのことを手順に書く
- テスト環境に、外部アカウントでのログインの提供元（テスト用）が設定されていて、確認済みのメールアドレスを持つテスト用の外部アカウントを使える

利用者の替え方は次の2つだけを使う。ログインしている間の MY-01 はログインの入口を示さないため、ログイン中のブラウザで MY-01 からログインへ進む手順は使わない。

- (a) そのブラウザのテスト環境の Cookie とサイトデータを消去し、MY-01 のログインから替える利用者のメールアドレスでログインする（テスト環境で受け取ったメールのコードを入力する）。端末の保存も消える。ブラウザ2で店舗管理者K とサービス運営者を替えるときは、これを使う。手順の「ブラウザ2で{利用者}が」は、ブラウザ2がその利用者でログインしていなければ、この替え方でその利用者にしてから操作することを指す
- (b) 別のブラウザ（ログインしていない）の MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクを、替えたいブラウザで開く。リンクを開いたブラウザでログインが成立し、そのブラウザがログイン中だったならアカウントが切り替わる。端末の保存は消えない。TC-KEP-023 が使う

### 事前準備

1. 他の文書のテストデータを残さず、discover.md の基本データとこの文書の P1 だけを投入した環境で始める（同じメールアドレス・名称が他の文書では別の立場・状態を持つ）
2. discover.md の「事前準備」の2のとおり、基本データを用意する。P1 を公開する
3. 各テストケースの始めに、ブラウザ1とブラウザ3で、テスト環境のサイトデータ（Cookie とサイトのストレージ）を消去する。各テストケースは、特に書かない限り、この状態（ログインしていない、端末の保存がない）のブラウザ1で始める。各テストケースの始めに、ブラウザ1とブラウザ3で、テスト環境の位置情報の許可も消す（ブラウザ1の Chrome はサイト設定で「確認する（デフォルト）」に戻す。ブラウザ3の Firefox はサイトの権限から位置情報の許可を消す）。位置情報の許可はサイトデータの消去では戻らず、残っていると VW-01 は現在地を利用中の状態で、VW-05 は周辺の地域の状態で開く（pages/browse.md VW-01・VW-05）
4. 「保存する」「解除する」は、対象の保存の操作（CF-04）を切り替えることを指す。保存した順を期待結果が使うので、手順の順に1件ずつ操作する
5. TC-KEP-041 の前に、ログインの成立の後に端末の保存をアカウントへ送る通信の URL を、開発者向けの資料またはブラウザ1の DevTools の Network で確かめ、Network request blocking の対象に登録できるようにしておく（通常はブロックを無効にしておく）
6. テストデータを変えるテストケースは、確認ポイントに戻し方を書く。戻してから次のテストケースへ進む
7. MY-01 から閲覧側の画面（VW・DT）へ移るときは、同じブラウザで新しいタブを開いて Lunt のトップ（VW-01）を開き、下部ナビゲーションから進む（MY-01 は下部ナビゲーションを示さない）。ログインが成立して MY-01 に戻った後の手順の「『保存』を開く」「{対象} の DT-0n で保存する」は、これを指す
8. 手順が経路を書かずに「{対象} の DT-0n を開く」「{対象} の DT-0n で保存する」と書くときは、そのブラウザで Lunt のトップ（VW-01）の検索の入口から VW-03 を開き、対象の名称で検索して結果から開く（VW-03 は参照の場面で、閉店・提供開始前・提供終了・終了・中止の対象も状態とともに示す。scenario/index.md「表示範囲」）。VW-01 へは、開いている画面の下部ナビゲーションの「みつける」で移る。MY-01 からは事前準備7のとおり新しいタブで Lunt のトップを開く。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
9. 手順の「『保存』を開き直す」は、同じタブで下部ナビゲーションの「みつける」へ進み、続けて「保存」を開くことを指す（TC-KEP-009 手順4 と同じ）

### ユースケースエラーケース対応表

| ユースケース | エラーケース | 対応TC | 備考 |
| --- | --- | --- | --- |
| saveBookmark | ログインせずに呼んだ（`UnauthorizedError`） | 対象外 | 画面は、ログインしていない間は端末に保存し、アカウントの保存の操作を呼ばない。ログインせずに端末へ保存できることは TC-KEP-001 が確かめる |
| removeBookmark | ログインせずに呼んだ（`UnauthorizedError`） | 対象外 | 同上（TC-KEP-004） |
| listBookmarks | ログインせずに呼んだ（`UnauthorizedError`） | 対象外 | ログインしていない間の保存一覧は、端末の参照を resolveReferences で解決する（TC-KEP-001、TC-KEP-033）。ログインしている間の保存一覧は、アカウントの保存の参照を listBookmarks で読み、resolveReferences で解決する。その取得の通信エラーは TC-KEP-049 が確かめる（通信エラーはユースケースのエラーケースでない） |
| getSavedTargets | ログインせずに呼んだ（`UnauthorizedError`） | 対象外 | 同上。ログインしていない間の保存済みの表示は端末が決める |
| mergeDeviceBookmarks | ログインせずに呼んだ（`UnauthorizedError`） | 対象外 | 合流はログインの成立の後にだけ行われる |
| saveBookmark・removeBookmark・mergeDeviceBookmarks | 要件が振る舞いを定めるエラーはない（保存済みの保存、保存のない解除、同じ一覧の送り直し、閲覧できない対象の保存は成功） | TC-KEP-030、TC-KEP-041、TC-KEP-048 | エラーにならないことを確かめる。閲覧できない対象のアカウントへの保存は TC-KEP-048 |
| listBookmarks・getSavedTargets | 要件が振る舞いを定めるエラーはない | TC-KEP-013、TC-KEP-032、TC-KEP-013 手順4・TC-KEP-020 手順5（getSavedTargets の保存済みの表示） | エラーにならないことを確かめる |
| resolveReferences | 要件が振る舞いを定めるエラーはない（0件、閲覧できない参照は閲覧できないことだけを返す） | TC-KEP-014、TC-KEP-019、TC-KEP-032 | |
