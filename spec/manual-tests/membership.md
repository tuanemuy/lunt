# 管理権限 テスト

## 概要

このドキュメントは、店舗・地域・イベントの管理権限に共通する、管理メンバーの確認・招待・招待の取り消し・承諾と、辞任・権限の解除に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/membership.md`（MEM-01〜MEM-05）

対象の画面: CM-02 メンバーの管理、MY-06 招待の承諾、OM-02 対象を探す、OM-03 対象の運営。確認に使う画面（MY-01、MY-02、MY-03、MY-05、SM-01、SM-02、SM-03、RM-01、EM-01、DT-02、RQ-03、CM-01、OM-01、OM-07）は、到達と状態だけを確かめる。

テストケースの ID は追加の順に振っているため、文書の中の並びと番号の順が違う箇所がある（TC-MEM-050 は TC-MEM-002 の後、TC-MEM-052 は TC-MEM-012 の後、TC-MEM-049 は正常系の最後、TC-MEM-047 は異常系の TC-MEM-026 の後、TC-MEM-051 は TC-MEM-027 の後、TC-MEM-053 は TC-MEM-034 の後に置く）。TC-MEM-049 は文書の最後に行う（事前準備8）。

## 前提条件

### 環境

- テスト環境の Lunt に、PC のブラウザでアクセスできる
- 独立した3つのブラウザ（以下「ブラウザ A」「ブラウザ B」「ブラウザ C」。別のブラウザ、または Cookie を共有しない別のプロファイル）を使う。特に断りがなければブラウザ A で操作する。ブラウザ C はログインせず、閲覧者として確かめる行だけで使う
- 「ログインしていないブラウザ A で」と書いた行は、そのブラウザの Cookie とサイトデータを消去してから始める
- テスト環境が送るメールは、宛先にかかわらずテスト環境で受け取り、内容とリンクを確かめられる（以下「テスト環境で受け取ったメール」）。招待のメールと、ログイン用のメールもここで受け取る
- ログインは、そのブラウザの MY-02 でメールアドレスを送り、テスト環境で受け取ったメールのコードを同じブラウザで入力して行う（手順では「〜でログインする」と書く）。リンクで行う手順は、そのことを手順に書く
- 1つのブラウザで操作する利用者を替えるときは、次のどちらかで替える。手順の「{利用者} でログインし」「{利用者} で」は、断りがなければ (a) を指す
  - (a) そのブラウザの Cookie とサイトデータを消去し、MY-01 のログインから替える利用者のメールアドレスでログインする
  - (b) 別のブラウザの MY-02 で替える利用者のメールアドレスを送り、テスト環境で受け取ったメールのリンクを、替えるブラウザで開く
- 閲覧側の「{店舗}の DT-02」「{掲載}の DT-01」「{イベント}の DT-04」「{地域}の DT-03」は、そのブラウザで VW-03 を開き、対象の名称で検索して結果から開くことを指す（地域は VW-05 から開いてもよい）。閲覧できない対象の詳細は、そのテストケースが控えた URL で開く
- サービス運営者の手順の「OM-02 から」「OM-01 から」「OM-07 を開き」は、MY-01 のサービス運営から OM-01 を開き、OM-02・OM-07 へは運営のナビゲーションの「対象を探す」「役割」で進むことを指す。「{対象} の OM-03 を開く」は、OM-02 でその対象の名称で探して（店舗は店舗の名称に、地域・イベントはキーワードに入力する）OM-03 を開くことを指す。サービス運営者の「{対象} の CM-02 を開く」は、その対象の OM-03 を開き、CM-02 へ進むことを指す
- 店舗管理者（招待の承諾や管理権限の申請の承認で店舗管理者になった利用者を含む）の手順の「{店舗}の CM-02 を開く」「{店舗}の CM-02 から」は、MY-01 の管理する店舗「{店舗}」から SM-01 を開き、メンバーの管理（CM-02）へ進むことを指す。地域運営者・イベント運営者の「{地域}の CM-02」「{イベント}の CM-02」は、MY-01 の管理する地域・イベントから RM-01・EM-01 を開き、管理ナビゲーション「メンバー」で開くことを指す。対象を書かない「CM-02 を開く」「CM-02 を開き直す」は、そのテストケースの対象の CM-02 を、その利用者のこの経路（サービス運営者は OM-03 から）で開くことを指す。通知・控えた URL・OM-03 から開く手順は、そのことを書く
- 対象の選択（CF-02）で対象を選ぶ手順が入力する語を書かないときは、その対象の名称をキーワードに入力して探し、候補から選ぶ
- ドメインイベントのリレーと消費者（通知の配送、申請の失効）が動いている。通知と申請の失効は非同期に反映されるため、反映されるまで待ち、画面を読み込み直して確かめる
- テスト環境の時刻を進められる（以下「テスト環境の時刻を N 日進める」）。日次のジョブは、手順が実行を指示したときだけ動く（テスト環境で自動の実行を止めておく）。日次のジョブの実行を指示するのは、最後に行う TC-MEM-049 だけ。時刻を進めるのも TC-MEM-049（400 日）だけで、時刻は戻さない
- 通信エラーは、ブラウザの開発者ツールでネットワークをオフラインにして起こす

### 事前準備

1. 他の文書のテストデータを残さず、この文書のテストデータだけを投入した環境で始める（同じメールアドレス・名称が他の文書では別の立場・状態を持つ）
2. 上のアカウントと、店舗・地域・イベント・掲載を用意する。`newbie@example.com` と `old-invitee@example.com` のアカウントがないことを確かめる
3. 利用者 P のアカウントを作った後に、店舗管理者 O1 で「喫茶こもれび」の CM-02 から `pending-1@example.com` に招待を送る（利用者 P の MY-03 に招待の通知が届く）
4. 店舗「谷中ベーカリー」と「千駄木文具店」の承諾前の招待は、店舗ごとに次の手順で作る。辞任で店舗は管理者のいない店舗になり、招待は残る
   1. 仮の店舗管理者 V（`former@example.com`）でログインし、その店舗の DT-02 の「このお店を管理する」から RQ-03 を開き、店舗との関係に `前の店主です`、確認に使える連絡先に `03-2222-3333（店舗の代表電話）` と入力して提出する
   2. サービス運営者 S1 で OM-01 からその申請の CM-01 を開いて承認する（CS-12 で確定する）
   3. V で MY-01 の管理する店舗からその店舗の SM-01 を開き、CM-02 へ進んで、上の表の宛先（「谷中ベーカリー」は `heir@example.com`、「千駄木文具店」は `old-invitee@example.com` と `late-accept@example.com`）に招待を送る
   4. V で CM-02 から辞任を確定する（CS-12）
5. 利用者 A で、店舗「谷中ベーカリー」の DT-02 から RQ-02 を開き、紹介を `天然酵母のパン屋` に変える情報修正の申請を提出する（手順4の辞任の後に行う）
6. 店舗管理者 L で、店舗「根津珈琲舎」の SM-05 から RQ-05 を開き、地域「谷中ぐるり」への所属を申請する
7. ブラウザ A・B・C の Cookie とサイトデータを消去する
8. テストケースは文書の順に行う。前のテストの結果（招待の承諾、辞任、解除）を後のテストが前提として使う。ただし時刻を進める TC-MEM-049 は、ほかのテストの後、文書の最後に行う
