# scenario の未決の問いへの決定

各担当が返した未決の問いへの決定。シナリオには現在形の事実として書く（「決定した」「〜とする判断」などの経緯は書かない）。

## 全カテゴリー共通

- C-1 同時編集は楽観ロックで扱う。他の人が先に保存した対象を保存しようとすると、競合が示され、最新の内容を読み直して操作し直す
- C-2 管理者・運営者が不在の対象への、管理者・運営者宛ての通知は、サービス運営者に届く（B-14・B-31）。店舗管理者として行った申請の申請者宛ての通知は、その時点のその店舗のすべての店舗管理者に届く（P-76）
- C-3 同じ申請者（個人、または店舗管理者としての店舗）が、同じ種類・同じ対象で確認中・差し戻し中の申請を持つ間は、重ねて申請できない（P-74）。別の申請者の申請は独立して確認される（P-75）。再申請は新しい申請として始め、前の申請の内容は引き継がない
- C-4 運営による非公開・店舗の非公開の間、管理者・運営者は対象の情報を更新できるが、対象の公開状態（公開・取り下げ・一時非公開・再公開）は変更できない。解除すると、掲載・地域・イベントは非公開にする前の公開状態に戻る。非公開の店舗の掲載は通常どおり操作できるが、解除まで閲覧者に表示されない
- C-5 管理権限・役割の付与先（地域運営者・イベント運営者・編集担当者・サービス運営者）は、既存のアカウントをメールアドレスで指定する。アカウントがなければ付与できない
- C-6 写真を持つ対象（掲載・店舗・地域・イベント・読みもの）は、どれも複数の写真を登録して並び替えられ、1枚目が代表写真（I-06）。見せる範囲の調整は掲載の写真だけ。掲載の申請者も見せる範囲を調整できる

## application / membership / shop

- A-0 すべての申請は、承認者への補足（自由記述）を持てる。差し戻された申請は、申請の内容と補足を修正して再提出する（P-72）。所属・離脱の申請のように内容が対象の指定だけの申請も、補足で追加の確認に答える

- A-1 確認中・差し戻し中の申請の対象が運営による非公開・店舗の非公開になっても、申請は失効しない。承認者が判断する
- A-2 代行（APP-08）でできるのは承認と否認だけ。「一定の期間」は、申請が確認中になった時点（提出または再提出）から数える
- A-3 対象の管理者が不在になると、承諾前の招待は無効になる。招待した管理者が権限を手放しても退会しても、他の管理者がいる間は招待は有効
- A-4 SHP-08 の営業状況の申請は、営業中・休業・閉店のどれへの変更も含む（営業状況の誤りの修正を含む）
- A-5 SHP-02 の既存店舗の確認にログインは要らない（B-18）。申請へ進むときにログインを求める。一覧の利用者は「閲覧者」
- A-6 店舗の登録では、種別（店舗・スポット）を選ぶ（P-21）。管理権限の申請に添える「確認に使える連絡先または資料」は文章で記す（ファイルは添えない）。管理者の一覧では、管理者をメールアドレスで識別する
- A-7 登録申請に併せた管理権限の申請は、登録の承認の後に判断する（本文のまま）

## listing / moderation

- L-1 下書きの保存に必要なのは店舗への紐づけだけ。ほかの項目は公開のときに公開条件として確かめる
- L-2 提供期間は開始日だけ、終了日だけでも設定できる。提供状態は提供期間・開催日・店舗管理者による提供終了と今日の日付から決まるので、自動で提供終了になった掲載から提供期間を外すと提供中に戻る
- L-3 複製は下書きとして作られ、名称・説明・カテゴリー・写真（見せる範囲を含む）を引き継ぐ。提供期間・開催日は引き継がない。運営による非公開の掲載は複製できない
- L-4 MOD-06: 店舗管理者は確認の依頼に対して、確認を終えたこと（情報を更新した、または誤りはなかった）をサービス運営者に伝えられる。伝えると連絡は対応済みになる
- L-5 サービス運営者は、申立てを確認した結果として措置を行わずに対応済みにできる（結果はメールで連絡する）。連絡も、店舗管理者に依頼せずに対応済みにできる
- L-6 連絡した利用者に結果の通知は届かず、申立人は申立てを取り消せない（本文のまま）

## region / event

- R-1 運営者が不在のイベントの開催地域の関連づけは、サービス運営者が行える（E-01・E-15）。EVT-13 に含める
- R-2 添える掲載と参加日はどちらも複数可。添えられるのは、その店舗の公開中で、提供中または提供開始前の掲載（EVT-10 の直接追加も同じ）。添えた後に提供終了になった掲載は状態を区別して表示される。参加日は開催期間内に限る。開催期間の変更で期間外になった参加日は表示されず、店舗管理者は開催期間の変更の通知を受けて参加日を変更する
- R-3 閲覧できない地域・イベントには申請できない（リソース不在）。取り下げ中・運営による非公開の地域との既存の所属は、店舗管理者の所属状況に状態つきで示され、離脱の申請と代表地域の選択の対象にできる（閲覧者への表示の代替は P-16）
- R-4 終了・中止したイベントでは、参加の申請・直接追加・参加内容の変更はできない。取りやめと除外はできる。終了したイベントは中止にできない。中止の取り消しは中止中ならできる
- R-5 除外に理由は求めない

## discover / explore

- D-1 V-49 の「一覧」は地図の一覧。イベントの一覧と地域内の一覧に、エリア・カテゴリーの条件は効かない。キーワード検索も条件と独立
- D-2 掲載詳細の「関連する地域」は、店舗のすべての公開中の所属地域（店舗詳細と同じ）
- D-3 並び順: 地図の一覧はフィードと同じ順。地域の一覧は、位置情報を許可していれば近い順、していなければ公開の新しい順。地域内の一覧は新しい順。読みもの一覧は公開の新しい順
  - 「新しい順」の基準は、対象が最初に公開された日時（掲載は最初の公開、店舗は登録の承認または代理登録、地域・イベント・読みものは最初の公開）。公開を取り下げて再び公開しても変わらない
  - 地図の一覧は店舗と地域を種類ごとに分けて示し、それぞれ位置情報を許可していれば近い順、していなければ新しい順
  - 地域内の一覧は、店舗はその地域に所属した日時の新しい順、掲載は新しい順
- D-4 絞り込みで条件に合う掲載が0件なら、結果がないことを示し、地域・イベント・読みものの挿入もしない
- D-5 廃止されたカテゴリーは選択中の条件から外れる。条件は閲覧中の画面の間で共有され、再訪時には保持されない

## keep / account

- K-1 メールアドレスでのログインは、メールに届くワンタイムのリンクを開いて成立する。リンクには有効期間があり、期限切れ・使用済みのリンクは無効。端末の保存の合流は、ログインが成立したブラウザの端末の保存に対して行う。合流後、端末の保存は空になり、アカウントの保存が正になる
- K-2 退会後に同じメールアドレスでログインすると、新しいアカウントになる（以前の保存・権限は戻らない）
- K-3 保存一覧は保存した日時の新しい順、通知一覧は新しい順
- K-4 後任の招待が承諾される前に退会すると、他の管理者がいなければ対象は管理者不在になり、承諾前の招待は無効になる（A-3）。退会の確認で、管理者不在になる対象が示される
- K-5 ログアウトとメールアドレスの変更は設計しない

## operation / editorial

- O-1 同じ名称のカテゴリーは置けない（入力エラー）。カテゴリーは作成順に並ぶ
- O-2 カテゴリーの廃止では、確認中・差し戻し中の掲載の申請・修正の申請の内容にあるカテゴリーも移行先に付け替える。移行先は常に必須で、最後の1つは廃止できない
- O-3 読みものの削除は設計しない。紹介先は、記事に付随する順序つきの一覧として結びつける（本文中の位置は持たない）。見え方の確認は公開の必須手順ではない
