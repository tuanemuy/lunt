# 台帳の読み

`spec/review/contract.md` を出典（`spec/idea.md`、`spec/requirements.md` = REQ、`spec/design-appendix.md` = APX）と突き合わせた指摘の一覧。成立の認定は含まない。

REQ の V / M / R / E / O / B の ID は、将来候補の M-06・M-14 を除いてすべて契約に番号がある。指摘は、番号の中身と、番号を持たない地の文・表に集中する。

## 指摘

### L-01 開発の各段階に管理・運営機能を含める条件

- 出典: REQ 3.4「各段階には、その対象に関わる管理・運営機能を含める」
- 契約: T-03
- 落ちている点: T-03 は開発の順序だけを写し、この一文を落としている。段階2（店舗・掲載）にサービス運営者の承認・代理登録が入る、という切り方の根拠がなくなる。T-03 の「spec の分割はこの順に縦に切れること」は出典にない

### L-02 掲載のエリアの決まり方

- 出典: REQ 4.2「店舗・スポットの所在地からエリアを判断し、紐づく掲載の絞り込みに使う」
- 契約: P-12
- 落ちている点: P-12 は「店舗・スポットのエリアは所在地から」で止まり、「紐づく掲載の絞り込みに使う」を落としている。掲載のエリアが紐づく店舗のエリアで決まることを述べる番号がない（V-09 は絞り込めることだけ、M-18 は所在地の参照だけ）

### L-03 用語の「主な情報」と、画面上の表記の扱い

- 出典: REQ 4.1 の用語表「主な情報」の列、および「画面上の表記は、画面設計で定める」
- 契約: P-10
- 落ちている点
  - P-10 は「10語とその主な情報」とまとめ、項目を列挙していない。他の番号に現れない項目が domains の分母から消える: エリア「郵便番号、対応する住所・町域」、店舗・スポット「訪問情報」、保存情報「保存対象、保存した利用者または端末」、管理権限「管理対象、管理者」、申請「申請者、対象、申請内容、確認状況、承認結果」
  - 「読みもの」を正式な呼称とする側だけを書き、画面上の表記を画面設計に委ねる側を落としている（APX 4 のナビゲーションは「読む」）

### L-04 カテゴリーの追加と変更

- 出典: REQ 4.4「追加と変更は、サービス運営者のカテゴリー管理で行う」
- 契約: P-18、O-06
- 落ちている点: 契約は「管理する」と廃止時の付け替えだけを書く。カテゴリー管理が追加・変更を含むことを述べる番号がない

### L-05 イベント運営者の権限の限界（片側）

- 出典: REQ 8.3 E-04「参加店舗の情報・掲載を直接更新するには、その店舗の管理権限を必要とする」
- 契約: E-04
- 落ちている点: R-04 は同じ構造の2文目を写しているが、E-04 は1文目だけ。AC-18 が確認する禁止側の条件が台帳にない

### L-06 管理権限取得後に掲載へ行える操作

- 出典: REQ 7.5 M-36「すべての掲載が店舗管理者の管理下に入り、編集・一時非公開・削除できる」
- 契約: M-36
- 落ちている点: 「管理下に入る」だけを写し、行える操作（編集・一時非公開・削除）を落としている。AC-30 はこの操作を確認する

### L-07 REQ 10.1 の表を1番号に畳んだこと

- 出典: REQ 10.1 の表
- 契約: P-70
- 落ちている点
  - 表は30行。契約の「31行」は誤り
  - 行ごとの申請者・実行者、承認者、反映する内容が usecases の分母にならない
  - 他の番号に現れない内容が畳まれて消えている
    - 「イベントの中止と、中止の取り消し: 対象イベントの運営者。不在の場合はサービス運営者」。契約の E-15・O-20 は不在時の中止だけを書き、サービス運営者による中止の取り消しがない
    - 「開催地域の関連づけの解除と、解除の取り消し」の反映内容「関連づけの解除、関連づけの回復」。R-13 は「解除は取り消せる」だけで、取り消すと関連づけが回復することがない
    - 除外の3行は代行の条件が「不在の場合」だけで、「一定の期間確認しない場合」を含まない。承認の行との非対称が P-78 からは読めない

### L-08 REQ 10.2 の状態表から落ちた行

- 出典: REQ 10.2 の1つ目の表「店舗登録: 申請の確認中と承認済みを区別する」「店舗管理権限: 申請の確認中と承認済みを区別する」「掲載の申請: 申請の確認中と承認済みを区別する」
- 契約: 該当なし（P-80〜P-86 は13行のうち10行を写す）
- 落ちている点: 3行に対応する番号がない

### L-09 利用シナリオを1番号に畳んだこと

- 出典: REQ 5 UC-01〜UC-15
- 契約: P-06
- 落ちている点
  - 15本が1番号で、scenario 層でどの UC が欠けたかを判定できない
  - UC にだけある流れが消える: UC-06「保存一覧 → 詳細や地図を再確認する」（V-35 は詳細だけ）、UC-15「対象の店舗・スポットを確認する → 掲載を申請する」（M-26 に確認の段がない）、UC-02 の終点「地図で位置を確認する」

### L-10 体験の確認基準を1番号に畳んだこと

- 出典: REQ 12 AC-01〜AC-80
- 契約: 「AC-01〜AC-80 は関連要件の確認基準で、新しい要求を足さない」
- 落ちている点
  - 80本が1行で、testcases 層でどの AC が欠けたかを判定できない。関連要件の対応も契約にない
  - 「新しい要求を足さない」が当てはまらない AC がある
    - AC-32「参加に添えた掲載が提供開始前でも、開催予定として紹介される」。V-42・V-46 にこの条件はない
    - AC-73「開催地域の関連づけによって、店舗・掲載の公開状態と提供状態が変わらない」。B-06 は所属と参加だけ、B-15 は所属・参加への影響だけを述べる
    - AC-53「位置情報を利用しない場合も、エリアの選択から地図と一覧で探せる」。V-18 は「探索を続けられる」まで
    - AC-75「任命を解かれた利用者は、読みものを作成・編集・公開できない」。P-60・O-16 は解任後の禁止側を述べない

### L-11 申立てによる地域・イベント・読みものの写真の削除

- 出典: REQ 7.6 M-39「サービス運営者は、申立てに基づいて、地域・イベント・読みものの写真も削除できる」、REQ 9 O-21「掲載、店舗・スポット、地域、イベント、読みものの写真の削除、または掲載、店舗・スポットの非公開」
- 契約: M-39、O-21
- 落ちている点: どちらも「写真の削除または掲載・店舗の非公開」とまとめ、削除の対象に地域・イベント・読みものの写真が入ることを落としている。B-19・B-49・M-49 から間接に読めるだけで、サービス運営者の操作として述べる番号がない

### L-12 連絡に対応がない場合に更新できる範囲

- 出典: REQ 7.2 M-48「O-16により管理権限を解除し、M-46・M-35により情報を更新できる」
- 契約: M-48、O-24
- 落ちている点: 「権限を解除して情報を更新できる」とまとめ、M-35（掲載の更新・一時非公開・提供終了・削除）が含まれることを落としている。連絡の対象は「店舗・スポットとその掲載」

### L-13 要件の後半を落とした番号

- 出典: REQ 7.3 M-42「時刻・定員・予約は項目とせず、説明で案内する」、REQ 7.2 M-13「営業状況の変化を閲覧者に伝えられる」
- 契約: M-42、M-13
- 落ちている点: M-42 は「項目にしない」だけで、説明で案内する側がない。M-13 は登録と復帰だけで、閲覧者に伝わるという目的がない

### L-14 APX 1 の扱いが決まっていない項目

- 出典: APX 1（ロゴ A、アイコン A₂、閲覧側のデザイン C₁、書体、「公開前プレビューには閲覧側の表現を使う」、大きな枠と個別掲載の区切りの共通の罫線）
- 契約: D-01、D-03、X-06
- 落ちている点: X-06 が範囲の外にするのは APX 3 だけ。APX 1 の上記項目は台帳にも範囲の外にもない。「公開前プレビューには閲覧側の表現を使う」は M-20・O-17 の見え方の確認に効く条件で、D-03 に入っていない

### L-15 プロトタイプの画面名

- 出典: APX 4・APX 5 の表「プロトタイプの画面」
- 契約: D-06、D-07
- 落ちている点: 画面群の名前だけを写し、画面名を落としている。pages 層の分母にならない
  - 閲覧側: ホーム、ジャンル別フィード、検索、検索結果、エリア選択、絞り込み、地図、地図の一覧、参加店舗マップ、地域一覧、地域詳細、地域内店舗、地域内イベント、掲載の詳細、店舗・スポット詳細、イベント一覧、イベント詳細、参加店舗一覧、読みものの一覧、記事、保存一覧、未保存、検索0件、イベント未開催、読み込み、通信エラー、位置情報未許可
  - 店舗側: 店舗を探す、管理申請、新規店舗登録、掲載追加、公開中・下書きなどの入口、編集、公開前プレビュー、公開・下書き保存後の状態、イベント詳細、提供内容・参加日、申請後の状態、店舗情報編集、保存後の状態

### L-16 画面設計で扱う事項の中身

- 出典: APX 6 の表「検討する内容」、REQ 11「具体的な画面表現、操作配置、入力方法は付属資料と画面設計で扱う」
- 契約: D-09
- 落ちている点: 8項目のうち5項目（入力・編集、申請、イベント、閲覧状態、管理操作）は対象の名前だけ。中身がない: 写真の選択・並び替え・切り抜きと確認方法、登録・修正・管理権限・所属・離脱の申請内容と結果の提示、イベントの選択と参加申請・管理操作の配置、終了・非公開・休業・閉店・空状態の表現、メンバー管理・地域運営・運営・編集機能の画面構成。フィードの「枠の比率」「先頭の表現」、エリア選択の「選択方法」もない

## 出典どうしの矛盾と、解釈が分かれる項目

### Q-01 退会で取り下げになる申請の範囲

- REQ 6.7 V-53「確認中・差し戻し中の申請は取り下げとする」に対し、REQ 10.1 の退会の行と REQ 10.3 B-55 は「確認中の申請」だけ
- 契約は V-53 の側を採り、B-55 を「V-53 と同旨」として差を隠している

### Q-02 店舗管理者が不在になったときに失効する申請の範囲

- REQ 10.1 の失効の柱書きは「確認中・差し戻し中の申請」、該当の場合は「店舗管理者として行った申請の確認中に、その店舗の店舗管理者が不在になった場合」
- 差し戻し中の申請が失効するかが文面から決まらない。契約の P-77b は出典の文面のまま

### Q-03 連絡に店舗管理者が対応しない場合の基準

- REQ 7.2 M-48・REQ 9 O-24 は「店舗管理者が対応しない場合」の期間・判断基準を定めず、運用に委ねるとも書いていない。契約の X-04 が運用とするのは、管理権限の確認手順と代行の期間だけ
- 店舗管理者が複数いる店舗で誰の権限を解除するかも決まらない。M-46 の更新は管理者不在が前提で、全員の解除が要るのかが読めない

### Q-04 閉店した店舗と「地図」の範囲

- REQ 10.2 は閉店した店舗を「地図」に表示しないとし、「イベント詳細の参加店舗」では状態を区別して表示するとする
- REQ 6.5 V-27 の参加店舗の地図（APX 4 の参加店舗マップ）と、UC-06 の保存一覧からの地図の再確認が「地図」に入るかが決まらない

### Q-05 読みものを扱える編集担当者の範囲と通知先

- 読みものはサービス全体に属し（REQ 4.5）、編集担当者は役割である（REQ 3.1）。どの編集担当者もすべての読みものを編集できるのか、作成者に限るのかを出典は述べない
- REQ 10.4 の編集担当者への通知の宛先（全員か、その読みものの担当か）が決まらない
- 運営による非公開の対象に読みものはない（B-48）。編集担当者が全員解任された場合、公開中の読みものの公開を取り下げられる主体がいない

### Q-06 写真の枚数・並び順の対象

- REQ 10.3 B-41 は複数の写真と代表写真を掲載・店舗・スポット・地域・イベントに認め、読みものを含めない。読みものは一覧とフィードに写真付きで出る（V-30、V-46、APX 1）が、枚数と代表写真の定めがない
- 並び替えは掲載だけ（M-41）、見せる範囲の調整も掲載だけ（M-19）。B-41 の「1枚目を代表写真」は店舗・地域・イベントにも順序を前提にする

### Q-07 APX と REQ の食い違い

REQ 優先で解けるものと、要否が決まらないものが混ざる。

- APX 2 の代表画面と APX 1 の大きな枠は地域・読みものだけで、イベントの枠がない。REQ 6.1 V-46 はイベントもフィードに挿入する
- APX 4 の下部ナビゲーションにイベント一覧（V-24）への入口がない
- APX 4「ジャンル別フィード」は REQ の「カテゴリー」と呼称が違う
- APX 4 の「検索候補」に対応する REQ の要件がない。要否が決まらない
- APX 4 の補助状態「イベント未開催」に対応する REQ の状態がない。V-37 は「イベントに閲覧できる掲載がない場合」で、同じものか決まらない

### Q-08 イベントの「終了」への遷移

- 掲載の提供終了は「自動で」と明記する（M-29、M-42、B-23）。イベントの開催前・開催中・終了は、開催期間から自動で決まるとは書いていない（REQ 10.2）
- 参加申請の失効（REQ 10.1）と編集担当者への「イベントの終了」の通知（REQ 10.4）は、この遷移が起点になる。終了後に開催期間を更新した場合（延期）の扱いも述べない

### Q-09 地域が「選択エリアにある」ことの定義が場面で違う

- 地域探索は「地域の位置、または所属する店舗・スポットの所在地が選択エリアにある」（V-16）、フィードは「条件に合うフィード対象の掲載を持つ」（V-47）
- 条件はフィード・地図・一覧で共有する（V-49）。地図と一覧の地域にどちらの定義を使うか、カテゴリーの条件が地域の表示に効くかが決まらない
