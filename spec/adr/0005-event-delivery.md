# ADR 0005: ドメインイベントを消費者ごとに配送し、成功の後に受領を記録する

- 状態: 採用

## 背景

テンプレートは消費者を別の Worker に置き、処理の前に処理済みの印を付けていた。開発時に消費者が動かず、処理が失敗すると出来事を失う。

## 決定

- 1つの Worker に fetch・queue・scheduled と DO を集める
- リレーは購読の台帳で、出来事を消費者ごとの1通 `{consumer, event}` に展開して Queue に送る。台帳はすべての出来事に消費者があることを型で強制する
- 消費者ごとの受領の記録 `consumer_receipts(consumer, event_id)` を DO に置き、処理の前に確かめ、成功の後に印を付ける
- Queue は出来事を JSON で運ぶので、消費の前に保存形式の復号器で出来事を組み立て直す
- リレーは Outbox の行を諦めず、上限1時間のバックオフで再試行し、一定回数から警告を出す。壊れた行だけを隔離し、同じ回の残りを配送する
- 再配送の上限に達したメッセージは DO の `dead_letters` に保存し、`OPS_TOKEN` 付きの `/__ops/*` で一覧・再投入・リレーの再開ができる

## 結果

- 消費者ごとに独立に再配送され、少なくとも1回の配送を保つ。消費者は冪等に作る（spec のとおり）
