# ADR 0003: DO の RPC を問い合わせとコミットに絞り、型つきの台帳で網羅する

- 状態: 採用

## 背景

約40のポートを DO の上で実装する。RPC の面を広げると、型安全と保守が崩れる。DO の SQLite は束縛パラメーターが 100 まで、`LIKE` のパターンの長さに上限があり、`BEGIN` を使えない。

## 決定

- DO の RPC は `query(name, args)`・`commit(request)` と少数の運用メソッド（リレーの再開、DLQ、開発用の道具）だけにする
- 問い合わせと書き込みコマンドは名前をキーにした型つきの台帳に並べ、`satisfies` で網羅を型で強制する。台帳・SQL・移行・UoW のリポジトリ・業務エラーのコードはドメインごとの断片ファイルに分け、集約ファイルが型で合成する
- ポートの SQL は DO の中で同期に動く。リクエスト側のポート実装は `query` の結果を `reconstruct` し、書き込みはコマンドを積んでコミットで送る
- コミットの失敗（版・一意性の `conflict`、`notFound`、条件の `refused`）は値で返し、リクエスト側が `ConflictError`・`NotFoundError`・`ForbiddenError` にする
- ID の集合は `json_each(?)` で1つのパラメーターとして渡す。文字列の一致はドメインの関数で行う
- 移行の版はグローバルに番号を割り当て、記録していない版をすべて小さい順に当てる

## 結果

- RPC で例外の型は運べないので、想定する結果はすべて値で運ぶ
- 新しい問い合わせ・コマンドの書き漏れは型エラーになる
