# ADR 0004: 確定の時点の権限をコミットの条件で確かめる

- 状態: 採用

## 背景

spec は「確定までの間に役割を解除された場合を含む」アクセスの拒否を `ForbiddenError` と定める（`spec/usecases/authority.md` ほか）。読み取りの後・コミットの前に役割や管理体制が変わると、読んだ時点の判断のまま書き込みが確定してしまう。

## 決定

- コミットは `{ conditions, writes, events }`。`conditions` はアクセスの判断が拠った事実（役割を持つ、対象の管理者である、代行先が不在のまま、席の対象に運営者がいる）
- DO は書き込みの前に条件を確かめ、満たさなければ `refused` を返す。同じ集約への書き込みの衝突は拒否より先に `conflict` を返す
- 条件の記録は `authorizeRole`・`authorizeOnTarget` が行い、個々のユースケースは書かない

## 結果

- `act_as_place`、期間超過の代行（`authority.staffed`）など同種の規定を同じ仕組みで満たす
- 期間超過の代行の判断は、確定までに対象が管理者不在になれば拒まれる
