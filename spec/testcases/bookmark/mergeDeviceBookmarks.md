# mergeDeviceBookmarks

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| アカウントの保存はない。端末の保存に、掲載 L（T1）と店舗 P（T2） | ログインが成立した後に、端末の保存の一覧を渡して合流する | 成功する。アカウントの保存に L（`savedAt` は T1）と P（`savedAt` は T2）が加わる。ドメインイベントは出ない（AC-20） | |
| アカウントの保存に掲載 L（T0）。端末の保存に掲載 L（T1）と掲載 M（T2） | 合流する | 成功する。L の保存は1つのままで `savedAt` は T0。M が T2 で加わる | |
| 上の合流の後 | `listBookmarks` を読む | 端末の保存とアカウントの保存を合わせたものが、`savedAt` の新しい順に並ぶ | |
| 端末の保存に、同じ掲載 L が2つ（T1 と、より新しい T2） | 合流する | L の保存は1つで、`savedAt` は T2 | |
| 端末の保存に、閲覧できなくなった掲載と、削除された掲載 | 合流する | 成功する。どちらも引き継がれ、`listBookmarks` に現れる | |
| 端末の保存に、現在より後の日時を持つ掲載 | 合流する | 成功する。`savedAt` は操作の時刻になる | |
| 端末の保存がない（空の一覧） | 合流する | 成功する。アカウントの保存は変わらない | |
| 端末の保存が、1回の合流の上限の100件を超える | すべてを1回で渡して合流する | `BusinessRuleError`（`COMMON_INVALID_INPUT`）。アカウントの保存は変わらない | |
| 端末の保存が、1回の合流の上限を超える | 上限までの一覧に分けて、2回合流する | どちらも成功する。すべてがアカウントの保存に加わる | |
| 合流が成立した後、端末の側で一覧を空にする前に通信が途切れた | 同じ一覧でもう一度合流する | 成功する。アカウントの保存は1回目の結果のまま | |
| 端末 1 で合流を済ませたアカウント。端末 2 の保存に掲載 N | 端末 2 でログインして合流する | N がアカウントの保存に加わる。端末 1 から `listBookmarks` を読むと N が現れる（AC-20） | |
| 利用者 A の端末の保存 | A として合流する | A の保存にだけ加わる。他のアカウントの保存は変わらない | |
