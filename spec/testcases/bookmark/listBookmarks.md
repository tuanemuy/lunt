# listBookmarks

表示の内容と、閲覧できるかどうかの判定は、Discovery の `resolveReferences` のテストが確かめる。ここでは、返す参照と、並び順・件数を確かめる。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 掲載 L を T1、店舗 P を T2、掲載 M を T3 に保存（T1 < T2 < T3） | 1ページ目を読む | M、P、L の順に返す。それぞれ対象の `BookmarkRef`（種類と ID）と `savedAt` を持つ。`count` は 3（AC-07） | |
| 保存が1件もない | 1ページ目を読む | 空の並びと `count` 0 を返す。エラーにならない（AC-54） | |
| 保存した掲載が、その後に一時非公開になった | 読み、返された参照を Discovery の `resolveReferences` に渡す | その保存を返す。並びの位置は `savedAt` のままで、`count` に含む。`resolveReferences` は、その参照に閲覧できないことだけを返す（AC-07） | |
| 保存した掲載が、その後に削除された | 読む | その保存を返す。対象が閲覧できるかどうかで絞らない（AC-27） | |
| 閲覧できなくなった保存を解除せずに残し、その後に掲載が再公開された | 読む | その保存を返す。`savedAt` は変わらない | |
| 別の端末で保存・解除した | 読む | 保存した対象が加わり、解除した対象がなくなっている（AC-20） | |
| 利用者 A と利用者 B がそれぞれ保存を持つ | A として読む | A の保存だけを返す | |
| ログインしていない | 読む | `UnauthorizedError`。ログインしていない間の保存一覧は、端末が持つ参照を `resolveReferences` に渡して得る | |
