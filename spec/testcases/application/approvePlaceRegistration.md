# approvePlaceRegistration

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 利用者 A の登録申請 r1 が確認中。予約した `reservedPlaceId` は p1。内容の写真は ph1、ph2（持ち主は r1）。操作する人はサービス運営者 O | O が、確かめたときの版を添えて r1 を承認する | r1 は承認になる（承認者の席が `operator` の申請の承認は、判断の立場を持たない）。ID が p1 の店舗が、申請の内容で、営業中・非公開でない状態で保存される。ph1・ph2 の持ち主は p1 になる。`application.approved`（申請者は A）が出て、`photos.released` は出ない。反映先として p1 への参照が返る。p1 の管理体制は作られず、A は p1 の店舗管理者でない（AC-08） | |
| 承認された r1 の店舗 p1 | 閲覧者が p1 を開く（Discovery の `isViewable`） | p1 は、管理者も掲載もなくても閲覧できる | |
| A の登録申請 r1 と、併せた管理権限の申請 s1 が、どちらも確認中 | O が r1 を承認する | r1 は承認になり、店舗 p1 が保存される。s1 は確認中のまま残り、出力に併せた申請として s1 の ID と確認中の状態が含まれる。承認の後、s1 の `ReviewPermission` は `approver` になる（AC-08） | |
| A の登録申請 r1 が確認中。r1 に併せた管理権限の申請 s1 は取り下げになり、その後に r1 を参照する再申請 s2 が確認中 | O が r1 を承認する | 出力の併せた申請は s2 と確認中の状態（進行中のもの） | |
| サービス運営者 O 自身の登録申請 r2 が確認中 | O が r2 を承認する | 承認が成立する（承認者は自分の申請も承認できる） | |
| 同じ店舗への登録申請 r1 と r3 が確認中 | O が r1 を承認する | r1 は承認になる。r3 は確認中のまま残る（1件ずつ判断する） | |
| 利用者 U はサービス運営者でない | U が r1 を承認する | `ForbiddenError` になる。r1 は確認中のまま、店舗は作られない | |
| r1 は、別のサービス運営者が先に否認した | O が r1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_REJECTED`）になる。店舗は作られない | |
| r1 は、判断の前に A が取り下げた | O が r1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_WITHDRAWN`）になる | |
| r1 は差し戻されている | O が r1 を承認する | `BusinessRuleError`（`APPLICATION_RETURNED`）になる | |
| ID が a1 の申請は、情報修正の申請 | O が、a1 を登録申請として承認する | `NotFoundError` になる | |
| r1 は、O が確かめた後に、別のサービス運営者が差し戻し、A が内容を直して再提出して確認中に戻った | O が、古い版を添えて r1 を承認する | `ConflictError` になる。r1 は確認中のまま、店舗は作られない | |
