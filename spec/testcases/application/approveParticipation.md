# approveParticipation

期間超過の代行ができるまでの期間（`ReviewPolicy.proxyAfterMs`）は7日とする。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 利用者 V はイベント e1（開催前）の運営者。店舗 p1（店舗管理者がいる）について店舗管理者として行った、掲載 l1・l2 と参加日2日を添えた e1 への参加の申請 c1 が確認中 | V が、確かめたときの版を添えて c1 を承認する | c1 は承認になる。p1 の e1 への参加が、l1・l2 と参加日を内容として保存される（`participatedAt` は現在時刻）。`application.approved`（申請者は店舗 p1）と `occasion.participation_established` が出る。反映先として e1 への参照が返る。店舗と掲載の公開状態・提供状態は変わらない（AC-17） | |
| 掲載も参加日も添えていない参加の申請 c2 が確認中 | V が c2 を承認する | 掲載も参加日もない参加が成立する | |
| c1 に添えた掲載 l2 が、確認中に一時非公開になった | V が c1 を承認する | 承認が成立し、参加は l1・l2 を持つ（承認は添えた掲載を確かめ直さない）。l2 は閲覧者に示されない | |
| c1 の参加日は、開催期間内の2日。確認中に e1 の開催期間が短くなり、そのうち1日が期間外になった | V が c1 を承認する | 承認が成立する（承認は参加日を確かめ直さない）。参加は申請の参加日の2日を持ち、期間外の1日は閲覧者に示されない | |
| V は e1 の運営者で、p1 の店舗管理者でもある。V が店舗管理者として行った c1 が確認中 | V が c1 を承認する | 承認が成立する | |
| イベント e2 に運営者がいない。e2 への参加の申請 c3 が確認中。操作する人はサービス運営者 O | O が c3 を承認する | c3 は承認になり、`reviewAs` は `approver`。参加が成立する（AC-17） | |
| e1 に運営者がいる。c1 は10日前から確認中。O は e1 の運営者でない | O が c1 を承認する | c1 は承認になり、`reviewAs` は `overdue_proxy`。参加が成立する（AC-67） | |
| e1 に運営者がいる。c1 は3日前から確認中 | O が c1 を承認する | `BusinessRuleError`（`APPLICATION_AWAITING_STEWARDS`）になる | |
| イベント e2 に運営者がいない。e2 への参加の申請 c4 は10日前から確認中。サービス運営者 O が不在の代行で c4 を確かめた後、承認の前に利用者 W が e2 の運営者に就いた | O が c4 を1回承認する | その1回の操作で c4 は承認になり（判断済み）、`reviewAs` は `overdue_proxy`。参加が成立する | |
| e2 に運営者がいない。c4 は3日前から確認中。O が不在の代行で c4 を確かめた後、承認の前に W が e2 の運営者に就いた | O が c4 を承認する | `BusinessRuleError`（`APPLICATION_AWAITING_STEWARDS`）になる。c4 は確認中のまま、参加は成立しない | |
| c1 の確認中に、e1 が中止になった。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `occasionOpen` が返る。参加は成立しない | |
| c1 の確認中に、e1 の開催期間が更新されて終了になった。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `occasionOpen` が返る | |
| c1 の確認中に、p1 の最後の店舗管理者が辞任して p1 は管理者不在になり、V が p1 を参加店舗として直接追加し、その後に利用者 T が p1 の店舗管理者に就いた。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `notParticipating` だけが返る（店舗管理者はいて、イベントは開催前）。参加は直接の追加のまま1つ | |
| c1 の確認中に、p1 の最後の店舗管理者が退会した。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `placeHasSteward` が返る | |
| c1 の確認中に、e1 が運営による非公開になった | V が c1 を承認する | 承認が成立し、参加が成立する | |
| 利用者 U は e1 の運営者でも、サービス運営者でもない | U が c1 を承認する | `ForbiddenError` になる | |
| c1 は、期間超過の代行をするサービス運営者が先に承認した | V が c1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_APPROVED`）になる。参加は1つのまま | |
| c1 は、V が確かめた後に、別の運営者が差し戻し、店舗管理者が掲載と参加日を直して再提出して確認中に戻った | V が、古い版を添えて c1 を承認する | `ConflictError` になる。c1 は確認中のまま、参加は成立しない | |
