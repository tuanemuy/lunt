# approveParticipation

代行できるまでの期間は7日とする。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 利用者 V はイベント e1（開催前）の運営者。店舗 p1（店舗管理者がいる）が行った、掲載 l1・l2 と参加日2日を添えた e1 への参加の申請 c1 が確認中 | V が、確かめたときの版を添えて c1 を承認する | c1 は承認になる。p1 の e1 への参加が、l1・l2 と参加日を内容として保存される（`participatedAt` は現在時刻）。`application.approved`（申請者は店舗 p1）と `occasion.participation_established` が出る。反映先として e1 への参照が返る。店舗と掲載の公開状態・提供状態は変わらない（AC-17） | |
| 掲載も参加日も添えていない参加の申請 c2 が確認中 | V が c2 を承認する | 掲載も参加日もない参加が成立する | |
| V は e1 の運営者で、p1 の店舗管理者でもある。V が店舗管理者として行った c1 が確認中 | V が c1 を承認する | 承認が成立する | |
| イベント e2 に運営者がいない。e2 への参加の申請 c3 が確認中。操作する人はサービス運営者 O | O が c3 を承認する | c3 は承認になり、`capacity` は `approver`。参加が成立する（AC-17） | |
| e1 に運営者がいる。c1 は10日前から確認中。O は e1 の運営者でない | O が c1 を承認する | c1 は承認になり、`capacity` は `proxy`。参加が成立する（AC-67） | |
| e1 に運営者がいる。c1 は3日前から確認中 | O が c1 を承認する | `BusinessRuleError`（`APPLICATION_AWAITING_STEWARDS`）になる | |
| c1 の確認中に、e1 が中止になった。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `occasionOpen` が返る。参加は成立しない | |
| c1 の確認中に、e1 の開催期間が更新されて終了になった。`occasion.ended` はまだ出ていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `occasionOpen` が返る | |
| c1 の確認中に、V が p1 を参加店舗として直接追加した。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `notParticipating` が返る | |
| c1 の確認中に、p1 の最後の店舗管理者が退会した。前提の再評価はまだ届いていない | V が c1 を承認する | 例外にならず、c1 が失効になったことと、成り立たない前提 `placeHasSteward` が返る | |
| c1 の確認中に、e1 が運営による非公開になった | V が c1 を承認する | 承認が成立し、参加が成立する | |
| 利用者 U は e1 の運営者でも、サービス運営者でもない | U が c1 を承認する | `ForbiddenError` になる | |
| c1 は、代行するサービス運営者が先に承認した | V が c1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_APPROVED`）になる。参加は1つのまま | |
| c1 の承認と、p1 の e1 への直接の追加が同時に行われる | V が c1 を承認する | 後からコミットした側が `ConflictError` になる。参加は1つだけ保存される。承認が後なら、c1 は確認中のまま残る | |
| c1 は、V が確かめた後に、別の運営者が差し戻し、店舗が掲載と参加日を直して再提出して確認中に戻った | V が、古い版を添えて c1 を承認する | `ConflictError` になる。c1 は確認中のまま、参加は成立しない | |
