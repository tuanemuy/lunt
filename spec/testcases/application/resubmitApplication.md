# resubmitApplication

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 利用者 A の管理権限の申請 a1（店舗 p1）が、追加で必要な確認 q を添えて差し戻されている | A が、確かめたときの版を添えて、確認に使える連絡先を直し、回答 w を添えて a1 を再提出する | a1 は同じ申請のまま確認中に戻る。内容は直した値、`since` は現在時刻、`answering` は q と w、`submittedAt` は変わらず、版が進む。`application.resubmitted`（承認者の席は `operator`）が出る（AC-21、AC-43） | |
| A の登録申請 a2 が差し戻し。内容の写真は ph1、ph2。A が登録した、持ち主のない写真 ph3 がある | A が、写真を ph1、ph3 にして a2 を再提出する | 内容の写真は ph1、ph3。ph3 の持ち主は a2 になる。ph2 を載せた `photos.released` が出る。予約した `reservedPlaceId` は変わらない | |
| A の情報修正の申請 a3（店舗 p1、名称の項目）が差し戻し。その後、p1 の紹介が別の承認で変わっている | A が、名称と営業時間を直した内容で a3 を再提出する | 内容は、p1 の現在の内容と違う項目（名称と営業時間）だけを持つ | |
| 店舗 p1 について店舗管理者として行った所属の申請 a4（地域 X）が、追加で必要な確認 q2 を添えて差し戻し。S は p1 の店舗管理者 | S が、回答 w2 だけを添えて a4 を再提出する | a4 は確認中に戻る。店舗・地域・種類は変わらず、`answering` は q2 と w2 | |
| 店舗 p1 の店舗管理者 T が店舗管理者として行った参加の申請 a5 が差し戻し。S は p1 の別の店舗管理者 | S が、添える掲載と参加日を直して a5 を再提出する | a5 は確認中に戻る（同じ店舗のどの店舗管理者も再提出できる）（AC-66） | |
| a5 を提出した T は、p1 の店舗管理者を辞任している。S は p1 の店舗管理者 | S が a5 を再提出する | a5 は確認中に戻る（AC-66） | |
| 参加の申請 a5 に添えた掲載 l1 は、差し戻しの間に提供終了になった。S は p1 の店舗管理者 | S が、l1 を添えたまま a5 を再提出する | a5 は確認中に戻り、内容は l1 を持つ（提供終了の掲載も添えられる） | |
| 参加の申請 a5 に添えた掲載 l2 は、差し戻しの間に一時非公開になった | S が、l2 を添えたまま a5 を再提出する | a5 は確認中に戻り、内容は l2 を持つ（添えてあった掲載は、添えられる掲載でなくなっても外さない） | |
| 参加の申請 a5 は掲載 l1 を添えて差し戻し。p1 の掲載 l3 は一時非公開 | S が、l3 を新たに添えて a5 を再提出する | `BusinessRuleError`（`OCCASION_LISTING_NOT_ATTACHABLE`）になる。a5 は差し戻しのまま | |
| A の登録申請 r1 が差し戻し。r1 に併せた管理権限の申請 s1 は確認中 | A が、店舗の情報を直し、回答を添えて r1 を再提出する | r1 は確認中に戻る。s1 は変わらない（登録申請の再提出は、併せた申請に及ばない） | |
| A の情報修正の申請 a3（店舗 p1）が差し戻しの間に、p1 に店舗管理者が就いた。前提の再評価はまだ届いていない | A が a3 を再提出する | 例外にならず、a3 が失効になったことと、成り立たない前提 `placeHasNoSteward` が返る。a3 は失効で保存され、`application.lapsed` が出る。`application.resubmitted` と `photos.released` は出ない | |
| A の情報修正の申請 a3 が差し戻しの間に、店舗 p1 がサービス運営者によって非公開になった | A が a3 を再提出する | a3 は確認中に戻る（対象が閲覧できるかどうかは、再提出では確かめない） | |
| A の申請 a1 が差し戻し。利用者 B は申請者でない | B が a1 を再提出する | `ForbiddenError` になる。a1 は変わらない | |
| 店舗 p1 について店舗管理者として行った申請 a4 が差し戻し。T は p1 の管理権限を解除されている | T が、自分が提出した a4 を再提出する | `ForbiddenError` になる | |
| A の申請 a1 は確認中（再提出の後） | A が a1 をもう一度再提出する | `BusinessRuleError`（`APPLICATION_UNDER_REVIEW`）になる。a1 は変わらない | |
| A の申請 a3 は、修正している間に失効した | A が a3 を再提出する | `BusinessRuleError`（`APPLICATION_ALREADY_LAPSED`）になる | |
| 店舗 p1 について店舗管理者として行った申請 a5 が差し戻し。S と T がどちらも同じ版で修正を始め、T が先に再提出して承認者がもう一度差し戻した | S が、古い版を添えて a5 を再提出する | `ConflictError` になる。a5 は T の内容のまま | |
| A の情報修正の申請 a3 が差し戻し | A が、店舗の現在の内容から何も変えない内容で再提出する | `BusinessRuleError`（`COMMON_INVALID_FIELD_PATCH`）になる。a3 は差し戻しのまま | |
| A の管理権限の申請 a1 が、追加で必要な確認 q を添えて差し戻し | A が、回答を添えずに、連絡先だけを直して再提出する | a1 は確認中に戻る。`answering` は q で、回答は `null` | |
| A の管理権限の申請 a1 が差し戻し | A が、回答を空白だけにして再提出する | `BusinessRuleError`（`APPLICATION_INVALID_RETURN_REPLY`）になる。a1 は差し戻しのまま | |
| A の管理権限の申請 a1 が差し戻し | A が、店舗との関係を空にして再提出する | `BusinessRuleError`（`APPLICATION_INVALID_STEWARDSHIP_CLAIM`）になる | |
| ID が a9 の申請はない | A が a9 を再提出する | `NotFoundError` になる | |
| A の情報修正の申請 a3 が差し戻し | A が、掲載の修正の内容で a3 を再提出する | `NotFoundError` になる。a3 は差し戻しのまま | |
