# approveNewListing

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 店舗 p1 に店舗管理者がいない。利用者 A の掲載の申請 a1 が確認中。予約した `reservedListingId` は l1。内容の写真は ph1、ph2（持ち主は a1）。操作する人はサービス運営者 O | O が、確かめたときの版を添えて a1 を承認する | a1 は承認になる。ID が l1 の掲載が、p1 に紐づく公開中の掲載として、申請の内容で保存される（`firstPublishedAt` は現在時刻）。ph1・ph2 の持ち主は l1 になる。`application.approved` が出て、`PhotosReleased` は出ない。反映先として l1 への参照が返る（AC-19） | |
| 承認された a1 の掲載 l1 | A が l1 を管理しようとする（`AccessPolicy.decide` の `manage_target`） | 行えない。p1 に店舗管理者がいない間、l1 を管理できるのはサービス運営者（申請者は掲載の管理権限を得ない） | |
| a1 の内容のカテゴリー c1 は、確認中の間に廃止され、移行先は c2 | O が a1 を承認する | 掲載のカテゴリーは c2 で保存される | |
| サービス運営者 O 自身の掲載の申請 a2 が確認中 | O が a2 を承認する | 承認が成立する | |
| a1 の確認中に、p1 がサービス運営者によって非公開になった | O が a1 を承認する | 承認が成立し、掲載は公開中で保存される。p1 の非公開が解除されるまで、掲載は閲覧できない | |
| 利用者 A と B の、p1 への掲載の申請がどちらも確認中 | O が A の申請を承認する | A の申請だけが承認になる。B の申請は確認中のまま残る | |
| a1 の確認中に、p1 に店舗管理者が就いた。前提の再評価はまだ届いていない | O が a1 を承認する | 例外にならず、a1 が失効になったことと、成り立たない前提 `placeHasNoSteward` が返る。掲載は作られず、ph1・ph2 を載せた `PhotosReleased` が出る | |
| 利用者 U はサービス運営者でない | U が a1 を承認する | `ForbiddenError` になる。掲載は作られない | |
| a1 は、判断の前に A が取り下げた | O が a1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_WITHDRAWN`）になる | |
| a1 が確認中 | 2人のサービス運営者が、同時に a1 を承認する | 一方が成立し、他方は `ConflictError` になる。掲載は1つだけ保存される | |
| a1 は、O が確かめた後に、別のサービス運営者が差し戻し、A が内容を直して再提出して確認中に戻った | O が、古い版を添えて a1 を承認する | `ConflictError` になる。a1 は確認中のまま残り、掲載は作られない | |
| ID が a9 の申請は、掲載の修正の申請 | O が、a9 を掲載の申請として承認する | `NotFoundError` になる | |
