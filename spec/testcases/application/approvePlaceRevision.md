# approvePlaceRevision

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 店舗 p1 に店舗管理者がいない。利用者 A の情報修正の申請 a1（名称と営業時間の項目）が確認中。操作する人はサービス運営者 O | O が、確かめたときの版を添えて a1 を承認する | a1 は承認になる。p1 の名称と営業時間が申請の値になり、ほかの項目は現在の内容のまま残る。p1 の版が進む。`application.approved` が出る。反映先として p1 への参照が返る（AC-09） | |
| a1 の提出の後に、別の承認で p1 の紹介が変わっている | O が a1 を承認する | 名称と営業時間だけが変わり、紹介は変わった後の値のまま残る | |
| A の情報修正の申請 a2 は、営業状況を「閉店」にする項目を持つ。p1 は営業中 | O が a2 を承認する | p1 の営業状況は閉店になる。`place.operating_status_changed` が出る（AC-09） | |
| p1 の写真は ph1、ph2。a3 の写真の項目は ph3、ph1（ph3 は a3 が持ち主） | O が a3 を承認する | p1 の写真は ph3、ph1。ph3 の持ち主は p1 になる。外れた ph2 を載せた `photos.released` が出る | |
| a1 の確認中に、p1 がサービス運営者によって非公開になった | O が a1 を承認する | 承認が成立し、p1 に反映される。p1 は非公開のまま | |
| 利用者 B の p1 への情報修正の申請 a4（名称の項目）も確認中 | O が a1 を承認し、続けて a4 を承認する | どちらも成立し、名称は a4 の値になる（1件ずつ判断する） | |
| a1 の確認中に、p1 に店舗管理者が就いた。前提の再評価はまだ届いていない | O が a1 を承認する | 例外にならず、a1 が失効になったことと、成り立たない前提 `placeHasNoSteward` が返る。a1 は失効で保存され、`application.lapsed` が出る。`photos.released` は出ず、申請の写真の持ち主は a1 のまま。p1 は変わらない | |
| a1 は、前提の再評価ですでに失効している | O が a1 を承認する | `BusinessRuleError`（`APPLICATION_ALREADY_LAPSED`）になる。p1 は変わらない | |
| 利用者 U はサービス運営者でない | U が a1 を承認する | `ForbiddenError` になる | |
| a1 は、O が確かめた後に、別のサービス運営者が差し戻し、A が項目を直して再提出して確認中に戻った | O が、古い版を添えて a1 を承認する | `ConflictError` になる。a1 は確認中のまま残り、p1 は変わらない | |
| a1 は、O が確かめた後に差し戻され、まだ再提出されていない | O が、古い版を添えて a1 を承認する | `BusinessRuleError`（`APPLICATION_RETURNED`）になる（状態のエラーを版の比較より先に判定する） | |
