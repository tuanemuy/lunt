# approveListingRevision

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 店舗 p1 に店舗管理者がいない。p1 の公開中の掲載 l1 への、利用者 A の修正の申請 a1（名称と提供の設定の項目）が確認中。操作する人はサービス運営者 O | O が、確かめたときの版を添えて a1 を承認する | a1 は承認になる。l1 の名称と提供の設定が申請の値になり、ほかの項目は現在の内容のまま残る。l1 は公開中のまま。`application.approved` が出る。反映先として l1 への参照が返る（AC-19） | |
| a1 の提出の後に、別の修正の申請の承認で l1 の説明が変わっている | O が a1 を承認する | 名称と提供の設定だけが変わり、説明は変わった後の値のまま残る | |
| l1 の写真は ph1、ph2。a2 の写真の項目は ph3、ph1（ph3 は a2 が持ち主） | O が a2 を承認する | l1 の写真は ph3、ph1。ph3 の持ち主は l1 になる。外れた ph2 を載せた `PhotosReleased` が出る | |
| a2 の写真の項目は ph3、ph1。a2 の提出の後に、ph1 は申立てで l1 から削除された | O が a2 を承認する | l1 の写真は ph3 だけになる | |
| a3 のカテゴリーの項目 c1 は、確認中の間に廃止され、移行先は c2 | O が a3 を承認する | l1 のカテゴリーは c2 になる（AC-72） | |
| a1 の確認中に、l1 が一時非公開になった。または運営による非公開になった | O が a1 を承認する | 承認が成立し、内容が反映される。l1 の公開状態と運営による非公開は変わらない | |
| a1 の確認中に、l1 が削除された。前提の再評価はまだ届いていない | O が a1 を承認する | 例外にならず、a1 が失効になったことと、成り立たない前提 `listingExists` が返る。`application.lapsed` が出る（AC-66） | |
| a1 の確認中に、p1 に店舗管理者が就いた。前提の再評価はまだ届いていない | O が a1 を承認する | 例外にならず、a1 が失効になったことと、成り立たない前提 `placeHasNoSteward` が返る。l1 は変わらない | |
| a4 の写真の項目は、l1 の写真だった ph1 だけ。a4 の提出の後に、ph1 は l1 から外された | O が a4 を承認する | `BusinessRuleError`（`LISTING_PATCH_PHOTOS_UNAVAILABLE`）になる。a4 は確認中のまま残り、l1 は変わらない | |
| 利用者 U はサービス運営者でない | U が a1 を承認する | `ForbiddenError` になる | |
| a1 は、別のサービス運営者が先に差し戻した | O が a1 を承認する | `BusinessRuleError`（`APPLICATION_RETURNED`）になる | |
| a1 の承認と同時に、サービス運営者の代理の更新が l1 を保存した | O が a1 を承認する | `ConflictError` になる。a1 は確認中のまま残る | |
| a1 は、O が確かめた後に、別のサービス運営者が差し戻し、A が項目を直して再提出して確認中に戻った | O が、古い版を添えて a1 を承認する | `ConflictError` になる。a1 は確認中のまま残り、l1 は変わらない | |
