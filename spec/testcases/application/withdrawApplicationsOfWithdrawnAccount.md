# withdrawApplicationsOfWithdrawnAccount

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 利用者 A が個人として行った、情報修正の申請 a1（確認中）、管理権限の申請 a2（差し戻し）、掲載の申請 a3（否認）がある。A が退会した | A の `account.withdrawn` を消費する | a1 と a2 は取り下げになる。申請ごとに、`application.withdrawn`（`approver` は承認者の席）と、申請が持ち主の写真を載せた `PhotosReleased` が出る。a3 は否認のまま変わらない（AC-70） | |
| A は店舗 p1 の店舗管理者で、店舗管理者として行った所属の申請 b1 が確認中。p1 には別の店舗管理者 S がいる。A が退会した | A の `account.withdrawn` を消費する | b1 は確認中のまま変わらない。S が b1 を扱える（AC-70、AC-66） | |
| A の登録申請 r1 と、併せた管理権限の申請 s1 が、どちらも確認中。A が退会した | A の `account.withdrawn` を消費する | r1 も s1 も取り下げになる | |
| 利用者 B の個人の申請 a4 が確認中。A が退会した | A の `account.withdrawn` を消費する | a4 は変わらない | |
| A の進行中の申請がない | A の `account.withdrawn` を消費する | 何も書き込まれず、ドメインイベントは出ない | |
| a1 と a2 は、`account.withdrawn` の消費ですでに取り下げになっている | 同じドメインイベントをもう一度消費する | どの申請も変わらず、ドメインイベントは出ない（冪等） | |
| a1 と a2 が確認中。a1 の `save` が、同時の承認者の承認と競合した | A の `account.withdrawn` を消費する | a2 の取り下げは確定する。a1 は承認のまま残り（先の操作が有効）、再配送では a1 は進行中でないので取り下げない | |
