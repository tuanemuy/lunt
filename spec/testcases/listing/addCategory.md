# addCategory

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 現役のカテゴリー「食べる」「買う」「体験」「見る」がある。操作する人はサービス運営者 | 新しい `CategoryId` と名称「泊まる」で追加する | 「泊まる」が現役のカテゴリーとして並びの最後に入り、`listCategories` の結果に加わる。ドメインイベントは出ない | |
| カテゴリー「体験」が廃止済み | 名称「体験」で追加する | 追加できる。新しい「体験」は並びの最後に入り、廃止済みの「体験」とは別のカテゴリーになる | |
| 操作する人はサービス運営者 | 空の名称で追加する | `BusinessRuleError`（`CATEGORY_INVALID_NAME`）。台帳は変わらない | |
| 現役のカテゴリー「買う」がある | 名称「買う」で追加する | `BusinessRuleError`（`CATEGORY_NAME_TAKEN`）。台帳は変わらない | |
| 同じ `CategoryId` と同じ名称の追加が、すでに成立している | 同じ要求を送り直す | 成功として扱う。台帳は書き込まれず、カテゴリーは増えない | |
| 同じ `CategoryId` のカテゴリーがある | 同じ `CategoryId` で、違う名称で追加する | `ConflictError`。台帳は変わらない | |
| 2人のサービス運営者が、同じ版の台帳を読んでいる | それぞれが別の名称のカテゴリーを同時に追加する | 一方が成立し、他方は `ConflictError`。台帳には成立した側のカテゴリーだけが入る | |
| 操作する人はサービス運営者の役割を持たない | 追加する | `ForbiddenError`。台帳は変わらない | |
| 操作する人は、操作の途中でサービス運営者の役割を解除された | 追加する | `ForbiddenError`。台帳は変わらない | |
