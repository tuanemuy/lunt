# retireCategory

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 現役のカテゴリー「食べる」「買う」「体験」「見る」がある。「体験」を設定した公開中の掲載がある。操作する人はサービス運営者 | 「体験」を、移行先「見る」で廃止する | 「体験」は廃止済みになり、移行先「見る」が記録される。`category.retired`（`categoryId`）が出る。`listCategories` に「体験」は現れない。掲載は書き込まれず、版と更新日時は進まない。`getManagedListing` はその掲載のカテゴリーを「見る」で返す。掲載の公開状態・提供状態は変わらない（AC-72） | |
| 現役のカテゴリー「泊まる」を設定した掲載も申請も、1件もない | 「泊まる」を、移行先「見る」で廃止する | 廃止できる。`category.retired` が出る | |
| 「体験」を保存した掲載が、公開中、下書き、一時非公開、運営による非公開、提供終了に1件ずつある | 「体験」を、移行先「見る」で廃止する | 5件すべてが、`getManagedListing` と `listPlaceListings` で「見る」の掲載として返る。どの掲載も書き込まれない | |
| 「体験」が移行先「見る」で廃止されている。「体験」を保存した掲載がある | 「見る」を、移行先「買う」で廃止する | その掲載は「買う」の掲載として返る（移行先を現役のカテゴリーに当たるまでたどる） | |
| 店舗管理者が、「体験」を保存した掲載（版 3）を読んで編集している。その間に「体験」が移行先「見る」で廃止された | 版 3 を添えて、カテゴリーに「見る」を選んで内容を保存する | 保存が成立し、「見る」が保存される。廃止は掲載の版を進めないので、`ConflictError` にならない | |
| 現役のカテゴリー「体験」がある | 「体験」を、移行先「体験」で廃止する | `BusinessRuleError`（`LISTING_CATEGORY_SUCCESSOR_INVALID`）。台帳は変わらない | |
| 選んだ移行先を、確定までの間に別のサービス運営者が廃止している | 廃止する | `BusinessRuleError`（`LISTING_CATEGORY_SUCCESSOR_INVALID`）。廃止は行われず、`category.retired` は出ない | |
| 指定した `CategoryId` が台帳にない | 移行先「見る」で廃止する | `BusinessRuleError`（`LISTING_CATEGORY_NOT_FOUND`）。台帳は変わらない | |
| 現役のカテゴリーが「見る」の1つだけで、「体験」が移行先「見る」で廃止されている | 「見る」を、移行先「体験」（廃止済み）で廃止する | `BusinessRuleError`（`LISTING_CATEGORY_LAST_ONE`。移行先の誤りより先に判定する）。台帳は変わらない | |
| 現役のカテゴリーが「見る」の1つだけ | 「見る」を、移行先「見る」で廃止する | `BusinessRuleError`（`LISTING_CATEGORY_LAST_ONE`）。台帳は変わらない | |
| 廃止するカテゴリーを、別のサービス運営者がすでに廃止している | 廃止する | `BusinessRuleError`（`LISTING_CATEGORY_RETIRED`）。移行先の記録は変わらず、`category.retired` は出ない | |
| 現役のカテゴリーが「体験」「見る」の2つ。2人のサービス運営者が、同じ版の台帳を読んでいる | 同時に、一方が「体験」を移行先「見る」で、他方が「見る」を移行先「体験」で廃止する | 一方が成立し、他方は `ConflictError`。現役のカテゴリーは1つ残り、廃止済みのカテゴリーの移行先は現役のカテゴリーを指す | |
| 操作する人はサービス運営者の役割を持たない | 廃止する | `ForbiddenError`。台帳は変わらない | |
