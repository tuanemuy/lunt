# submitInfoReport

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 閲覧できる店舗に店舗管理者がいる。操作する人はログインした利用者 | 対象をその店舗、種類を情報の誤りにし、内容を添えて提出する | 成功し、連絡の ID を返す。未対応の連絡が、対象（`kind: "place"`）、種類、内容、連絡した人（操作する人の `AccountId`）、受け付けた日時（現在時刻）で保存される。`info_report.submitted`（`reportId`、対象、種類）が出る（AC-77） | |
| 店舗管理者のいる閲覧できる店舗に、閲覧できる掲載がある | 対象をその掲載、種類を閉店にし、内容を添えて提出する | 成功する。連絡の対象は `kind: "listing"` で、掲載の ID と、その掲載が紐づく店舗の `placeId` を持つ。`info_report.submitted`（`category: "closure"`）が出る（AC-77） | |
| 閲覧できる店舗に店舗管理者がいない | その店舗を対象に提出する | `BusinessRuleError`（`INFO_REPORT_PLACE_WITHOUT_STEWARD`）。連絡もドメインイベントも残らない | |
| 店舗管理者のいない店舗に、閲覧できる掲載がある | その掲載を対象に提出する | `BusinessRuleError`（`INFO_REPORT_PLACE_WITHOUT_STEWARD`）。連絡もドメインイベントも残らない | |
| 店舗管理者のいる店舗が、入力している間に非公開になった | その店舗を対象に提出する | `BusinessRuleError`（`INFO_REPORT_TARGET_UNAVAILABLE`）。連絡もドメインイベントも残らない | |
| 店舗管理者のいる店舗の掲載が、入力している間に一時非公開になった | その掲載を対象に提出する | `BusinessRuleError`（`INFO_REPORT_TARGET_UNAVAILABLE`）。連絡もドメインイベントも残らない | |
| 店舗管理者のいる店舗の掲載が、入力している間に削除された | その掲載を対象に提出する | `BusinessRuleError`（`INFO_REPORT_TARGET_UNAVAILABLE`）。閲覧できない対象と同じに扱う。連絡もドメインイベントも残らない | |
| 店舗管理者のいない店舗が、入力している間に非公開になった | その店舗を対象に提出する | `BusinessRuleError`（`INFO_REPORT_TARGET_UNAVAILABLE`）。対象が閲覧できないことを、店舗管理者の有無より先に判定する | |
| 掲載を対象にした連絡を提出した後、その掲載が削除された | 同じ利用者が、同じ ID・同じ対象・種類・内容で、もう一度提出する | 成功し、同じ ID を返す。連絡は1件のままで、`info_report.submitted` は新たに出ない | |
| 店舗管理者のいる閲覧できる店舗がある | 内容を空にして提出する | `BusinessRuleError`（`InfoReportContent` のコード）。連絡もドメインイベントも残らない | |
| 店舗管理者のいる閲覧できる店舗がある | 2つの値のどちらでもない種類で提出する | `BusinessRuleError`（`InfoReportCategory` のコード）。連絡もドメインイベントも残らない | |
| 連絡を提出して、未対応の連絡が保存されている | 同じ利用者が、同じ ID・同じ対象・種類・内容で、もう一度提出する | 成功し、同じ ID を返す。連絡は1件のままで、`info_report.submitted` は新たに出ない | |
| 連絡を提出して、未対応の連絡が保存されている | 同じ利用者が、同じ ID で、内容だけを変えて提出する | `ConflictError`。保存されている連絡は変わらず、ドメインイベントは出ない | |
| 利用者が、ある店舗についての連絡を1件提出している | 同じ利用者が、同じ店舗を対象に、別の ID で連絡を提出する | 成功する。2件の連絡が、互いに独立した未対応の連絡として保存され、`info_report.submitted` がそれぞれ出る | |
| 店舗管理者のいる店舗についての未対応の連絡がある | その店舗のすべての店舗管理者が辞任した後、連絡を読む | 連絡は未対応のまま残っている | |
