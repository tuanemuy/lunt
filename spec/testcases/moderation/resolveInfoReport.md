# resolveInfoReport

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 未対応の連絡がある。操作する人はサービス運営者 | 確認を依頼せずに対応を終える | 成功する。連絡は対応済みになり、対応した日時（現在時刻）を持ち、依頼を持たない。ドメインイベントは出ない。以後の `listUnresolvedInfoReports` に現れない | |
| 確認依頼中の連絡がある | サービス運営者が対応を終える | 成功する。連絡は対応済みになり、確認依頼中の依頼（依頼の日時）を引き継ぐ。ドメインイベントは出ない。以後の `listUnresolvedInfoReports` と `listConfirmationRequestsForPlace` に現れず、`getConfirmationRequest` では対応済みとして読める（AC-77） | |
| 確認依頼中の連絡の対象の店舗で、すべての店舗管理者の権限が解除され、店舗は管理者不在になっている | サービス運営者が対応を終える | 成功する。店舗管理者の有無を確かめずに対応済みになる。管理体制は書き換わらない（AC-77） | |
| 未対応の連絡の対象の掲載が削除されている | サービス運営者が、依頼せずに対応を終える | 成功する。対象の有無を確かめずに対応済みになる | |
| 未対応の連絡の対象の店舗が非公開になっている | サービス運営者が対応を終える | 成功する | |
| 対応済みの連絡がある | サービス運営者が対応を終える | `BusinessRuleError`（`INFO_REPORT_ALREADY_RESOLVED`）。対応した日時は変わらない | |
| サービス運営者 A と B が、同じ未対応の連絡を読んだ。B が先に確認を依頼した | A が対応を終える | 成功する。連絡は対応済みになり、B の依頼（依頼の日時）を引き継ぐ | |
| サービス運営者 A と B が、同じ確認依頼中の連絡を読んだ。B が先に対応を終えた | A が対応を終える | `BusinessRuleError`（`INFO_REPORT_ALREADY_RESOLVED`）。連絡は B が対応を終えた状態のままで、対応した日時は変わらない | |
| 確認依頼中の連絡がある。操作する人は、対象の店舗の店舗管理者で、サービス運営者の役割を持たない | 対応を終える | `ForbiddenError`。連絡は確認依頼中のまま | |
