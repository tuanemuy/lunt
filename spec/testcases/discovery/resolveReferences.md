# resolveReferences

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 提供中の掲載 L と、営業中の店舗 P がある。ログインしていない | L、P の順の参照で、`Actor` なしで解決する | L の掲載の要約、P の店舗の要約が、引数の順で、状態つきで返る。各要約は詳細を開くための ID を持つ。ログインせずに保存した掲載と店舗を、一覧で見返せる（AC-20） | |
| 提供開始前の掲載、提供終了の掲載、休業中の店舗、閉店した店舗がある | それぞれの参照で解決する | どれも内容つきで返り、提供状態と営業状況を区別できる（AC-14） | |
| 一時非公開の掲載、運営による非公開の掲載、非公開の店舗の掲載、非公開の店舗、削除された掲載の参照がある | それぞれの参照で解決する | どの参照も、閲覧できないことだけが返る。名称・写真などの対象の情報と、閲覧できない理由を持たない（AC-07、AC-48） | |
| 閲覧できる掲載 L1、一時非公開の掲載 L2、閲覧できる店舗 P がある | L1、L2、P の順の参照で解決する | 結果は3件で、引数の順。L1 と P は内容つき、L2 は閲覧できないことだけ。どの参照も結果から落ちない | |
| ログインしていない閲覧者が端末に保存した掲載 L が、保存の後に一時非公開になった | 端末の保存の参照（L を含む）で、`Actor` なしで解決する | L は参照と閲覧できないことだけが返る。端末は、この結果の参照で、L の保存を解除できる（AC-07） | |
| ログインしていない閲覧者が、閲覧できる掲載 L を端末に保存しようとしている | L の参照で、`Actor` なしで解決する | L が内容つきで返り、保存の時点で対象が閲覧できることを確かめられる（AC-20） | |
| ログインしていない閲覧者が、端末に保存を持つ（1件以上の場合と、0件の場合） | 端末の保存の参照で、`Actor` なしで解決する | どちらもエラーにならず、端末の保存の一覧の内容が返る。結果は `Actor` の有無で変わらない。端末の保存が失われる条件とログインによる引き継ぎの案内は、この結果で作る端末の保存の一覧に添えられる（AC-42） | |
| 一時非公開だった掲載 L が、再び公開されている | L の参照で解決する | L が内容つきで返る | |
| 写真のない店舗 P に、写真のある閲覧できる掲載がある | P の参照で解決する | P の要約の写真は、その掲載の代表写真で代用される（AC-29） | |
| 閲覧できる掲載 L がある | L の参照で解決した後、保存されているものを確かめる | 受け取った参照は、どの保存先にも残っていない。アカウントの保存は変わらない | |
| 参照が0件 | 解決する | 空の並びを返す。エラーにならない | |
| 参照が101件 | 解決する | `BusinessRuleError`（`DISCOVERY_TOO_MANY_REFS`） | |
