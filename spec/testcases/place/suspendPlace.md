# suspendPlace

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 店舗 p1（営業中、店舗管理者 A がいる、公開中の掲載がある）がある。操作する人は、p1 の店舗管理者でないサービス運営者 O | O が p1 を非公開にする | 店舗が非公開（`suspended: true`）で保存され、版が進む。`place.suspended` が出る。店舗情報と営業状況は変わらない。掲載・所属・参加・保存は書き換えられない。既存店舗の確認（`matchPlaces`）に p1 は現れなくなる（AC-64） | |
| 店舗 p1 に店舗管理者がいない。操作する人はサービス運営者 O | O が p1 を非公開にする | 非公開が成立する（店舗管理者の有無を問わない） | |
| 店舗 p1（版 0）がある。サービス運営者 O が p1 を開いた後、店舗管理者 A が店舗情報を更新して、版が 1 になった | O が p1 を非公開にする | 非公開が成立する（要求は版を含まない）。店舗情報は A が保存した内容のまま | |
| 店舗 p1 は閉店している。操作する人はサービス運営者 O | O が p1 を非公開にする | 非公開が成立する。営業状況は閉店のまま（営業状況にかかわらず行える） | |
| 同じ店舗が p1 と p2 に重複して登録されている。p2 に公開中の掲載がある。操作する人はサービス運営者 O | O が、残す店舗を p1 と決めて、p2 を非公開にする | p2 が非公開になる。p1 は変わらず、p2 の掲載・所属・参加・保存は p1 に移らない（店舗は統合されない）。サービス運営者が名称・所在地で店舗を探す読み取り（`matchPlacesForOperation`）には、p1 と非公開の p2 の両方が現れる（AC-48） | |
| 店舗 p1 はすでに非公開（別のサービス運営者が先に非公開にした）。操作する人はサービス運営者 O | O が p1 を非公開にする | `BusinessRuleError`（`PLACE_ALREADY_SUSPENDED`）になる。店舗は変わらず、ドメインイベントは出ない | |
| 利用者 A は店舗 p1 の店舗管理者で、サービス運営者の役割を持たない | A が p1 を非公開にする | `ForbiddenError` になる。店舗は非公開にならない（店舗管理者は店舗を自ら非公開にできない）（AC-65） | |
| 操作する人はサービス運営者 O。ID が p9 の店舗はない | O が p9 を非公開にする | `NotFoundError` になる | |
| 店舗 p1 がある。サービス運営者 O が非公開にする操作と、店舗管理者 A の p1 の店舗情報の更新が同時に確定する | O が p1 を非公開にする | 後に確定する側が `ConflictError` になり、その側の変更もドメインイベントも残らない | |
