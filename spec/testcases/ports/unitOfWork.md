# UnitOfWork

契約: [../../domains/index.md](../../domains/index.md) の「UnitOfWork ポート」と「トランザクションとドメインイベント」。

- 前提条件は、`UnitOfWorkContext` に入る集約のリポジトリ（`insert`・`findById`・`save`・`delete` のうち、そのケースが使うメソッドを持つもの。`delete` のケースは、`delete` を持つ `ListingRepository` などで組み立てる）と `collectEvents` だけで組み立てる。集約 X・Y は、同じリポジトリの2件でも、別のリポジトリの1件ずつでもよい
- 「保存されたドメインイベント」は、リレーが配送の対象として取り出すドメインイベント（`OutboxRepository.claimPending`。[../../domains/index.md](../../domains/index.md) の「トランザクションとドメインイベント」）で確かめる
- 「スコープ」は、1回の `run` の `fn` が動いている間を指す
- 「変更を `save` する」は、集約の状態を変える振る舞いと同じく版を1つ進めた集約を `save` することを指す（[../../domains/index.md](../../domains/index.md) の「リポジトリの共通の契約」）。「進んだ版」はその版
- 集約のリポジトリは `UnitOfWorkContext` からだけ得る。期待結果の「後の `run` の `findById`」は、その `run` の完了の後に開いた、書き込まない別の `run` の中で読むことを指す

## コミット

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X がない | `fn` の中で X を `insert` し、値を返す | `run` は `fn` が返した値で解決する。後の `run` の `findById` が X を返す | |
| 集約 X がある | `fn` の中で X を `findById` し、変更を `save` して、値を返す | `run` が解決する。後の `run` の `findById` が、変更した X と進んだ版を返す | |
| 集約 X がある | `fn` の中で X を `findById` し、`delete` して、値を返す | `run` が解決する。後の `run` の `findById` は `null` | |
| 集約 X がある。集約 Y がない | `fn` の中で X を `save` し、Y を `insert` して、値を返す | 両方が反映される | |
| なし | `fn` の中で何も書き込まず、値を返す | `run` は `fn` が返した値で解決する。何も変わらない | |

## ロールバック

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X がない | `fn` の中で X を `insert` し、その後に例外を投げる | `run` は `fn` が投げた例外のまま拒否する。後の `run` の `findById` は `null` | |
| 集約 X がある | `fn` の中で X を `save` し、その後に例外を投げる | X は変更の前の内容と版のまま | |
| 集約 X がある | `fn` の中で X を `delete` し、その後に例外を投げる | X は残る | |
| 集約 X がある。集約 Y がない | `fn` の中で X を `save` し、Y を `insert` し、その後に例外を投げる | X は変わらず、Y はない。書き込みは1件も残らない | |
| 集約 X がない | `fn` の中で X を `insert` し、ドメインイベントの下書きを `collectEvents` に渡し、その後に例外を投げる | X はなく、保存されたドメインイベントにも現れない | |
| なし | `fn` の中で、書き込まずに下書きを `collectEvents` に渡し、その後に例外を投げる | 保存されたドメインイベントに現れない | |
| 集約 X がある。集約 Y がある | `fn` の中で Y を `insert` する（`ConflictError`）。その前に X を `save` している | `run` は `ConflictError` で拒否する。X は変わらない | |
| 集約 X がある。一度も `insert` していない集約 Z | `fn` の中で X を `save` し、その後に、X の `findById` で得た `expectedVersion` で Z を `save` する（`NotFoundError`） | `run` は `NotFoundError` で拒否する。X は変わらない | |

## ドメインイベント

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X がない | `fn` の中で X を `insert` し、下書きを1件 `collectEvents` に渡して、値を返す | X が反映され、保存されたドメインイベントに、下書きの型・`aggregateId`・ペイロードを保った1件が現れる | |
| 集約 X がある | `fn` の中で X を `save` し、`collectEvents` を2回呼んで、合わせて3件の下書きを渡す | 3件とも保存される | |
| 集約 X がある | `fn` の中で X を `save` し、空の下書きの一覧を `collectEvents` に渡す | X が反映され、ドメインイベントは保存されない | |
| 集約 X がある | `fn` の中で X を `save` し、`collectEvents` を呼ばない | X が反映され、ドメインイベントは保存されない | |
| なし | `fn` の中で、書き込まずに下書きを1件 `collectEvents` に渡して、値を返す | その1件が保存される | |
| 集約 X がある。別のスコープの `save` で X の版が進んでいる | `fn` の中で古い版の X を `save` し、下書きを `collectEvents` に渡す | `run` は `ConflictError` で拒否する。X の書き込みも、ドメインイベントも残らない。書き込みだけ、またはドメインイベントだけが残ることはない | |
| コミットしたスコープが保存したドメインイベント | コミットの直後に、保存されたドメインイベントを確かめる | 即座に現れる。書き込みと同じスコープで保存されている | |

## スコープの独立

スコープはネストしない。呼び出し側は `fn` の中で `run` を呼ばないので、`run` は常に独立したスコープを開く。スコープが互いに独立していることを確かめる。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X・Y がない | 1つ目の `run` で X を `insert` してコミットし、その完了の後に、2つ目の `run` で Y を `insert` して例外を投げる | X は残り、Y はない。後のスコープのロールバックは、先にコミットしたスコープに及ばない | |
| 集約 X・Y がない | 1つ目の `run` で X を `insert` して例外を投げ、その完了の後に、2つ目の `run` で Y を `insert` してコミットする | X はなく、Y は残る。ロールバックしたスコープの書き込みとドメインイベントが、後のスコープに持ち越されない | |
| 集約 X・Y がない | X を `insert` してコミットする `run` と、Y を `insert` して例外を投げる `run` を、同時に実行する | X は残り、Y はない。片方の下書きが、もう片方のスコープで保存されない | |

## スコープ内の読み取り

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X がない | `fn` の中で X を `insert` し、同じスコープの中で X を `findById` し、値を返す | スコープの中の `findById` の結果を確かめない（X でも `null` でもよい）。後の `run` の `findById` は X を返す | |
| 集約 X がある | `fn` の中で X を `save` し、同じスコープの中で X を `findById` し、値を返す | スコープの中の `findById` が返す内容を確かめない（変更の前でも後でもよい）。後の `run` の `findById` は変更した X を返す | |
| 集約 X・Y がある | `fn` の中で、X と Y の `findById` をすべて終えてから、X と Y を `save` する | どのアダプターでも同じ結果になる。両方が反映される | |
| 集約 X がある。それより前の `run` が X を `save` してコミットした | `fn` の中で X を `findById` し、値を返す（書き込まない） | 前の `run` でコミットした、最新の X を返す。`run` は `fn` が返した値で解決し、何も変わらない | |
| 集約 X・Y がある | スコープ A の `fn` の中で X を `findById` し、A が値を返す前に、別の `run` が Y を `save` してコミットする。その後に A の中で Y を `findById` し、値を返す（書き込まない） | A の中の Y の `findById` が、別の `run` のコミットの前の Y と後の Y のどちらを返すかを確かめない。A の `run` は解決し、何も変わらない。後の `run` の `findById` は変更した Y を返す | |

## 楽観ロックの競合と一意性の違反

競合と違反は、`save`・`insert` の呼び出しの時点でも、コミットの時点でもよい。確かめるのは `run` の結果で、`fn` の中のどの行で起きたかを確かめない。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 集約 X がある。スコープ A と B が、X の同じ版を読んだ | A が X を `save` してコミットし、その後に B が X を `save` して値を返す | B の `run` は `ConflictError` で拒否する。X は A の内容のまま | |
| 集約 X・Y がある。スコープ B が読んだ後に、X の版が別のスコープで進んだ | B が Y を `save` し、古い版で X を `save` して、値を返す | B の `run` は `ConflictError` で拒否する。Y も変わらない。スコープ全体がロールバックされる | |
| 集約 X がある | X の同じ版を読んだ2つの `run` を同時に実行し、どちらも X を `save` する | 片方だけが解決し、もう片方は `ConflictError` で拒否する。X は、解決した側の内容になる | |
| 集約 X がない。集約 Y がある | 同じ ID の X を `insert` する2つの `run` を同時に実行する。片方は、その前に Y も `save` する | 片方だけが解決し、もう片方は `ConflictError` で拒否する。拒否した側が Y を `save` していれば、Y は変わらない | |
| 集約 X がある | `fn` の中で、X と同じ ID の集約を `insert` して、値を返す | `run` は `ConflictError` で拒否する。`fn` が値を返していても、コミットは成立しない | |
| ID のほかの一意性をポートが担保する集約（`AccountRepository` の「同じメールアドレスのアカウントは1つ」）。集約 Y がある | 同じメールアドレスで ID の違うアカウント2件を、別々の `run` で `insert` する。後の `run` は、その前に Y を `save` し、下書きを `collectEvents` に渡す | 後の `run` は `ConflictError` で拒否する。Y は変わらず、後の `run` のドメインイベントも保存されない | |

## 再試行しない

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 楽観ロックの競合で拒否される `run` | `fn` が呼ばれた回数を数える | `fn` は1回だけ呼ばれる。`run` は競合を自分で再試行しない | |
| 楽観ロックの競合で拒否された `run` | 呼び出し側が、X を読み直して、同じ変更の `run` をもう一度実行する | 解決する。変更が反映され、ドメインイベントは1回分だけ保存される | |

## コミットの後の読み取り

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| X を `insert` した `run` が解決した | 解決の直後に、新しい `run` の中で `findById` する | X を返す | |
| X を `save` した `run` が解決した | 解決の直後に、新しい `run` の中で `findById` し、返された `expectedVersion` で、次の `run` の中で `save` する | 成功する。コミットした版が、以後の読み取りに即座に反映されている | |
| X を `delete` した `run` が解決した | 解決の直後に、新しい `run` の中で `findById` する | `null` を返す | |
| X を `insert` した `run` が解決した | 解決の直後に、新しい `run` の中で、X を含むはずの一覧の問い合わせを読む | X が現れる | |
