# changeParticipationByOccasion

共通の前提: イベント O の開催期間は 10/1〜10/3。店舗 P は店舗管理者がいなく、イベント O に参加中。店舗 P の掲載 L1・L2 は公開中で提供中、L3 は下書き。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 操作する人はイベント O の運営者。店舗 P の参加は `addParticipationDirectly` で成立した。参加内容は、添えた掲載 L1、参加日 10/1 | 添える掲載を L1、L2 に、参加日を 10/2 にして保存する | 保存される。版が1つ進む。`changedBy: "occasion"` の `occasion.participation_changed` が出る（AC-33） | |
| 操作する人はイベント O の運営者。店舗 P の参加は、店舗管理者の参加の申請の承認で成立し、その後に店舗管理者が不在になった | 参加内容を変更して保存する | 保存される。参加が成立した経緯を問わない | |
| 操作する人はイベント O の運営者。イベント O は中止中 | 参加内容を変更して保存する | 保存される。開催の状態を問わない | |
| イベント O にイベント運営者がいない。操作する人はサービス運営者 | 参加内容を変更して保存する | 保存される（代行） | |
| 操作する人はイベント O の運営者。保存するまでの間に、店舗 P に店舗管理者が就いた | 参加内容を変更して保存する | `BusinessRuleError`（`PLACE_HAS_STEWARD`）。参加内容は変わらず、参加は保たれる（AC-33） | |
| 操作する人はイベント O の運営者。編集を始めた後に、店舗 P に店舗管理者が就き、その店舗管理者が参加内容を保存して版が進んでいる | 編集を始めたときの版を添えて保存する | `BusinessRuleError`（`PLACE_HAS_STEWARD`）。状態のエラーを、版の比較より先に判定する | |
| 操作する人はイベント O の運営者で、店舗管理者のいる店舗 Q が参加中 | 店舗 Q の参加内容を変更して保存する | `BusinessRuleError`（`PLACE_HAS_STEWARD`）（AC-18） | |
| 操作する人はイベント O の運営者 | 下書きの掲載 L3 を添えて保存する | `BusinessRuleError`（`LISTING_NOT_ATTACHABLE`） | |
| 操作する人はイベント O の運営者 | 参加日を 9/30 にして保存する | `BusinessRuleError`（`PARTICIPATION_DATE_OUT_OF_PERIOD`） | |
| 操作する人はイベント O の運営者 | 現在と同じ参加内容で保存する | 成功する。版は進まず、ドメインイベントは出ない | |
| 操作する人はイベント O の運営者。保存するまでの間に、別の運営者が店舗 P を除外した | 参加内容を変更して保存する | `NotFoundError` | |
| 操作する人はイベント O の運営者。編集を始めた後に、別の運営者が参加内容を保存して版が進んでいる | 編集を始めたときの版を添えて保存する | `ConflictError` | |
| イベント O にイベント運営者がいる。操作する人は、イベント O の管理権限を持たないサービス運営者 | 参加内容を変更して保存する | `ForbiddenError` | |
| 操作する人はイベント O の運営者。参加日は 10/3。その後にイベントの開催期間が 10/1〜10/2 に更新された | 参加日 10/3 を残したまま、添える掲載だけを変更して保存する | `BusinessRuleError`（`PARTICIPATION_DATE_OUT_OF_PERIOD`）。参加内容は変わらない | |
