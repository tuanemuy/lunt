# suspendOccasion

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 操作する人はサービス運営者。イベントは公開中で、イベント運営者がいる | 運営による非公開にする | 運営による非公開（`suspended: true`）になる。公開状態は `published` のまま書き換わらない。`occasion.suspended` が出る（AC-64） | |
| 操作する人はサービス運営者。イベントは `draft` で、イベント運営者がいない | 運営による非公開にする | 運営による非公開になる。公開状態は `draft` のまま | |
| 操作する人はサービス運営者。イベントは公開の取り下げ中で、中止中。店舗 P が参加中で、地域 R が関連づけ中 | 運営による非公開にする | 運営による非公開になる。公開状態と中止は変わらない。店舗 P の参加と、地域 R との関連づけは変わらない | |
| 操作する人はサービス運営者。イベントを運営による非公開にした後 | イベント運営者が `publishOccasion`・`unpublishOccasion` を行う | どちらも `BusinessRuleError`（`OCCASION_SUSPENDED`）。`updateOccasionContent` は成立する（AC-64） | |
| 操作する人はサービス運営者。別のサービス運営者がすでに運営による非公開にしている | 運営による非公開にする | `BusinessRuleError`（`OCCASION_ALREADY_SUSPENDED`）。イベントは変わらず、`occasion.suspended` は重ねて出ない | |
| 操作する人は、そのイベントのイベント運営者で、サービス運営者の役割を持たない | 運営による非公開にする | `ForbiddenError`。イベントは変わらない | |
| 操作する人はサービス運営者。指定した ID のイベントがない | 運営による非公開にする | `NotFoundError` | |
| 操作する人はサービス運営者。運営による非公開と、イベント運営者のイベント情報の保存が同時に確定する | 運営による非公開にする | 後に確定する側が `ConflictError` になり、その側の変更もドメインイベントも残らない | |
