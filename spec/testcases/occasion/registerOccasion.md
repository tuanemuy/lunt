# registerOccasion

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 操作する人はサービス運営者。イベント運営者にするアカウントは決まっていない | 名称・開催期間・開催場所（町域と位置）・紹介・キャッチコピーと、自分が登録した持ち主のない写真2枚を載せて登録する | `draft` で、運営による非公開でなく、中止でないイベントが保存される。イベントの所在地の `areaCode` は選んだ町域の値。1枚目が代表写真。2枚の写真の持ち主が `{ kind: "occasion"; id }` になる。ドメインイベントは出ない。不足する公開条件は空で返る（AC-17） | |
| 操作する人はサービス運営者 | 名称だけを入力して登録する | `draft` のイベントが保存される。不足する公開条件として開催期間・開催場所・写真が返る（AC-68） | |
| 操作する人はサービス運営者。同じ `OccasionId` と同じイベント情報での登録が成立している | 同じ `OccasionId` と同じイベント情報で、もう一度登録する | 成功する。イベントの版は進まず、写真の持ち主の設定もドメインイベントの保存も起きない | |
| 操作する人はサービス運営者。同じ `OccasionId` のイベントがある | 同じ `OccasionId` で、名称の違うイベント情報を登録する | `ConflictError`。保存されたイベントは変わらない | |
| 操作する人はサービス運営者 | 終了日が開始日より前の開催期間で登録する | `BusinessRuleError`（`COMMON_INVALID_DATE_RANGE`）。イベントは保存されない | |
| 操作する人はサービス運営者。写真 A は別の人が登録した持ち主のない写真 | 写真 A を載せて登録する | `BusinessRuleError`（`MEDIA_PHOTO_NOT_REGISTRANT`）。イベントは保存されず、写真 A の持ち主は設定されない | |
| 操作する人はサービス運営者 | 存在しない `PhotoId` を載せて登録する | `BusinessRuleError`（`MEDIA_PHOTO_NOT_AVAILABLE`）。イベントは保存されない | |
| 操作する人は、サービス運営者の役割を持たない利用者（編集担当者の役割と、別のイベントの管理権限は持つ） | イベント情報を入力して登録する | `ForbiddenError`。イベントは保存されない | |
| 操作する人はサービス運営者。選んだ町域が `AreaCatalog` にない | その町域を開催場所にして登録する | `BusinessRuleError`（`AREA_TOWN_NOT_FOUND`）。イベントは保存されない | |
| 操作する人はサービス運営者。自分が登録した写真のうち1枚は、すでに別のイベントが持ち主 | その写真を含むイベント情報で登録する | `BusinessRuleError`（`MEDIA_PHOTO_ALREADY_OWNED`）。イベントは保存されず、どの写真にも持ち主は設定されない | |
