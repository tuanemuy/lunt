# getMyAuthority

どの操作も `Pagination` に `{ page: 1, limit: 100 }` を渡す。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| A は、どの対象の管理者でもなく、役割も持たない | A を `Actor` として実行する | 空の管理する対象と、空の役割を返す | |
| A は店舗 P1、店舗 P2、地域 R の管理者で、編集担当者 | A を `Actor` として実行する | 管理する対象を P1、P2、R（店舗、地域、イベントの順。同じ種類の中は ID の昇順）で、それぞれの名称つきで返す。管理する対象の全件数は 3。役割は `editor` だけ（AC-37） | |
| A は、運営による非公開の店舗 P と、名称が未入力の下書きの地域 R の管理者 | A を `Actor` として実行する | P を名称つきで、R を名称なしで返す。公開状態と運営による非公開を問わない | |
| 店舗 P に A のメールアドレス宛ての承諾前の招待がある。A は P の管理者ではない | A を `Actor` として実行する | 管理する対象に P は含まれない | |
| A はサービス運営者で、どの対象の管理者でもない | A を `Actor` として実行する | 空の管理する対象と、役割 `operator` を返す。役割は管理する対象を増やさない | |
| A は編集担当者だったが、任命を解かれている | A を `Actor` として実行する | 役割に `editor` は含まれない。`AccessPolicy` は A の `edit_articles` を許さない（AC-75） | |
| A と B は店舗 P の管理者 | A を `Actor` として実行する | A の管理する対象だけを返す。B の情報は返さない | |
