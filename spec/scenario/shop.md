# 店舗

店舗の登録、管理権限の取得、店舗情報と営業状況の更新と、それらの申請に対するサービス運営者の判断・代理登録を定める。

## 共通の規則

- 「店舗」は店舗・スポットを指す。店舗に属さない景色・見どころの場所はスポットとして登録し、店舗と同じ手続きで登録・修正・管理する（P-21、B-16）。店舗とスポットは同じ情報を持ち、種別で区別しない（I-21）
- 店舗の情報は、名称、写真、紹介、所在地、位置、営業時間、連絡先。公開には名称・所在地・位置が必須で、写真は任意（M-10、M-34、B-33）
- 所在地の入力と、その入力エラーは、`index.md` の「共通の規則 > 所在地の入力」が定める。店舗とその掲載のエリアは、店舗の所在地の町域で決まる
- 写真は複数登録して並び替えられ、1枚目が代表写真になる（B-41、I-06）。写真の登録のたびの同意と、その入力エラーは、`index.md` の「共通の規則 > 写真の登録と同意」が定める
- 登録が承認された店舗と代理登録された店舗は、管理者や掲載がなくても公開される（P-40、B-03）。写真のない店舗も、詳細・地図・検索結果・各一覧に表示される（P-43、B-57）
- 登録の承認と管理権限の承認は別の判断で、登録の承認だけでは申請者に管理権限は付かない（B-03、P-40）。店舗の管理権限は、管理権限の申請の承認（SHP-04、SHP-10）、または招待の承諾（MEM-03）で得る
- 公開中の店舗の表示範囲は、`index.md` の「共通の規則 > 表示範囲」が定める
- 既存店舗の確認にログインは要らない。申請にはログインが必要（M-02、B-18）。管理権限の申請に添える、確認に使える連絡先または資料は、文章で記す。ファイルは添えない。紙の許可証や名刺のような資料は、記載の内容を文章で記す。足りなければ承認者が差し戻す（M-40、I-20）。申請の確認・再提出・取り下げ・再申請・失効と、承認者の承認・否認・差し戻しの共通の流れは `application.md` が定める
- 地域への所属・離脱は、管理権限の有無にかかわらず申請と承認による（P-44、B-05）。`region.md` が定める
- 管理者のいる店舗とその掲載の情報の誤り・閉店は、申請ではなく連絡で扱う（MOD-04）
- 店舗管理者は店舗を自ら非公開・削除できない。Lunt への掲載をやめるときは、取り下げを申し立てる（MOD-01）（M-47、B-50）
- 店舗の非公開とその解除、非公開の間に行える操作（MOD-08）と、重複する店舗の整理（MOD-09）は `moderation.md` が定める
- 同時編集の競合と、その異常系は、`index.md` の「共通の規則 > 同時編集の競合」が定める。店舗情報の保存と営業状況の確定に当たる
- 重ねて申請できない規則と、その異常系は、`index.md` の「共通の規則 > 重ねて申請できない」が定める
- 個人の申請（情報修正、休業・閉店、掲載、所属・離脱）が管理者のいない店舗に限られることと、その異常系は、`index.md` の「共通の規則 > 申請の前提」が定める（B-20）
- 操作の途中で管理権限を失った場合と、不在の代行の途中で店舗に店舗管理者が就いた場合の扱いは、`index.md` の「共通の規則 > 立場を失ったとき」が定める
- 管理メンバーの招待・辞任・解除は `membership.md` が定める
- 通知は ACC-03 の表による
- サービス運営者が行う SHP-09〜SHP-13 の入口と、サービス運営者でない利用者がたどり着いたときの扱いは、`index.md` の「共通の規則 > サービス運営者の操作」が定める

## SHP-01 店舗詳細と店舗向け案内から、店舗の管理を始める入口に進む

- 利用者: 閲覧者
- 契約: M-01、D-04、B-18、UC-08、AC-56

### 流れ

1. 閲覧者は、店舗の詳細（EXP-07）でその店舗を管理する入口を選ぶ。または、店舗向け案内を開く
2. 店舗の詳細から進んだ閲覧者は、その店舗の管理権限の申請（SHP-04）へ進む
3. 店舗向け案内では、店舗の登録、管理権限の取得、店舗情報と掲載の管理ができることを読み、既存店舗の確認（SHP-02）へ進む
4. 既存店舗の確認はログインせずに行える。ログインしていない閲覧者は、申請へ進むところでログインへ案内され、ログイン後に元の操作へ戻る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | すでにその店舗の店舗管理者である | 申請の入口ではなく、店舗の管理（SHP-05）へ進む |
| リソース不在 | 店舗が非公開で閲覧できない | 閲覧できないことが示される。他の探索へ進む |
| 操作の取り消し | ログインの途中でやめた | 申請は始まらない。閲覧は続けられる |

## SHP-02 名称・所在地で既存店舗を確認する

- 利用者: 閲覧者
- 契約: M-02、B-04、B-18、P-43、P-87（b）、P-88、B-57、UC-07、UC-15、AC-29、AC-56

### 流れ

1. 閲覧者は、店舗向け案内（SHP-01）から既存店舗の確認を始める。ログインは要らない。目当ての店舗の詳細（EXP-07）を開いている閲覧者は、確認を経ずに、店舗の詳細から手順4の操作へ進む
2. 名称・所在地で店舗を探す（`index.md` の「探し方」）
3. 当たる店舗を一覧で見る。店舗ごとに名称、所在地、写真を見る。写真のない店舗の写真の代用は、`explore.md` の共通の規則による。既存店舗の確認は参照の場面で、休業・閉店の店舗も状態を区別して示される
4. 目当ての店舗があれば選び、詳細を確かめて次へ進む
   - 店舗を管理する: 管理権限を申請する（SHP-04）
   - 管理者のいない店舗の情報を直す: 情報修正、休業・閉店を申請する（SHP-08）
   - 管理者のいない店舗の掲載、所属・離脱を申請する: LST-12、REG-03
   - 管理者のいる店舗の情報の誤り・閉店を伝える: 連絡する（MOD-04）
5. 目当ての店舗がなければ、新規店舗の登録の申請（SHP-03）へ進む
6. 申請または連絡へ進むところで、ログインしていない閲覧者はログインへ案内され、ログイン後に進もうとした操作へ戻る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称も所在地も入力せずに探そうとした | 探せないことが示される。名称または所在地を入力する |
| リソース不在 | 当たる店舗がない | 結果がないことが示される。語を変えて探し直すか、新規店舗の登録を申請する（SHP-03） |
| 操作の取り消し | 申請へ進むところで、ログインをやめた | 申請は始まらない。確認は続けられる |
| 契約（P-88、B-60） | 目当ての店舗が非公開で、一覧に現れない | 閲覧者には既存の店舗がないように見える。登録を申請すると、サービス運営者の照合で重複として否認される（SHP-09） |

## SHP-03 新規店舗の登録を申請する（管理権限の申請を併せられる）

- 利用者: 利用者
- 契約: M-03、M-45、M-34、M-37、M-40、B-03、B-04、B-16、B-33、B-56、P-40、P-42、P-70（01）、P-89、I-20、I-21、UC-07、AC-08、AC-74
- 前提: 既存店舗の確認（SHP-02）で、目当ての店舗がないことを確かめている

### 流れ

1. 利用者は、既存店舗の確認の結果から登録の申請を始める
2. 店舗の情報を入力する。名称・所在地・位置は必須。写真、紹介、営業時間、連絡先は任意
3. 写真を添えるときは、登録のたびに同意を確認する。複数の写真は並び替えられる
4. 管理権限の申請を併せるかを選ぶ。併せるときは、店舗との関係と、確認に使える連絡先または資料を記す。記し方は共通の規則による（I-20）。併せた管理権限の申請は、登録申請の内容ではなく、登録申請と同時に提出する別の申請（M-45）
5. 内容を確かめて提出する。登録申請が確認中になる。管理権限の申請を併せたときは、2つの申請がそれぞれ確認中になる
6. 確認状況と結果は APP-01 で確認する
   - 登録が承認されると、店舗が公開される。登録の承認だけでは管理権限は付かない
   - 併せた管理権限の申請は、登録の承認の後に別に判断される。承認されると店舗管理者になり、店舗の管理へ進む（SHP-05）
   - 登録申請が差し戻されたら、登録申請の内容を修正し、必要なら回答を書いて再提出する（APP-02）。再提出で、管理権限の申請を併せるかどうかは変わらない。併せた管理権限の申請は、別の申請として取り下げられる（APP-03）。併せていない登録申請で管理権限を求めるときは、登録の承認の後に管理権限を申請する（SHP-04）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称・所在地・位置のいずれかを欠いている | 欠けている項目が示される。入力して提出する |
| 入力エラー | 管理権限の申請を併せたが、店舗との関係、または連絡先・資料を欠いている | 欠けている内容が示される。入力するか、管理権限の申請を併せずに提出する |
| 操作の取り消し | 提出の前にやめた | 申請は作られない |
| 操作の取り消し | 提出した後でやめたい | 申請を取り下げる（APP-03）。登録申請を取り下げると、併せた管理権限の申請は失効する |
| 契約（P-42、B-60） | 既存の店舗と重複していて、登録が否認された。非公開の店舗との重複も同じ | 否認の理由を確認する（APP-01）。既存の店舗が公開されていれば、その店舗の管理権限を申請する（SHP-04） |
| 契約（M-45） | 登録が否認され、併せた管理権限の申請が失効した | APP-05 へ進む |
| 契約（M-45、B-56） | 登録は承認され、併せた管理権限の申請は否認された | 店舗は公開され、管理権限は付かない。否認の理由を確認し、管理権限を再申請する（APP-04、SHP-04） |

## SHP-04 店舗の管理権限を申請する

- 利用者: 利用者
- 契約: M-04、M-05、M-07、M-40、P-41、P-70（04）、P-77（d）、P-89、I-20、UC-08、AC-23、AC-43、AC-57
- 前提: 対象の店舗が公開されている

### 流れ

1. 利用者は、店舗の詳細の管理の入口（SHP-01）、または既存店舗の確認の結果（SHP-02）から申請を始める
2. 既存の店舗管理者の有無に応じた案内を見る
   - 店舗管理者がいる店舗: 既存の店舗管理者から招待を受ける方法（MEM-03）が案内される。申請も続けられ、サービス運営者が既存の店舗管理者との関係を確認して判断する
   - 店舗管理者がいない店舗: 申請へ進む。代理登録された店舗を店舗本人が引き継ぐ場合も同じ
3. 店舗との関係と、確認に使える連絡先または資料を記す。記し方は共通の規則による（I-20）
4. 内容を確かめて提出する。申請が確認中になる
5. 確認状況と結果は APP-01 で確認する
   - 追加の確認が必要なら差し戻される。求められた確認を添えて再提出する（APP-02）
   - 承認されると店舗管理者になり、店舗の管理へ進む（SHP-05）。その店舗のすべての掲載が管理下に入る（LST-11）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 店舗との関係、または連絡先・資料を欠いている | 欠けている内容が示される。入力して提出する |
| 権限不足 | すでにその店舗の店舗管理者である | 申請できないことが示される。店舗の管理（SHP-05）へ進む |
| リソース不在 | 店舗が非公開で閲覧できない | 閲覧できないことが示され、申請を始められない |
| 操作の取り消し | 提出の前にやめた | 申請は作られない |
| 操作の取り消し | 提出した後でやめたい | 申請を取り下げる（APP-03） |
| 契約（P-77d） | 申請の確認中・差し戻し中に、招待でその店舗の店舗管理者になった | 申請は失効する（APP-05）。店舗の管理へ進む |
| 契約（P-41） | 既存の店舗管理者との関係が確認できず、否認された | 否認の理由を確認する。既存の店舗管理者から招待を受けるか（MEM-03）、再申請する（APP-04） |

## SHP-05 管理する店舗の状況を確認する

- 利用者: 店舗管理者
- 契約: M-08、M-09、M-28、M-44、M-48、D-07、AC-37

### 流れ

1. 店舗管理者は、管理する店舗から店舗を選んで、店舗の管理を開く
2. 複数の店舗を管理しているときは、店舗をいつでも切り替えられる
3. 選んだ店舗について、次を確認する
   - 店舗の情報と営業状況
   - 掲載。公開中・下書き・非公開・提供終了の別に把握でき、状態別の確認（LST-05）へ進む
   - 対応が必要な申請。店舗管理者として行った申請のうち差し戻されたものを把握し、対応へ進む（APP-06）
   - 確認の依頼。確認依頼中の依頼を把握し、確認へ進む（MOD-06）
   - 公開内容。閲覧者に見える店舗の詳細を開く
4. ここから、店舗情報の更新（SHP-06）、営業状況の登録（SHP-07）、掲載の作成（LST-01）、所属地域の確認（REG-05）、イベントへの参加（EVT-01）、メンバーの管理（MEM-01）へ進む

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 管理する店舗が1つもない。店舗の管理の入口は示されない | 店舗を管理するには、店舗向け案内（SHP-01）から既存店舗の確認（SHP-02）へ進む |
| 権限不足 | 辞任した、または管理権限を解除された店舗の管理に直接たどり着いた | 操作できないことが示される |
| リソース不在 | 対応が必要な申請も、確認依頼中の依頼もない | 対応が必要なことがないことが示される |
| 契約（M-44、P-93） | 管理する店舗が非公開になっている。店舗が非公開であることと、店舗管理者は解除できないことが示される | 店舗情報の更新と掲載の操作を続ける（MOD-08）。解除はサービス運営者を待つ |

## SHP-06 店舗情報を更新する

- 利用者: 店舗管理者
- 契約: M-10、M-34、M-37、M-47、B-05、B-33、B-41、B-50、P-12、P-70（05）、I-06、AC-09
- 前提: 対象の店舗の店舗管理者である

### 流れ

1. 店舗管理者は、店舗の状況（SHP-05）から店舗情報の編集を開く
2. 名称、写真、紹介、所在地・位置、営業時間、連絡先を変える。写真は追加・削除・並び替えができ、1枚目が代表写真になる。写真の追加では、登録のたびに同意を確認する
3. 保存する。申請なしで、保存した時点で公開内容に反映される。所在地を変えると、店舗と、その掲載のエリアも新しい所在地で決まる
4. 保存した後、閲覧者に見える店舗の詳細で公開内容を確かめる

所属地域はここでは変えられない。所属と離脱は申請する（REG-01、REG-02）。営業状況は SHP-07 で登録する。

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称・所在地・位置のいずれかを空にして保存しようとした | 保存できないことと、欠けている項目が示される。入力して保存する |
| 権限不足 | 対象の店舗の店舗管理者でない利用者がたどり着いた | 操作できないことが示される。管理者のいない店舗なら修正を申請する（SHP-08）。管理者のいる店舗なら連絡する（MOD-04） |
| 操作の取り消し | 保存せずに編集をやめた | 店舗情報は変わらない |
| 操作の取り消し | 保存した内容を元に戻したい | 元に戻す操作はない。もう一度編集して保存する |
| 契約（M-47、B-50） | 店舗を非公開にしたい、または削除したい | 店舗管理者は店舗を非公開・削除できない。取り下げを申し立てる（MOD-01） |

## SHP-07 休業・閉店を登録し、営業中に戻す

- 利用者: 店舗管理者
- 契約: M-13、P-45、P-81、P-87（b、c）、B-09、B-11、B-46、V-40、AC-14、AC-65
- 前提: 対象の店舗の店舗管理者である

### 流れ

1. 店舗管理者は、店舗の状況（SHP-05）から営業状況を開き、現在の営業状況（営業中・休業・閉店）を見る
2. 休業または閉店を選ぶ。閲覧者への見え方が示される
   - 休業: 店舗と掲載は、発見の場面と参照の場面のどちらでも、休業中と区別して表示される
   - 閉店: 店舗と掲載は、発見の場面に表示されなくなり、参照の場面では閉店と区別して表示される
3. 確定する。申請なしで、確定した時点で反映される
4. 営業中に戻すときは、同じところで営業中を選んで確定する。店舗と掲載は、営業中の表示に戻る。休業と閉店の間も、同じ操作で切り替えられる

閉店した店舗の公開に期限はなく、営業状況の登録で掲載の公開状態・提供状態は変わらない。

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 対象の店舗の店舗管理者でない利用者がたどり着いた | 操作できないことが示される。管理者のいない店舗なら休業・閉店を申請する（SHP-08）。管理者のいる店舗なら連絡する（MOD-04） |
| 操作の取り消し | 確定の前にやめた | 営業状況は変わらない |
| 操作の取り消し | 誤って休業・閉店を登録した | 営業中に戻す |
| 契約（P-45、M-47） | 閉店した店舗を Lunt から消したい | 閉店した店舗は期限なく公開される。店舗管理者は非公開・削除できない。取り下げを申し立てる（MOD-01） |

## SHP-08 管理者のいない店舗の情報修正、休業・閉店を申請する

- 利用者: 利用者
- 契約: M-11、M-34、M-37、P-44、P-74、P-70（02）、P-77（a）、B-20、UC-09、AC-09
- 前提: 対象の店舗が公開されていて、店舗管理者がいない

### 流れ

1. 利用者は、店舗の詳細、または既存店舗の確認の結果（SHP-02）から、情報の修正の申請を始める。管理権限は要らない
2. 現在の店舗情報を見て、修正する項目を入力する。申請は修正の申請（`application.md` の「修正の申請」）で、対象はその店舗。名称、写真、紹介、所在地・位置、営業時間、連絡先を修正できる。営業状況は、営業中・休業・閉店のどれへの変更も申請でき、誤って休業・閉店になっている店舗を営業中に直す申請も含む。営業状況の変更は、情報の修正と併せて、または単独で申請できる
3. 写真を添えるときは、登録のたびに同意を確認する
4. 内容を確かめて提出する。申請が確認中になる
5. 確認状況と結果は APP-01 で確認する。承認で反映される内容は、修正の申請の規則による

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称・所在地・位置のいずれかを空にする修正 | 提出できないことが示される。値を入力する |
| 契約（P-77a） | 申請の確認中・差し戻し中に、その店舗に店舗管理者が就いた | 申請は失効する（APP-05）。必要なら連絡する（MOD-04） |
| リソース不在 | 店舗が非公開で閲覧できない | 閲覧できないことが示され、申請を始められない |
| 操作の取り消し | 提出の前にやめた | 申請は作られない |
| 操作の取り消し | 提出した後でやめたい | 申請を取り下げる（APP-03） |

## SHP-09 登録申請を既存店舗と照合して判断する

- 利用者: サービス運営者
- 契約: O-01、O-04、M-03、M-34、M-45、P-40、P-42、P-75、B-03、B-60、P-70（01）、AC-08、AC-78
- 前提: 登録申請が確認中の状態にある

### 流れ

1. サービス運営者は、新しい申請の通知、または対応が必要な申請の一覧（OPE-01）から登録申請を開く
2. 申請者と、申請された店舗の情報を確認する。管理権限の申請が併せて出されていれば、そのことが分かる
3. 既存の店舗と照合する。申請された名称・所在地で探した既存の店舗が、非公開の店舗を含めて示される。名称・所在地で店舗を探して（`index.md` の「探し方」）、自分でも確かめられる
4. 判断する（APP-07）
   - 重複がなく、内容に問題がなければ承認する。店舗は、管理者や掲載がなくても公開される。申請者に管理権限は付かない
   - 既存の店舗と重複していれば、重複を理由に添えて否認する。非公開の店舗との重複も否認する。その店舗を公開する場合は、非公開を解除する（MOD-08）
   - 内容に追加の確認が必要なら、必要な確認を添えて差し戻す
5. 併せた管理権限の申請は、登録を承認した後に判断する（SHP-10）。登録を否認すると、併せた管理権限の申請は失効する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（P-75） | 同じ店舗への登録申請が複数ある | 1件ずつ判断する。1件を承認した後の残りは、公開された店舗との重複として否認する |
| 契約（M-34） | 名称・所在地・位置が実際の店舗と合わない | 必要な確認を添えて差し戻す。承認した後は、管理者のいない店舗の情報として更新できる（SHP-13） |
| 契約（O-18） | 承認した後で、既存の店舗との重複に気づいた | 重複する店舗を整理する（MOD-09） |
| 入力エラー、権限不足、リソース不在、操作の取り消し | APP-07 と同じ | APP-07 と同じ |

## SHP-10 管理権限の申請を確認して判断する

- 利用者: サービス運営者
- 契約: O-03、O-04、O-05、M-04、M-07、M-36、M-40、M-45、P-41、P-75、P-77（a、c、d）、P-93、X-04、P-70（04）、AC-43、AC-57
- 前提: 管理権限の申請が確認中の状態にある。登録申請に併せた申請では、登録申請が承認されている

### 流れ

1. サービス運営者は、新しい申請の通知、または対応が必要な申請の一覧（OPE-01）から管理権限の申請を開く
2. 申請者、対象の店舗、申請者が文章で記した店舗との関係と連絡先または資料、既存の店舗管理者の有無を確認する
3. 申請者が店舗を管理する立場にあることを確かめる。確かめる手順は運用が定める。既存の店舗管理者がいる店舗では、申請者と既存の店舗管理者との関係を確かめる
4. 判断する（APP-07）
   - 確かめられたら承認する。申請者は店舗管理者になり、その店舗のすべての掲載が申請者の管理下に入る
   - 確認が足りなければ、必要な確認を添えて差し戻す
   - 確かめられなければ、理由を添えて否認する
5. 管理者のいなかった店舗で承認すると、個人がその店舗に行った確認中・差し戻し中の申請（情報修正・掲載・掲載の修正・所属・離脱）は、前提（その店舗に店舗管理者がいない）を失って失効する

代理登録した店舗を店舗本人に引き継ぐ場合も、この流れで承認する。

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-45） | 併せた登録申請がまだ確認中である | 管理権限は判断できないことが示される。先に登録申請を判断する（SHP-09） |
| 契約（P-75） | 別の申請者による、同じ店舗への管理権限の申請が複数ある | 1件ずつ判断する。複数を承認すると、それぞれが同じ操作範囲の店舗管理者になる |
| 契約（M-44） | 申請の確認中に、対象の店舗が非公開になった | 申請は失効せず、確認中のまま残る。同じ流れで判断する。承認すると、申請者は非公開の店舗の店舗管理者になる |
| リソース不在 | 判断する前に、申請が前提を失って失効した（登録申請の否認・取り下げ、招待の承諾による店舗管理者への就任） | 判断できず、失効が示される。対応は要らない |
| 操作の取り消し | 誤って承認した | 承認は変えられない。その利用者の権限を解除する（MEM-05） |
| 入力エラー、権限不足 | APP-07 と同じ | APP-07 と同じ |

## SHP-11 情報修正、休業・閉店の申請を判断する

- 利用者: サービス運営者
- 契約: O-02、M-11、M-34、M-46、P-75、P-77（a）、P-70（02）、AC-09
- 前提: 管理者のいない店舗への情報修正、営業状況の変更の申請が確認中の状態にある

### 流れ

1. サービス運営者は、新しい申請の通知、または対応が必要な申請の一覧（OPE-01）から申請を開く
2. 申請者と、申請の内容を確認する。見比べ方と承認で反映される内容は、`application.md` の「修正の申請」による
3. 判断する（APP-07）
   - 内容が正しければ承認する。申請の項目が店舗に反映され、公開内容が変わる
   - 追加の確認が必要なら、必要な確認を添えて差し戻す
   - 内容が正しくなければ、理由を添えて否認する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-44） | 申請の確認中に、対象の店舗が非公開になった | 申請は失効せず、確認中のまま残る。同じ流れで判断する。承認した内容は店舗に反映され、解除まで閲覧者に表示されない |
| 契約（M-46） | 申請の内容の一部だけが正しい | 項目ごとの採否は選べない（修正の申請）。修正を求めて差し戻すか、否認して正しい内容を自分で更新する（SHP-13） |
| リソース不在 | 判断する前に、店舗に店舗管理者が就き、申請が前提を失って失効した | 判断できず、失効が示される。対応は要らない |
| 入力エラー、権限不足、操作の取り消し | APP-07 と同じ | APP-07 と同じ |

## SHP-12 店舗を代理登録する

- 利用者: サービス運営者
- 契約: O-05、O-04、M-07、M-34、M-37、B-33、P-40、P-43、AC-29、AC-57

### 流れ

1. サービス運営者は、名称・所在地で店舗を探し（`index.md` の「探し方」）、登録する店舗が非公開の店舗を含めて存在しないことを確かめる
2. 店舗の情報を入力する。名称・所在地・位置は必須。写真、紹介、営業時間、連絡先は任意。写真の登録では、登録のたびに同意を確認する。複数の写真は並び替えられる
3. 登録する。申請なしで、店舗は管理者のいない店舗として公開される
4. 登録した店舗の情報と営業状況は SHP-13 で、掲載は LST-15・LST-16 で管理する
5. 店舗本人が管理権限を申請したら（SHP-04）、SHP-10 で承認して管理を引き継ぐ

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称・所在地・位置のいずれかを欠いている | 登録できないことと、欠けている項目が示される。入力して登録する |
| 契約（O-04） | 登録する店舗がすでに存在する | 登録しない。管理者のいない店舗なら情報を更新する（SHP-13）。非公開の店舗を公開する場合は、非公開を解除する（MOD-08） |
| 操作の取り消し | 登録の前にやめた | 店舗は作られない |
| 操作の取り消し | 誤って登録した、または登録した後で重複に気づいた | 店舗を削除する操作はない。誤った内容は更新する（SHP-13）。公開をやめるときは店舗を非公開にする（MOD-08）。重複は整理する（MOD-09） |

## SHP-13 管理者のいない店舗の情報と営業状況を更新する

- 利用者: サービス運営者
- 契約: M-46、O-19、M-34、M-37、M-48、O-24、B-31、P-70（03）、I-03、AC-65
- 前提: 対象の店舗に店舗管理者がいない

### 流れ

1. サービス運営者は、対象の店舗を名称・所在地で探す（`index.md` の「探し方」）。結果に店舗管理者がいないことが示され、結果から店舗の更新を始める
2. 名称、写真、紹介、所在地・位置、営業時間、連絡先を変える。写真は追加・削除・並び替えができる。写真の追加では、登録のたびに同意を確認する
3. 営業状況を営業中・休業・閉店のいずれかに変える
4. 保存する。申請なしで、保存した時点で公開内容に反映される。表示範囲の変化は SHP-06、SHP-07 と同じ

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称・所在地・位置のいずれかを空にして保存しようとした | 保存できないことと、欠けている項目が示される。入力して保存する |
| 契約（I-03、M-48） | 対象の店舗に店舗管理者がいる | 更新できないことが示される。連絡への対応（MOD-05）で店舗管理者に確認を依頼する。対応がなければ、その店舗のすべての店舗管理者の権限を解除して（MEM-05）から更新する |
| リソース不在 | 探した店舗が見つからない。店舗が Lunt に登録されていない | 店舗を代理登録する（SHP-12） |
| 契約（P-75） | 更新する店舗に、確認中の情報修正の申請がある | 更新しても申請は確認中のまま残る。判断は、更新した後の値と見比べる（修正の申請、SHP-11） |
| 操作の取り消し | 保存せずに編集をやめた | 店舗情報と営業状況は変わらない |
| 操作の取り消し | 保存した内容を元に戻したい | 元に戻す操作はない。もう一度編集して保存する |
