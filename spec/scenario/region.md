# 地域

店舗の地域への所属・離脱・除外と、地域の運営者による地域の運営を扱う。

## 共通の規則

- 所属は所属申請の承認で成立し、離脱の承認または除外で解除される。店舗と地域の関係は、申請中と所属中を区別して示す（P-14、P-85）
- 所属・離脱の申請は地域ごとに独立する。ある地域での承認・否認・除外は、他の地域の所属に影響しない（R-08、B-13）
- 所属の承認・離脱の承認・除外で、店舗と掲載の公開状態・提供状態は変わらない（B-06）
- 所属の承認・離脱の承認・除外は、地域の所属店舗と、店舗・掲載の所属地域の両方に反映される（R-10）
- 地域の運営者は、[index.md](index.md) の「利用者」が定める（地域運営者のいる地域ではその地域運営者、不在の地域ではサービス運営者）。REG-06〜REG-11 は地域の運営者が行う
- 所属・離脱の申請の承認者は、対象地域の地域の運営者（R-11）。地域運営者が一定の期間確認しない申請は、サービス運営者が期間超過の代行（APP-08）で承認・否認できる。除外に、期間超過の代行はない（P-70 の 14 行）
- 申請の確認・再提出・取り下げ・再申請・失効と、承認・否認・差し戻しの共通の流れは APP-01〜APP-08 による。店舗管理者として行った申請は、その店舗のすべての店舗管理者が扱える（APP-06）
- 地域の運営者の権限は、地域情報と所属関係の管理に限る。所属店舗の情報・掲載を更新するには、その店舗の管理権限が要る（R-04）
- 管理権限のない利用者は、地域の情報修正を申請できない。入口は示されない（P-51、B-43）
- 重ねて申請できない規則と、その異常系は、[index.md](index.md) の「重ねて申請できない」が定める。所属・離脱の申請の対象は、店舗と地域の組
- 確認中・差し戻し中の申請の失効は、[index.md](index.md) の「申請の前提」による。前提を欠く申請は承認もできない。所属の申請と離脱の申請には、所属の有無の前提と、申請者に応じた店舗管理者の有無の前提の両方が当たる
- 対象の地域・店舗が非公開になっても、確認中・差し戻し中の申請は失効しない（`application.md` の共通の規則）
- 否認・取り下げ・失効の後の再申請は APP-04 による。前の申請の内容が入った状態で始まり、新しい申請として提出される
- 通知は ACC-03 の表による。店舗管理者として行った申請の申請者宛ての通知の宛先は `application.md` の共通の規則が、店舗管理者・地域運営者が不在の対象への通知の宛先と通知から進む先は [index.md](index.md) の「不在の対象への通知」が定める
- 同時編集の競合と、その異常系は、[index.md](index.md) の「同時編集の競合」が定める
- 地域の公開状態は 下書き・公開・公開の取り下げ。下書きと公開の取り下げは未公開（[index.md](index.md) の「用語」）。運営による非公開はそれとは別の状態で、その間に行える操作と解除の後の公開状態は [index.md](index.md) の「運営による非公開」が定める（R-15）
- 未公開の地域と運営による非公開の地域は、閲覧者のどの場面にも表示されず、店舗・掲載の所属地域としても表示されない。所属関係は保たれ、店舗管理者の所属地域の状況には、地域の状態と分かるように示される（P-16、P-88）
- 店舗管理者は、閲覧者に表示されない地域との所属も、離脱の申請（REG-02）と代表地域の選択（REG-04）の対象にできる。管理者のいない店舗について個人が行う離脱の申請（REG-03）では、閲覧者に表示される所属地域（公開中で、運営による非公開でない地域）だけを選べる
- 代表地域の決まり方と、一覧で示す地域名は、[index.md](index.md) の「代表地域」が定める
- 閲覧できない地域には、所属を申請できない
- 地域の所在地の入力と、写真の登録のたびの同意は、その入力エラーを含めて、[index.md](index.md) の「所在地の入力」「写真の登録と同意」が定める
- 地域運営者の管理メンバーの招待・辞任・解除は MEM-01〜MEM-05 による
- サービス運営者が行う REG-12・REG-13 の入口と、サービス運営者でない利用者がたどり着いたときの扱いは、[index.md](index.md) の「サービス運営者の操作」が定める
- 操作の途中で、店舗の管理権限を失った店舗管理者、または地域の地域の運営者でなくなった利用者の扱いは、[index.md](index.md) の「立場を失ったとき」が定める
- 個人の所属・離脱の申請が管理者のいない店舗に限られることと、その異常系は、[index.md](index.md) の「申請の前提」が定める（B-20）

次の異常系は、地域の運営者が行う REG-06〜REG-11 に共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足（R-15、P-70 の 14・20・26 行） | その地域の地域の運営者でない利用者には、入口が示されない。直接たどり着いても操作できないことが示される。地域運営者のいる地域のサービス運営者を含む | 操作をやめる |

## REG-01 管理する店舗の地域への所属を申請する

- 利用者: 店舗管理者
- 契約: R-05、R-08、R-09、P-14、P-44、P-70（12 行）、P-74、P-77（b・f）、P-85、B-05、B-13、B-20、UC-11
- 前提: ログインしている。店舗の管理権限を持つ

### 流れ

1. 管理する店舗の所属地域の状況を開く。所属中の地域と、申請中の地域を確認する。未公開の地域・運営による非公開の地域との所属は、その状態と分かるように示される
2. 所属を申請する地域を、公開中の地域からキーワードで探して選ぶ（[index.md](index.md) の「探し方」）。地域の詳細を確認できる。または、閲覧中の地域の詳細（EXP-04）から所属の申請へ進み、管理する店舗を選ぶ（管理する店舗が1つなら選ばない）。このときは、その地域が選ばれた状態で手順3へ進む
3. 店舗と地域を確認して申請する。申請は確認中になり、その地域との関係が申請中として示される
4. 確認状況と結果は APP-01 で確認する。承認されると所属が成立する。店舗詳細と掲載の所属地域、地域の所属店舗に反映される
5. 代表地域は、[index.md](index.md) の「代表地域」の規則で決まる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 管理権限のない店舗では、所属申請の入口が示されない。直接たどり着いても申請できないことが示される | 管理者のいない店舗なら REG-03 で申請する。店舗管理者のいる店舗なら SHP-04 で管理権限を申請する |
| リソース不在 | 選んだ地域が、申請するまでの間に公開を取り下げられた、または運営による非公開になった。閲覧できないことが示され、申請できない | 別の地域を選ぶ |
| 契約（申請の前提） | すでに所属中の地域は、キーワードの候補では所属中を理由に選べない対象として示される。地域の詳細から始めた場合は、所属中であることが示され、申請できない | 別の地域を選ぶ |
| 契約（申請の前提） | 確認中・差し戻し中に、店舗の店舗管理者が不在になった。申請は前提を失って失効する | APP-05 による |
| 契約（P-71） | 否認された。理由を確認できる。差し戻された場合は追加で必要な確認が示される | 否認は APP-04 で再申請する。差し戻しは APP-02 で再提出する |
| 操作の取り消し | 申請する前にやめた。申請は作られない | 所属地域の状況に戻る |
| 操作の取り消し | 申請した後にやめたい | APP-03 で取り下げる |

## REG-02 管理する店舗の地域からの離脱を申請する

- 利用者: 店舗管理者
- 契約: R-06、R-08、R-09、P-15、P-16、P-44、P-70（13 行）、P-74、P-77（b・f）、P-85、B-05、B-20、UC-12
- 前提: ログインしている。店舗の管理権限を持つ。店舗が対象の地域に所属中

### 流れ

1. 管理する店舗の所属地域の状況を開き、所属中の地域から離脱する地域を選ぶ。未公開の地域・運営による非公開の地域も選べる
2. 店舗と地域を確認して、離脱を申請する。申請は確認中になる。承認されるまで所属は続く
3. 確認状況と結果は APP-01 で確認する。承認されると所属が解除される。店舗詳細と掲載の所属地域、地域の所属店舗から外れる
4. 解除された地域が代表地域だった場合、代表地域は [index.md](index.md) の「代表地域」の規則で決まり直す

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 管理権限のない店舗では、離脱申請の入口が示されない。直接たどり着いても申請できないことが示される | 管理者のいない店舗なら REG-03 で申請する |
| リソース不在 | 選んだ地域との所属が、申請するまでの間に除外または別の離脱申請の承認で解除された。所属していないことが示され、申請できない | REG-05 で所属を確認する |
| 契約（申請の前提） | 確認中・差し戻し中に、地域の運営者が店舗を除外した。申請は前提を失って失効する | REG-05 で所属の解除を確認する |
| 契約（申請の前提） | 確認中・差し戻し中に、店舗の店舗管理者が不在になった。申請は前提を失って失効する | APP-05 による |
| 契約（P-71） | 否認された。理由を確認できる。所属は続く | APP-04 で再申請する |
| 操作の取り消し | 申請する前にやめた。申請は作られない | 所属地域の状況に戻る |
| 操作の取り消し | 申請した後にやめたい | APP-03 で取り下げる。所属は続く |
| 操作の取り消し | 離脱が承認された後に、所属へ戻したい。承認は取り消せない | REG-01 で所属を申請する |

## REG-03 管理者のいない店舗の所属・離脱を申請する

- 利用者: 利用者
- 契約: R-05、R-06、R-08、R-09、P-44、P-70（12・13 行）、P-74、P-75、P-77（a・f）、B-18、B-20、AC-22
- 前提: 対象の店舗に店舗管理者がいない

### 流れ

1. 管理者のいない店舗の詳細から、所属・離脱の申請に進む。または、閲覧中の地域の詳細（EXP-04）から所属の申請へ進み、管理者のいない店舗をキーワードで探して選ぶ（[index.md](index.md) の「探し方」）。このときは、その地域が選ばれた所属の申請になる。ログインしていなければログインへ案内され、ログイン後に戻る
2. 所属を申請する場合は、公開中の地域から対象をキーワードで探して選ぶ。離脱を申請する場合は、店舗の所属地域のうち、閲覧者に表示される地域（公開中で、運営による非公開でない地域）から対象を選ぶ
3. 店舗・地域・申請の種類（所属または離脱）を確認して申請する。申請は確認中になる。管理権限の取得は要らない
4. 確認状況と結果は APP-01 で確認する。承認されると、所属の追加または解除が、店舗詳細と掲載の所属地域、地域の所属店舗に反映される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 店舗が非公開になり、閲覧できない | 他の探索へ進む |
| リソース不在 | 選んだ地域が閲覧できなくなった。または離脱の対象の所属がすでに解除されていた。申請できないことが示される | 別の地域を選ぶ。または申請をやめる |
| 契約（申請の前提） | 店舗の詳細から始めた場合、店舗がすでに所属中の地域は、地域の候補で所属中を理由に選べない対象として示される。地域の詳細から始めた場合、その地域にすでに所属中の店舗は、店舗の候補で同じく選べない対象として示される | 別の地域または別の店舗を選ぶ。または申請をやめる |
| 契約（申請の前提） | 確認中・差し戻し中に、店舗に店舗管理者が就いた。申請は前提を失って失効する | APP-05 による。以後は店舗管理者が REG-01・REG-02 で申請する |
| 契約（申請の前提） | 確認中・差し戻し中に、所属申請の対象の所属が別の申請の承認で成立した。または離脱申請の対象の所属が、除外か別の離脱申請の承認で解除された。申請は前提を失って失効する | APP-05 による |
| 契約（P-71） | 否認または差し戻しを受けた | 否認は APP-04、差し戻しは APP-02 による |
| 操作の取り消し | 申請する前にやめた。申請は作られない | 店舗の詳細に戻る |
| 操作の取り消し | 申請した後にやめたい | APP-03 で取り下げる |

## REG-04 代表地域を選ぶ

- 利用者: 店舗管理者
- 契約: R-12、P-15、P-16、V-05、B-25、AC-25
- 前提: ログインしている。店舗の管理権限を持つ。店舗が複数の地域に所属中

### 流れ

1. 管理する店舗の所属地域の状況を開く。現在の代表地域と、それが選んだ代表地域か、選んだ代表地域がなく最初に所属した地域が代表地域になっているかが示される
2. 所属中の地域から1つを選び、代表地域にする。承認は要らず、選んだ時点で反映される。選べる地域は [index.md](index.md) の「代表地域」による
3. 一覧で店舗と掲載に示す地域名が、選んだ代表地域になる（[index.md](index.md) の「代表地域」）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 管理権限のない店舗では、代表地域を選ぶ入口が示されない。直接たどり着いても操作できないことが示される | 操作をやめる |
| リソース不在 | 所属が1つ以下で、選ぶ対象がない。所属が1つの店舗は、一覧にその地域が表示される | 所属を増やすには REG-01 で申請する |
| リソース不在 | 選んだ地域との所属が、選ぶまでの間に解除された。選べないことが示され、最新の所属が示される | 残る所属から選び直す |
| 操作の取り消し | 選んだ後に元へ戻したい | 元の地域を選び直す |

## REG-05 所属関係の変更結果を確認する

- 利用者: 店舗管理者
- 契約: R-09、R-10、P-15、P-85、P-91、P-93、B-06
- 前提: ログインしている。店舗の管理権限を持つ

### 流れ

1. 店舗管理者は、所属・離脱の申請の結果と、地域の運営者による除外を、通知で知る
2. 管理する店舗の所属地域の状況を開く。所属中の地域、申請中の地域、代表地域を確認する。店舗管理者のいなかった時期に成立した所属も含まれる。未公開の地域・運営による非公開の地域との所属は、その状態と分かるように示される
3. 個々の申請の確認状況、否認の理由、差し戻しの内容は APP-01 で確認する。同じ店舗の別の店舗管理者が行った申請も確認できる（APP-06）
4. 所属が解除された場合、店舗詳細と掲載の所属地域からその地域が外れていることを確認する。解除された地域が選んだ代表地域だった店舗では、選んだ代表地域がなく、最初に所属した地域が代表地域になっていることが示される（[index.md](index.md) の「代表地域」）。店舗と掲載の公開状態・提供状態は変わらない

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 辞任した、または管理権限を解除された店舗の所属地域の状況は開けない。操作できないことが示される | 公開されている所属地域は、店舗の詳細（EXP-07）で確認する |
| リソース不在 | 通知から開いた地域が、公開を取り下げられた、または運営による非公開になっていて閲覧できない | 所属地域の状況で所属の有無を確認する |
| 操作の取り消し | 除外された地域に、再び所属したい。除外を店舗管理者が取り消すことはできない | REG-01 で所属を申請する |

## REG-06 地域情報を更新する

- 利用者: 地域の運営者
- 契約: R-01、R-04、R-14、M-37、P-31、P-51、B-38、B-41、B-43、B-53、I-06、AC-13、AC-60、AC-74
- 前提: ログインしている。対象の地域の地域の運営者である

### 流れ

1. 管理する地域の情報を開く
2. 名称・所在地・位置・写真・紹介・キャッチコピーを編集する。位置は1点で指定する。写真は複数登録でき、並び替えられる。1枚目が代表写真になる
3. 写真を登録するときは、登録のたびに同意を確認する
4. 保存する。公開中の地域では、保存した時点で閲覧者に反映される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー（R-14） | 公開中の地域で、名称・所在地・位置・写真のいずれかを欠く内容を保存しようとした。不足する項目が示され、保存できない | 不足を埋めて保存する。欠いたまま保存するなら、先に REG-07 で公開を取り下げる |
| 権限不足（R-04） | 所属店舗の情報や掲載を更新しようとした。地域の運営者の権限ではできない | その店舗の管理権限を持つ場合に限り、SHP-06・LST-06 で更新する |
| 契約（R-15） | 地域が運営による非公開になっている。そのことが示される | 更新を続ける。閲覧者への表示は解除を待つ |
| 操作の取り消し | 保存せずに編集をやめた。変更は残らない | 地域の管理に戻る |

## REG-07 地域を公開し、公開を取り下げる

- 利用者: 地域の運営者
- 契約: R-02、R-14、R-15、M-49、P-16、P-83、P-88、P-96、B-06、B-10、B-51、AC-60、AC-68
- 前提: ログインしている。対象の地域の地域の運営者である

### 流れ

1. 管理する地域を開く。現在の公開状態（下書き・公開・公開の取り下げ）と、運営による非公開かどうかを確認する
2. 公開する。名称・所在地・位置・写真がそろっていれば公開され、閲覧者は地域探索と地域詳細で地域を見られる。地域はフィードで紹介する対象になる。所属店舗とその掲載には、所属地域としてこの地域が表示される
3. 公開中の地域の公開を取り下げる。地域はどの場面にも表示されなくなり、所属店舗とその掲載の所属地域としても表示されない。この地域を代表地域とする店舗の地域名は、[index.md](index.md) の「代表地域」の規則による
4. 取り下げても、所属関係と関連づけは保たれる。店舗と掲載の公開状態・提供状態は変わらない
5. 取り下げた地域は、再び公開できる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー（R-14） | 名称・所在地・位置・写真のいずれかが欠けている。不足する項目が示され、公開できない | REG-06 で不足を埋めてから公開する |
| 契約（R-15） | 地域が運営による非公開になっている。公開も公開の取り下げもできないことが示される | サービス運営者による解除を待つ |
| 契約（M-49） | 申立てによる写真の削除で写真がなくなり、地域の公開が取り下げられた。写真がないため公開できない | MOD-03 で写真を登録して再び公開する |
| 操作の取り消し | 公開または取り下げを元に戻したい | 公開した地域は取り下げる。取り下げた地域は再び公開する |

## REG-08 所属店舗と、所属・離脱の申請を確認する

- 利用者: 地域の運営者
- 契約: R-03、R-04、P-85、P-92、AC-60
- 前提: ログインしている。対象の地域の地域の運営者である

### 流れ

1. 管理する地域を開く
2. 所属中の店舗の一覧を確認する。各店舗の詳細へ進める
3. 所属・離脱の申請を確認する。申請の種類（所属・離脱）、対象の店舗、申請者、確認中か差し戻し中かが分かる。申請についての通知から開いてもよい
4. 確認中の申請を選び、REG-09 で判断する。所属店舗を選び、REG-10 で除外する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足（R-04） | 所属店舗の情報や掲載は、この確認から更新できない | その店舗の管理権限を持つ場合に限り、店舗の管理から更新する |
| リソース不在 | 所属店舗がない、または申請がない。ないことが示される | 地域の管理に戻る |
| リソース不在 | 通知から開いた申請が、取り下げ・失効となった、またはサービス運営者の期間超過の代行で判断済みだった。その状態が示される | 申請の一覧に戻る |

## REG-09 所属・離脱の申請を判断する

- 利用者: 地域の運営者
- 契約: R-05、R-06、R-08、R-10、R-11、P-15、P-70（12・13 行）、P-71、P-77（f）、P-78、B-06、B-42、AC-11、AC-12、AC-45
- 前提: ログインしている。対象の地域の地域の運営者である。対象の申請が確認中

### 流れ

1. REG-08 から確認中の申請を開く。申請の種類、対象の店舗、申請者を確認する。店舗の詳細を確認できる
2. 承認・否認・差し戻しのいずれかを行う。共通の流れは APP-07 による
3. 所属申請を承認すると所属が成立する。地域の所属店舗に店舗が加わり、店舗詳細と掲載の所属地域にこの地域が加わる。同じ店舗とこの地域への他の所属申請は、申請の前提により失効する
4. 離脱申請を承認すると所属が解除される。地域の所属店舗から店舗が外れ、店舗詳細と掲載の所属地域からこの地域が外れる。同じ所属への他の離脱申請は、申請の前提により失効する。この地域が店舗の代表地域だった場合、代表地域は [index.md](index.md) の「代表地域」の規則で決まり直す
5. どの判断も、店舗の他の地域への所属と、店舗・掲載の公開状態・提供状態を変えない
6. 店舗管理者を兼ねる地域の運営者は、自分が行った申請も承認できる（P-04）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 理由を添えずに否認しようとした | APP-07 による |
| リソース不在 | 判断するまでの間に、申請が取り下げられた、または前提を失って失効した。判断できないことが示される。前提を欠く申請は承認できない | REG-08 の申請の一覧に戻る |
| 契約（P-78） | 一定の期間確認しなかった申請を、サービス運営者が期間超過の代行で判断した（APP-08）。判断済みであることが示される | REG-08 で結果を確認する |
| 操作の取り消し | 所属を承認した後に取り消したい。承認は取り消せない | REG-10 で店舗を除外する |
| 操作の取り消し | 離脱を承認した後、または否認した後に取り消したい。判断は取り消せない | 店舗側の再度の申請（REG-01〜REG-03、APP-04）を待って判断する |

## REG-10 所属店舗を除外する

- 利用者: 地域の運営者
- 契約: R-07、R-10、P-15、P-70（14 行）、P-77（f）、P-85、P-93、B-06、UC-13、AC-11
- 前提: ログインしている。対象の地域の地域の運営者である。対象の店舗が所属中

### 流れ

1. REG-08 の所属店舗から、除外する店舗を選ぶ
2. 除外を実行する。承認は要らず、理由も求められない
3. 所属が解除される。地域の所属店舗から店舗が外れ、店舗詳細と掲載の所属地域からこの地域が外れる。店舗と掲載の公開状態・提供状態、他の地域への所属は変わらない
4. その店舗のこの地域からの離脱申請は、申請の前提により失効する
5. この地域が店舗の代表地域だった場合、代表地域は [index.md](index.md) の「代表地域」の規則で決まり直す

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 除外するまでの間に、離脱の承認または別の地域の運営者の除外で所属が解除されていた。所属していないことが示される | REG-08 の所属店舗に戻る |
| 操作の取り消し | 実行する前にやめた。所属は変わらない | REG-08 の所属店舗に戻る |
| 操作の取り消し | 除外した後に取り消したい。除外は取り消せない | 店舗側の所属申請（REG-01、REG-03）を待ち、REG-09 で承認する |

## REG-11 イベントからの関連づけを確認し、解除し、解除を取り消す

- 利用者: 地域の運営者
- 契約: R-13、E-12、P-70（20 行）、P-94、P-95、B-15、B-37、AC-34、AC-73
- 前提: ログインしている。対象の地域の地域の運営者である

### 流れ

1. イベントの運営者は、地域を開催地域として関連づけられる。関連づけに地域の運営者の承認は要らない。地域の運営者は、関連づけの通知からも関連づけを確認できる
2. 管理する地域に関連づけられたイベントを確認する。イベントの詳細へ進める。未公開のイベント・運営による非公開のイベントは、その状態と分かるように示され、解除と解除の取り消しの対象にできる
3. 関連づけを解除する。地域詳細の関連するイベントと、イベント詳細の関連する地域の両方から外れる。イベントの運営者は、この地域に同じイベントを再び関連づけられない
4. 解除したイベントを確認し、解除を取り消す。関連づけが回復し、地域詳細とイベント詳細に再び表示される
5. 関連づけ・解除・解除の取り消しは、店舗の地域所属、イベント参加、店舗・掲載の公開状態・提供状態に影響しない

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 解除するまでの間に、イベントの運営者が関連づけを外していた。関連づけがないことが示される | 関連づけられたイベントの確認に戻る |
| リソース不在 | 関連づけられたイベントがない。ないことが示される | 地域の管理に戻る |
| 操作の取り消し | 解除を元に戻したい | 解除を取り消す。取り消した後に、再び解除できる |

## REG-12 地域を登録・公開し、地域運営者に管理権限を付与する

- 利用者: サービス運営者
- 契約: O-10、P-50、R-14、M-37、P-70（25・27 行）、P-99、B-51、B-53、X-05、AC-16、AC-68
- 前提: ログインしている。地域の登録の依頼と、運営を希望する連絡は、サービス外で受けている

### 流れ

1. 地域の登録を始め、名称・所在地・位置・写真・紹介・キャッチコピーを入力する。写真を登録するときは、登録のたびに同意を確認する
2. 保存する。地域は下書きとして登録される。すぐに公開するときは、保存してそのまま手順3へ進む。後で公開するときは、地域を開いて公開する（REG-07）
3. 公開する。名称・所在地・位置・写真がそろっていれば公開される。地域運営者がいなくても公開できる
4. 地域運営者にする利用者を、既存のアカウントのメールアドレスで指定して、管理権限を付与する。承認は要らない。付与は公開の前でも後でもできる
5. 付与された利用者は、地域運営者として REG-06〜REG-11 と MEM-01〜MEM-04 を行える
6. 地域運営者が就くまでは、サービス運営者が地域の運営者として地域を管理する（REG-13）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー（R-14） | 名称・所在地・位置・写真のいずれかが欠けている。不足する項目が示され、公開できない。下書きとしては保存できる | 不足を埋めてから公開する |
| リソース不在 | 指定したメールアドレスのアカウントがない。付与できないことが示される | メールアドレスを確かめて指定し直す。相手にアカウントがなければ、アカウントができてから付与する |
| リソース不在 | 指定した利用者が、すでにその地域の地域運営者になっている。そのことが示される | 付与をやめる |
| 操作の取り消し | 保存せずに登録をやめた。地域は登録されない | サービス運営の入口に戻る |
| 操作の取り消し | 公開または付与を元に戻したい | 公開は、地域運営者が就く前なら REG-07 で取り下げる。就いた後は地域運営者が取り下げ、閲覧できなくするには MOD-07 による。付与した管理権限は MEM-05 で解除する |

## REG-13 運営者が不在の地域を、地域の運営者として引き受ける

- 利用者: サービス運営者
- 契約: R-11、R-13、R-15、O-11、O-20、P-70（12〜14・20・26 行）、P-92、P-94、B-14、B-31、I-16、AC-16、AC-67
- 前提: ログインしている

### 流れ

1. 地域運営者がいない地域では、サービス運営者が地域の運営者になる。地域運営者がいないのは、管理権限が付与されていない地域と、最後の地域運営者が辞任・解除・退会した地域（[index.md](index.md) の「管理者不在」）
2. サービス運営者は、地域の運営者宛ての通知（[index.md](index.md) の「不在の対象への通知」）から、申請の判断（REG-09）、または地域の運営（REG-06〜REG-11）へ進む。通知によらず、地域をキーワードで探し（[index.md](index.md) の「探し方」）、結果で地域運営者がいないことを確かめて、結果から運営へ進むこともできる
3. 地域は、地域運営者が不在の間も公開を継続する
4. REG-12 で管理権限を付与すると、以後は地域運営者が地域の運営者になり、サービス運営者は地域の運営者でなくなる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 開いた地域に地域運営者がいる。サービス運営者は地域の運営者ではなく、REG-06〜REG-11 の操作は共通の規則の権限不足による | 地域運営者に任せる |
