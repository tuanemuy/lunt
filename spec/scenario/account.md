# アカウントと通知

ログインしてアカウントを持ち、自分に届いた通知を確認し、退会する。

## 共通の規則

- 閲覧、保存、取り下げの申立てにログインは要らない。申請、管理操作、情報の誤り・閉店の連絡、通知の確認、退会にはログインが要る
- ログインが必要な操作をログインせずに始めると、ログインへ案内され、ログイン後に元の操作へ戻る
- アカウントはメールアドレスを必ず持つ。メールアドレスは通知の宛先と、管理メンバーの招待の宛先になる
- ログインにパスワードを使わない。初めてログインした時点でアカウントが作られる
- ログインの方法にかかわらず、同じメールアドレスは同じアカウントを指す
- ログインが成立すると、ログインが成立したブラウザの端末の保存がアカウントの保存に合流する（KEP-04）

## ACC-01 メールアドレスでログインする

- 利用者: 閲覧者
- 契約: V-51、P-33、B-18、B-40、I-18、AC-20、AC-42

### 流れ

1. 閲覧者は、ログインの入口、保存一覧の案内、またはログインが必要な操作からログインへ進む
2. メールアドレスを入力して送る
3. そのメールアドレスに、ワンタイムのリンクとワンタイムのコードの両方を載せたログイン用のメールが届く
4. メールアドレスを入力したブラウザでコードを入力すると、そのブラウザでログインが成立する。リンクを開くと、開いたブラウザでログインが成立する。パスワードは求められない。一方を使うと他方は無効になる。リンクとコードには有効期間があり、コードの誤入力が上限の回数に達すると、リンクとコードの両方が無効になる（I-18）
5. そのメールアドレスのアカウントがなければ、このときに作られる
6. ログインが成立したブラウザで、元の操作へ戻る。ログインの入口から始めた場合は、始めた場面へ戻る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | メールアドレスの形式が正しくない。メールは送られず、誤りが示される | 直して送り直す |
| 入力エラー | メールアドレスを誤って送った、またはメールが届かない | メールアドレスを確かめて送り直す。または外部アカウントでログインする（ACC-02） |
| 入力エラー | 入力したコードが正しくない。ログインは成立せず、誤りが示される | 誤入力が上限の回数に達するまでは、メールのコードを確かめて入力し直す |
| 入力エラー（I-18） | コードの誤入力が上限の回数に達した。リンクとコードの両方が無効になったことが示され、ログインは成立しない | メールアドレスの入力からやり直し、新しいメールのリンクまたはコードを使う |
| 契約（V-51、I-18） | リンクまたはコードが、有効期間を過ぎているか、一方の使用または誤入力の上限で無効になっている。無効であることが示され、ログインは成立しない | メールアドレスの入力からやり直す |
| 契約（V-38） | 通信エラーでメールの送信または確認が成立しない | 再試行する |
| 操作の取り消し | リンクを開かず、コードも入力せずにやめる。ログインは成立せず、アカウントも作られない | ログインせずに閲覧と保存を続ける。またはあらためてログインする |

## ACC-02 外部アカウントでログインする

- 利用者: 閲覧者
- 契約: V-51、P-33、B-18、B-40、AC-20、AC-42

### 流れ

1. 閲覧者は ACC-01 と同じ入口からログインへ進み、外部アカウントでのログインを選ぶ
2. 外部アカウントの提供元で認証し、Lunt にメールアドレスを渡すことを認める。Lunt は、提供元が確認済みとしたメールアドレスだけを受け取る
3. Lunt に戻り、ログインが成立する。Lunt はパスワードを求めない
4. 外部アカウントのメールアドレスのアカウントがなければ、このときに作られる。すでにあれば、そのアカウントにログインする
5. 元の操作へ戻る。ログインの入口から始めた場合は、始めた場面へ戻る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（P-33、B-40） | 外部アカウントから確認済みのメールアドレスを受け取れない（メールアドレスがない、または提供元で確認済みでない）。ログインは成立せず、アカウントも作られない。確認済みのメールアドレスが必要であることが示される | メールアドレスでログインする（ACC-01）。または別の外部アカウントでログインする |
| 契約（V-38） | 通信エラー、または提供元の障害で認証が成立しない | 再試行する。またはメールアドレスでログインする（ACC-01） |
| 操作の取り消し | 提供元での認証、またはメールアドレスを渡すことの承認をやめる。ログインは成立しない | ログインせずに閲覧と保存を続ける。またはあらためてログインする |

## ACC-03 通知を確認する

- 利用者: 利用者
- 契約: B-39、P-33、P-90〜P-100、I-05、AC-41
- 前提: ログインしている

### 流れ

1. 通知する出来事が起きると、当事者のメールアドレスにメールが届き、同じ通知がサービス内の通知一覧に加わる
2. 利用者は通知一覧を開く。メールから Lunt を開いてもよい。通知は新しい順に並ぶ。通知がなければ、通知がないことが示される
3. 通知ごとに、起きた出来事とその対象を確認する
4. 通知から、その出来事に応じた操作へ進む（下の表）

複数の管理権限と役割を持つ利用者の通知は、1つの通知一覧に届く。宛先が店舗管理者・地域の運営者・イベントの運営者・編集担当者・サービス運営者の通知は、その対象のその立場にある全員に届く。管理者・運営者が不在の対象への通知の宛先と、サービス運営者が通知から進む先は、[index.md](index.md) の「不在の対象への通知」が定める。店舗管理者として行った申請の申請者宛ての通知の宛先は、`application.md` の共通の規則が定める。

| 宛先 | 出来事 | 通知から進む操作 |
| --- | --- | --- |
| 申請者 | 申請の差し戻し | 修正して再提出する（APP-02）。または取り下げる（APP-03） |
| 申請者 | 申請の承認 | 結果を確認する（APP-01） |
| 申請者 | 申請の否認 | 理由を確認する（APP-01）。再申請する（APP-04） |
| 申請者 | 申請の失効（イベントの終了のように、日付で起きる失効を含む） | 失効を確認する（APP-05） |
| 承認者 | 新しい申請、差し戻した申請の再提出 | 申請を判断する（APP-07） |
| 承認者 | 申請の取り下げ | 確認だけ行う。その申請の判断は要らなくなる |
| 店舗管理者 | 地域からの除外 | 所属関係の変更結果を確認する（REG-05） |
| 店舗管理者 | イベントからの除外 | 店舗のイベントの状況で、参加の解除を確認する。再び参加するには申請する（EVT-01） |
| 店舗管理者 | 参加するイベントの中止、開催期間の変更 | イベントの詳細を確認する（EXP-09）。参加日を変更する（EVT-02）。または参加を取りやめる（EVT-03） |
| 店舗管理者 | 店舗の非公開とその解除、運営による掲載の非公開とその解除 | 店舗は、店舗の状況を確認する（SHP-05）。掲載は、その掲載を開いて状態を確認し、必要なら内容を編集する（LST-06） |
| 店舗管理者 | 申立てによる店舗・掲載の写真の削除 | 写真を登録して再び公開する（MOD-03） |
| 店舗管理者 | 情報の誤り・閉店の連絡に基づく確認の依頼 | 店舗の情報を確認する（MOD-06） |
| 店舗管理者 | カテゴリーの廃止に伴う掲載の付け替え | 付け替え後のカテゴリーを確認する（LST-05）。変更する（LST-06） |
| 店舗管理者 | 申請の承認による店舗管理者の追加 | 管理メンバーを確認する（MEM-01） |
| 地域の運営者 | イベントからの開催地域の関連づけ | 関連づけを確認し、解除する（REG-11） |
| 地域の運営者 | 運営による地域の非公開とその解除 | 確認だけ行う |
| 地域の運営者 | 申立てによる地域の写真の削除 | 写真を登録して再び公開する（MOD-03） |
| イベントの運営者 | 参加の取りやめ、参加に添えた掲載・参加日の変更 | 参加店舗と変更内容を確認する（EVT-07） |
| イベントの運営者 | 開催地域の関連づけの解除 | 確認だけ行う。解除された地域には再び関連づけられない |
| イベントの運営者 | 運営によるイベントの非公開とその解除 | 確認だけ行う |
| イベントの運営者 | 申立てによるイベントの写真の削除 | 写真を登録して再び公開する（MOD-03） |
| 編集担当者 | 公開中の読みものが紹介する対象の変化: 非公開（掲載の一時非公開・運営による非公開、店舗の非公開、地域・イベントの運営による非公開）、公開の取り下げ、削除、店舗の閉店（店舗管理者の登録、申請の承認、サービス運営者の更新）、掲載の提供終了（店舗管理者の操作と、期日による自動の提供終了）、イベントの終了（開催期間による）・中止 | 紹介内容を修正する（EDT-06） |
| 編集担当者 | 申立てによる読みものの写真の削除 | 写真を登録して再び公開する（MOD-03） |
| サービス運営者 | 運営者が一定の期間確認していない申請 | 期間超過の代行として承認・否認する（APP-08） |
| サービス運営者 | 取り下げの申立て | 申立てに対応する（MOD-02） |
| サービス運営者 | 情報の誤り・閉店の連絡 | 連絡に対応する（MOD-05） |
| 招待された利用者 | 管理メンバーへの招待 | 招待を受けて管理者になる（MEM-03） |
| 権限を付与された利用者 | 地域・イベントの管理権限の付与、編集担当者への任命、サービス運営者の役割の付与 | 付与された対象の管理、読みものの編集、サービス運営を始める |
| 本人 | 管理権限の解除、編集担当者の任命の解除、サービス運営者の役割の解除 | 確認だけ行う。解除された操作は行えなくなっている |

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | ログインせずに、通知一覧またはメールからの行き先を開く。ログインへ案内される | ログインして、元の行き先へ戻る |
| 権限不足 | 通知を受けた後に、その対象の管理権限または役割を失っている。通知から進んだ先で、操作できないことが示される | 通知一覧に戻る |
| リソース不在 | 通知の対象が、非公開・公開の取り下げ・削除で閲覧できなくなっている。通知から進んだ先で、閲覧できないことが示される | 通知一覧に戻る |
| 契約（B-39） | メールが届かない、または見落とした | 通知一覧で同じ通知を確認する |
| 契約（B-39） | 招待された時点で、そのメールアドレスのアカウントがない。招待はメールで届く | そのメールアドレスでログインし、招待を受ける（MEM-03） |
| 契約（V-38） | 通知一覧の読み込み中に通信エラーが起きる | 再試行する |

## ACC-04 退会する

- 利用者: 利用者
- 契約: V-53、P-34、P-70（30）、P-76、P-77（b）、P-92、B-28、B-29、B-31、B-55、B-58、I-01、I-02、AC-66、AC-70、AC-76
- 前提: ログインしている

### 流れ

1. 利用者は退会へ進む
2. 退会で起きることが示される
   - アカウントの保存を失う
   - 店舗・地域・イベントの管理権限と、編集担当者・サービス運営者の役割を失う
   - 個人として行った確認中・差し戻し中の申請は取り下げになる
   - 店舗管理者として行った申請は取り下げにならず、その店舗の他の店舗管理者が引き続き扱う（P-76）
   - 自分が最後の管理者である店舗・地域・イベントは管理者不在になる。管理者不在になる対象と、その帰結（[index.md](index.md) の「管理者不在」）が示される
   - 公開済みの内容は残る
3. 管理を引き継ぐ利用者は、退会をやめて後任を招待し（MEM-02）、退会へ戻る。後任の承諾を待たずに退会できる。承諾前の招待は退会の後も有効で、後任は後から承諾して管理者になる（MEM-03）
4. 利用者は内容を確認して退会する
5. 退会が成立し、ログインしていない状態になる。アカウントはなくなり、通知は届かなくなる。端末の保存は合流で空になっているため、保存一覧は空になる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（V-53、B-58） | サービス運営者が自分1人だけである。退会できないことと、その理由が示される | 別の利用者にサービス運営者の役割を付与し（OPE-05）、その後に退会する |
| 契約（V-38） | 通信エラーで退会が成立しない。アカウントは変わらない | 再試行する |
| リソース不在 | 確認している間に、別の端末で退会が先に成立していた。確定すると、ログインしていない状態になり、退会の操作は行われない | 閲覧を続ける。再びログインすると、新しいアカウントとして始まる |
| 操作の取り消し | 確認の前にやめる。アカウントは変わらない | そのまま利用を続ける |
| 操作の取り消し | 退会が成立した後に取り消したい。退会は取り消せず、失った保存・管理権限・役割・申請は戻らない | 同じメールアドレスでログインすると、新しいアカウントになる。以前の保存・管理権限・役割は戻らない |
