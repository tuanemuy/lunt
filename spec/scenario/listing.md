# 掲載

店舗の商品・体験・景色・見どころを掲載として作成・公開・更新する操作と、管理者のいない店舗の掲載を申請・代理作成・管理する操作を定める。

## 共通の規則

- 商品・体験・景色・見どころは、同じ手順で掲載として登録する。掲載の種類はカテゴリーが兼ねる（M-15、B-24）
- 掲載は1つの店舗に紐づく。所在地と所属地域は店舗情報から表示し、掲載では入力しない（M-18）
- 公開する掲載には写真・名称・カテゴリーが要る。説明と、提供期間または開催日は任意。価格とキャッチコピーの入力欄はない（M-16、B-08）
- カテゴリーは、サービス運営者が提供するものから1つを選ぶ（M-17、P-18）
- 公開状態（下書き・公開・一時非公開・運営による非公開）と提供状態（提供開始前・提供中・提供終了）は別々に示される。提供開始前と、期日による提供終了は、日本時間の日付で自動で決まる（P-82、B-23）
- 公開中かつ提供中の掲載は、自動でフィードの対象になる。紹介の申し込みや選定の操作はない（B-07）
- 提供開始前・提供終了の掲載は、発見の場面に表示されず、参照の場面に状態を区別して表示される。場面の区分は `index.md` の「表示範囲」による（P-87、B-46）
- 掲載の申請と掲載の修正の申請の失効は、`index.md` の「申請の前提」による。前提は、その店舗に店舗管理者がいないことと、修正の申請では対象の掲載があること（P-77）
- 写真の登録のたびの同意と、その入力エラーは、`index.md` の「共通の規則 > 写真の登録と同意」が定める
- 掲載の操作にはログインが要る。ログインせずに始めた利用者はログインへ案内され、ログイン後に元の操作へ戻る（B-18）
- 店舗管理者が操作できるのは、管理権限を持つ店舗の掲載だけ。権限のない店舗の掲載には操作の入口が示されず、直接たどり着いても操作できないことが示される。操作の途中で管理権限を失った場合も、保存・公開・削除はできないことが示される
- 同じ掲載を別の管理者が先に保存していた場合、保存しようとすると競合が示される。最新の内容を読み直して操作し直す
- 運営による非公開の掲載に行える操作と、解除の後の公開状態は、`index.md` の「共通の規則 > 運営による非公開」が定める。止まるのは公開・一時非公開・再公開だけで、編集・複製・削除は行える
- サービス運営者が行う LST-14〜LST-16 の入口と、サービス運営者でない利用者がたどり着いたときの扱いは、`index.md` の「共通の規則 > サービス運営者の操作」が定める
- 店舗が非公開の間も、その店舗の掲載は通常どおり操作できる。店舗の非公開が解除されるまで、閲覧者には表示されない（M-44、MOD-08）
- 削除された掲載を開くと、存在しないことが示され、掲載の一覧へ戻れる
- 複数の店舗を管理する店舗管理者は、店舗を選んでから掲載の操作を始める（M-28、SHP-05）

## LST-01 掲載を作成し、下書きを保存する

- 利用者: 店舗管理者
- 契約: M-15、M-16、M-17、M-18、M-21、B-24、P-18、UC-10、AC-10、AC-49、AC-59、AC-72

### 流れ

1. 店舗管理者は、管理する店舗の掲載の管理から、掲載の作成を始める
2. 名称と説明を入力し、カテゴリーを1つ選ぶ。写真は LST-02、提供期間または開催日は LST-03 の操作で設定する
3. 紐づく店舗と、店舗情報から引いた所在地・所属地域が示される
4. 下書きとして保存する。下書きの保存に要るのは店舗への紐づけだけで、ほかの項目は空でも保存できる。写真・名称・カテゴリーは、公開のときに公開条件として確かめられる
5. 保存した掲載は、下書きとして掲載の一覧に現れる（LST-05）。閲覧者には表示されない
6. 後から下書きを開いて編集を続け、公開へ進む（LST-04）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 入力した項目の内容に誤りがあり、保存できない。誤りのある項目が示される | 項目を直して保存し直す |
| リソース不在 | 選んだカテゴリーが保存までに廃止され、保存できない | 提供中のカテゴリーから選び直して保存する |
| 操作の取り消し | 保存せずに作成をやめる。入力した内容は残らない | 必要なら作成を最初から始める |
| 操作の取り消し | 保存した下書きが不要になる | 下書きを削除する（LST-10） |

## LST-02 写真を登録し、並び替え、見せる範囲を調整する

- 利用者: 店舗管理者
- 契約: M-19、M-37、M-41、B-41、B-53、D-03、I-06、AC-31、AC-38、AC-44
- 前提: 掲載を作成または編集している

### 流れ

1. 写真を選んで登録する。登録のたびに同意を確認し、同意すると写真が掲載に加わる
2. 写真は複数登録できる。並び替えると、1枚目が一覧に表示される代表写真になる
3. 写真ごとに、閲覧者に見せる範囲を調整する。一覧のカードと掲載詳細での見え方は、公開前の確認で確かめる（LST-04）
4. 登録した写真は、別の写真に差し替えるか、掲載から外せる
5. 掲載を保存すると、写真の登録・並び順・見せる範囲が反映される。公開中の掲載では、保存した時点で閲覧者への表示に反映される（M-32）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-16） | 公開中の掲載の写真をすべて外して保存しようとした。公開条件を欠くため保存できない | 写真を1枚以上残して保存する。写真のない状態にするなら、先に一時非公開にする（LST-07） |
| 操作の取り消し | 並び替えや範囲の調整を保存せずにやめる。写真は保存済みの状態のまま | 必要なら調整し直して保存する |

## LST-03 提供期間または開催日を設定する

- 利用者: 店舗管理者
- 契約: M-16、M-29、M-30、M-31、M-42、B-23、AC-24、AC-35、AC-47
- 前提: 掲載を作成または編集している

### 流れ

1. 提供の設定を「設定しない」「提供期間」「開催日」から1つ選ぶ。選べるのは1つだけで、切り替えると前の設定は残らない
2. 提供期間は、開始日と終了日の両方、開始日だけ、終了日だけのどれでも設定できる。開始日より前は提供開始前、終了日を過ぎると自動で提供終了になる。提供開始前の掲載は、詳細を閲覧でき、開始日を確認できる。発見の場面には表示されない
3. 開催日は複数登録でき、追加と削除ができる。時刻・定員・予約の項目はなく、必要な案内は説明に書く。開催日を登録した掲載は、最初の開催日より前から提供中で、最後の開催日を過ぎると自動で提供終了になる
4. 「設定しない」を選んだ掲載は提供中で、店舗管理者が提供終了にする（LST-08）
5. 提供状態は、提供期間、開催日、店舗管理者による提供終了（LST-08）と、今日の日付から決まる。自動で提供終了になった掲載は、提供期間を更新するか、開催日を追加すると、日付に応じて提供中に戻る。「設定しない」に切り替えた場合も提供中に戻る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 終了日が開始日より前になっている。保存できない | 日付を直して保存する |
| 入力エラー | 「提供期間」を選んで開始日も終了日も入力していない、または「開催日」を選んで開催日を1つも登録していない。保存できない | 日付を入力するか、「設定しない」を選んで保存する |
| 契約（M-29、M-42） | 終了日または最後の開催日が今日より前の内容で保存した。掲載は提供終了になる | 提供中にするなら、提供期間を更新する、開催日を追加する、または「設定しない」に切り替える |
| 操作の取り消し | 設定を保存せずにやめる。提供の設定は保存済みの状態のまま | 必要なら設定し直して保存する |
| 操作の取り消し | 保存した切り替えを戻したい。切り替える前の提供期間・開催日は残っていない | 元の設定を選び、日付を入力し直して保存する |

## LST-04 公開前に見え方を確認して公開する

- 利用者: 店舗管理者
- 契約: M-16、M-20、M-23、B-07、B-08、D-03、UC-10、AC-10、AC-35、AC-38、AC-58
- 前提: 下書きの掲載がある

### 流れ

1. 下書きの掲載から、公開前の確認を開く
2. 一覧のカードでの見え方と、掲載詳細での見え方を、閲覧者向けと同じ表現で確認する。確認は公開の必須手順ではなく、確認せずに手順4へ進める。写真の見せる範囲、名称、店舗名、地域名、カテゴリー、説明、提供期間または開催日が示される。価格とキャッチコピーは示されない
3. 直したい点があれば編集に戻る
4. 公開する。写真・名称・カテゴリーが揃っていれば、掲載は公開になる。承認は要らない
5. 公開した掲載は、提供中であれば自動でフィードの対象になる。提供開始前であれば、参照の場面にだけ表示される
6. 店舗管理者は、閲覧者向けの掲載詳細と店舗詳細を開き、公開した掲載と店舗の公開内容を確認する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-16、B-08） | 写真・名称・カテゴリーのいずれかが欠けている。公開できず、不足している項目が示される | 不足を補って公開する。後で補うなら下書きのまま保存する |
| 契約（M-44） | 店舗が非公開になっている。掲載は公開にできるが、店舗の非公開が解除されるまで閲覧者には表示されない | 店舗の非公開の解除を待つ |
| 操作の取り消し | 確認だけを行い、公開しない。掲載は下書きのまま | 後から公開する |
| 操作の取り消し | 公開した掲載を閲覧者から見えない状態に戻す | 一時非公開にする（LST-07） |

## LST-05 店舗の掲載を状態別に確認する

- 利用者: 店舗管理者
- 契約: M-08、M-09、M-23、M-28、P-82、AC-37、AC-58

### 流れ

1. 店舗管理者は、管理する店舗の掲載の一覧を開く
2. 公開中・下書き・非公開（一時非公開、運営による非公開）の掲載と、提供終了した掲載を区別して確認する。提供開始前の掲載もそれと分かる
3. 掲載を選び、編集（LST-06）、一時非公開と再公開（LST-07）、提供終了と提供中への復帰（LST-08）、複製（LST-09）、削除（LST-10）へ進む
4. 公開中の掲載からは、閲覧者向けの掲載詳細を開いて公開内容を確認できる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 店舗に掲載が1件もない。掲載がないことが示される | 掲載を作成する（LST-01） |
| リソース不在 | 選んだ状態に当てはまる掲載がない。当てはまる掲載がないことが示される | 別の状態の掲載を確認する |

## LST-06 公開中の掲載を編集する

- 利用者: 店舗管理者
- 契約: M-17、M-19、M-22、M-32、AC-27、AC-58

### 流れ

1. 掲載の一覧から公開中の掲載を開く
2. 名称、説明、カテゴリー、写真（LST-02）、提供期間または開催日（LST-03）を変更する
3. 保存する。承認は要らず、保存した時点で公開内容に反映される
4. 閲覧者向けの掲載詳細を開き、反映された内容を確認する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-16） | 写真・名称・カテゴリーのいずれかを欠く内容で保存しようとした。保存できない | 不足を補って保存する |
| 入力エラー | 入力した内容に誤りがあり、保存できない。誤りのある項目が示される | 項目を直して保存し直す |
| 契約（M-43） | 編集している間に、掲載が運営による非公開になった。編集は保存できるが、閲覧者には表示されない | 解除を待つ。解除されると、公開に戻る |
| リソース不在 | 編集している間に、別の店舗管理者が掲載を削除した。保存できない | 掲載の一覧へ戻る。必要なら掲載を作り直す（LST-01） |
| 操作の取り消し | 保存せずに編集をやめる。公開内容は変わらない | なし |
| 操作の取り消し | 保存した変更を戻したい。保存前の内容へ戻す操作はない | もう一度編集して保存する |

## LST-07 掲載を一時非公開にし、再公開する

- 利用者: 店舗管理者
- 契約: M-22、M-33、M-43、M-49、P-82、P-88、AC-58、AC-64、AC-79

### 流れ

1. 公開中の掲載を一時非公開にする
2. 掲載は、発見の場面にも参照の場面にも表示されなくなる。保存している閲覧者と、読みものからたどった閲覧者には、閲覧できないことが示される。公開中の読みものが紹介している掲載であれば、編集担当者に一時非公開が通知される
3. 一時非公開の掲載は、掲載の一覧に非公開として残り、編集できる
4. 再公開する。写真・名称・カテゴリーが揃っていれば、掲載は公開に戻る。提供状態は、一時非公開の間も日付と店舗管理者の操作に従って決まり、再公開の時点の状態で表示される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-43） | 運営による非公開の掲載を、一時非公開にしようとした、または再公開しようとした。どちらもできず、サービス運営者だけが解除できることが示される | 解除を待つ。解除されると、運営による非公開にする前の公開状態に戻る。編集・複製・削除は解除の前でもできる |
| 契約（M-49） | 申立てで写真が削除され、掲載が一時非公開になっている。写真がないため再公開できない | 写真を登録して再公開する（MOD-03） |
| 契約（M-16） | 一時非公開の間の編集で、公開条件を欠いている。再公開できず、不足している項目が示される | 不足を補って再公開する |
| 操作の取り消し | 一時非公開にした掲載を元に戻す | 再公開する |

## LST-08 掲載を提供終了にし、提供中に戻す

- 利用者: 店舗管理者
- 契約: M-22、M-24、M-29、M-31、B-23、P-87、P-96、AC-14、AC-24、AC-47、AC-58

### 流れ

1. 公開中の掲載を提供終了にする。提供期間も開催日も設定していない掲載は、この操作だけで提供終了になる
2. 提供終了した掲載は、掲載詳細で終了を知らせ、店舗と別の掲載へ案内する。発見の場面には表示されず、参照の場面に提供終了と分かる形で表示される
3. 公開中の読みものが紹介している掲載であれば、編集担当者に提供終了が通知される
4. 店舗管理者が提供終了にした掲載は、提供中に戻せる。戻すと、再びフィードの対象になる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-31） | 終了日または最後の開催日を過ぎて自動で提供終了になった掲載を、提供中に戻したい。提供中に戻す操作は使えない | 提供期間を更新する、開催日を追加する、または提供の設定を「設定しない」に切り替える（LST-03） |
| 契約（M-29、M-42） | 店舗管理者が提供終了にした掲載を戻そうとしたが、終了日または最後の開催日をすでに過ぎている。戻しても提供終了のまま | 提供期間を更新する、開催日を追加する、または提供の設定を「設定しない」に切り替える（LST-03） |
| 操作の取り消し | 誤って提供終了にした | 提供中に戻す |

## LST-09 掲載を複製して作成する

- 利用者: 店舗管理者
- 契約: M-22、AC-58

### 流れ

1. 掲載の一覧から元にする掲載を選び、複製する。公開状態と提供状態を問わず複製でき、運営による非公開の掲載も複製できる
2. 新しい下書きが、同じ店舗の掲載として作られる。運営による非公開の掲載の複製も、運営による非公開ではない下書きになる。名称・説明・カテゴリー・写真（並び順と見せる範囲を含む）を引き継ぐ。提供期間と開催日は引き継がない。元の掲載は変わらない
3. 下書きを編集し（LST-01〜LST-03）、見え方を確認して公開する（LST-04）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 複製しようとした掲載が、別の店舗管理者に削除されている。複製できない | 掲載の一覧へ戻る。別の掲載を複製するか、新しく作成する（LST-01） |
| 操作の取り消し | 複製でできた下書きが不要になる | 下書きを削除する（LST-10） |

## LST-10 掲載を削除する

- 利用者: 店舗管理者
- 契約: M-33、M-36、B-27、P-96、AC-27

### 流れ

1. 掲載の一覧から掲載を選び、削除を始める。公開状態と提供状態を問わず削除できる
2. 削除した掲載は復元できないことが示される。確認して削除する
3. 掲載は一覧から消え、発見の場面にも参照の場面にも表示されなくなる。保存している閲覧者と、読みものからたどった閲覧者には、閲覧できないことが示される
4. 公開中の読みものが紹介している掲載であれば、編集担当者に削除が通知される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 操作の取り消し | 確認の段階で削除をやめる。掲載は変わらない | なし |
| 操作の取り消し | 削除した掲載を戻したい。復元できない | 掲載を新しく作成する（LST-01） |
| リソース不在 | 別の店舗管理者が先に削除している。存在しないことが示される | 掲載の一覧へ戻る |

## LST-11 管理権限を取得した店舗の既存の掲載を管理する

- 利用者: 店舗管理者
- 契約: M-36、M-43、M-49、B-31、B-34、P-77、AC-30、AC-64、AC-66、AC-79
- 前提: 管理者のいなかった店舗の管理権限を、申請の承認（SHP-04）または招待の承諾（MEM-03）で得ている

### 流れ

1. 店舗管理者は、管理権限を得た店舗の掲載の一覧を開く。代理作成や申請で公開された掲載を含む、その店舗のすべての掲載が並ぶ
2. どの掲載も、自分で作成した掲載と同じ操作で編集・一時非公開・提供終了・複製・削除できる（LST-06〜LST-10）
3. 運営による非公開の掲載は、その状態が示される。編集・複製・削除はできるが、公開状態は変えられない
4. 店舗管理者が就いた時点で、その店舗への利用者による確認中・差し戻し中の掲載の申請と掲載の修正の申請は、前提を失って失効し、申請者に通知される（APP-05）

### 異常系

| --- | --- | --- |
| 契約（M-43） | 運営による非公開の掲載を再公開しようとした。管理権限を後から得た店舗管理者も再公開できない | 解除を待つ |
| 契約（M-49） | 申立てで写真が削除され、一時非公開になっている掲載がある | 写真を登録して再公開する（MOD-03） |
| リソース不在 | 店舗に掲載が1件もない | 掲載を作成する（LST-01） |
| 契約（B-31） | 最後の店舗管理者が権限を手放した。下書きを含むすべての掲載がサービス運営者の管理下に入る | 再び管理するには、管理権限を申請する（SHP-04） |

## LST-12 管理者のいない店舗の掲載を申請する

- 利用者: 利用者
- 契約: M-26、M-19、M-20、M-27、M-37、B-17、B-20、P-70、P-75、P-77、UC-15、AC-19、AC-31、AC-66
- 前提: 対象の店舗に店舗管理者がいない

### 流れ

1. 利用者は、店名・住所で対象の店舗を確認する（SHP-02）。閲覧中の店舗詳細から始めてもよい
2. 店舗管理者のいない店舗の詳細から、掲載の申請を始める。ログインしていなければログインへ案内され、ログイン後に戻る
3. 写真を登録し、並び替え、見せる範囲を調整する（LST-02 と同じ操作）。名称を入力し、カテゴリーを選ぶ。説明は任意で入力する。提供の設定は「設定しない」「提供期間」「開催日」から1つ選ぶ（LST-03 と同じ規則）。価格とキャッチコピーの入力欄はない
4. 提出の前に、一覧のカードと掲載詳細での閲覧者への見え方を確かめられる（LST-04 と同じ表現）。確認は必須ではなく、確認から公開はできない。確認を終えると入力に戻る
5. 申請を提出する
6. 申請は確認中になり、サービス運営者に通知される。確認状況と結果の確認、差し戻しへの再提出、取り下げ、再申請は APP-01〜APP-04 による
7. 承認されると掲載が公開され、申請者に通知される。掲載はサービス運営者の管理下に入り、申請者は掲載の管理権限を得ない。公開後に直したい点があれば、修正を申請する（LST-13）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-26、B-20） | 店舗管理者のいる店舗である。掲載の申請の入口は示されず、直接たどり着いても受け付けないことが示される | 店舗の関係者であれば、管理権限を申請する（SHP-04） |
| 契約（M-27） | 写真・名称・カテゴリーのいずれかが欠けている。提出できず、不足している項目が示される | 不足を補って提出する |
| リソース不在 | 対象の店舗が Lunt に登録されていない | 店舗の登録を申請する（SHP-03）。店舗の公開後に掲載を申請する |
| 契約（P-77） | 確認中または差し戻し中に、申請の前提を失った（その店舗に店舗管理者が就いた）。申請は失効し、通知が届く | 失効を確認する（APP-05） |
| 操作の取り消し | 提出せずに申請をやめる。入力した内容は残らず、申請は送られない | 必要なら申請を最初から始める |
| 操作の取り消し | 提出した申請をやめる | 申請を取り下げる（APP-03） |

## LST-13 管理者のいない店舗の掲載の修正を申請する

- 利用者: 利用者
- 契約: M-35、M-19、M-20、M-27、M-37、B-20、P-70、P-75、P-77、AC-19、AC-31、AC-66
- 前提: 対象の店舗に店舗管理者がいない。対象の掲載が公開されている

### 流れ

1. 利用者は、店舗管理者のいない店舗の公開された掲載の詳細から、修正の申請を始める。ログインしていなければログインへ案内され、ログイン後に戻る
2. 掲載の現在の内容が示される。直したい項目（名称、説明、カテゴリー、写真、提供の設定）を修正する。申請は、変更した項目だけを持つ。提供の設定は「設定しない」「提供期間」「開催日」から1つ選ぶ（LST-03 と同じ規則）。写真は、加える・外す・並び替える・見せる範囲を調整する、のどれもできる（LST-02 と同じ操作）
3. 提出の前に、修正を反映した掲載の、一覧のカードと掲載詳細での閲覧者への見え方を確かめられる（LST-04 と同じ表現）。確認は必須ではなく、確認から公開はできない。確認を終えると入力に戻る
4. 申請を提出する。申請は確認中になり、サービス運営者に通知される。確認状況と結果の確認、差し戻しへの再提出、取り下げ、再申請は APP-01〜APP-04 による
5. 承認されると、変更した項目だけが掲載のその時点の内容に反映され、申請者に通知される。変更していない項目は、承認の時点の掲載の内容のまま

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-35、B-20） | 店舗管理者のいる店舗の掲載である。修正の申請は受け付けず、情報の誤りの連絡が案内される | サービス運営者に連絡する（MOD-04） |
| 契約（M-27、M-16） | 変更した項目が公開条件を欠く（写真をすべて外した、名称を空にした）。提出できない | 内容を直して提出する |
| 入力エラー | 現在の内容から何も変えていない。提出できない | 直したい項目を修正して提出する |
| 契約（P-74） | 同じ掲載への自分の修正の申請が、確認中または差し戻し中である。重ねて申請できない | 差し戻し中なら修正して再提出する（APP-02）。内容を変えるなら、取り下げてから申請し直す（APP-03、APP-04） |
| リソース不在 | 申請を始める前、または入力している間に、掲載が非公開または削除になった。閲覧できないことが示される | 他の探索へ進む |
| 契約（P-77） | 確認中または差し戻し中に、申請の前提を失った（対象の掲載が削除された、その店舗に店舗管理者が就いた）。申請は失効し、通知が届く | 失効を確認する（APP-05） |
| 操作の取り消し | 提出せずに申請をやめる。申請は送られない | なし |
| 操作の取り消し | 提出した申請をやめる | 申請を取り下げる（APP-03） |

## LST-14 掲載の申請と修正の申請を判断する

- 利用者: サービス運営者
- 契約: M-38、O-14、M-27、P-71、P-75、P-77、B-17、B-42、AC-19、AC-31、AC-66、AC-72

### 流れ

1. サービス運営者は、対応が必要な申請（OPE-01）または通知から、掲載の申請か掲載の修正の申請を開く
2. 掲載の申請では、対象の店舗、名称、説明、カテゴリー、写真、提供期間または開催日、申請者を確認する。修正の申請では、変更する項目について、掲載の現在の値と申請の値を見比べる
3. 内容と写真の品質を確認する
4. 承認・否認・差し戻しの操作は APP-07 による。自分が行った申請も判断できる
5. 掲載の申請を承認すると、掲載が公開され、サービス運営者の管理下に入る。修正の申請を承認すると、変更する項目だけが掲載のその時点の内容に反映される。どちらも申請者に通知される
6. 申請の内容にあるカテゴリーが廃止された場合、そのカテゴリーは移行先に付け替えられて示される（OPE-03）
7. 別の申請者による同じ店舗・同じ掲載への申請は、1件ずつ独立して判断する。先に承認した修正が反映された後の申請は、その時点の掲載の値と見比べる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（P-77） | 判断の前に、申請が前提を失って失効した。失効と示され、判断できない。承認の操作も同じ前提を確かめ、前提を欠く申請は承認できない | なし |
| リソース不在 | 判断の前に申請者が申請を取り下げた。取り下げと示され、判断できない | なし |
| 契約（P-82） | 申請の対象の店舗が非公開、または修正の申請の対象の掲載が一時非公開・運営による非公開になっている。申請は失効しない。承認すると内容は反映されるが、閲覧者には表示されない | 承認・否認・差し戻しを判断する |
| 操作の取り消し | 承認した掲載に問題が見つかった。承認は取り消せない | 掲載を更新・一時非公開・削除する（LST-16） |
| 操作の取り消し | 誤って否認した。否認は取り消せない | 申請者の再申請を待つ（APP-04）。必要な掲載は代理で作成する（LST-15） |

## LST-15 管理者のいない店舗の掲載を代理で作成・公開する

- 利用者: サービス運営者
- 契約: M-25、M-27、M-37、O-13、B-17、B-31、P-70、AC-19、AC-31

### 流れ

1. サービス運営者は、店舗管理者のいない店舗を選び、掲載の作成を始める
2. 店舗管理者と同じ操作で、内容を入力し、写真を登録し、提供期間または開催日を設定し、下書きを保存する（LST-01〜LST-03）。写真の登録では、サービス運営者が登録のたびに同意を確認する
3. 公開前に見え方を確認して公開する（LST-04）。写真・名称・カテゴリーの公開条件は同じく適用される。承認は要らない
4. 公開した掲載は、サービス運営者の管理下に入る（LST-16）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-25） | 店舗管理者のいる店舗である。代理作成の入口は示されず、作成できない | なし。その店舗の掲載は店舗管理者が作成する |
| 契約（M-36） | 作成している間に、その店舗に店舗管理者が就いた。保存・公開できないことが示される。保存済みの下書きは店舗管理者の管理下に入る | なし |
| 契約（M-27） | 写真・名称・カテゴリーのいずれかが欠けている。公開できず、不足している項目が示される | 不足を補って公開する。後で補うなら下書きのまま保存する |
| リソース不在 | 対象の店舗が Lunt に登録されていない | 店舗を代理登録する（SHP-12） |
| 操作の取り消し | 公開した掲載を取りやめる | 一時非公開にするか、削除する（LST-16） |

## LST-16 管理者のいない店舗の掲載を更新・一時非公開・提供終了・削除する

- 利用者: サービス運営者
- 契約: M-35、M-49、O-15、B-31、B-34、P-77、I-03、AC-19、AC-30、AC-66、AC-79

### 流れ

1. サービス運営者は、店舗管理者のいない店舗を選び、その掲載の一覧を開く。代理作成した掲載、申請の承認で公開された掲載、店舗管理者が不在になった店舗の掲載（下書きを含む）が、状態別に並ぶ
2. 掲載を選び、店舗管理者と同じ操作で、更新（LST-06）、一時非公開と再公開（LST-07）、提供終了と提供中への復帰（LST-08）、削除（LST-10）を行う。承認は要らず、更新は保存した時点で公開内容に反映される
3. 掲載を削除すると、その掲載への確認中・差し戻し中の修正の申請は、前提を失って失効し、申請者に通知される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（B-34、M-36） | その店舗に店舗管理者が就いた。掲載は店舗管理者の管理下に入り、サービス運営者は更新・一時非公開・提供終了・削除できない | 閲覧できなくする必要がある掲載は、運営による非公開にする（MOD-07） |
| 契約（I-03） | 情報の誤りの連絡を受けた掲載を直したいが、店舗に店舗管理者が残っている。更新できない | 連絡への対応として、すべての店舗管理者の権限を解除してから更新する（MOD-05） |
| 契約（M-16） | 公開中の掲載を、公開条件を欠く内容で保存しようとした。保存できない | 不足を補って保存する |
| 契約（M-49） | 申立てで写真が削除され、掲載が一時非公開になっている | 写真を登録して再公開する（MOD-03） |
| 操作の取り消し | 削除した掲載を戻したい。復元できない | 掲載を代理で作成する（LST-15） |
