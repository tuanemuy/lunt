# サービス運営

サービス運営者が、対応が必要な申請・申立て・連絡を把握し、カテゴリーと、編集担当者・サービス運営者の役割を管理する。

## 共通の規則

- すべての操作は、サービス運営者の役割を持つアカウントでログインして行う。入口と、役割を持たない利用者の扱いは `index.md` の「共通の規則 > サービス運営者の操作」が、操作の途中で役割を解除された利用者の扱いは同じく「立場を失ったとき」が定める
- サービス運営者は全員が同じ操作範囲を持つ。どのサービス運営者が行っても結果は同じになる
- 同時編集の競合と、その異常系は、`index.md` の「共通の規則 > 同時編集の競合」が定める
- 役割の付与・任命の相手は、既存のアカウントをメールアドレスで指定する。アカウントがなければ付与・任命できない
- 役割の付与・任命・解除に相手の承諾は要らず、確定した時点で効く
- 通知は ACC-03 の表による
- 役割は対象ごとの管理権限から独立している。付与・任命・解除で、相手が持つ店舗・地域・イベントの管理権限と他の役割は変わらない（P-04）

## OPE-01 対応が必要な申請・申立て・連絡を確認する

- 利用者: サービス運営者
- 契約: O-01、O-02、O-03、O-11、O-12、O-14、O-21、O-24、P-70、P-78、P-92、P-97

### 流れ

1. サービス運営者は、サービス運営の入口から対応が必要なものを開く。対応が必要なものについての通知からも、該当のものを直接開ける（ACC-03）
2. 次の4種を区別して確認する
   - サービス運営者が承認者である確認中の申請: 店舗の新規登録（併せた管理権限の申請を含む）、管理者のいない店舗の情報修正と休業・閉店、店舗の管理権限取得、管理者のいない店舗の掲載とその修正、運営者が不在の地域への所属・離脱、運営者が不在のイベントへの参加
   - 期間超過の代行ができる申請: 地域運営者・イベント運営者が一定の期間確認していない、所属・離脱・参加の確認中の申請
   - 対応を終えていない取り下げの申立て
   - 対応を終えていない情報の誤り・閉店の連絡
3. それぞれについて、種類、対象、申請者（申立てでは申立人、連絡では連絡した利用者）を確認する
4. 1件を選んで内容を開き、種類に応じた対応へ進む

   | 種類 | 進む先 |
   | --- | --- |
   | 店舗の新規登録 | SHP-09 |
   | 店舗の管理権限取得 | SHP-10 |
   | 管理者のいない店舗の情報修正、休業・閉店 | SHP-11 |
   | 管理者のいない店舗の掲載、その修正 | LST-14 |
   | 運営者が不在の地域への所属・離脱 | REG-09（サービス運営者が地域の運営者として判断する） |
   | 運営者が不在のイベントへの参加 | EVT-08（サービス運営者がイベントの運営者として判断する） |
   | 運営者が一定の期間確認していない申請 | APP-08 |
   | 取り下げの申立て | MOD-02 |
   | 情報の誤り・閉店の連絡 | MOD-05 |

   承認・否認・差し戻しの共通の流れは APP-07 が定める
5. 承認・否認した申請、取り下げ・失効となった申請、対応を終えた申立て・連絡は、対応が必要なものから外れる。差し戻した申請は、申請者が再提出して確認中に戻るまで現れない

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 対応が必要なものが1件もない | ないことが示される。対応は不要 |
| リソース不在 | 選んだ申請が、申請者の取り下げ、失効、他のサービス運営者の判断によって、すでに確認中でない | 現在の状態が示され、判断はできない。対応が必要なものの確認に戻る |
| リソース不在 | 選んだ申立て・連絡を、他のサービス運営者がすでに対応し終えている | 対応済みであることが示される。対応が必要なものの確認に戻る |
| 契約（P-78） | 期間超過の代行ができる申請を開いた時点で、地域運営者・イベント運営者がすでに判断している | 判断の結果が示され、代行はできない。対応が必要なものの確認に戻る |

## OPE-02 カテゴリーを追加・変更する

- 利用者: サービス運営者
- 契約: O-06、P-18、B-24、B-45、AC-03、AC-49
- 前提: 開設時に「食べる」「買う」「体験」「見る」の4つのカテゴリーがある

### 流れ

1. サービス運営者は、カテゴリーの管理を開き、現役のカテゴリーを確認する。カテゴリーは1階層で、作成順に並ぶ
2. 追加する場合は、名称を入力して追加する。追加したカテゴリーは並びの最後に入り、掲載に設定するカテゴリーの選択肢と、閲覧者の絞り込みの選択肢に加わる
3. 変更する場合は、カテゴリーを選び、名称を書き換えて保存する。そのカテゴリーを設定している掲載は付け替えなしに新しい名称で表示され、絞り込みの選択肢も新しい名称になる。閲覧者が選択中の条件と、掲載の公開状態・提供状態は変わらない

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 名称を入力せずに追加・保存する | 追加・保存できず、名称が必要なことが示される。名称を入力してやり直す |
| 入力エラー | 他のカテゴリーと同じ名称で追加・保存する | 追加・保存できず、同じ名称のカテゴリーがあることが示される。別の名称にしてやり直す |
| リソース不在 | 変更しようとしたカテゴリーを、他のサービス運営者がすでに廃止している | 廃止済みであることが示される。カテゴリーの確認に戻る |
| 操作の取り消し | 追加・保存の前にやめる | 何も変わらない |
| 操作の取り消し | 追加・変更を確定した後に取り消したい | 変更は名称を書き換え直す。追加は OPE-03 で廃止する |

## OPE-03 カテゴリーを廃止し、掲載を移行先に付け替える

- 利用者: サービス運営者
- 契約: O-06、P-18、B-24、B-31、P-93、V-10、AC-72
- 前提: カテゴリーが2つ以上ある

### 流れ

1. サービス運営者は、カテゴリーの管理で廃止するカテゴリーを選ぶ
2. 移行先のカテゴリーを、廃止するカテゴリー以外から1つ選ぶ
3. 廃止するカテゴリーと移行先を確認して、廃止を確定する
4. 廃止したカテゴリーを持つ掲載の内容は、`listing.md` の「掲載の内容」の規則で移行先に付け替わる。掲載は公開状態・提供状態にかかわらず付け替わり、掲載の公開状態・提供状態は変わらない
5. 掲載の申請と掲載の修正の申請の内容にある廃止したカテゴリーは、同じ規則で移行先に読み替えられる。申請の状態は変わらない
6. 廃止したカテゴリーは、掲載に設定するカテゴリーの選択肢と、閲覧者の絞り込みの選択肢から消える。閲覧者が選択中の条件に廃止したカテゴリーがあれば、条件から外れる。付け替わった掲載は、移行先のカテゴリーで絞り込みに現れる
7. 付け替わった掲載のカテゴリーを別のものにしたい店舗管理者は、掲載ごとにカテゴリーを変更する（M-17）。管理者のいない店舗の掲載はサービス運営者が変更する（LST-16）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 移行先を選ばずに確定する。そのカテゴリーの掲載と申請が1件もない場合も同じ | 廃止できず、移行先が必要なことが示される。移行先を選んでやり直す |
| 契約（P-18） | カテゴリーが1つしかなく、移行先にできるカテゴリーがない。最後の1つは廃止できない | 廃止できないことが示される。OPE-02 で移行先にするカテゴリーを追加してからやり直す |
| リソース不在 | 廃止するカテゴリー、または選んだ移行先を、確定までの間に他のサービス運営者が廃止している | 廃止も付け替えも行われず、廃止済みであることが示される。カテゴリーの確認に戻り、必要なら移行先を選び直す |
| 操作の取り消し | 確定の前にやめる | 何も変わらない |
| 操作の取り消し | 確定の後に取り消したい | 廃止を取り消す操作はなく、付け替わった掲載は元のカテゴリーに戻らない。同じ名称のカテゴリーが必要なら OPE-02 で追加し（並びの最後に入る）、掲載のカテゴリーは掲載ごとに変更する |

## OPE-04 編集担当者を任命し、任命を解く

- 利用者: サービス運営者
- 契約: P-60、O-16、B-19、P-70、P-99、P-100、I-05、AC-75

### 流れ

任命する。

1. サービス運営者は、編集担当者の管理を開き、現在の編集担当者を確認する
2. 任命する利用者をメールアドレスで指定し、任命を確定する。自分自身も任命できる
3. 任命された利用者は編集担当者になる
4. 任命された利用者には読みもの編集の入口が示され、すべての読みものを作成・編集・公開できる（`editorial.md`）

任命を解く。

1. サービス運営者は、現在の編集担当者から1人を選び、任命を解くことを確認して確定する
2. 任命を解かれた利用者は、読みもの編集の入口が示されなくなり、読みものを作成・編集・公開できない
3. その利用者が作成した読みものは残り、公開状態は変わらない。他の編集担当者が引き続き編集する
4. 最後の1人の任命も解ける。編集担当者がいない間、読みものは公開状態のまま残り、紹介先の変化の通知は誰にも届かない。読みものを扱うには、サービス運営者が自分自身か別の利用者を任命する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | メールアドレスの形式が正しくない | 任命できず、誤りが示される。直してやり直す |
| 入力エラー | 指定した利用者がすでに編集担当者である | すでに編集担当者であることが示され、何も変わらない |
| リソース不在 | 指定したメールアドレスのアカウントがない | 任命できず、該当する利用者がいないことが示される。メールアドレスを確かめてやり直すか、相手がアカウントを作成した後にやり直す |
| リソース不在 | 任命を解こうとした利用者が、すでに任命を解かれているか退会している | 編集担当者でないことが示される。現在の編集担当者の確認に戻る |
| 操作の取り消し | 確定の前にやめる | 何も変わらない |
| 操作の取り消し | 確定の後に取り消したい | 任命は任命を解いて取り消す。解除は同じ利用者を任命し直す |

## OPE-05 サービス運営者の役割を付与し、解除する

- 利用者: サービス運営者
- 契約: O-23、B-58、V-53、P-70、P-99、P-100、AC-76
- 前提: 最初のサービス運営者は、サービスの開設時に設定されている

### 流れ

付与する。

1. サービス運営者は、サービス運営者の管理を開き、現在のサービス運営者を確認する
2. 付与する利用者をメールアドレスで指定し、付与を確定する
3. 付与された利用者はサービス運営者になる
4. 付与された利用者にはサービス運営の入口が示され、サービス運営者のすべての操作を行える

解除する。

1. サービス運営者は、現在のサービス運営者から1人を選び、解除することを確認して確定する。サービス運営者が2人以上いる間は、自分自身も選べる
2. 解除された利用者は、サービス運営の入口が示されなくなり、サービス運営者の操作を行えない
3. サービス運営者が承認者である申請、申立て、連絡は、残るサービス運営者が引き続き扱う

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（O-23、B-58） | サービス運営者が1人だけで、その役割を解除しようとする。確定の時点で1人だけになっている場合を含む | 解除できないことが示される。別の利用者に役割を付与してからやり直す |
| 契約（V-53） | サービス運営者が1人だけの間に、そのサービス運営者が退会しようとする | 退会できない（ACC-04）。別の利用者に役割を付与してから退会する |
| 入力エラー | メールアドレスの形式が正しくない | 付与できず、誤りが示される。直してやり直す |
| 入力エラー | 指定した利用者がすでにサービス運営者である | すでにサービス運営者であることが示され、何も変わらない |
| リソース不在 | 指定したメールアドレスのアカウントがない | 付与できず、該当する利用者がいないことが示される。メールアドレスを確かめてやり直すか、相手がアカウントを作成した後にやり直す |
| リソース不在 | 解除しようとした利用者が、すでに解除されているか退会している | サービス運営者でないことが示される。現在のサービス運営者の確認に戻る |
| 操作の取り消し | 確定の前にやめる | 何も変わらない |
| 操作の取り消し | 確定の後に取り消したい | 付与は解除して取り消す。解除は同じ利用者に付与し直す。自分自身を解除した場合は、残るサービス運営者に付与を依頼する |
