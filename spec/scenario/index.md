# シナリオ一覧

Lunt が提供する操作を、利用者の視点でカテゴリーごとに列挙する。詳細はカテゴリーごとのファイルが定める。

各シナリオの「契約」の行と本文が引く要求の番号（V・M・R・E・O・B・AC・UC・P・D・T・X・I）は、[要求台帳](../ledger.md) が定義する。

## 用語

| 語 | 意味 |
| --- | --- |
| 店舗 | 店舗・スポット（[shop.md](shop.md) の共通の規則） |
| 管理者のいない店舗 | 店舗管理者がいない店舗 |
| 未公開 | 地域・イベント・読みものの公開状態のうち、下書きと公開の取り下げ。どちらも閲覧者に表示されない |
| 辞任 | 管理者が自分の管理権限を手放すこと（MEM-04） |

## 利用者

| 利用者 | 説明 |
| --- | --- |
| 閲覧者 | 掲載や地域を探し、詳細・地図を確認し、保存する。ログインを必要としない |
| 利用者 | ログインしたアカウントの持ち主。申請者、連絡する人になる |
| 申立人 | 取り下げを申し立てる店舗本人または写真の権利者。ログインを必要としない |
| 店舗管理者 | 管理権限を持つ店舗の情報と掲載を管理する |
| 地域運営者 | 管理権限を持つ地域の情報と所属関係を管理する |
| イベント運営者 | 管理権限を持つイベントの情報と参加関係を管理する |
| 地域の運営者 | 地域の情報と所属関係を管理する立場。地域運営者のいる地域ではその地域運営者、地域運営者が不在の地域ではサービス運営者（P-70） |
| イベントの運営者 | イベントの情報と参加関係を管理する立場。イベント運営者のいるイベントではそのイベント運営者、イベント運営者が不在のイベントではサービス運営者（P-70） |
| 編集担当者 | 読みものを作成・編集・公開する |
| サービス運営者 | 申請の承認、代理登録、代行、非公開、役割の管理を行う |

代行は、サービス運営者が対象の管理者・運営者の代わりに行うことを指し、次の2つがある。

- 不在の代行: 管理者・運営者が不在の対象について、サービス運営者が行う（B-14、R-11、E-09）。地域・イベントでは、サービス運営者が地域の運営者・イベントの運営者になる。店舗では、管理者のいない店舗の更新（SHP-13）、掲載の代理作成と管理（LST-15、LST-16）、承諾前の招待の取り消し（MEM-02）に当たる
- 期間超過の代行: 地域運営者・イベント運営者が一定の期間確認しない申請を、サービス運営者が承認・否認する（APP-08。P-78、I-13）

運営者のいる地域・イベントでは、サービス運営者は地域の運営者・イベントの運営者ではない。サービス運営者として行う操作は、それぞれのシナリオが定める。

## 共通の規則

### 表示範囲

公開中の対象は、場面の種類に応じて表示する。各シナリオは、どちらの場面かだけを述べる。

| 場面 | 規則 | 当たる場面 |
| --- | --- | --- |
| 発見の場面 | 提供開始前・提供終了の掲載、閉店した店舗とその掲載、終了・中止したイベントを表示しない | フィード、絞り込みの結果、地図と地図の一覧、地域の一覧、地域内の一覧、イベントの一覧、地域詳細の店舗と掲載、掲載詳細の他の掲載、掲載・店舗・地域の詳細の関連するイベント |
| 参照の場面 | 提供開始前・提供終了の掲載、閉店した店舗とその掲載、終了・中止したイベントを、状態を区別して表示する | キーワード検索、既存店舗の確認、保存一覧、掲載詳細、店舗詳細（その店舗の掲載と地図を含む）、イベント詳細（参加店舗、添えた掲載、参加店舗の地図）、読みものからのリンク、入力の途中の対象の選択の候補 |

- 休業中の店舗とその掲載、開催前のイベントは、どちらの場面でも状態を区別して表示する
- 非公開・公開の取り下げ・削除の対象と、非公開の店舗の掲載は、どちらの場面にも表示しない
- 入力の途中の対象の選択では、候補の範囲を各シナリオが定める。範囲に入る対象を、参照の場面として状態を区別して示す。範囲に入らない対象（例: 参加の申請での終了・中止したイベント、直接の追加での管理者のいる店舗）は示さない。範囲に入り、その操作を受け付けない事情に当たる対象（例: すでに参加中のイベントや店舗、すでに所属中の地域、関連づけ済みの地域、地域の運営者が関連づけを解除した地域、結びつけ済みの紹介先）は、理由とともに選べない対象として示す。対象の詳細から始め、その対象が選ばれた状態で入力が始まる入口では、その対象が事情に当たると、そのことが示され、別の対象を選べる
- 現在地の周辺: 位置情報の利用を許可した閲覧者の現在地から、一定の距離（値は設定）の範囲。地図の初めの範囲（EXP-01）と地域の一覧（EXP-03）の周辺は、同じ範囲
- 地域の判定: 地域が選択エリアにあるかは、地域の所在地、または閲覧できる所属店舗の所在地が選択エリアにあるかで決まる（V-16）。現在地の周辺にあるかは、地域の位置、または閲覧できる所属店舗の位置が周辺にあるかで決まる。閲覧できる所属店舗は休業・閉店の店舗を含み、非公開の店舗を含まない。発見の場面で閉店した店舗を表示しないことは、この判定に効かない
- 地域の「現在地に近い順」: 地域の位置と、閲覧できる所属店舗の位置のうち、現在地に最も近いものまでの距離の順。閲覧できる所属店舗は、地域の判定と同じ

### 代表地域

店舗は、所属地域のうち1つを代表地域として持つ（P-15、P-16、R-12、B-25）。一覧で店舗と掲載に示す地域名は、代表地域による。

- 店舗管理者は、所属地域から代表地域を選べる（REG-04）。公開の取り下げ・運営による非公開の地域も選べる
- 選んだ代表地域がない店舗では、所属地域のうち最初に所属した地域が代表地域になる
- 選んだ代表地域との所属が、離脱の承認または除外で解除されると、選んだ代表地域はなくなる。代表地域は、残る所属のうち最初に所属した地域になる
- 代表地域が公開の取り下げまたは運営による非公開の間は、閲覧者には、公開中の所属地域のうち最初に所属した地域を代わりに示す。公開中の所属地域がなければ、地域名を示さない。代表地域が再び閲覧できるようになると、代表地域を示す

### 申請の前提

申請の失効は、「申請の前提が成り立たなくなった」という1つの規則で決まる（P-77、I-19）。申請の前提は、次の表のうち、その申請が当たるすべての行の前提。申請は、当たる行の前提のすべてが成り立つ間だけ有効で、確認中・差し戻し中の申請は、そのどれかが成り立たなくなると失効する。承認も同じ前提を確かめ、前提を欠く申請は承認できない。

| 申請 | 前提 |
| --- | --- |
| 店舗の新規登録 | なし（失効しない） |
| 個人が管理者のいない店舗に行う申請（情報修正、掲載、掲載の修正、所属、離脱） | その店舗に店舗管理者がいない |
| 店舗管理者として行う申請（所属、離脱、参加） | その店舗に店舗管理者がいる |
| 掲載の修正 | 対象の掲載がある |
| 所属 | その店舗とその地域の所属がまだない |
| 離脱 | その所属がある |
| 参加 | イベントが終了も中止もしていない。その店舗の参加がまだない |
| 管理権限 | 申請者がその店舗の店舗管理者でない。登録申請に併せた申請は、加えて、登録申請が否認・取り下げになっていない |

店舗管理者として行う参加の申請は「店舗管理者として行う申請」と「参加」の2行に、個人が行う掲載の修正の申請は「個人が管理者のいない店舗に行う申請」と「掲載の修正」の2行に当たる。

個人が行う申請（情報修正、掲載、掲載の修正、所属、離脱）は、管理者のいない店舗に限る（B-20）。次の異常系は、これらの申請を始める・提出するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（B-20、M-11、M-26、M-35） | 店舗管理者のいる店舗、またはその掲載である。個人の申請の入口は示されず、直接たどり着いても受け付けないことが示される | 情報の誤り・閉店は連絡する（MOD-04）。店舗の関係者は管理権限を申請する（SHP-04） |

### 重ねて申請できない

同じ申請者が、同じ種類・同じ対象で確認中または差し戻しの申請を持つ間は、重ねて申請できない。申請者は、個人として行う申請では利用者、店舗管理者として行う申請では店舗（P-74、I-10）。別の申請者による同じ対象への申請は、それぞれ独立して確認される（P-75）。新しく対象を作る申請（店舗の新規登録、掲載の申請）には同じ対象がなく、この制限はかからない（I-10）。

次の異常系は、申請を提出・再申請するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（P-74） | 同じ種類・同じ対象で、同じ申請者の確認中または差し戻しの申請がすでにある。申請中であることが示され、重ねて申請できない | その申請を開き（APP-01）、結果を待つ。差し戻しなら修正して再提出する（APP-02）。確認中の申請の内容を変えるなら、取り下げて（APP-03）再申請する（APP-04）。店舗管理者として行う申請では、同じ店舗の別の店舗管理者が行った申請も扱える（APP-06） |

### 所在地の入力

店舗、地域、イベントの開催場所の所在地は、郵便番号、または都道府県・市区町村・町域の階層から町域を選んで決め、続く住所を入力する。対象のエリアは選んだ町域で決まり、利用者はエリアを別に入力しない（P-12、P-13）。

店舗、地域、イベントの開催場所の位置は、所在地から決まらない。利用者が地図の上の1点として指定する（P-10）。

次の異常系は、所在地を入力するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー（P-12） | 入力した郵便番号が町域に対応しない（事業所固有の郵便番号を含む）。町域の候補が示されず、所在地は決まらない | 郵便番号を直す。または階層から町域を選び直す |

### 探し方

対象を探す方法は次の2つ。各シナリオは、どちらで探すかを述べる。

| 探し方 | 規則 | 当たるシナリオ |
| --- | --- | --- |
| 名称・所在地で店舗を探す | 名称と所在地を文字で入力する（どちらか一方でもよい。どちらも入力しなければ探せない）。所在地は「所在地の入力」の町域の選択ではなく、文字で入力する。名称または所在地が入力した文字を含む店舗と、名称または所在地が入力した文字に含まれる店舗が、関連度の高い順に示される | 既存店舗の確認（SHP-02）、登録申請の照合（SHP-09）、サービス運営者が店舗を探す操作（SHP-12、SHP-13、LST-15、LST-16、MEM-01、MOD-08） |
| キーワードで探す | 1つのキーワードを入力する。キーワードが下の表の項目に当たる対象が、種類ごとに関連度の高い順に示される | DIS-05（閲覧者の検索）、入力の途中の対象の選択（REG-01、REG-03、EVT-01、EVT-05、EVT-10、EDT-02）、サービス運営者が掲載・地域・イベントを探して開く操作（LST-16、REG-13、EVT-13、MEM-01、MOD-07） |

| 対象 | キーワードが当たる項目 |
| --- | --- |
| 店舗 | 名称、所在地 |
| 掲載 | 名称、説明 |
| 地域 | 名称、キャッチコピー、紹介、所在地 |
| イベント | 名称、キャッチコピー、紹介、開催場所の所在地 |
| 読みもの | タイトル、本文 |

示す範囲は探す場面で決まる。閲覧者の検索と既存店舗の確認は「表示範囲」の参照の場面、入力の途中の対象の選択は各シナリオが定める候補の範囲、サービス運営者が探す操作（登録申請の照合を含む）は、閲覧者に表示されない対象（下書き、一時非公開、公開の取り下げ、運営による非公開、非公開の店舗）を含むすべての対象。

### 写真の登録と同意

写真を登録する操作のたびに、自ら撮影した写真または利用の許諾を得た写真であることと、Lunt での利用への同意を確認する。同意しない写真は登録されない。店舗、掲載、地域、イベント、読みものの写真と、申請に添える写真に共通し、サービス運営者が登録する場合も同じ（M-37、B-53）。

次の異常系は、写真を登録するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー（M-37） | 同意を確認せずに登録しようとした。写真は登録されない | 同意して登録する。またはその写真を登録せずに続ける |
| 入力エラー | 写真として扱えないファイルを選んだ。登録されず、扱えないことが示される | 別の写真を選ぶ |

### 運営による非公開

掲載・地域・イベントの運営による非公開は、公開状態に重なる別の状態（I-15）。店舗の非公開は MOD-08 が定める。

- サービス運営者だけが行い、サービス運営者だけが解除する。店舗管理者・運営者の有無を問わない（B-48、MOD-07）
- その間、対象は閲覧者のどの場面にも表示されない
- その間に止まるのは、公開状態の変更（公開、公開の取り下げ、一時非公開、再公開）だけ。管理者・運営者は、情報の更新、写真の登録、複製、削除をはじめ、ほかの操作を通常どおり行える。後から管理権限を得た管理者にも同じ（M-43、R-15、E-15）
- 解除すると、運営による非公開にする前の公開状態に戻る
- その間に、申立てで最後の写真が削除されて公開条件を欠いた対象は、公開していない状態（掲載は一時非公開、地域・イベントは公開の取り下げ）になる。解除しても、写真を登録して公開し直すまで閲覧できない（M-49、MOD-03）

### 同時編集の競合

同じ対象を別の人（同じ対象の別の管理者、別のサービス運営者、別の編集担当者）が先に保存していた場合、保存しようとすると競合が示され、保存されない（M-12、O-19）。店舗の営業状況の確定も同じ。

次の異常系は、対象の情報を保存・確定するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-12、O-19） | 編集している間に、別の人が同じ対象を保存した。競合が示され、保存されない | 最新の内容を読み直して、操作をやり直す |

### 立場を失ったとき

店舗管理者・地域の運営者・イベントの運営者・編集担当者・サービス運営者の操作は、確定・保存（公開・取り下げを含む）の時点で、その操作を行う立場にあるかを確かめる。操作の途中で立場を失っていれば、操作は反映されない。立場を失う出来事と、失った利用者の次の操作は次のとおり。

| 立場 | 立場を失う出来事 | 次の操作 |
| --- | --- | --- |
| 管理者（店舗管理者、地域運営者、イベント運営者） | 辞任（別のブラウザでの辞任を含む。MEM-04）、管理権限の解除（MEM-05） | 管理する対象の一覧へ戻る |
| 不在の代行をしているサービス運営者（地域の運営者・イベントの運営者であるサービス運営者を含む） | 代行している対象に管理者が就いた（招待の承諾 MEM-03、管理権限の申請の承認 SHP-10、管理権限の付与 REG-12・EVT-12） | その対象を開き直し、管理者がいることを確かめる |
| 編集担当者 | 任命の解除（OPE-04。AC-75） | 操作をやめる |
| サービス運営者 | 役割の解除（OPE-05） | 操作をやめる |

運営者が不在の地域・イベントへの申請を、地域の運営者・イベントの運営者として判断している間に運営者が就いた場合、その申請が期間超過の代行（APP-08）の対象（確認中になってから一定の期間を過ぎている）なら、サービス運営者は立場を失わず、期間超過の代行として判断を続けられる。その時点の承認・否認は、そのまま期間超過の代行として反映される。差し戻しは反映されず、以後は承認と否認だけを行える。期間超過の前の申請では、立場を失う。

次の異常系は、これらの立場で確定・保存するすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 操作の途中で、その操作を行う立場を失った。確定・保存の時点で操作できないことが示され、操作は反映されない | 上の表の、立場ごとの次の操作 |

### 管理者不在

最後の管理者（店舗管理者、地域運営者、イベント運営者）が辞任する（MEM-04）、管理権限を解除される（MEM-05）、または退会する（ACC-04）と、対象は管理者不在になる（B-31、P-34）。地域・イベントでは、管理権限を付与する前の対象も管理者不在に当たる。

- 対象の公開は続く
- 店舗では、その店舗の掲載が、下書きを含めてサービス運営者の管理下に入る（LST-16）。店舗管理者として行った確認中・差し戻し中の申請は、前提を失って失効する（「申請の前提」、APP-05）
- 地域・イベントでは、サービス運営者が地域の運営者・イベントの運営者になる（「利用者」、REG-13、EVT-13）
- 承諾前の招待は有効のまま残り、招待の承諾で管理者が就く。管理者不在の間、承諾前の招待はサービス運営者が取り消せる（MEM-02）
- 最後の管理者の辞任の確認（MEM-04）、権限の解除の確認（MEM-05）、退会の確認（ACC-04）では、管理者不在になる対象と、この規則による帰結が示される

### 通知

通知の出来事と宛先は、ACC-03 の表だけが定める。各シナリオは、通知が起きることを書かず、通知を受けた人が通知から進む操作だけを書く。

### 不在の対象への通知

店舗管理者・地域運営者・イベント運営者が不在の対象では、その立場宛ての通知はサービス運営者に届く（B-14、B-31、I-16）。地域・イベントでは、サービス運営者は地域の運営者・イベントの運営者として通知を受ける。

- 地域・イベントへの申請（新しい申請、再提出、取り下げ）の通知からは、申請の判断（REG-09、EVT-08）へ進む
- それ以外の通知からは、対象の運営へ進む。店舗は SHP-13・LST-16、地域は REG-06〜REG-11、イベントは EVT-04〜EVT-11

### サービス運営者の操作

サービス運営者の操作の入口（サービス運営の入口）は、サービス運営者の役割を持つ利用者だけに示される。

次の異常系は、サービス運営者が行うすべてのシナリオに共通する。各シナリオの異常系には書かない。

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | サービス運営者の役割を持たない利用者が、直接たどり着いた。操作できないことが示される | 操作をやめる |

操作の途中で役割を解除されたときの扱いは、「立場を失ったとき」が定める。
