# 申立て・連絡・非公開

取り下げの申立て、管理者のいる店舗の情報の誤り・閉店の連絡、サービス運営者による非公開と重複する店舗の整理の操作を定める。

## 共通の規則

- 取り下げの申立てと、情報の誤り・閉店の連絡は申請ではない。差し戻し・再提出・取り下げ・再申請・失効はなく、`application.md` の流れを適用しない（P-79、B-49、B-59）
- 申立ては、未対応から対応済みへ進む。サービス運営者が結果を添えて対応を終えると対応済みになり、結果が申立人にメールで届く。措置を行わない場合も、その結果を添えて対応を終える
- 連絡は、未対応・確認依頼中・対応済みの順に進む。サービス運営者が店舗管理者に確認を依頼すると確認依頼中になる。連絡を対応済みにするのはサービス運営者だけ。サービス運営者は、依頼せずに対応を終えるか、確認依頼中の連絡の対応を終える。店舗管理者が連絡を対応済みにする操作はない
- 申立人との連絡はメールで行う。申立人はサービス内で申立ての状況を確認せず、提出した申立てを取り消せない（P-47）
- 連絡した利用者に、連絡の結果の通知は届かない。通知の出来事は P-91〜P-100 が正
- 掲載・地域・イベントの運営による非公開の間に行える操作、解除の後の公開状態、その間に最後の写真が削除された対象の扱いは、`index.md` の「共通の規則 > 運営による非公開」が定める。店舗の非公開も、サービス運営者だけが行い、サービス運営者だけが解除する（B-48）
- 店舗管理者・運営者が不在の対象への通知の宛先は、`index.md` の「共通の規則 > 不在の対象への通知」が定める
- 同じ申立て・連絡を別のサービス運営者が先に対応していた場合（対応を終えた、確認を依頼した）、現在の状態が示され、操作は反映されない
- 非公開の対象と、非公開の店舗の掲載は、発見の場面にも参照の場面にも表示されない（`index.md` の「表示範囲」）。紹介元の読みもの・地域・店舗の公開は続き、紹介元や保存一覧からたどった閲覧者には、閲覧できないことが示される（P-88、B-10）
- サービス運営者の操作の入口と、サービス運営者でない利用者がたどり着いたときの扱いは、`index.md` の「共通の規則 > サービス運営者の操作」が定める

## MOD-01 取り下げを申し立てる

- 利用者: 申立人
- 契約: M-39、M-47、B-18、B-49、B-50、P-47、P-97、AC-31、AC-46、AC-65

### 流れ

1. 申立人は、ログインせずに、対象の詳細から取り下げの申立てを始める。店舗本人は掲載と店舗の詳細から、写真の権利者は掲載・店舗・地域・イベント・読みものの詳細から始める
2. 申立人の立場（店舗本人、写真の権利者）を選ぶ。地域・イベント・読みものの詳細では、写真の権利者だけを選べる
3. 写真の権利者は、取り下げを求める写真を示す
4. 理由とメールアドレスを入力し、提出する
5. 申立てを受け付けたことと、結果がメールで届くことが示される。サービス運営者に申立てが通知される
6. 結果は、入力したメールアドレスに届く
7. 店舗の Lunt への掲載をやめたい店舗管理者も、店舗詳細から店舗本人として同じ流れで申し立てる。店舗管理者が店舗を自ら非公開・削除する操作はない

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 理由・立場・メールアドレスのいずれかが欠けている、またはメールアドレスの形式が誤っている。提出できず、該当の項目が示される | 項目を直して提出する |
| 入力エラー | 写真の権利者が、対象の写真を示していない。提出できない | 写真を示して提出する |
| リソース不在 | 入力している間に、対象が非公開・公開の取り下げ・削除になった。閲覧できないことが示される | 申立てをやめる |
| 操作の取り消し | 提出せずに申立てをやめる。申立ては送られない | なし |
| 操作の取り消し | 提出した申立てを取り消したい。取り消す操作はない | 結果のメールを待つ |

## MOD-02 取り下げの申立てに対応する

- 利用者: サービス運営者
- 契約: M-39、M-49、O-21、O-22、B-19、B-49、B-61、P-47、P-93、P-94、P-95、P-96、AC-31、AC-46、AC-79

### 流れ

1. サービス運営者は、申立ての通知、または対応が必要な申立て（OPE-01）から、未対応の申立てを開く
2. 対象、示された写真、理由、申立人の立場、メールアドレスを確認する。追加の確認は、申立人とメールで行う
3. 措置を行うか、行わないかを判断する。写真の削除は、掲載・店舗・地域・イベント・読みもののどの写真にも行える。非公開は、掲載（MOD-07）と店舗（MOD-08）に行える
4. 写真を削除しても写真が残る対象は、公開が続く。1枚目を削除した場合は、次の写真が代表写真になる
5. 写真の削除で写真がなくなった掲載は一時非公開になり、地域・イベント・読みものは公開の取り下げになる。運営による非公開の間の対象も同じ。店舗は、写真がなくなっても公開が続く
6. 写真の削除は、店舗と掲載では店舗管理者に、地域では地域運営者に、イベントではイベント運営者に、読みものではすべての編集担当者に通知される。通知を受けた管理者は、写真を登録して再び公開できる（MOD-03）
7. 行った措置、または措置を行わないことを結果として添え、対応を終える。申立ては対応済みになり、結果が申立人にメールで届く
8. 対応を終えると、申立ては対応が必要なもの（OPE-01）から外れる。サービス運営者は対応が必要なものへ戻り、次の申立て・連絡へ進む。行った措置の結果は、対象を選んで現在の状態を見ると確かめられる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| リソース不在 | 対象または示された写真が、対応の前に削除されている | 措置を行わず、その旨を結果として添えて対応を終える |
| リソース不在 | 対象がすでに非公開になっている | 追加の措置が要るかを判断し、結果を添えて対応を終える |
| 入力エラー | 結果を添えずに対応を終えようとした。終えられない | 結果を入力して対応を終える |
| 契約（M-49） | 写真がなくなって一時非公開になった掲載の店舗に、店舗管理者がいない | サービス運営者が写真を登録して再公開する（MOD-03） |
| 操作の取り消し | 削除した写真を戻したい。削除した写真は戻せない | 対象の管理者が写真を登録し直す（MOD-03） |
| 操作の取り消し | 非公開にした掲載・店舗を戻す | 非公開を解除する（MOD-07、MOD-08） |
| 操作の取り消し | 対応を終えた後で、措置が足りないと分かった。対応済みの申立ては未対応に戻らず、添えた結果は変えられない。対応済みの申立てからは写真を削除できない | 掲載・店舗の非公開は、対象を直接選んで行う（MOD-07、MOD-08）。写真の削除は、同じ対象への新しい申立て（MOD-01）への対応で行う |

## MOD-03 申立てで写真が削除された対象に写真を登録して再び公開する

- 利用者: 店舗管理者、地域運営者、イベント運営者、編集担当者、サービス運営者
- 契約: M-37、M-49、B-61、R-15、E-15、P-93、P-94、P-95、P-96、AC-31、AC-79
- 前提: 申立てによる写真の削除で、掲載が一時非公開、または地域・イベント・読みものが公開の取り下げになっている

### 流れ

1. 対象の管理者は、写真の削除の通知から対象を開き、写真が削除されたことと、現在の公開状態を確認する
2. 写真を登録する。登録のたびに同意を確認する（`index.md` の「写真の登録と同意」）
3. 公開条件が揃ったら、公開する。掲載は再公開（LST-07）、地域は公開（REG-07）、イベントは公開（EVT-06）、読みものは公開（EDT-03）の操作による。写真を登録しただけでは公開に戻らない
4. 店舗管理者のいない店舗の掲載は、サービス運営者が写真を登録して再公開する（LST-16）。運営者が不在の地域・イベントは、サービス運営者が写真を登録して公開する（REG-13、EVT-13）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-16、B-51） | 写真を登録せずに公開しようとした。公開条件を欠くため公開できない | 写真を登録して公開する |
| 契約（M-43、R-15、E-15） | 対象が運営による非公開にもなっている。写真は登録できるが、公開できない | サービス運営者による解除を待つ。解除されると、掲載は一時非公開、地域・イベントは公開の取り下げになり、公開できる |
| 操作の取り消し | 写真を登録せず、再び公開しない。対象は一時非公開または公開の取り下げのまま | なし |

## MOD-04 管理者のいる店舗の情報の誤り・閉店を連絡する

- 利用者: 利用者
- 契約: M-11、M-35、M-48、B-18、B-59、P-97、AC-09、AC-77
- 前提: ログインしている

### 流れ

1. 利用者は、店舗管理者のいる店舗の詳細、またはその店舗の掲載の詳細から、連絡を始める。その店舗や掲載の修正を申請しようとした利用者も、この連絡へ案内される（SHP-08、LST-13）
2. 連絡の種類（情報の誤り、閉店）を選び、内容を入力する
3. 提出する。連絡を受け付けたことが示され、サービス運営者に通知される
4. 連絡に基づいて更新された内容は、店舗詳細と掲載詳細で確認する

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | 種類または内容が欠けている。提出できず、該当の項目が示される | 項目を直して提出する |
| 権限不足 | ログインしていない。ログインへ案内される | ログインして、連絡の続きへ戻る |
| 契約（M-48） | 店舗管理者のいない店舗、またはその掲載である。連絡の入口は示されず、修正の申請が案内される | 修正、休業・閉店を申請する（SHP-08）。掲載の修正を申請する（LST-13） |
| リソース不在 | 入力している間に、対象が非公開または削除になった。閲覧できないことが示される | 連絡をやめる |
| 操作の取り消し | 提出せずに連絡をやめる。連絡は送られない | なし |
| 操作の取り消し | 提出した連絡を取り消したい。取り消す操作はない | なし |

## MOD-05 情報の誤り・閉店の連絡に対応する

- 利用者: サービス運営者
- 契約: M-35、M-46、M-48、O-16、O-24、B-59、P-77、P-93、P-100、I-03、AC-77

### 流れ

1. サービス運営者は、連絡の通知、または対応が必要な連絡（OPE-01）から、未対応の連絡を開く
2. 対象の店舗または掲載、連絡の種類、内容を確認する
3. 店舗管理者への依頼が要らないと判断した連絡は、依頼せずに対応を終える。連絡は対応済みになる
4. 依頼が要る連絡は、店舗管理者に情報の確認を依頼する。連絡の内容を添えた依頼が、その店舗のすべての店舗管理者に通知され、連絡は確認依頼中になる
5. 店舗管理者は依頼を読み、必要なら店舗の情報と掲載を更新する（MOD-06）
6. サービス運営者は、店舗と掲載の現在の内容を見て、店舗管理者が対応したか、情報に誤りが残っていないかを判断する。判断の時期はサービス運営者が決める。対応が済んだと判断した場合は、連絡の対応を終える。連絡は対応済みになる
7. 店舗管理者が対応しないと判断した場合は、その店舗のすべての店舗管理者の権限を解除する（MEM-05）。解除された本人に通知される。店舗管理者として行った確認中・差し戻し中の申請は、前提を失って失効する（`index.md` の「申請の前提」）
8. 店舗は管理者不在になる。サービス運営者は、店舗の情報と営業状況を更新し（SHP-13）、掲載を更新・一時非公開・提供終了・削除して（LST-16）、連絡の対応を終える

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（I-03） | 店舗管理者が1人でも残っている間に、店舗の情報や掲載を更新しようとした。更新できない | すべての店舗管理者の権限を解除してから更新する |
| 契約（M-46、M-35） | 連絡の後、辞任・退会によって店舗管理者が不在になった。確認を依頼する相手がいない | 確認を依頼せず、店舗の情報と掲載を更新して（SHP-13、LST-16）対応を終える |
| リソース不在 | 連絡の対象の掲載が削除されている、または対象が非公開になっている | 追加の対応が要るかを判断する。要らなければ、依頼せずに対応を終える |
| 操作の取り消し | 確認を依頼した後で、依頼が要らなかったと分かった。依頼は取り消せない | 連絡の対応を終える。連絡は対応済みになる |
| 操作の取り消し | 権限の解除を取り消したい。解除は取り消せない | 解除された利用者が、管理権限を申請する（SHP-04） |

## MOD-06 確認の依頼を受けて店舗の情報を確認する

- 利用者: 店舗管理者
- 契約: M-48、M-10、M-13、M-22、P-93、P-100、I-03、AC-77

### 流れ

1. 店舗管理者は、メールまたは通知一覧で、情報の確認の依頼を受ける。依頼には、対象の店舗または掲載と、連絡の種類・内容が示される
2. 店舗の情報と掲載を、連絡の内容と照らして確認する
3. 情報に誤りがあれば、店舗情報を更新する（SHP-06）。掲載に誤りがあれば、掲載を編集する（LST-06）
4. 閉店していれば、閉店を登録する（SHP-07）。提供していない掲載は、提供終了にするか（LST-08）、一時非公開にするか（LST-07）、削除する（LST-10）
5. 情報に誤りがなければ、何も更新しない。確認の結果をサービス運営者に伝える操作はなく、サービス運営者が店舗と掲載の現在の内容を見て判断する（MOD-05）
6. 依頼は、その店舗のすべての店舗管理者に届く。1人が対応すれば足りる

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-48、I-03） | 誤りのある情報を更新しないまま、サービス運営者が対応なしと判断した。その店舗のすべての店舗管理者の権限が解除され、本人に通知が届く | 再び管理するには、管理権限を申請する（SHP-04） |
| 権限不足 | 依頼を受けた後に、その店舗の管理権限を手放した。店舗の情報と掲載を更新できない | なし。残る店舗管理者が対応する |
| リソース不在 | 連絡の対象の掲載が、すでに削除されている | 残る店舗の情報と掲載を確認する |
| リソース不在 | 依頼を開いたとき、サービス運営者がすでに連絡の対応を終えている。依頼の内容は読める | 直す点が残っていれば、店舗の情報と掲載を更新する |

## MOD-07 掲載・地域・イベントを運営による非公開にし、解除する

- 利用者: サービス運営者
- 契約: M-36、M-43、R-15、E-15、O-22、B-10、B-48、P-82、P-83、P-88、P-93、P-94、P-95、P-96、AC-15、AC-64

### 流れ

1. サービス運営者は、対象の掲載・地域・イベントを選ぶ。申立てへの対応（MOD-02）から進むか、対象を直接選ぶ。店舗管理者・運営者の有無を問わない
2. 運営による非公開にする
3. 対象は閲覧できなくなる。掲載では店舗管理者に、地域では地域運営者に、イベントではイベント運営者に通知される。公開中の読みものが紹介している対象であれば、編集担当者にも通知される
4. 運営による非公開の間に店舗管理者・運営者が行える操作は、`index.md` の「共通の規則 > 運営による非公開」が定める
5. サービス運営者は、運営による非公開を解除する。解除は店舗管理者・運営者に通知される
6. 解除の後の公開状態は、同じ規則が定める。公開中だった対象は再び閲覧できる。その間に申立てで最後の写真が削除された対象は、写真を登録して公開し直すまで閲覧できない（MOD-03）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（B-48） | 読みものを閲覧できなくしたい。読みものは運営による非公開の対象ではない | 写真の申立てであれば写真を削除する（MOD-02）。公開の取り下げは編集担当者が行う（EDT-05） |
| 契約（M-44） | 店舗を閲覧できなくしたい。店舗はこの操作の対象ではない | 店舗を非公開にする（MOD-08） |
| リソース不在 | 運営による非公開の間に、店舗管理者が掲載を削除した。解除の対象がない | なし |
| 操作の取り消し | 誤って運営による非公開にした | 解除する |

## MOD-08 店舗を非公開にし、解除する

- 利用者: サービス運営者
- 契約: M-44、M-47、O-22、B-10、B-47、B-48、B-50、P-42、P-81、P-88、P-93、P-96、AC-15、AC-48、AC-64、AC-65

### 流れ

1. サービス運営者は、対象の店舗を選ぶ。申立てへの対応（MOD-02）、重複する店舗の整理（MOD-09）から進むか、店舗を直接選ぶ。店舗管理者の有無を問わない
2. 店舗を非公開にする
3. 店舗は閲覧できなくなり、紐づく掲載も閲覧できなくなる。地域の所属店舗とイベントの参加店舗にも表示されない。店舗管理者に通知される。公開中の読みものが紹介している店舗・掲載であれば、編集担当者にも通知される
4. 非公開の間も、店舗管理者は店舗の情報を更新でき、掲載を通常どおり操作できる。掲載は、店舗の非公開が解除されるまで閲覧者に表示されない
5. 非公開の店舗は、店舗の登録申請の照合の対象に残る（SHP-09）
6. サービス運営者は、非公開を解除する。解除は店舗管理者に通知される
7. 解除すると、店舗は再び閲覧でき、公開中の掲載は再び閲覧できる。非公開の間に店舗管理者が変えた掲載の公開状態は、そのまま反映される。地域の所属店舗とイベントの参加店舗にも再び表示される

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（M-47、B-50） | 店舗管理者が、店舗を自ら非公開にしたい、または削除したい。その操作はない | 店舗本人として取り下げを申し立てる（MOD-01） |
| 契約（B-48） | 店舗管理者が、非公開を解除したい。解除できるのはサービス運営者だけ | サービス運営者による解除を待つ |
| 操作の取り消し | 誤って非公開にした | 解除する |

## MOD-09 重複する店舗を整理する

- 利用者: サービス運営者
- 契約: O-04、O-18、B-10、B-44、B-47、P-42、P-75、P-93、AC-48、AC-78

### 流れ

1. サービス運営者は、登録申請の照合（SHP-09）や連絡・申立ての確認で、同じ店舗が重複して登録されていることを把握する
2. 残す店舗と、非公開にする店舗を決める
3. 一方の店舗を非公開にする（MOD-08）。非公開にした店舗の掲載・所属地域・イベント参加・保存は、残す店舗に引き継がれない。店舗は統合されない
4. 必要な掲載は、残す店舗に作り直す。残す店舗に店舗管理者がいなければ、サービス運営者が代理で作成する（LST-15）。店舗管理者がいれば、店舗管理者が作成する（LST-01）
5. 残す店舗の地域への所属とイベントへの参加は、その店舗について改めて申請する（REG-01、REG-03、EVT-01）。管理者のいない店舗のイベント参加は、イベント運営者が追加する（EVT-10）
6. 非公開にした店舗を保存していた閲覧者には、保存一覧で閲覧できないことが示される（KEP-03）

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 契約（B-44） | 2つの店舗の掲載・所属・参加・保存を1つにまとめたい。統合の操作はない | 一方を非公開にし、必要な掲載を残す店舗に作り直す |
| 契約（M-25） | 残す店舗に店舗管理者がいる。サービス運営者は掲載を代理で作成できない | 掲載の作成は店舗管理者が行う（LST-01） |
| 操作の取り消し | 非公開にする店舗を誤った | 非公開を解除し（MOD-08）、もう一方の店舗を非公開にする |
