# 管理権限

店舗・地域・イベントの管理権限に共通する、管理メンバーの確認・招待・承諾と、辞任・権限の解除の流れを定める。

## 共通の規則

- 管理者は、店舗の店舗管理者、地域の地域運営者、イベントのイベント運営者を指す。対象は、管理権限が及ぶ店舗・地域・イベントを指す
- 同じ対象の管理者は、全員が同じ操作範囲を持つ。招待で管理者になった利用者も同じ（B-28、M-12）
- 管理権限は対象ごとに独立する。1人の利用者が複数の対象の管理者になれ、兼任で操作範囲は広がらない（P-04、M-28）
- 管理者は、招待の承諾で就く（MEM-03）。ほかに、店舗では管理権限の申請の承認で（SHP-04、SHP-10）、地域・イベントではサービス運営者の付与で就く（REG-12、EVT-12）。管理者のいない対象でも、承諾前の招待が残っていれば、招待の承諾で管理者が就く
- 招待に、サービス運営者の承認は要らない（B-21、B-28）
- 管理権限は、期間の経過や利用状況で失効しない（B-32）。招待に期限はなく、承諾前の招待が有効のまま残ることは MEM-02 が定める
- 最後の管理者が辞任する、管理権限を解除される、または退会したときの帰結（管理者不在）と、管理者不在の対象への通知の宛先は、`index.md` の「共通の規則 > 管理者不在」「不在の対象への通知」が定める
- 通知は ACC-03 の表による
- サービス運営者が行う MEM-01 の確認、MEM-02 の招待の取り消し、MEM-05 の入口と、サービス運営者でない利用者がたどり着いたときの扱いは、`index.md` の「共通の規則 > サービス運営者の操作」が定める
- 操作の途中で管理権限を失った場合と、管理者不在の対象の招待を取り消す途中で対象に管理者が就いた場合の扱いは、`index.md` の「共通の規則 > 立場を失ったとき」が定める

## MEM-01 管理メンバーを確認する

- 利用者: 店舗管理者、地域運営者、イベント運営者、サービス運営者（MEM-02 の招待の取り消しと MEM-05 の権限の解除の前の確認）
- 契約: M-12、B-21、B-28
- 前提: 対象の管理者である。またはサービス運営者である

### 流れ

1. 管理者は、管理する対象のメンバーの管理を開く。サービス運営者は、対象の店舗・地域・イベントを探して開く（`index.md` の「探し方」。店舗は名称・所在地で、地域・イベントはキーワードで探す）
2. 対象の管理者の一覧を見る。管理者はメールアドレスで識別され、管理者は自分がどれかが分かる
3. 承諾前の招待を、宛先のメールアドレスとともに見る
4. 管理者は、ここから招待（MEM-02）、招待の取り消し（MEM-02）、辞任（MEM-04）へ進む。サービス運営者は、管理者不在の対象の招待の取り消し（MEM-02）と、権限の解除（MEM-05）へ進む

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 対象の管理者でも、サービス運営者でもない利用者がたどり着いた。辞任した、または管理権限を解除された後も同じ | 操作できないことが示される |
| リソース不在 | 承諾前の招待がない | 招待がないことが示される。必要なら招待する（MEM-02） |

## MEM-02 管理メンバーを招待し、招待を取り消す

- 利用者: 店舗管理者、地域運営者、イベント運営者、サービス運営者（管理者不在の対象の招待の取り消し）
- 契約: M-12、B-14、B-21、B-28、B-32、P-98、P-70（06）、AC-23
- 前提: 招待では、対象の管理者である。招待の取り消しでは、対象の管理者、または管理者不在の対象のサービス運営者である

### 流れ

1. 管理者は、対象のメンバーの管理（MEM-01）から招待を始める
2. 招待する相手のメールアドレスを入力して、招待を送る
3. 招待は承諾前の招待として一覧に加わる。招待の通知は、入力したメールアドレスに届く（ACC-03）
4. 相手が承諾すると（MEM-03）、相手は管理者の一覧に加わり、招待は承諾前の招待から消える
5. 承諾前の招待は、同じ対象の管理者と、管理者不在の対象ではサービス運営者が取り消せる。サービス運営者は、メンバーの確認（MEM-01）で承諾前の招待を見て取り消す。取り消した招待では承諾できない
6. 招待した管理者が辞任しても退会しても、対象が管理者不在になっても、招待は有効のまま残る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 入力エラー | メールアドレスが空、またはメールアドレスの形でない | 招待できないことが示される。入力を直す |
| 入力エラー | そのメールアドレスのアカウントが、すでに同じ対象の管理者である | すでに管理者であることが示される。招待は要らない |
| 入力エラー | そのメールアドレスへの承諾前の招待がすでにある | すでに招待していることが示される。相手に承諾を促す |
| 権限不足 | 対象の管理者でない利用者がたどり着いた。招待の取り消しでは、管理者不在の対象のサービス運営者を除く | 操作できないことが示される |
| リソース不在 | 取り消そうとした招待が、先に承諾された、または別の人に取り消されていた。取り消せないことが示され、最新の招待の一覧が示される。管理者不在の対象で取り消すサービス運営者が、承諾で対象に管理者が就いていた場合は、`index.md` の「立場を失ったとき」による | 最新の一覧を確かめる。承諾された相手の権限の解除はサービス運営者だけが行う（MEM-05） |
| 操作の取り消し | 送った招待をやめたい | 承諾前なら招待を取り消す。承諾された後は取り消せない。権限の解除はサービス運営者だけが行う（MEM-05） |
| 操作の取り消し | 誤ったメールアドレスに招待を送った | 招待を取り消し、正しいメールアドレスに招待する |

## MEM-03 招待を受けて管理者になる

- 利用者: 利用者
- 契約: B-28、M-12、P-98、P-77（d）、B-18、AC-23
- 前提: 自分のメールアドレス宛ての承諾前の招待がある

### 流れ

1. 招待された利用者は、招待の通知から招待を開く
2. ログインしていなければログインへ案内され、招待されたメールアドレスのアカウントでログインして招待へ戻る。アカウントがなければ、そのメールアドレスで作る（ACC-01、ACC-02）
3. 招待の対象と、管理者として行えることを確認する
4. 承諾する。利用者は対象の管理者になり、対象の管理へ進む（店舗は SHP-05）
5. 店舗の招待を承諾した利用者に、その店舗への確認中・差し戻し中の管理権限の申請があれば、申請は失効する（APP-05）
6. 管理者不在の対象の招待を承諾すると、対象に管理者が就く。店舗では、すべての掲載が承諾した利用者の管理下に入り（LST-11）、個人がその店舗に行った確認中・差し戻し中の申請は前提を失って失効する（APP-05）
7. 承諾しない利用者は、何もしない。招待は承諾前のまま残る

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 招待されたメールアドレスと異なるメールアドレスのアカウントでログインしている | 承諾できないことが示される。招待されたメールアドレスのアカウントでログインし直す |
| リソース不在 | 招待が取り消されている | 招待が取り消されたことが示される。招待した管理者に確かめる |
| リソース不在 | すでにその対象の管理者である（管理権限の申請が先に承認された、など） | すでに管理者であることが示される。対象の管理へ進む |
| 操作の取り消し | 承諾した後で、管理者をやめたい | 辞任する（MEM-04） |

## MEM-04 辞任する

- 利用者: 店舗管理者、地域運営者、イベント運営者
- 契約: B-29、B-31、P-34、P-76、P-77（b）、P-70（07）、AC-28、AC-66
- 前提: 対象の管理者である

### 流れ

1. 管理者は、対象のメンバーの管理（MEM-01）から、辞任を始める
2. 他に管理者がいるかが示される。自分が最後の管理者なら、対象が管理者不在になることと、その帰結（`index.md` の「管理者不在」）が示される
3. 確定する。利用者はその対象の管理者でなくなり、対象の管理の入口が示されなくなる
4. 他の管理者がいる店舗では、店舗管理者として行った申請は残る店舗管理者が引き続き扱う（APP-06）
5. 最後の店舗管理者が辞任した店舗で失効した申請の通知は、辞任した本人には届かない（`index.md` の「不在の対象への通知」）。本人は手順2の確認で失効を把握する

管理を引き継ぐ管理者は、後任を招待し（MEM-02）、辞任する。後任が承諾する前に辞任してもよい。招待は有効のまま残り、後任は後から承諾して管理者になる（MEM-03）。

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 操作の取り消し | 確定の前にやめた | 権限は変わらない |
| 操作の取り消し | 辞任した後で、管理者に戻りたい | 辞任は元に戻せない。残る管理者から招待を受ける（MEM-03）。店舗では管理権限を申請できる（SHP-04） |
| 契約（B-29、B-31） | 後任が招待を承諾する前に、最後の管理者として辞任する | 後任が承諾するまで、対象は管理者不在になる（`index.md` の「管理者不在」）。店舗管理者として行った申請を続けるなら、確定の前にやめ、後任の承諾を待ってから辞任する |
| 権限不足 | 他の管理者の権限をなくしたい | 他の管理者の権限は解除できない。解除はサービス運営者だけが行う（MEM-05） |

## MEM-05 管理者の権限を解除する

- 利用者: サービス運営者
- 契約: O-16、B-30、B-31、P-100、P-70（08）、M-48、O-24、I-03、AC-28、AC-77
- 前提: 対象に管理者がいる

### 流れ

1. サービス運営者は、メンバーの確認（MEM-01）で対象の管理者の一覧を見る
2. 権限を解除する管理者を選ぶ
3. 解除の結果が示される。その管理者が最後の管理者なら、対象が管理者不在になることと、その帰結（`index.md` の「管理者不在」）が示される
4. 確定する。その利用者は対象の管理者でなくなる
5. 情報の誤り・閉店の連絡に店舗管理者が対応しない店舗では、その店舗のすべての店舗管理者の権限を解除してから、店舗の情報と掲載を更新する（MOD-05、SHP-13、LST-16）

編集担当者の任命を解く操作は OPE-04 が定める。

### 異常系

| 観点 | 状況 | 利用者の次の操作 |
| --- | --- | --- |
| 権限不足 | 対象の管理者が、他の管理者の権限を解除しようとした。サービス運営者でなければ操作できないことが示される | 管理者が行えるのは自分の辞任だけ（MEM-04） |
| リソース不在 | 確定する前に、その管理者が辞任した、または退会した | すでに管理者でないことが示される。対応は要らない |
| 操作の取り消し | 確定の前にやめた | 権限は変わらない |
| 操作の取り消し | 解除した後で、権限を戻したい | 解除は元に戻せない。店舗では本人の管理権限の申請を承認する（SHP-10）か、残る店舗管理者が招待する（MEM-02）。地域・イベントでは管理権限を付与する（REG-12、EVT-12） |
