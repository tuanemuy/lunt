# 要求台帳

spec の各層が辿り先として引く要求の番号（V・M・R・E・O・B・AC は要件定義書の ID、P・D・T・X・I はこの台帳が振る番号）を定義する。出典は [初期アイデア](idea.md) と、それが指す [要件定義書](requirements.md)（以下 REQ）・[付属資料](design-appendix.md)（以下 APX）。機能と業務上のルールは REQ を優先する。

## 範囲

scenario / pages / domains / usecases / flows / testcases の全層。

- X-01 REQ 3.3 の将来候補（タグ、スタンプラリー、クーポン、決済、アプリ内予約、日付による絞り込み、地域の範囲の地図表示、動画、店舗からの読みもの掲載候補の受付、公式サイト・外部予約先への案内、重複店舗の統合）は設計しない
- X-02 M-06（承認待ちの下書き準備）と M-14（外部予約先の登録）は将来候補で、設計しない
- X-03 非機能要件、技術構成、物理スキーマは設計しない（REQ 1）
- X-04 管理権限を確認する具体的な手順、代行の対象とする期間の値は運用で定める（REQ 7.1、9）。spec は値を設定として扱う
- X-05 地域・イベントの登録の依頼、運営を希望する連絡、紹介先への公開前確認、読みもの掲載候補の受付、事実確認の依頼はサービス外で行う（REQ 8.1、8.3、9）
- X-06 APX 1 のロゴ・アイコン・デザイン案 C₁・書体・罫線と、APX 3（色・寸法・文字・Figma の構成）は UI デザインの資料で、spec の層には写さない
- X-07 APX 4 の「検索候補」は REQ に対応する要件がなく、設計しない（REQ 優先）

## 前提

- T-01 閲覧者向け機能と管理機能を同じ Web サービスとして提供する。閲覧者向け機能はスマートフォン中心（REQ 2.3）
- T-02 実装は `AGENTS.md` のテンプレートに従う。ヘキサゴナル + DDD、UnitOfWork、Outbox によるドメインイベント（少なくとも1回の配送・順序保証なし・消費者は冪等）、冪等な作成、DB 操作を再試行しない、入力バリデーションは転送境界と値オブジェクト生成の2点（`spec/idea.md`）
- T-03 初期リリースは採用方針の要件すべてを対象とし、開発は「アカウント・管理権限・申請の共通の進み方 → 店舗・スポット、カテゴリー、掲載 → 地域、イベント → 閲覧者向け機能 → 読みもの、通知」の順に進める。各段階には、その対象に関わる管理・運営機能を含める（REQ 3.4）

## 台帳

ID のある要求は REQ の ID をそのまま台帳の番号にする。出典の節は ID の頭文字で決まる（V: REQ 6、M: REQ 7、R: REQ 8.1–8.2、E: REQ 8.3–8.4、O: REQ 9、B: REQ 10.3）。地の文と表の要求は P- の番号を振り、出典を添える。

### 体験の方針と利用者（REQ 2–5）

- P-01 目的を決めずに眺め、気になるものを入口に店舗や地域へ関心を広げる。特定のものを探す検索と、偶然の発見の両方を提供する（REQ 2.1）
- P-02 体験の方針8項目（選ばずに閲覧開始、写真を入口に混在、掲載を中心に地域・イベント・読みものを織り交ぜる、地域をまとまりとして扱う、イベントを店舗が参加する催しとして扱う、関連をたどれる、絞り込み・地図・保存で補助、掲載は価格なし・キャッチコピーなし）（REQ 2.2）
- P-03 主体は閲覧者、申請者、店舗管理者、地域運営者、イベント運営者、編集担当者、サービス運営者の7種。役割は業務上の責任を表す（REQ 3.1）
- P-04 1つのアカウントが複数の管理権限と役割を併せ持てる。権限は対象ごとに独立し、兼任で範囲は広がらない。承認者は自分の申請も承認できる（REQ 3.1、B-42）
- P-05 対象機能は閲覧・申請・店舗管理・地域管理・イベント管理・運営・編集の6区分（REQ 3.2）
- P-06 主な利用シナリオ UC-01〜UC-15 の流れと到達点を実現する（REQ 5）
  - UC-01 なんとなく眺める: 写真を見る → 掲載詳細 → 店舗や地域に関心を広げる
  - UC-02 気になった店の周囲を知る: 掲載 → 店舗 → 地域 → 別の掲載・店舗 → 地図で位置を確認する
  - UC-03 エリアや地域から探す: エリアを選ぶ、または地域を探す → 掲載・店舗を確認する
  - UC-04 イベントから探す: イベントを選ぶ → 参加店舗と添えた掲載を見る → 店舗の位置や所属地域を確認する
  - UC-05 記事から興味を広げる: 読みもの一覧 → 記事 → 紹介先を見る
  - UC-06 後から見返す: 閲覧中に保存 → 保存一覧 → 詳細や地図を再確認する
  - UC-07 店舗を登録する: 既存店舗を確認 → 登録を申請（管理権限の申請を併せられる） → 承認 → 公開
  - UC-08 店舗の管理を始める: 管理権限を申請 → 承認 → 店舗情報を更新
  - UC-09 管理者のいない店舗の情報を直す: 修正または休業・閉店を申請 → 承認 → 反映
  - UC-10 店舗の魅力を掲載する: 写真・名称・カテゴリーを設定 → 公開前に確認 → 公開
  - UC-11 地域に所属する: 所属を申請 → 地域の運営者が承認 → 反映
  - UC-12 地域から離脱する: 離脱を申請 → 地域の運営者が承認 → 解除
  - UC-13 所属店舗を除外する: 地域運営者が除外 → 解除
  - UC-14 イベントに参加する: 掲載と参加日を添えて申請 → イベントの運営者が承認 → 反映
  - UC-15 管理者のいない場所の魅力を掲載する: 対象の店舗・スポットを確認 → 掲載を申請 → 承認 → 公開

### 扱う情報（REQ 4）

- P-10 用語は次の10語。「読みもの」を正式な呼称とし、画面上の表記は画面設計で定める（REQ 4.1）。主な情報は次のとおり
  - エリア: 郵便番号、対応する住所・町域
  - 地域: 名称、所在地、写真、紹介、キャッチコピー、位置、所属する店舗・スポット
  - 店舗・スポット: 名称、写真、紹介、所在地、位置、訪問情報、所属地域
  - 掲載: 名称、写真、説明、カテゴリー、店舗・スポットとの関係、提供期間、開催日
  - イベント: 名称、開催期間、開催場所（所在地・位置）、写真、紹介、キャッチコピー、関連する地域、参加する店舗・スポット、参加に添えた掲載・参加日
  - カテゴリー: 名称
  - 読みもの: タイトル、写真、本文、紹介する掲載・店舗・地域・イベントへのリンク
  - 保存情報: 保存対象、保存した利用者または端末
  - 管理権限: 管理対象、管理者
  - 申請: 申請者、対象、申請内容、確認状況、承認結果
- P-11 申請は登録・修正・管理権限取得・所属・離脱・イベント参加・掲載について承認を求めるもの。取り下げの申立てと情報の誤り・閉店の連絡は申請に含めない（REQ 4.1）
- P-12 エリアは町域の郵便番号を単位とする。事業所固有の郵便番号は独立したエリアにしない。店舗・スポットのエリアは所在地から判断し、紐づく掲載の絞り込みに使う（掲載のエリアは紐づく店舗・スポットのエリア）。イベントのエリアは開催場所の所在地から判断する（REQ 4.2）
- P-13 エリアは都道府県・市区町村・町域の順にたどって選べる。都道府県または市区町村を選ぶと、含まれるすべてのエリアを選んだものとして扱う（REQ 4.2）
- P-14 地域はエリアから独立し、複数のエリアにまたがれる。階層を設けず、範囲は重なってよい。店舗は複数の地域に所属でき、所属は所属申請の承認で成立する（REQ 4.2）
- P-15 複数の地域に所属する店舗は代表地域を1つ持つ。店舗管理者が選ぶ。選ばない場合と代表地域との所属が解除された場合は、残る所属のうち最初に所属した地域を代表地域とする（REQ 4.2）
- P-16 公開を取り下げた地域と運営による非公開の地域は、店舗・掲載の所属地域として表示しない。代表地域がその状態の間は、公開中の所属地域のうち最初に所属した地域を代わりに表示する（REQ 4.2）
- P-17 イベントは地域から独立し、開催地域を任意で複数関連づけられる。参加は参加申請の承認で成立し、提供する掲載と参加日を添えられる。延期は開催期間の更新、開催しない場合は中止で扱う（REQ 4.3）
- P-18 カテゴリーはサービス運営者が管理し、1階層、掲載ごとに1つ。カテゴリーは掲載の種類を兼ねる。公開する掲載に必須。廃止時は移行先を指定して付け替える。初期値は「食べる」「買う」「体験」「見る」で、追加と変更はサービス運営者のカテゴリー管理で行う（REQ 4.4）
- P-19 情報の関係7項目（掲載→店舗・所属地域、店舗→掲載・所属地域・参加イベント、地域→所属店舗・その掲載・関連イベント、イベント→参加店舗・添えた掲載・関連地域、読みもの→紹介先、紹介先→公開中の読みもの、フィードで隣り合う地域と掲載の所属関係は登録された所属情報に基づく）をたどれる（REQ 4.5）
- P-20 読みものはサービス全体に属し、地域・イベント・店舗に所属しない。紹介先との関連は所属を表さない（REQ 4.5）
- P-21 掲載は店舗・スポットのいずれかに紐づく。店舗に属さない景色・見どころは場所をスポットとして登録する。スポットは店舗と同じ手続きで登録・修正・管理する（REQ 4.5、7 冒頭）

### 閲覧者向け機能（REQ 6）

- V-01 選ばずに写真から見始められる
- V-02 商品・体験・景色・見どころを共通の閲覧体験で確認できる
- V-03 掲載を眺めながら地域・イベント・読みものも発見できる
- V-04 複数地域の掲載を混在させ、地域と掲載を独立して紹介する
- V-05 掲載名・店舗名・地域名を区別し、実際の関連に基づいて表示する。一覧では代表地域、地域内の一覧ではその地域を表示する。公開を取り下げた地域は表示しない
- V-06 掲載は価格を表示せず、キャッチコピーなしで紹介する
- V-07 紹介された地域・イベント・読みものの詳細を閲覧できる
- V-08 閲覧中に保存、エリア・カテゴリーの絞り込み、地図での確認を行える
- V-09 掲載をエリアとカテゴリーで絞り込める。それぞれ複数選べる。エリアは都道府県・市区町村・町域のどの単位でも選べる
- V-10 選択中の条件を確認し、変更・解除できる
- V-11 店舗・地域・掲載・イベント・読みものをキーワードで探せる。結果は種類ごとに分ける。提供開始前・提供終了の掲載、閉店した店舗、終了・中止したイベントも含め、状態を区別して表示する
- V-12 検索結果から各対象の詳細を閲覧できる
- V-13 結果がないことを把握し、検索語や条件を変更できる
- V-14 訪問先の位置を地図で確認し、地図と一覧の両方から探せる
- V-15 地図上の場所の概要を確認し、詳細を閲覧できる
- V-16 周辺や選択エリアの地域を探せる。地域の位置、または所属する店舗・スポットの所在地が選択エリアにある地域を、そのエリアの地域とする
- V-17 写真・名称・所在地から地域を選べる
- V-18 位置情報を利用しない場合もエリアの選択から探索を続けられる
- V-19 掲載詳細: 写真、名称、説明、カテゴリー、関連する店舗・地域・イベント、設定された開催日・提供期間
- V-20 店舗・スポット詳細: 写真、紹介、所在地、訪問に必要な情報、その場所の掲載、地図、すべての所属地域、参加するイベント
- V-21 地域詳細: 写真と紹介、所属する店舗・スポット、その場所の掲載、関連するイベント
- V-22 地域に所属する店舗・スポットと掲載を一覧で確認できる
- V-23 詳細から、関係のある掲載・店舗・地域・イベントと、その対象を紹介している読みものをたどれる
- V-24 イベントを一覧から探し、選べる
- V-25 イベントの写真・紹介・開催期間・開催場所・関連する地域を確認できる
- V-26 イベントの参加店舗と、参加に添えた掲載・参加日を確認できる。提供開始前の掲載はそれと分かるように表示する
- V-27 参加店舗の所在地を地図で確認できる
- V-28 イベントから見つけた店舗の所属地域をたどれる
- V-29 イベントと参加に添えた掲載をフィードにも紹介する。添えた掲載は他の掲載と同じ条件でフィードの対象とする
- V-30 読みものを一覧から探せる
- V-31 フィードで紹介された記事を開き、読みもの一覧も閲覧できる
- V-32 記事の写真と本文を読める
- V-33 記事から紹介先の詳細を閲覧できる
- V-34 掲載と店舗・スポットを保存・解除できる
- V-35 保存一覧から見返し、詳細を閲覧できる
- V-36 保存済みかどうかが分かり、保存・解除の結果を一覧で確認できる
- V-37 保存がない、検索結果がない、地域やイベントに閲覧できる掲載がない、を区別できる
- V-38 読み込み中・通信エラー・位置情報未許可を区別し、再試行や別の探索手段を選べる
- V-39 保存対象が非公開・削除になった場合、閲覧できないことを把握し、保存を解除できる
- V-40 休業・閉店・提供開始前・提供終了を営業中・提供中と区別できる。イベントの開催前・終了・中止を開催中と区別できる
- V-41 ログインせずに保存でき、保存は端末に残る。ログインすると保存をアカウントに引き継ぎ、別の端末からも見返せる
- V-42 開催前のイベントを開催予定として一覧・フィード・詳細で確認できる
- V-43 終了・中止したイベントは、一覧・フィード・掲載/店舗/地域の詳細の関連イベントに表示しない。詳細では終了・中止を確認して閲覧できる
- V-44 フィードの対象は公開中の対象から自動で選ぶ。提供開始前・提供終了の掲載、閉店した店舗の掲載、終了・中止したイベントは対象外。休業中の店舗の掲載は対象
- V-45 位置情報を許可した閲覧者には現在地に近い掲載・地域・イベントを、許可しない閲覧者には新しい掲載を優先する。どちらも同じ店舗・同じ地域の掲載が連続しないように混ぜる
- V-46 地域・イベント・読みものを掲載の間に一定の間隔で紹介する。地域はフィード対象の掲載を持つもの、イベントは開催前または開催中で参加店舗を持つものに限る
- V-47 エリア・カテゴリーの選択中はフィードを絞り込む。掲載は V-09 の条件、地域は条件に合うフィード対象の掲載を持つもの、イベントは開催場所が選択エリアにあるもの（カテゴリーでは絞らない）、読みものは絞り込まない
- V-48 検索結果は関連度の高い順、絞り込みの結果はフィードと同じ順、イベントの一覧は開催日の順
- V-49 エリア・カテゴリーの条件をフィード・地図・一覧で共有する
- V-50 地域をその位置で地図に表示する。広がりは所属店舗の位置で確認できる
- V-51 メールアドレスまたは外部アカウントでログインできる。メールアドレスでのログインにパスワードを使わない
- V-52 端末の保存に期限を設けない。保存一覧で、端末のデータ消去で保存が失われることと、ログインによる引き継ぎを案内する
- V-53 退会できる。保存・管理権限・役割を失う。確認中・差し戻し中の申請は取り下げ。店舗管理者として行った申請は取り下げず、他の店舗管理者が引き続き扱う。公開済みの内容は残す。サービス運営者が1人だけの間、そのサービス運営者は退会できない
- P-30 地域・イベント・読みものを挿入する間隔の値は画面設計で定める（REQ 6.1）。APX 2 の代表画面は「地域 → 掲載6件 → 読みもの → 掲載6件 → 地域」
- P-31 地域は位置を1点で持ち、範囲の図形を持たない（REQ 6.3、B-38）
- P-32 関連情報の選び方は画面設計で定める（REQ 6.4）
- P-33 アカウントにはメールアドレスを必須とし、通知の宛先に使う（REQ 6.7、B-40）
- P-34 最後の管理者が退会した対象は管理者不在として扱う。最後の店舗管理者が退会した店舗の、店舗管理者として行った申請は失効とする（REQ 6.7）

### 店舗の登録・修正・管理（REQ 7）

- M-01 店舗情報の閲覧や店舗向け案内から管理権限の申請に進める
- M-02 店名・住所で既存店舗を確認できる。写真のない店舗も対象。申請にはアカウントの作成とログインが必要
- M-03 新規店舗の登録を申請でき、サービス運営者の承認後に公開する
- M-04 店舗の管理権限を申請でき、サービス運営者の承認後に権限を得る
- M-05 申請の確認状況、追加で必要な確認、承認結果を把握できる。管理権限申請では既存管理者の有無に応じた案内を受ける
- M-07 代理登録された店舗について、店舗本人が管理権限を取得して管理を引き継げる
- M-08 管理権限を持つ店舗の情報、掲載、対応が必要な申請、公開内容を確認できる
- M-09 公開中・下書き・非公開の掲載と、提供終了した掲載を確認できる
- M-10 店舗管理者は店舗名、写真、紹介、住所・位置、営業時間、連絡先を申請なしで更新できる
- M-11 管理者のいない店舗の情報修正と休業・閉店を利用者が申請でき、承認内容を反映する。管理者のいる店舗への修正申請は受け付けず、M-48 の連絡を案内する
- M-12 店舗管理者は管理メンバーを招待でき、複数の店舗管理者を置ける。招待されたメンバーは同じ操作範囲を持つ
- M-13 店舗管理者は休業・閉店を登録し、営業状況の変化を閲覧者に伝えられる。営業中に戻せる
- M-15 商品・体験・景色・見どころを共通の掲載として登録できる
- M-16 公開する掲載は写真・名称・カテゴリーが必須。説明と、提供期間または開催日は任意。提供期間と開催日はどちらか一方だけ。価格とキャッチコピーの入力を求めない
- M-17 運営が提供するカテゴリーから1つを選び、設定・変更できる
- M-18 管理中の店舗を掲載に紐づけ、所在地・所属地域を店舗情報から参照する
- M-19 写真を変更し、閲覧者に見せる範囲を調整できる
- M-20 公開前に閲覧者への見え方を確認できる
- M-21 下書きを保存し、後から編集・公開できる
- M-22 公開中の掲載を編集・一時非公開・提供終了にできる。掲載を複製して作成できる
- M-23 公開した掲載と、その店舗の公開内容を確認できる
- M-24 提供終了した掲載で終了を知らせ、店舗や別の掲載へ案内する。提供終了の掲載をフィードから除外する
- M-25 サービス運営者は管理者のいない店舗の掲載を代理で作成・公開できる
- M-26 利用者は管理者のいない店舗の掲載を申請でき、承認後に公開する。管理者のいる店舗への掲載申請は受け付けない
- M-27 代理作成と申請の掲載にも写真・名称・カテゴリーの公開条件を適用する
- M-28 1人の利用者が複数の店舗を管理できる
- M-29 提供期間の終了日を過ぎた掲載を自動で提供終了とする。提供期間のない掲載は店舗管理者が提供終了にする
- M-30 提供期間の開始日より前の掲載は提供開始前として詳細を閲覧でき、開始日を確認できる。フィードの対象にしない
- M-31 店舗管理者が提供終了にした掲載は提供中に戻せる。自動で提供終了になった掲載は、提供期間の更新または開催日の追加で提供中に戻る
- M-32 公開中の掲載への編集は保存した時点で反映する
- M-33 一時非公開の掲載を再公開できる。掲載を削除でき、復元できない
- M-34 店舗・スポットの公開には名称・所在地・位置が必須。写真は任意
- M-35 管理者のいない店舗の掲載はサービス運営者が更新・一時非公開・提供終了・削除する。利用者は公開された掲載の修正を申請でき、承認内容を反映する。管理者のいる店舗の掲載への修正申請は受け付けない
- M-36 店舗管理者が管理権限を取得すると、その店舗のすべての掲載が管理下に入り、編集・一時非公開・削除できる。運営による非公開の掲載は再公開できない
- M-37 写真を登録する利用者は、自ら撮影または許諾を得た写真であることと Lunt での利用に同意する。申請に添える写真と、申請なしで登録する写真の両方に適用する
- M-38 サービス運営者は掲載申請の承認時に内容と写真の品質を確認する
- M-39 店舗本人と写真の権利者は、ログインせずに取り下げを申し立てられる。店舗本人は掲載と店舗の詳細から、写真の権利者は掲載・店舗・地域・イベント・読みものの詳細から。理由・立場・メールアドレスを添える。サービス運営者は対象の写真の削除または掲載・店舗の非公開を行い、結果をメールで連絡する。サービス運営者は申立てに基づいて地域・イベント・読みものの写真も削除できる
- M-40 管理権限の申請者は店舗との関係と、確認に使える連絡先または資料を添える。追加の確認が必要なら差し戻す
- M-41 掲載に複数の写真を登録し、並び替えられる。1枚目が代表写真
- M-42 掲載に任意で複数の開催日を登録できる。時刻・定員・予約は項目にせず、説明で案内する。最初の開催日より前から提供中、最後の開催日を過ぎると自動で提供終了
- M-43 サービス運営者は掲載を運営による非公開にできる。閲覧できず、店舗管理者は再公開できない。サービス運営者だけが解除できる
- M-44 サービス運営者は店舗を非公開にでき、解除できる。紐づく掲載は閲覧できず、所属店舗・参加店舗にも表示しない。解除後は掲載を元の公開状態で閲覧できる
- M-45 登録申請に管理権限の申請を併せて提出できる。それぞれ判断する。登録を否認した場合、併せた管理権限の申請は失効
- M-46 サービス運営者は管理者のいない店舗の情報と営業状況を申請なしで更新できる
- M-47 店舗管理者は店舗を自ら非公開・削除できない。やめる場合は M-39 で申し立てる
- M-48 利用者は管理者のいる店舗とその掲載について、情報の誤りと閉店をサービス運営者に連絡できる。ログインが必要。サービス運営者は店舗管理者に確認を依頼し、対応がない場合は O-16 で管理権限を解除し、M-46（店舗の情報と営業状況）と M-35（掲載の更新・一時非公開・提供終了・削除）で情報を更新できる
- M-49 申立てによる写真の削除で公開条件を満たさなくなった掲載は一時非公開、地域・イベント・読みものは公開を取り下げる。写真を登録して再び公開できる。管理者のいない店舗の掲載はサービス運営者が再公開する
- P-40 店舗登録の承認だけでは申請者に管理権限を付与しない。登録が承認された店舗は管理者や掲載がなくても公開できる（REQ 7.1、B-03）
- P-41 既存の店舗管理者がいる店舗への管理権限申請では招待を案内する。申請も受け付け、サービス運営者が既存管理者との関係を確認して判断する（REQ 7.1）
- P-42 登録申請は非公開の店舗とも照合し、重複する申請は否認する。公開する場合は非公開を解除する（REQ 7.1、B-60）
- P-43 写真のない店舗も詳細・地図・検索結果・各一覧に表示する。一覧ではその場所の公開中の掲載の代表写真で代用し、代用できなければ写真なしで表示する（REQ 7.1、B-57）
- P-44 修正申請に管理権限の取得は必要ない。管理権限の有無にかかわらず、地域への所属・離脱は申請・承認による（REQ 7.2）
- P-45 閉店した店舗の公開に期限を設けない（REQ 7.2、B-09）
- P-46 店舗管理者はイベント参加を申請し、その店舗の公開中の掲載（提供開始前を含む）と参加日を添えられる（REQ 7.4）
- P-47 REQ 7.6 はすべての掲載と店舗に適用する。写真の権利への同意と権利者による申立ては地域・イベント・読みものにも適用する。申立人との連絡はメールで行う（REQ 7.6）

### 地域・イベントの運営（REQ 8）

- R-01 地域運営者は地域の名称・所在地・位置・写真・紹介・キャッチコピーを更新できる
- R-02 地域運営者は地域を公開し、公開を取り下げられる
- R-03 地域運営者は所属店舗と、所属・離脱の申請を確認できる
- R-04 地域運営者の権限は地域情報と所属関係の管理に限る。所属店舗の情報・掲載の更新にはその店舗の管理権限が必要
- R-05 店舗管理者は所属を申請できる。管理者のいない店舗は利用者が申請できる。地域の運営者の承認後に反映する
- R-06 店舗管理者は離脱を申請できる。管理者のいない店舗は利用者が申請できる。地域の運営者の承認後に解除する
- R-07 地域運営者は所属店舗を除外できる
- R-08 所属・離脱の申請は地域ごとに独立し、他の地域の所属に影響しない
- R-09 申請者は所属・離脱申請の確認状況と結果を把握できる。店舗管理者は所属関係の変更結果を確認できる
- R-10 所属の承認・離脱の承認・除外を、地域の所属店舗情報と店舗・掲載の所属地域情報に反映する
- R-11 運営者が不在の地域ではサービス運営者が承認・除外する。運営者が一定の期間確認しない申請もサービス運営者が代行して承認・否認できる
- R-12 店舗管理者は代表地域を所属地域から選べる
- R-13 地域運営者はイベントの関連づけを確認し、解除できる。解除された地域には同じイベントを再び関連づけられない。解除は取り消せる。運営者が不在の地域ではサービス運営者が行う
- R-14 公開する地域は名称・所在地・位置・写真が必須。紹介・キャッチコピーは任意
- R-15 運営者が不在の地域ではサービス運営者が更新・公開・取り下げできる。サービス運営者は運営者の有無にかかわらず地域を運営による非公開にできる。地域運営者は公開できず、サービス運営者だけが解除でき、解除後は元の公開状態に戻る
- E-01 イベント運営者は名称・開催期間・開催場所（所在地・位置）・写真・紹介・キャッチコピー・関連する地域を更新できる
- E-02 イベント運営者はイベントを公開し、公開を取り下げられる
- E-03 イベント運営者は参加店舗と参加の申請を確認できる
- E-04 イベント運営者の権限はイベント情報と参加関係の管理に限る。参加店舗の情報・掲載の更新にはその店舗の管理権限が必要
- E-05 店舗管理者は参加を申請でき、掲載と参加日を添えられる。イベントの運営者の承認後に反映する
- E-06 イベント運営者は参加店舗を除外できる
- E-07 店舗管理者は参加申請の確認状況と結果を把握できる
- E-08 参加の承認・取りやめ・除外と参加内容の変更を、イベントの参加店舗情報と店舗・掲載のイベント情報に反映する
- E-09 運営者が不在のイベントではサービス運営者が承認・除外する。一定の期間確認しない申請も代行できる
- E-10 店舗管理者は承認なしで参加を取りやめ、添えた掲載・参加日を変更できる。イベント運営者は変更内容を確認できる
- E-11 イベント運営者は管理者のいない店舗を参加店舗として直接追加でき、公開中の掲載と参加日を添えられる。管理者のいない店舗の参加内容は、成立の経緯にかかわらずイベント運営者が変更できる。運営者が不在ならサービス運営者。店舗管理者が就いた後は店舗管理者が取りやめと変更を行う
- E-12 イベント運営者は承認なしで開催地域を関連づけられる。地域運営者が解除した地域には再び関連づけられない
- E-13 公開するイベントは名称・開催期間・開催場所・写真が必須。紹介・キャッチコピー・関連する地域は任意
- E-14 イベント運営者はイベントを中止にでき、取り消せる。中止は終了と同じ範囲に表示し、詳細で確認できる
- E-15 運営者が不在のイベントではサービス運営者が更新・公開・取り下げ・中止できる。運営による非公開は R-15 と同じ扱い
- P-50 地域・イベントはサービス運営者が登録し、公開できる。運営者の管理権限はサービス運営者が付与する（REQ 8.1、8.3）
- P-51 管理権限のない利用者からの地域・イベントの情報修正は受け付けない（REQ 8.1、B-43）

- O-01 登録申請を確認し、承認する
- O-02 管理者のいない店舗への修正申請と休業・閉店の申請を確認し、反映する
- O-03 管理権限申請を確認し、承認した利用者に権限を付与する
- O-04 追加確認、既存管理者との関係確認、重複店舗の照合（非公開の店舗も対象）に対応する
- O-05 公開条件を満たす情報で申請なしに店舗を代理登録し、店舗本人への引き継ぎに対応する
- O-06 カテゴリーを管理する（追加・変更・廃止）。廃止するカテゴリーの掲載を移行先に付け替える
- O-07 イベントを登録・公開し、イベント運営者に管理権限を付与する
- O-08 編集担当者が読みもののタイトル・写真・本文・紹介先リンクを作成・編集・公開し、公開を取り下げられる。紹介先は掲載・店舗・地域・イベント。公開にはタイトル・写真・本文が必須
- O-09 編集担当者が紹介先の変化に応じて紹介内容を修正できる
- O-10 地域を登録・公開し、地域運営者に管理権限を付与する
- O-11 地域所属の代行承認（R-11 と同旨）
- O-12 イベント参加の代行承認（E-09 と同旨）
- O-13 管理者のいない店舗の掲載を代理で作成・公開する
- O-14 掲載申請を内容と写真の品質を確認して承認し公開する。掲載の修正申請を確認し反映する
- O-15 管理者のいない店舗の掲載を更新・一時非公開・提供終了・削除する
- O-16 店舗・地域・イベントの管理者の権限を解除する。編集担当者の任命を解く
- O-17 編集担当者が公開前に読みものの見え方を確認する
- O-18 重複する店舗の一方を非公開にする。掲載・所属地域・イベント参加・保存は残す店舗に引き継がない
- O-19 管理者のいない店舗の情報と営業状況を申請なしで更新する
- O-20 運営者が不在の地域・イベントの情報を更新・公開・取り下げる。運営者が不在のイベントを中止にする
- O-21 取り下げの申立てを確認し、掲載・店舗・地域・イベント・読みものの写真の削除、または掲載・店舗の非公開を行い、結果をメールで連絡する
- O-22 掲載・地域・イベントを運営による非公開にし、店舗を非公開にする。解除する。対象は店舗管理者・運営者が公開できない
- O-23 サービス運営者の役割を付与・解除する。最初のサービス運営者は開設時に設定する。1人だけの間は解除できない
- O-24 管理者のいる店舗への連絡を確認し、店舗管理者に確認を依頼する。対応がなければ権限を解除して、店舗の情報と掲載を更新する（M-48 と同旨）
- P-60 編集担当者はサービス運営者が任命する。読みものの作成・編集・公開は編集担当者だけが行う（REQ 9、B-19）
- P-61 フィードに紹介する対象は自動で選び、運営・編集担当者による選定を必要としない（REQ 9）

### 申請と承認（REQ 10.1）

- P-70 REQ 10.1 の表の30行が、対象ごとの申請者・実行者、承認者、反映する内容を定める。承認を必要とする対象は、店舗の新規登録、管理者のいない店舗の情報修正と休業・閉店、店舗の管理権限取得、地域所属、地域からの離脱、イベント参加、管理者のいない店舗の掲載、その掲載の修正の8種。行は次のとおり（実行者 / 承認者 / 反映）
  - 01 店舗の新規登録: 利用者（管理権限の申請を併せられる） / サービス運営者 / 店舗情報の公開
  - 02 管理者のいない店舗の情報修正、休業・閉店: 利用者 / サービス運営者 / 修正内容、営業状況
  - 03 管理者のいない店舗の情報と営業状況の更新: サービス運営者 / 不要 / 店舗情報の更新
  - 04 店舗の管理権限取得: 利用者 / サービス運営者 / 管理権限
  - 05 管理権限を持つ店舗の通常更新: 店舗管理者 / 不要 / 店舗情報の更新
  - 06 店舗・地域・イベントの管理メンバー招待: 対象の管理者 / 不要 / 招待された利用者の管理権限
  - 07 管理権限の辞任: 管理者本人 / 不要 / 本人の管理権限の解除
  - 08 管理権限の解除: サービス運営者 / 不要 / 対象者の管理権限の解除
  - 09 取り下げの申立て: 店舗本人または写真の権利者 / サービス運営者（申請の進み方は適用しない） / 写真の削除、または掲載・店舗の非公開
  - 10 情報の誤り・閉店の連絡: 利用者 / サービス運営者（申請の進み方は適用しない） / 店舗管理者への確認の依頼。対応がない場合は管理権限の解除と情報の更新
  - 11 運営による非公開とその解除: サービス運営者 / 不要 / 掲載・店舗・地域・イベントの非公開
  - 12 店舗の地域所属: 店舗管理者。管理者のいない店舗では利用者 / 地域の運営者。不在の場合と一定の期間確認しない場合はサービス運営者 / 所属の追加
  - 13 店舗の地域からの離脱: 12 と同じ / 12 と同じ / 所属の解除
  - 14 地域からの店舗除外: 地域の運営者。不在の場合はサービス運営者（一定の期間確認しない場合の代行はない） / 不要 / 所属の解除
  - 15 店舗のイベント参加: 店舗管理者 / イベントの運営者。不在の場合と一定の期間確認しない場合はサービス運営者 / 参加の追加
  - 16 参加の取りやめ、掲載・参加日の変更: 店舗管理者 / 不要 / 参加の解除、参加内容の更新
  - 17 イベントからの店舗除外: イベントの運営者。不在の場合はサービス運営者 / 不要 / 参加の解除
  - 18 管理者のいない店舗のイベント参加と参加内容の変更: イベントの運営者。不在の場合はサービス運営者 / 不要 / 参加の追加、参加内容の更新
  - 19 開催地域の関連づけ: イベントの運営者。地域運営者が解除した地域には再び関連づけられない / 不要 / 関連づけの追加
  - 20 関連づけの解除と、解除の取り消し: 地域の運営者。不在の場合はサービス運営者 / 不要 / 関連づけの解除、関連づけの回復
  - 21 イベントの中止と、中止の取り消し: イベントの運営者。不在の場合はサービス運営者 / 不要 / イベントの開催状態
  - 22 管理者のいない店舗の掲載: 利用者 / サービス運営者 / 掲載の公開
  - 23 管理者のいない店舗の掲載の修正: 利用者 / サービス運営者 / 修正内容
  - 24 管理者のいない店舗の掲載の代理作成: サービス運営者 / 不要 / 掲載の公開
  - 25 地域・イベントの新規登録: サービス運営者 / 不要 / 登録・公開
  - 26 運営者が不在の地域・イベントの情報更新、公開、公開の取り下げ: サービス運営者 / 不要 / 情報の更新、公開状態
  - 27 地域・イベントの管理権限付与: サービス運営者 / 不要 / 管理権限
  - 28 編集担当者の任命と解除: サービス運営者 / 不要 / 編集担当者の役割
  - 29 サービス運営者の役割の付与と解除: サービス運営者（1人だけの間は解除できない） / 不要 / 役割
  - 30 退会: 利用者本人（サービス運営者が1人だけの間、そのサービス運営者は退会できない） / 不要 / 保存・管理権限・役割の喪失、申請の取り下げ。店舗管理者として行った申請は取り下げない
- P-71 承認者は確認中の申請を承認するか、理由を添えて否認する。追加の確認が必要な申請は差し戻せる
- P-72 申請者は差し戻された申請を修正して再提出できる
- P-73 申請者は確認中または差し戻し中の申請を取り下げられる
- P-74 否認または取り下げの後、同じ対象に再申請できる
- P-75 同じ対象への複数の申請はそれぞれ独立して確認する。店舗登録の重複は照合と整理で扱う
- P-76 店舗管理者として行った申請は、その店舗のすべての店舗管理者が確認・修正・取り下げできる。申請した店舗管理者が権限を手放すか退会しても、他の店舗管理者がいる間は継続する
- P-77 前提を失った確認中・差し戻し中の申請は失効とし、申請者に通知する。失効の場合は次の7つ
  - a 管理者のいない店舗への情報修正・掲載・掲載修正・所属・離脱の申請中に、店舗管理者が就いた
  - b 店舗管理者として行った申請の確認中に、店舗管理者が不在になった
  - c 登録申請が否認または取り下げとなり、併せた管理権限の申請が残った
  - d 管理権限の申請者が招待でその店舗の店舗管理者になった
  - e 掲載の修正申請の対象の掲載が削除された
  - f 所属申請の対象の所属がすでに成立した、離脱申請の対象の所属が除外で解除された
  - g 参加申請の対象のイベントが終了または中止した
- P-78 地域運営者・イベント運営者が一定の期間確認しない申請は、サービス運営者が代行して承認・否認できる（B-52）
- P-79 取り下げの申立てと、情報の誤り・閉店の連絡には申請の進み方を適用しない

### 状態と公開範囲（REQ 10.2）

- P-83 地域・イベント・読みものは公開と公開の取り下げを区別する。地域・イベントは運営による非公開を公開状態とは別に扱う

- P-89 店舗登録、店舗管理権限、掲載の申請は、申請の確認中と承認済みを区別する（REQ 10.2）

### 適用するルール（REQ 10.3）

- B-01 フィード上の配置と地域への所属関係を独立して扱う
- B-02 掲載名・店名・地域名を区別し、価格を表示しない
- B-03 登録の承認と管理権限の承認を区別する。登録承認済みの店舗は管理者が未確定でも公開できる
- B-04 既存店舗を確認してから新規登録を申請する。管理者がいる店舗への対応も同じ店舗の情報を対象とする
- B-05 店舗管理者は通常情報を申請なしで更新できる。所属地域の追加・離脱には承認が必要
- B-06 所属の承認・離脱の承認・除外、参加の承認・除外で、店舗や掲載の公開・提供状態は変わらない
- B-07 公開中かつ提供中の掲載は自動でフィードの対象とする。読みものへの採用は掲載の公開と区別する
- B-08 掲載は写真・名称・カテゴリーを公開条件とする。地域紹介や読みものの執筆を公開条件にしない
- B-09 閉店した店舗とその掲載を新たな訪問先を発見する対象から除外する。詳細では閉店・提供終了を確認できる。公開に期限を設けない
- B-10 関連先が非公開になっても紹介元の公開を継続できる。非公開の対象情報は紹介元や保存一覧からも閲覧できない
- B-11 閉店・提供終了後も公開されている対象は状態を確認して閲覧できる
- B-12 記事本文は編集担当者が更新する。参照先の非公開で本文を自動で書き換えない
- B-13 店舗は複数の地域に所属できる。階層なし。所属・離脱は地域ごとに独立
- B-14 運営者が不在の地域・イベントではサービス運営者が承認・除外と情報の更新・公開・取り下げを代行する
- B-15 イベントは地域から独立。開催地域の関連づけは店舗の地域所属とイベント参加に影響しない
- B-16 掲載は店舗・スポットのいずれかに紐づく。スポットは店舗と同じ手続き
- B-17 管理者のいない店舗の掲載は代理作成または承認された申請で公開する
- B-18 閲覧と保存にログイン不要。申請と管理操作にログイン必要。取り下げの申立てはログイン不要
- B-19 読みものは編集担当者だけが作成・編集・公開する。申立てに基づく写真の削除はサービス運営者が行う
- B-20 管理者のいる店舗の所属・離脱は店舗管理者だけが申請できる。管理者のいる店舗への情報修正・掲載・掲載修正の申請は受け付けない
- B-21 複数の店舗管理者を置ける。招待にサービス運営者の承認は不要
- B-22 申請は6状態を区別する。否認には理由を添え、否認・取り下げの後は再申請できる。前提を失った申請は失効
- B-23 提供期間の終了日または最後の開催日を過ぎた掲載は自動で提供終了。開始日より前は提供開始前でフィード対象外。提供期間と開催日は一方だけ。開催日を登録した掲載は最初の開催日より前から提供中
- B-24 カテゴリーは1階層、掲載ごとに1つ、種類を兼ねる
- B-25 代表地域を1つ持つ。店舗詳細ではすべての所属地域を表示する。取り下げた地域は表示せず、代わりに公開中の所属地域のうち最初に所属した地域を表示する
- B-26 参加の取りやめと参加内容の変更に承認は不要
- B-27 削除した掲載は復元できない。紹介元や保存一覧から閲覧できない
- B-28 店舗・地域・イベントの管理者は管理メンバーを招待できる。同じ操作範囲。承認不要
- B-29 管理者は自分の権限を手放せる。引き継ぎは後任を招待した後に手放す
- B-30 他の管理者の権限の解除はサービス運営者だけが行う
- B-31 最後の管理者が権限を手放した対象は管理者不在として扱い、公開を継続する。店舗の掲載は下書きを含めてサービス運営者の管理下に入る。解除と退会による不在も同じ
- B-32 管理権限は期間の経過や利用状況で自動失効しない
- B-33 店舗は名称・所在地・位置を公開条件とし、写真を条件にしない
- B-34 管理者のいない店舗の掲載はサービス運営者が管理する。管理権限の取得で店舗管理者の管理下に入る
- B-35 終了・中止したイベントを発見の対象から除外する。詳細で確認できる。開催前は開催予定として紹介する
- B-36 管理者のいない店舗のイベント参加はイベント運営者による直接の追加で成立する。その参加内容はイベント運営者が変更できる
- B-37 開催地域の関連づけに地域運営者の承認は不要。地域運営者は解除でき、解除された地域には再び関連づけられない
- B-38 地域は位置を1点で持つ
- B-39 通知はメールで届け、サービス内の通知一覧でも確認できる。プッシュ通知は対象外
- B-40 アカウントにメールアドレス必須
- B-41 掲載・店舗・地域・イベントに複数の写真を登録でき、1枚目が代表写真。動画は扱わない
- B-42 兼任できる。権限は対象ごとに独立。承認者は自分の申請も承認できる
- B-43 管理権限のない利用者からの地域・イベントの情報修正は受け付けない
- B-44 重複する店舗は統合しない。一方を非公開にし、必要な掲載は残す店舗に作り直す
- B-45 初期のカテゴリーは4つ
- B-46 発見の場面と検索・詳細・保存一覧の表示範囲は REQ 10.2 による。休業中の店舗とその掲載は除外しない
- B-47 非公開の店舗の掲載は閲覧できない。解除すると元の公開状態で閲覧できる
- B-48 サービス運営者は管理者の有無にかかわらず掲載・店舗・地域・イベントを非公開にできる。運営による非公開はサービス運営者だけが解除できる
- B-49 申立てはすべての掲載と店舗を対象とする。写真の権利者の申立ては地域・イベント・読みものの写真も対象。申請の進み方を適用しない
- B-50 店舗管理者は店舗を自ら非公開・削除できない
- B-51 公開条件: 地域は名称・所在地・位置・写真、イベントは名称・開催期間・開催場所・写真、読みものはタイトル・写真・本文
- B-52 一定の期間確認しない申請はサービス運営者が代行できる
- B-53 写真を登録するすべての利用者は写真の権利と利用に同意する
- B-54 読みものは掲載・店舗・地域・イベントを紹介でき、紹介先から読みものをたどれる
- B-55 退会（V-53 と同旨）
- B-56 登録申請に管理権限の申請を併せられ、それぞれ判断する
- B-57 写真のない店舗も検索結果と各一覧に表示する
- B-58 サービス運営者の役割の付与・解除と、最後の1人の保護
- B-59 管理者のいる店舗の情報の誤りと閉店は利用者がサービス運営者に連絡する。申請に含めない
- B-60 登録申請は非公開の店舗とも照合し、重複は否認する
- B-61 申立てによる写真の削除で公開条件を欠いた掲載は一時非公開、地域・イベント・読みものは取り下げ。写真を登録すると再び公開できる

## 解釈

出典の文面が場面によって揺れる項目は、次の読みで統一する。詳細な要件の文面を要約の文面より優先し、REQ を APX より優先する。

- I-01 退会で取り下げになるのは、本人が個人として行った確認中・差し戻し中の申請（V-53）。REQ 10.1 の表と B-55 の「確認中の申請」は同じ範囲を指す
- I-02 店舗管理者が不在になったときに失効するのは、店舗管理者として行った確認中・差し戻し中の申請（REQ 10.1 の失効の柱書き）
- I-03 連絡に「店舗管理者が対応しない」の判断はサービス運営者が行い、システムは期間を持たない。店舗に店舗管理者が残っている間は M-46・M-35 の更新はできず、サービス運営者は O-16 でその店舗のすべての店舗管理者の権限を解除してから更新する
- I-04 REQ 10.2 の「地図」は探索の地図（V-14、V-15）を指す。イベントの参加店舗の地図（V-27）は「イベント詳細の参加店舗」、店舗詳細の地図（V-20）は「店舗詳細」の範囲に従い、閉店した店舗も状態を区別して表示する
- I-05 編集担当者は役割で、すべての編集担当者がすべての読みものを編集できる。編集担当者への通知は全員に届ける。サービス運営者は自分を編集担当者に任命できる（P-04）
- I-06 写真を持つ対象（掲載・店舗・地域・イベント・読みもの）は、順序のある複数の写真を持ち、1枚目を代表写真とする。見せる範囲の調整は掲載の写真だけが持つ（M-19）
- I-07 イベントもフィードでは大きな枠で紹介する（V-46）。APX 4 の「ジャンル別フィード」はカテゴリーで絞り込んだフィード、「イベント未開催」はイベントの一覧に表示できるイベントがない状態を指す。イベントの一覧への入口は pages が定める
- I-08 イベントの開催前・開催中・終了は、開催期間と現在の日付から自動で決まる。終了後に開催期間を未来へ更新すると、開催前または開催中に戻る。失効した参加申請は戻らず、再申請する
- I-09 地域探索（地域の一覧と地図上の地域）で「選択エリアにある地域」は V-16 の定義により、カテゴリーの条件は地域の表示に効かない。フィードに紹介する地域は V-47 の定義による
- I-10 同じ申請者（個人、または店舗管理者としての店舗）は、同じ種類・同じ対象で確認中・差し戻し中の申請を持つ間、重ねて申請できない（P-74 が再申請を否認・取り下げの後に置くことの帰結）。P-75 の独立した確認は、別の申請者の申請どうしに適用する。新しく対象を作る申請（店舗の新規登録、掲載の申請）には「同じ対象」がなく、この制限はかからない
- I-11 M-11 の「休業・閉店の申請」は営業状況の修正の申請で、営業中へ戻す修正も含む
- I-12 既存店舗の確認（M-02）にログインは要らず、申請へ進むときにログインを求める（B-18）
- I-13 代行（P-78）でできるのは承認と否認。期間は申請が確認中になった時点から数える
- I-14 運営者が不在のイベントの開催地域の関連づけは、イベント情報の更新（E-01・E-15）に含まれ、サービス運営者が行える
- I-15 運営による非公開は公開状態に重なる別の状態で、その間は公開状態を変更できず、解除で元の公開状態に戻る（R-15・E-15・M-44 の「元の公開状態」を掲載にも適用する）。情報の更新はできる
- I-16 管理者・運営者が不在の対象への管理者・運営者宛ての通知は、代行するサービス運営者に届ける（B-14・B-31）
- I-17 ログアウトとメールアドレスの変更は出典になく、設計しない
- I-18 メールアドレスでのログインのワンタイムのリンクとコードには有効期間があり、コードは誤入力の回数の上限で無効になる（V-51 のパスワードを使わないログインを安全に成り立たせるため。値は設定）
- I-19 申請の失効（P-77）は「申請の種類ごとの前提が成り立たなくなった」という1つの規則で、P-77 の a〜g はその例。参加の申請の前提は、所属の申請（P-77 f）と同じく「その店舗の参加がまだない」を含む。離脱の申請の前提は「その所属がある」で、別の離脱の申請の承認で所属が解除された場合も失効する
