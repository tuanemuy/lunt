デザイン・画面構成・プロトタイプは、[付属資料](design-appendix.md)にまとめる。機能と業務上のルールは本書を優先する。

## 2. サービス概要

### 2.1 目的

Lunt（ラント）は、地域のお店・商品・体験・景色・見どころを写真から発見するアプリである。利用者は目的を決めずに眺め、気になるものを入口に店舗や地域へ関心を広げる。

提供する体験は「眺める → 気になる → お店や地域を知る → 行ってみたくなる」とする。特定のものを探す検索と、偶然の発見を提供する。

### 2.2 体験の方針

- 目的やカテゴリーを選ばずに閲覧を始められる。
- 商品・体験・景色・見どころを、写真を入口として混在させる。
- 個別の掲載を中心に、地域・イベント・読みものを織り交ぜて紹介する。
- 商店街・横丁などを、まとまりと雰囲気のある地域として扱う。
- 祭り・マルシェなど期間を定めた催しを、店舗が参加するイベントとして扱う。
- 掲載、店舗・スポット、地域、イベント、読みものの関連をたどれる。
- エリア・カテゴリーによる絞り込み、地図、保存で発見を補助する。
- 個別の掲載は価格を表示せず、キャッチコピーを登録条件にしない。

### 2.3 提供形態

閲覧者向け機能と、店舗・地域・イベント・運営の管理機能は、同じWebサービスとして提供する。閲覧者向け機能はスマートフォンでの利用を中心とする。

## 3. 利用者と対象範囲

### 3.1 利用者・管理主体

| 主体 | 役割 |
| --- | --- |
| 閲覧者 | 掲載や地域を探し、詳細・地図を確認し、気になる対象を保存する |
| 申請者 | 店舗・スポットの登録・情報修正・管理権限取得を申請する。管理者のいない店舗・スポットについて、地域所属・離脱と掲載を申請する |
| 店舗管理者 | 管理権限を持つ店舗の情報・掲載を更新し、掲載にカテゴリーを設定する。地域への所属・離脱、イベントへの参加を申請する。管理メンバーを招待する |
| 地域運営者 | 管理権限を持つ地域の情報を整備し、店舗の所属・離脱申請を承認し、所属店舗を除外する |
| イベント運営者 | 管理権限を持つイベントの情報を整備し、店舗の参加申請を承認し、参加店舗を除外する |
| 編集担当者 | サービス運営者の任命を受けて読みものを作成・編集・公開し、掲載・店舗・地域を紹介する |
| サービス運営者 | 店舗の登録・修正・管理権限申請と掲載の申請を承認し、カテゴリー管理、重複店舗対応、店舗・掲載の代理登録などを行う。地域・イベントを登録し、その運営者に管理権限を付与する。運営者が不在の地域・イベントでは、運営者の承認を代行する |

役割は業務上の責任を表す。同じ人が複数の役割を持つ場合の権限構成は未決とする。

## 4. 扱う情報

### 4.1 用語

| 用語 | 定義 | 主な情報 |
| --- | --- | --- |
| エリア | 町域に設定された郵便番号に対応する地理的な区分 | 郵便番号、対応する住所・町域 |
| 地域 | 商店街、横丁、温泉街、旧市街などのまとまり | 名称、所在地、写真、紹介、位置、所属する店舗・スポット |
| 店舗・スポット | カフェ、雑貨店、神社、公園など、訪問先となる場所 | 名称、写真、紹介、所在地、位置、訪問情報、所属地域 |
| 掲載 | 商品・体験・景色・見どころなど、興味を持つ直接のきっかけ | 名称、写真、説明、カテゴリー、店舗・スポットとの関係、提供期間 |
| イベント | 祭り、マルシェなど、期間を定めて開催され、店舗・スポットが参加する催し | 名称、開催期間、開催場所、写真、紹介、関連する地域、参加する店舗・スポット、参加に添えた掲載・参加日 |
| カテゴリー | サービス運営者が提供する、掲載を分類するための区分 | 名称 |
| 読みもの | テーマに沿って地域や掲載を紹介する記事・特集 | タイトル、写真、本文、紹介する掲載・店舗・地域へのリンク |
| 保存情報 | 閲覧者が後から見返すために残した掲載、店舗・スポット | 保存対象、保存した利用者または端末 |
| 管理権限 | 店舗・地域・イベントを管理する権限 | 管理対象、管理者 |
| 申請 | 登録・修正・管理権限取得・所属・離脱・イベント参加・掲載について、承認を求めるもの | 申請者、対象、申請内容、確認状況、承認結果 |

主な情報の必須条件は、各機能の要件で定める。「読みもの」の正式な呼称は未決とする。

### 4.2 エリアと地域

エリアは町域に設定された郵便番号を単位とする。事業所固有の郵便番号は、独立したエリアとして扱わない。店舗・スポットの所在地からエリアを判断し、紐づく掲載の絞り込みに使う。

地域はエリアから独立したまとまりであり、複数のエリアにまたがることができる。店舗の地域所属は、所属申請の承認によって成立する。

地域に階層は設けない。地域の範囲は互いに重なってよい。店舗は複数の地域に所属できる。

複数の地域に所属する店舗は、代表地域を1つ持つ。店舗管理者が所属地域から代表地域を選ぶ。選ばない場合と、代表地域との所属が解除された場合は、残る所属のうち最初に所属した地域を代表地域とする。

### 4.3 イベント

イベントは期間を定めて開催される催しであり、地域から独立したまとまりとする。開催地域を任意で関連づけられ、複数の地域にまたがることができる。

店舗のイベント参加は、参加申請の承認によって成立する。参加には、イベントで提供する掲載と参加日を添えられる。

### 4.4 カテゴリー

サービス運営者がカテゴリーを管理し、店舗管理者が掲載に設定する。公開する掲載にはカテゴリーを必須とする。

カテゴリーは1階層とし、掲載ごとに1つを設定する。カテゴリーは掲載の種類を兼ね、掲載に別の種類項目を設けない。カテゴリーを廃止する場合は、サービス運営者が移行先を指定し、既存の掲載を付け替える。

カテゴリーの具体的な構成は未決とする。

### 4.5 情報の関係

- 掲載から、紐づく店舗・スポットと所属地域をたどれる。
- 店舗・スポットから、その場所の掲載、所属地域、参加するイベントをたどれる。
- 地域から、所属する店舗・スポット、その場所の掲載、関連するイベントをたどれる。
- イベントから、参加する店舗・スポット、参加に添えた掲載、関連する地域をたどれる。
- 読みものから、紹介した掲載・店舗・地域をたどれる。
- フィードで隣り合う地域と掲載の所属関係は、登録された所属情報に基づく。

読みものはサービス全体に属し、地域・イベント・店舗には所属しない。記事内で紹介する対象との関連は、読みものの所属を表さない。

掲載は店舗・スポットのいずれかに紐づく。店舗に属さない景色・見どころは、その場所をスポットとして登録し、掲載を紐づける。スポットは店舗と同じ手続きで登録・修正・管理する。

## 5. 主な利用シナリオ

| ID | シナリオ | 流れ・到達点 |
| --- | --- | --- |
| UC-01 | なんとなく眺める | 写真を見る → 掲載詳細を開く → 店舗や地域に関心を広げる |
| UC-02 | 気になった店の周囲を知る | 掲載 → 店舗 → 地域 → 別の掲載・店舗 → 地図で位置を確認する |
| UC-03 | エリアや地域から探す | エリアを選ぶ、または地域を探す → 掲載・店舗を確認する |
| UC-04 | イベントから探す | イベントを選ぶ → 参加店舗と、参加に添えた掲載を見る → 店舗の位置や所属地域を確認する |
| UC-05 | 記事から興味を広げる | 読みもの一覧 → 記事 → 紹介された掲載・店舗・地域を見る |
| UC-06 | 後から見返す | 閲覧中に保存 → 保存一覧 → 詳細や地図を再確認する |
| UC-07 | 店舗を登録する | 既存店舗を確認する → 新規店舗の登録を申請する → サービス運営者が承認する → 店舗情報が公開される |
| UC-08 | 店舗の管理を始める | 対象店舗の管理権限を申請する → サービス運営者が承認する → 店舗情報を更新する |
| UC-09 | 管理権限のない店舗の情報を直す | 修正を申請する → サービス運営者が承認する → 承認内容が反映される |
| UC-10 | 店舗の魅力を掲載する | 写真・名称・カテゴリーを設定する → 公開前に確認する → 公開する |
| UC-11 | 地域に所属する | 所属を申請する → 対象地域の運営者が承認する → 地域との所属関係が反映される |
| UC-12 | 地域から離脱する | 離脱を申請する → 対象地域の運営者が承認する → 所属が解除される |
| UC-13 | 所属店舗を除外する | 地域運営者が対象店舗を地域から除外する → 所属が解除される |
| UC-14 | イベントに参加する | 提供する掲載と参加日を添えて参加を申請する → 対象イベントの運営者が承認する → イベントとの参加関係が反映される |
| UC-15 | 管理者のいない場所の魅力を掲載する | 対象の店舗・スポットを確認する → 掲載を申請する → サービス運営者が承認する → 掲載が公開される |

## 6. 閲覧者向け機能要件

| 店舗の新規登録 | 登録を希望する利用者 | サービス運営者 | 店舗情報の公開 |
| 管理権限のない店舗の情報修正 | 修正を希望する利用者 | サービス運営者 | 承認された修正内容 |
| 店舗の管理権限取得 | 管理を希望する利用者 | サービス運営者 | 対象店舗の管理権限 |
| 管理権限を持つ店舗の通常更新 | 店舗管理者 | 承認不要 | 店舗情報の更新 |
| 店舗・地域・イベントの管理メンバー招待 | 対象の管理者 | 承認不要 | 招待された利用者の管理権限 |
| 管理権限の辞任 | 対象の管理者本人 | 承認不要 | 本人の管理権限の解除 |
| 管理権限の解除 | サービス運営者 | 承認不要 | 対象者の管理権限の解除 |
| 掲載の取り下げの申立て | 店舗本人または写真の権利者 | サービス運営者 | 掲載の取り下げ |
| 店舗の地域所属 | 店舗管理者。店舗管理者のいない店舗・スポットでは、所属情報の修正を希望する利用者 | 対象地域の運営者。不在の場合はサービス運営者 | 所属の追加 |
| 店舗の地域からの離脱 | 店舗管理者。店舗管理者のいない店舗・スポットでは、所属情報の修正を希望する利用者 | 対象地域の運営者。不在の場合はサービス運営者 | 所属の解除 |

| イベントからの店舗除外 | 対象イベントの運営者。不在の場合はサービス運営者 | 別途の承認不要 | 参加の解除 |
| 管理者のいない店舗・スポットのイベント参加 | 対象イベントの運営者。不在の場合はサービス運営者 | 承認不要 | 参加の追加 |

| 管理者のいない店舗・スポットの掲載 | 掲載を希望する利用者 | サービス運営者 | 掲載の公開 |
| 管理者のいない店舗・スポットの掲載の代理作成 | サービス運営者 | 承認不要 | 掲載の公開 |
| 地域・イベントの新規登録 | サービス運営者 | 承認不要 | 地域情報・イベント情報の登録 |
| 地域・イベントの管理権限付与 | サービス運営者 | 承認不要 | 対象地域・イベントの管理権限 |

承認を必要とするすべての申請は、次の進み方に従う。

- 承認者は確認中の申請を承認するか、理由を添えて否認する。追加の確認が必要な申請は、申請者に差し戻せる。
- 申請者は、差し戻された申請の内容を修正して再提出できる。
- 申請者は、確認中または差し戻し中の申請を取り下げられる。
- 否認または取り下げの後、同じ対象に再申請できる。
- 同じ対象への複数の申請は、それぞれ独立して確認する。店舗登録の重複は、O-04の照合・統合で扱う。

### 10.2 状態と公開範囲

| 対象 | 業務上区別する状態・条件 |

| 店舗管理権限 | 申請の確認中と承認済みを区別する |

| 掲載の公開 | 下書き・公開・一時非公開を区別する |
| 掲載の提供 | 提供開始前・提供中・提供終了を公開状態とは別に扱う |
| 地域・イベント・読みもの | 公開されている情報と、公開を取り下げた情報を区別する |
| イベントの開催 | 開催前・開催中・終了を公開状態とは別に扱う |

| 保存 | 保存済みかどうかと、対象を閲覧できるかどうかを区別する |

### 10.3 適用するルール

| AC-34 | イベント運営者が承認なしで開催地域を関連づけられ、地域詳細に関連するイベントが表示される。地域運営者は関連づけを解除できる | V-21、R-13、E-12、B-37 |
| AC-35 | 公開中かつ提供中の掲載と、公開中の地域・イベント・読みものが、選定の操作なしでフィードに紹介される。提供開始前の掲載はフィードに表示されない | V-44、M-30、B-07、B-23 |
| AC-36 | キーワードで店舗・地域・掲載・イベント・読みものを探し、種類ごとに分かれた結果から詳細を閲覧できる。結果がない場合は検索語や条件を変更できる | V-11、V-12、V-13、V-48 |
| AC-37 | 1人の利用者が複数の店舗の管理権限を持ち、それぞれの店舗を管理できる | M-08、M-28 |

| AC-40 | 複数選んだエリア・カテゴリーの条件が、フィード・地図・一覧で共有される。地域が位置で地図に表示される | V-09、V-47、V-49、V-50、B-38 |
